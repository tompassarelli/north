- Agent builds offload first: a heavy build started inside a fleet session (`NORTH_FLEET_SCOPE` set) is offered to the `[hosts.NAME]` build hosts before the laptop decides on it, and runs on the first with room even when the laptop would admit it; it stays for local admission only when no host has room or none is configured, then waits there while the laptop is at its CPU pressure mark. Builds outside a fleet session, landing checks and pinned work (GPU, native, Warcraft, private assets) keep their classes. `heavy-command-guard` finds `cargo`, `tsc` and `bun` runs behind `bwrap`, `systemd-run`, `sudo`, `taskset`, `xargs` and similar launchers, so those route through admission too (north#259, 2026-11-06). An offload runs the whole command on the build host, so the guard refuses to route a build whose command also writes files or the git index (`sed -i`, `git add`, `cargo fmt`, a `>` redirect to a file and similar) and asks for that part as its own command first (north#674, 2026-11-06).
