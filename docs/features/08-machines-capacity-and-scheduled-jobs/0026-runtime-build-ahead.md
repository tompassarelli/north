- Runtime build ahead: when `north land serve` builds a north candidate that changes a runtime input and carries a `Live-fix:` trailer, the one landing promoted at once instead of at its slot, it asks for that candidate tree's release north through `north runtime build-ahead --tree TREE --commit COMMIT` while the candidate's checks run. The request runs in its own transient unit, one at a time, and never builds on the host it runs on, which settles the fleet while people work on it (a release build per candidate took the laptop to load 109 on 2026-11-11): it sends the candidate commit to the build host with the most free cores under `refs/build-ahead/COMMIT`, has that host run `north runtime build COMMIT`, which builds a commit on origin/main or one sent that way and nothing else, copies the two runtime programs back, refuses them unless their stamp names that commit, and keeps them with the host that built them under `${XDG_STATE_HOME:-$HOME/.local/state}/north/runtime-artifacts/TREE`, never for a tree an artifact already covers. The promotion of the landed commit carrying that tree installs the artifact instead of reusing or building, and journals `artifact-ready` with 0 s in `runtime-pins.jsonl`; a landing whose tree differs (a rebased or bisected candidate) builds as before, and so does one whose request found no build host answering or failing, since the request then keeps nothing (north#1022).
