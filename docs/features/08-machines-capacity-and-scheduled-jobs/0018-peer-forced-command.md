- Peer forced command: a peer host's ssh key runs `north remote-serve --peer HOST --repos REPO,...` as its forced command, which lexes `SSH_ORIGINAL_COMMAND` without a shell, admits only allowlisted verbs, and then guards them for that peer: `threads queue add` and `job-run --host` must name the peer, `queue take` only the peer and `pool`, `queue msg` and `drop` only the peer's own jobs and a `failed` or `requeued` message only on a granted repository, no `queue follow` step, every item ref only in a granted repository, and every `fleet row put|exchange|register|wait|settle` runs with `--peer HOST` forced. A refusal exits 126; every call, admitted or refused, appends one row (verb, refusal, exit, milliseconds) to `~/.local/state/north/remote-serve/HOST.jsonl`. `north remote-serve audit --peer HOST` counts the calls, refusals and failures in that log and prints the key's days to its `expiry-time` in `~/.ssh/authorized_keys`.
