- Records mirror: sessions on hosts that cannot reach the laptop read its lander and runtime records without stopping for it. On the host that settles the fleet, each fleet tick starts `north runtime mirror` in a scope of its own, which copies to every host it ships runtimes to, over rsync, into `~/.local/state/north/records-mirror/` in the same layout as its own state home: the land queues' tickets, logs and `spans.jsonl`, `north/gates/`, the placement decision log, files changed within 7 days, plus `enqueue-refusals.jsonl`, `runtime-live.jsonl`, `safe-push/post-land.tsv` and `north/fleet-tick.log`, the fleet tick's journal lines. A symlinked directory in the source's state home, as the laptop's `north` is, is copied as a directory. A path that leaves that set is deleted from the copy on the next tick. `north/records-stamp.json` names the source host and when it was copied, and the next tick prints any host the last copy missed. On a host holding a copy from another host, `north land profile`, `north land gate-stats`, `north ledger flow`, `north dash` (its spans and landing-to-live bars) and `north ops strategy refusals` read the copy, and each says on stderr whose records it read and how old they are. The worker ledger reaches those hosts as the threads `snapshot.db` (north#738).
