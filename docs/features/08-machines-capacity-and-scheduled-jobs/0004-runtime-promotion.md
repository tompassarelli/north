- Runtime promotion: the fleet runs a pinned runtime, not origin/main's HEAD. The host that settles the fleet promotes origin/main at most 6 times in 24 h, 4 h apart, or at once when the commits since the pin carry a `Main-red:` trailer; it runs the core-loop probes on the promoted runtime there, and only when they pass does `north runtime promote` or `north runtime settle` ship it to the other hosts, so a runtime that breaks the core loop is rolled back on the settling host and reaches no second one. Every other host the settling host ships to runs only the pinned runtime and never follows origin/main itself. `north runtime status` prints the pinned SHA, when it was promoted and why, whether it walked the spine here, the promotions in the last 24 h against the cap, and since when origin/main has waited for the next promotion, read from `runtime-pins.jsonl` (or the records mirror on a host that holds another host's records). After a north landing safe-push runs `north runtime follow`, and each host's `north-runtime-follow` timer runs `north runtime update`, which pulls or builds the runtime (a build in progress always finishes), has the incoming runtime run `north check calls` against every north call on the host (system and user unit Exec lines and the store scripts they run, Claude settings hooks, and its own ssh hops to other hosts) and holds it for an hour with the live runtime kept and one proxy alarm naming the unit and line when its dispatcher lacks a verb or its table drops a subcommand the live table listed (north#825), swaps `current`, and swaps back with an alert to the proxy only when `north runtime health` fails; a failing `agents sync` keeps the runtime, alerts once per cause and retries each tick (north#731). On the host that settles the fleet, `north runtime settle` runs the bounded core-loop probes on the promoted runtime here first and ships it to the other hosts in parallel only when it passed, then runs the probes on every host per promoted SHA, on the host itself (a sandboxed worker shell reaching the hub host, the hub fetching a repository with its credential, each repository's lander minting its push token by the credential path its running `land serve` was started with, a host with no running lander or a repository no running lander serves reported once as not applicable, and a host that cannot mint by any path paged once as a host fault with no rollback, one `--test` worker per provider the host can launch answering its first turn inside a scratch state root that carries the threads ledger `north fleet` opens and widens (north#1027), with a provider whose binary or launch key is missing reported once as not applicable rather than probed, on every host but the placement-only hub, where a launch that never reaches a worker is unrun), rolling a host back with a proxy alarm naming the failing probe (north#1022); a probe the judged runtime cannot run is unrun rather than failed, the rollback target is trusted and never judged again, and a rollback behind a held update lock defers to the promotion holding it. Each promotion, walk and rollback is journaled to `runtime-pins.jsonl`, from which the scoreboard reads three bars: promotions that broke the core loop on a second host (at most 0), the slowest rollback after its swap (at most 2 min) and how long origin/main has waited for the pin (at most 24 h). Deploy and settle move a host forward only (north#651). A host set `publishes_host_facts = false` has its config facts published by the settling host (north#653). See `north runtime --help`.
