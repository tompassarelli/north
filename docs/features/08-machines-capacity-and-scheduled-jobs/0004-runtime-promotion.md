- Runtime promotion: every host runs a pinned north runtime, not origin/main's head. The host that settles the fleet promotes the newest ready head at fixed slots, one every `runtime_promotion_slot_sec`, and at once for a landing whose commit carries a `Live-fix: REASON` trailer; `north runtime order --reason REASON [--commit REV]` promotes a commit already on origin/main to every host at once (north#1171). A promotion reuses a binary already built from the same build inputs or has a build host build that commit, then judges it on the settling host with the runtime's own canary probes, its `verify-north` and one scratch landing, and ships it to the other hosts only when every one passes; a host whose probes then fail rolls back to the last runtime that passed and pages the coordinator (north#1022, north#1103). Each host's follow timer runs `north runtime update`, which has the incoming runtime run `north check calls` against every north call on the host before it swaps, and swaps back when `north runtime health` fails (north#731, north#825). Every step is journaled to `runtime-pins.jsonl`, which the scoreboard reads,; `north runtime status` prints the pin, the last slot with its outcome and the next slot, and `north runtime lag --json` shows how far each host and long-lived process runs behind the pin (north#1081). Why: docs/rationale/propagation.md and docs/rationale/runtime-follow.md.
