- Runtime promotion: every host runs origin/main's north within minutes of a landing, and rolls back on its own when the new runtime cannot run the core loop. After a north landing safe-push runs `north runtime follow`, and each host's `north-runtime-follow` timer runs `north runtime update`, which pulls or builds the runtime (a build in progress always finishes), has the incoming runtime run `north check calls` against every north call on the host (system and user unit Exec lines and the store scripts they run, Claude settings hooks, and its own ssh hops to other hosts) and holds it for an hour with the live runtime kept and one proxy alarm naming the unit and line when its dispatcher lacks a verb or its table drops a subcommand the live table listed (north#825), swaps `current`, and swaps back with an alert to the proxy only when `north runtime health` fails; a failing `agents sync` keeps the runtime, alerts once per cause and retries each tick (north#731). On the host that settles the fleet, `north runtime settle` ships to the other hosts in parallel, runs bounded core-loop probes on every host per promoted SHA, on the host itself (a sandboxed worker shell reaching the hub host, the hub fetching a repository with its credential, each repository's lander minting its push token by the credential path its running `land serve` was started with, and a host that cannot mint by any path paged once as a host fault with no rollback, one `--test` worker per provider the host has installed answering its first turn inside a scratch state root that carries the threads ledger `north fleet` opens and widens (north#1027), with a provider the host cannot launch reported once as not applicable rather than probed, on every host but the placement-only hub, where a launch that never reaches a worker is unrun), rolling a host back with a proxy alarm naming the failing probe (north#1022); a probe the judged runtime cannot run is unrun rather than failed, the rollback target is trusted and never judged again, and a rollback behind a held update lock defers to the promotion holding it, and logs each host's swap time per landing to `runtime-live.jsonl` for the scoreboard's landing-to-live bar. Deploy and settle move a host forward only (north#651). A host set `publishes_host_facts = false` has its config facts published by the settling host (north#653). See `north runtime --help`.
