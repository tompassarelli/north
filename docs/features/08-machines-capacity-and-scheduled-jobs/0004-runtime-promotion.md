- Runtime promotion: after a north landing safe-push runs `north runtime follow`, which starts `north runtime promote` in the background, and every host also runs `north runtime update` from its `north-runtime-follow` timer. An update pulls origin/main's runtime from a peer that has it, reuses the live binaries when the change touches no Rust build input, else builds it under a `runtime` capacity lease or offloads the build while the host is in game-reserve; it installs `runtimes/<sha>/`, swaps `current`, and swaps back with an alert to the proxy when `north runtime health` or `agents sync` fails. `north runtime deploy` ships the runtime built here to other hosts, and on the host that settles the fleet `north runtime settle` judges each landing live on every host by `landing_live_deadline_sec`, reopening its issue when it is not. After a host promotes a runtime, settle also runs one offloaded land check (`true`, bounded at 5 minutes) on that host once per promoted SHA; when it exits non-zero settle runs `north runtime rollback --from SHA` there, which relinks `current` to the runtime recorded in `runtime-previous` and writes `runtime-failed` so the SHA is held back for an hour, and alarms the proxy with the check and its log tail. A host with no offload route, or a canary that never reached a slot, is not judged. See `north runtime --help`.
