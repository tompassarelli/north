- Runtime promotion: every host runs origin/main's north within minutes of a landing, and rolls back on its own when the new runtime cannot run a land check. After a north landing safe-push runs `north runtime follow`, and each host's `north-runtime-follow` timer runs `north runtime update`, which pulls or builds the runtime, swaps `current` and swaps back with an alert to the proxy when `north runtime health` fails. On the host that settles the fleet, `north runtime settle` judges each landing live on every host by `landing_live_deadline_sec` and runs one canary land check per promoted SHA on each host, calling `north runtime rollback` there when it fails. `north runtime deploy` and settle move a host forward only: `north runtime update --sha SHA` on a host whose live runtime descends from SHA leaves it and prints `not moving HOST back from NEWER to OLDER` (north#651); `north runtime rollback` and the failed-sync swap-back still move back. A host set `publishes_host_facts = false` only records its config facts on promotion; the settling host publishes them to south after shipping to it (north#653). Staging a runtime on another host, before a swap or for an offloaded land check, copies its tree with its programs, so a host that runs a runtime it did not build, such as ccx33, finds the runtime's harness without NORTH_HOME (north#671). See `north runtime --help`.
