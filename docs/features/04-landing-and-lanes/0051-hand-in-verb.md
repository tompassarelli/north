- `hand-in` is the one tool call a headless Claude fleet session hands its lane in with: north's tool server offers it to every session (`harness/worker-tools.toml`), taking a commit message and the absolute paths the session changed. `north hand-in --message TEXT -- PATH...` stages and commits the changed named paths in the lane that holds them (or queues the lane as it stands when they are already committed), landing the lane's earlier commits whole and printing in one line the paths they change that the call did not name, refusing only an unnamed deletion among them, and rebases a lane that is behind main and published nowhere else onto main, carrying its uncommitted changes, whenever the replay and those changes apply without a conflict, so its checks run on the tree that lands; a real conflict is still refused naming its files (north#1239), refusing a path in another checkout, a checkout on its default branch or paths with no changes before anything is committed, and, inside a worker sandbox, a checkout whose git lock files the session may not remove (another project's lane), which it names with `safe-push --to main --wait` run from that lane as the road, before git touches it, since the sandbox lets git create a lock there but not remove it (north#1172); then runs `safe-push --to main` in that lane, so every gate and the private-kind judge come back as the tool result, word for word, ending at the lane's `Done: queued` ticket without waiting on the lander, and the session goes on with its next step on a fresh lane from main; a refusal or the lander's revert notice reaches it as a message (north#1632). The server's call timeout sits above the 25-minute hand-in wait, so the checks before queueing end inside it, and `safe-push --to main`, run in the background, stays the hand-in where the tool is absent (north#1158).
