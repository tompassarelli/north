- Red main event: when a land check fails on Actions, `north land red-check` asks whether the failed cargo and harness tests also fail on main's own tree, and if so keeps one box per red main commit in the rolling `main is red` issue and tells the proxy and the session's Fleet parent. It reads the failed cargo (`---- NAME stdout ----`, `test NAME ... FAILED`) and harness (`land check: FILE exited`, `FAIL`) tests and answers from a result recorded for that tree under `safe-push/red-check/` or by rerunning only them there through `north capacity offload run --host HOST` on a build host. The box is kept from the first red verdict, and the issue is named in its `Main-red:` marker; an unchanged red main posts nothing and a new red main commit edits it, never a comment. The one line to the proxy and the Fleet parent names the tests and the newest main commit since the last green run that changed their inputs. The lane prints `blocked by red main, not this lane` with the red main named in the refusal, and it can land once a `Main-red:` lane lands. Main CI runs on main are never cancelled in progress.
