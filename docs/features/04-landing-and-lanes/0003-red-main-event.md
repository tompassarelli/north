- Red main event: when a land check fails on Actions, `north land red-check` asks whether the failed cargo and harness tests also fail on main's own tree, and if so names the rolling `main is red` issue in its `Main-red:` marker and tells the coordinator and the session's Fleet parent, appending no box to any issue body. It reads the failed cargo (`---- NAME stdout ----`, `test NAME ... FAILED`) and harness (`land check: FILE exited`, `FAIL`) tests and answers from a result recorded for that tree under `safe-push/red-check/` or by rerunning only them there through `north capacity offload run --host HOST` on a build host. The one line to the coordinator and the Fleet parent names the tests and the newest main commit since the last green run that changed their inputs, and a new red main commit sends its own line, never a comment. The lane prints `blocked by red main, not this lane` with the red main named in the refusal, and it can land once a `Main-red:` lane lands. Main CI runs on main are never cancelled in progress.
