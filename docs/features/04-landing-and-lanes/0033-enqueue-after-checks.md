- Enqueue runs the cheap after-landing checks: a `land.after` line in `.safe-push` whose paths list carries `@enqueue` also runs in `north land enqueue` beside clippy, before the ticket is written while `landing_refusals` is `enforce` (in `shadow` only clippy runs there), so a lane that fails one is refused in the worker's turn instead of after the lander's queue wait. The checks are citations, the features and rationale indexes, the verbs sort, the owners check, code-health layers and the tests/it module list; they run on the lane's tree, and the lander still runs the same line after landing. `--no-build` is dropped for the early run so a checker the live runtime does not cover is built from the lane's tree, and checks that need the merged candidate stay after-landing only (north#697). Before them, enqueue folds the mechanical facts into the lane: it regenerates each `regenerate` index of `harness/merge-sets.toml` whose sources the lane changed and sorts each `sorted` block (the verbs table), amending the lane's last commit, so a stale index or an out-of-order verb never refuses a lane (north#729).
