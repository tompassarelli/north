- Runtime-floor gate: `north runtime-floor-gate --repo DIR --base REV --head REV [--north DIR]`, which safe-push runs after the build-cache gate for every repository, refuses a landing whose added lines in scripts and `.nix` files call a `north` subcommand, or pass a `--flag` to one, that the oldest live runtime this host knows lacks (its own `current` link and every host in its last `north runtime settle` record; with none known, the landing's base, or north main for another repository). A flag counts as accepted only when a non-test `"--flag"` literal sits in the subcommand's own source module (`land` reads `land/`, `runtime-floor-gate` reads `runtime_floor_gate*`), so a `--all` parsed by some other command does not make `north land serve --all` pass. A north landing is refused only for what its own change adds beyond the floor; a nixos-config or south landing reads the runtime's source from `--north`, `NORTH_HOME` or `~/code/north/main` and is refused for any flag the floor lacks, and for a subcommand north main has but the floor lacks. A subcommand call passes when the script probes it first with `north SUB --help` or `north_offers SUB`; a flag has no probe, so it waits for every host to run a runtime that accepts it. safe-push itself probes each gate subcommand before it runs it, and a runtime that lacks one gets `run north runtime update to SHA or later`, naming safe-push's own commit, instead of a language-gate refusal; the lander records that candidate as transient.
