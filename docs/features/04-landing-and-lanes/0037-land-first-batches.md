- Land-first batches (north#902): every queued lane has passed its own checks before queueing (gates, compile and clippy of its changed crates in safe-push, and its land test selection: the tests the change graph traces to the lane, `north graph ask affected`, or for a lane the graph cannot trace the crate-level fallback; both add the tree-wide tests/it modules and unit tests), so each lander round cherry-picks all queued lanes onto main as one candidate, runs only the pick-time gates and scans, and pushes it with a lease on main; no merged tree is checked before the push and no push waits for an earlier batch's checks. The after-landing run checks the landed batch's merged tree with the land.check and land.after lines, its tests narrowed to the batch range's affected tests that no lane's current alone pass already ran unless another landed lane or a landing the pass did not see can affect them (`north graph ask affected --lane --ran`, north#917; `north land missed --since DATE` compares main's failing Cargo runs with that selection), several runs in flight at once, and a red run bisects inside the batch and reverts the culprit (land/blame.rs). Three queued lanes land in one push with the checker never called; a batch carrying a bad lane is reverted to exactly that lane.
