- Lane removal from a worker sandbox (north#954): `north lane remove LANE...` removes each lane directory directly under a project's `worktrees/`, named by its absolute path, from outside the worker sandbox, so no unregistered directory is left behind. A registered worktree goes only when it is clean, holds no ignored file beyond build output and caches, has every commit on main or a change main already holds, and is neither locked, waiting in the land queue nor the cwd of a live process; it is removed with its branch, as `north lane reap` does but with no minimum age. A lane whose commits a squash landing combined under a new SHA is spent, not unmerged (north#958). A directory git no longer registers (its `.git` file names a git directory that is gone) goes only when no process or ticket holds it and every file git does not ignore in it is already stored in the repository. Anything else is kept with the reason named. A kept lane whose tip is on main or whose change main already holds loses its git-ignored `target/` at once unless a process holds it open, as `north lane gc` does, so a landed lane leaves no build output behind (north#1021). The guard refuses `git worktree remove` of a lane there and names the verb.
