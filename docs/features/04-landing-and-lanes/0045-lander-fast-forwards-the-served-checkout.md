- A landing fast-forwards the checkout its lander serves (north#872): after `north land serve` pushes `origin/main`, it fast-forwards the clean checkout of `main` it serves to the landed commit, so a host reads the resident cap in south's `agents/orchestration.toml` and every other file placement, `north config agents sync` or a new lane reads in that checkout within the landing, not at the next runtime promotion. A checkout on another branch, with uncommitted changes or with a commit the landing does not hold is left exactly where it is and the reason is printed, so a landing never moves local work. The test `a_landing_fast_forwards_the_main_checkout_the_lander_serves_without_a_hand_merge` replays a south landing that raises the resident cap and reads the served head.
