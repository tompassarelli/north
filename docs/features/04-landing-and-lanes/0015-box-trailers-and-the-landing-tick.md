- Box trailers and the landing tick: a lane's commit carries `Item: REPO#N` and `Box: TEXT` trailers naming the box it closes, which `north work brief new` prints and `north cloud land` keeps when it folds a handback. A launch keeps its brief's item, box and Done-when command in the lane (`north finish --brief-trailers`), and the session's `north finish` and `north hand-in` add `Item:` to a message that names no item, which restores the issue on the commit and ticks nothing. Only `north finish` adds `Box:`, and only when its check command is the brief's Done-when command and the message has no `Box:` line, so a commit carries the box exactly when the call has just run and passed the command that completes it; a hand-in, a finish with another check and a brief with no Done-when command never add it (north#1367). `north land scan boxes BASE..HEAD` refuses a `Box:` with no `Item:` before it or one matching no single unticked box. After a landing, `north after-landing` (safe-push's direct and train paths, the lander's follow step) first runs `north task check --done-when --box TEXT REPO#N` per trailer, which ticks a box naming its own ``Done when: `CMD` `` with its `Evidence:` stamp when the command passes, the stamp the closed-box report counts as checker-verified. It then queues one tick per trailer in the issue-body outbox and drains it: the box is ticked with its landed sha, a parent with it once every box under it is ticked, and the issue closes once every box is ticked. A box with its own command, a box marked `(observed)`, `(headless run)` or an owner check, a box with unticked boxes under it, and an issue with no checkboxes get no such tick and a refusal note naming why. Why is in docs/rationale/proxy-role.md section 4.
