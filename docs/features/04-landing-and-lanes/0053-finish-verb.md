- `finish` is the one tool call a headless Claude fleet session finishes its lane with, offered beside `hand-in` (`harness/worker-tools.toml`) and named by the worker's instructions as the way to finish. `north finish --check COMMAND --message TEXT -- PATH...` resolves the lane from the named paths with hand-in's refusals, runs COMMAND with `sh -c` in the lane root and, only when it exits 0, commits the changed named paths and takes the `safe-push --to main` road without `--wait`, so every gate runs as before and the call returns at `Done: queued ..., ticket NAME` instead of waiting for the lander. A failing check stages, commits and queues nothing and returns its output with `NOT committed, NOT queued` (north#1194). An accepted call is the turn's last model request: north's PostToolUse hook answers `continue: false` for `mcp__north__finish`, which Claude Code fires only for a result that is no error, so a refused call still reaches the model, and the session's report is the call's `Done: queued` line (north#1194). When the whole change fits in one answer, the instructions and the tool's description have the worker send its edits and the finish call in one message without running the check first; Claude Code starts a tool that is not concurrency-safe, as an MCP tool without `readOnlyHint` is, only once every earlier call in the message has finished, so the edits are on disk when the check runs (north#1218). The call can carry the change itself: `files`, each a path and its whole new content, which the tool server hands to `north finish --files -` on stdin; it writes them into the session's own lane, the checkout holding its directory, before the check, refusing any path that does not resolve inside that lane before anything is written, and a failing check leaves them as written (north#1218).
