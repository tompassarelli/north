- Lander after-landing revert: the lander pushes a candidate after only the seconds-long checks (clean pick, outgoing scans, stale-revert and trailer gates) and runs every `land.after` line on main, up to `landing.after-runs` runs at once, offloaded to a build host under `landing.capacity`. A red run bisects the landed lanes on each prefix, reverts the first lane whose prefix is red as a red-fix ticket with `Reverts:` trailers, and tells its session to re-queue it with `Follows:`. When the first lane is blamed, the base the batch sat on is run too, and a red base blames nobody. Each prefix and the base run with the red run's own test selection (`north land checks --after --tree TREE`; verdict-cache keys hold it), so a failure only a wider selection runs is never blamed on a lane that merely widened it (north#622). A red fix whose own run is red alarms the proxy instead of reverting again. Each batch is journaled in `<queue>/following/HEAD.json` until its run reaches a verdict and is rerun after a lander restart (north#639). Batches that land during a run wait as one run of the newest head, which bisects all their lanes when red; a run with no verdict waits again (north#634).
