- Lander after-landing revert: the lander pushes a candidate after only the seconds-long checks (clean pick, outgoing scans, stale-revert and trailer gates) and runs every `land.after` line once per landed batch on main. A red run bisects the landed lanes by running the after set on each prefix, reverts exactly the first lane whose prefix is red as a red-fix ticket that lands ahead of the queue (`Reverts:` trailers on every commit of the lane), and tells the lane's session to re-queue it with `Follows:`. When the first landed lane is blamed, the lander runs the after set once on the base the batch sat on and blames nobody if that is red too, so a main that was already red draws no revert. The after run is offloaded to a build host under `landing.capacity` and never runs unleased in the lander's cgroup. A red fix whose own run is red is not reverted again; the proxy is alarmed instead.
