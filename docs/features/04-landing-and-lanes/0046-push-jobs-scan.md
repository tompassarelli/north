- A push-to-main job a lane adds runs before landing or records why: `north land scan push-jobs BASE..HEAD` reads each workflow at the lane head whose `on.push` admits main (a branches pattern matching main, a branches-ignore not matching it, or no branch or tag filter) and compares its jobs with the same workflow at the base, then refuses each job the lane adds or changes whose run steps are not all `land.check` commands unless a `land.after-only = REASON :: FILE:JOB` line names it, where FILE is the workflow file under `.github/workflows` and JOB its job id. A job already on main before the lane is the repository's inherited gate and is not re-judged. The "after-only reason" lane gate applies the same rule at safe-push and the lander's pick, so a lane cannot add wisp's ci.yml code-health job — the after-landing copy of the gate that caught wisp af6ed3fa — without a pre-land copy or a reason (north#892).
