- A deny-list scan reads the list from its mirror only when the list's source confirms at that moment that its main branch still points where the mirror's copy does; otherwise it fetches as before. `north denylist hold SOUTH_DIR`, started by the first scan that finds none, keeps one connection to the source open (git's own `remote-https` helper, which gets its credential from git's credential helper as a fetch does) and answers one question on an owner-only socket under `$XDG_RUNTIME_DIR/north-denylist`: given the mirror's commit id, whether the source advertises the same one (`equal`) or another (`moved`). It returns no list content and serves nothing else. A moved ref, an absent, slow (over 1 s) or failing holder, or a source that is not plain HTTPS makes the scan fetch exactly as before, so the list a scan uses is always one its source confirmed or one fetched then. The holder repeats the same question every 30 s to keep the connection warm and exits 10 minutes after the last scan asks or when the runtime changes. On a build host on 2026-11-12 the question took 0.18 s against 0.75 s for the fetch (north#1239).
