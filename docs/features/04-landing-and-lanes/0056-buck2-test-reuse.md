- Buck2 test reuse in the landing's log (north#1115): `north land reuse observe`, which wraps the landing's test line, reads a `buck2 test` line back from Buck2's own record of the run (`buck2 log show` of the event log the run names, behind the same shell words as the test) instead of looking up recorded path sets. It prints one `north-reuse` unit per test binary, carrying the action's key when Buck2 answered the binary from its action cache and no key when it ran, so `north land reuse report` counts that reuse from the lines the lander already harvests; its summary line names the cases the binaries printed and how many failed. The build seam's Buck2 test run passes `--unstable-allow-compatible-tests-on-re`, because Buck2 otherwise runs every test on the invoking host, where no result is cached. The case runner each Buck2 test target runs (`north-test-cases`) captures a case's output in an unlinked file, so a process a case leaves behind cannot keep the runner waiting. A fetch that meets a sibling worktree holding the same ref's lock runs again like one that lost the ref (`north-git-locks`).
