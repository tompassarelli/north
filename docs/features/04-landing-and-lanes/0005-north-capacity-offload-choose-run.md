- `north capacity offload choose|run`: while this host is in game-reserve and its CPU split is not enforced, `safe-push` ships the lane by git bundle to the first other `[hosts.NAME]` with an `ssh` destination and room, and runs the land checks there. An ENFORCED `game-reserve status` runs the checks here on the agent CPUs. Room means free cores, the heavy memory request, and 20 GiB free where the host's offload slot lives; the checks run in `~/.cache/land-offload/<checkout>`, whose `target` persists between runs. `land.local-only` entries in `.safe-push` and a missing host keep the checks on this host (`land.machine-bound` ones may ship); a repository whose `.safe-push` names a `land.workflow`, north among them, runs its checks on GitHub Actions instead and never offloads. `choose --any` weighs each `--taken HOST` as one land check already on its way there and leaves out each `--avoid HOST`, the hosts a lane found unfit. A slot goes first to a red-fix land check (`NORTH_LAND_RED_FIX=1`, north#646), then to any land check, then to worker builds (north#634). `run` fails unless the remote reports its command's exit status (north#658). A `land.host-input = PATH... :: COMMAND` entry names files the check reads on the host that runs it, such as `~/.local/state/north/graph.db`: the check goes only to a host holding every one (`choose --needs`), stays on its assigned host when that host holds them, and runs on this host when no build host that answers does; `choose` surveys only the hosts this host's `reaches` lists (north#892). An entry written `STORE@PINS` names a content-addressed store: `PINS` is a directory at the check's head with one file per input family, each holding the 64-hex entry that family's build reads, and the check goes only to a host holding `STORE` and every pinned `STORE/FAMILY/ENTRY`, so a host whose store exists but lacks a pinned entry takes no check that reads it (north#892). A host that offloads no builds, such as the laptop, never counts as a land-check host beside the build hosts: while they are all full it queues the check on the least busy one, and it runs the check itself only when no build host answers (north#1036).
