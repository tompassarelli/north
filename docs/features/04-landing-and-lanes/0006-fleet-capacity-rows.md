- Fleet capacity rows: `north capacity pull [--host NAME]` copies each other `[hosts.NAME]` ssh host's `capacity_runs` rows into this machine's capacity.db under a `host` column, and `north capacity actions-pull` records each started job of the north, makgora and wisp Actions runs as an `actions:LABEL` row. The pull reads rows newer than the last one pulled for that host (read-only `sqlite3` over ssh), and this machine's own rows carry its name. Each `actions:LABEL` row holds `queuedSeconds` (created to started) and `wallSeconds` (started to completed); the first pull covers 7 days. `actions-pull` then prints the p50 queue per runner label and an `incident: REPO main is red` line (exit 3) for each repository whose latest push-to-main run failed; a second run of either adds no rows. Sizing reads only this machine's own rows (`capacity_history`), so pulled rows feed placement and reports, never its estimates.
