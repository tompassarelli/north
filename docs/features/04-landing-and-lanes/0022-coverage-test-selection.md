- Coverage test selection: `north test coverage refresh` records, on a check host through `north capacity offload run`, which functions each Rust test executes. It builds the workspace tests with `-C instrument-coverage`, runs nextest with `north test coverage exec` as the runner so each test writes its own LLVM profile, and keeps the map in `~/.local/state/north/coverage/REPO.json` along with the commit it was recorded at. The change graph ingests the map as the edges from each changed function to the tests that reach it, so `graph ask affected` selects the nextest land check's tests together with the reads it records. `north test coverage select` prints the same selection by hand, and `north test coverage miss` names the after-push failures the selection would have skipped and refreshes the map. A function edited since the map was recorded selects every test reaching its file; a line outside every function, a file with no mapped function and a run-time input a Rust source names select every test reaching the whole file or those sources, and a test the lane adds runs by name. Cargo.toml, Cargo.lock, build.rs, an input no source names, a map over 3 days old or over 400 selected tests run nothing. `north test coverage refresh --repo north` runs nightly from nixos-config. The landing lists the lane's tests with `cargo nextest list` through `bin/land-shell --dev` and drops a selected test binary the listing lacks; a tree it cannot list runs the crate closure, so a binary the map still names after its crate is gone never reaches the nextest filter (north#1099). The full suite still runs after the push, and the pre-push coverage land check is retired (north#634, north#944).
