- Land checks on a Buck2 host (north#1115 box 7b): a host whose `[hosts.NAME]` table in the orchestration policy says `build_system = "buck2"` runs the landing's lint line as the Buck2 clippy gate (`buck2 bxl --remote-only --materializations=none //lint/clippy.bxl:clippy -- --targets //...`) and lists tests with a Buck2 query that compiles nothing; once the host also sets `buck2_tests = true`, every nextest line runs as one `buck2 test //...` on the remote-execution workers. The land checks read each `.safe-push` line through the build seam (`north-build-system`), so the declared Cargo lines stay as they are, a reason or deadline declared for one holds for the line issued in its place, and a host without the key runs every line as declared. The north a check runs from a tree is built the same way: `bin/head-north` asks the live runtime (`north runtime tree-build`), which builds it with the host's side, and a host that builds and tests with Buck2 warms no land-check slot. A repository with no `.buckconfig` keeps its Cargo lines on any host. A host can instead move the lint line alone with `buck2_lint = true`: the checks before a landing hand their lint line to `north land lint` on the host that executes it, which runs the gate, judges it by Buck2's exit status alone, and keeps the declared Cargo line for a tree whose gate script or Buck2 configuration is not the base's; the run after a landing always lints the landed tree with Cargo. No host sets any of the three keys yet (docs/rationale/compile-reuse.md, Cut-over).
- Tests of listed crates on a build host (north#1115): a host whose `[hosts.NAME]` table sets `buck2_test_crates = ["NAME", ...]` runs the tests of each listed crate a check before a landing selects through `buck2 test --remote-only` on the workers and the declared nextest line for the rest; a lane that changes a `BUCK`, `TARGETS` or `.bzl` file, `toolchains/` or the Buck2 configuration is tested by Cargo in full, a crate Buck2 gives no plain verdict on stays on the Cargo line, and the run after a landing always tests with Cargo.
