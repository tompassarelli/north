- Land checks on a Buck2 host (north#1115 box 7b): a host whose `[hosts.NAME]` table in the orchestration policy says `build_system = "buck2"` runs the landing's lint line as the Buck2 clippy gate (`buck2 bxl --remote-only --materializations=none //lint/clippy.bxl:clippy -- --targets //...`) and lists tests with a Buck2 query that compiles nothing; once the host also sets `buck2_tests = true`, every nextest line runs as one `buck2 test //...` on the remote-execution workers. The land checks read each `.safe-push` line through the build seam (`north-build-system`), so the declared Cargo lines stay as they are, a reason or deadline declared for one holds for the line issued in its place, and a host without the key runs every line as declared. The north a check runs from a tree is built the same way: `bin/head-north` asks the live runtime (`north runtime tree-build`), which builds it with the host's side, and a host that builds and tests with Buck2 warms no land-check slot. A repository with no `.buckconfig` keeps its Cargo lines on any host. No host sets either key yet (docs/rationale/compile-reuse.md, Cut-over).
