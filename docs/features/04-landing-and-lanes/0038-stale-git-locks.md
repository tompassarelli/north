- Stale git locks: `north lane unlock [CHECKOUT...]` removes each git lock file (`index.lock`, `HEAD.lock` and the other upper-case pseudo-ref locks, `config.lock`, `packed-refs.lock` (also in `packed/`), `shallow.lock`, `commit-graph.lock`, and any `*.lock` under `refs/`) in a checkout's git directory and common directory that no process holds open and that is older than 60 s, and names each lock it keeps with its holder or age; north's own flock files there are never touched. It is the one removal an agent may make in a primary checkout's git directory, so a git process killed mid-update never leaves Tom a command to run. `agents sync` runs it on south, north and nixos-config before it fetches and fast-forwards each main, every lander and enqueue `git fetch` that fails naming a lock runs it and fetches once more, and the primary-checkout guard answers an `rm` of a git lock with this verb (north#937). `north lane restore-packed-refs [CHECKOUT...]` undoes the `packed/` layout: under git's lock in `packed/` it renames `packed/packed-refs` back over the link and removes `packed/` once empty. A layout interrupted before its rename leaves `packed-refs` the regular file git keeps using and an extra link to it in `packed/`, which the next layout replaces; a killed layout's `packed-refs.lock` is a stale lock like any other. `north lane stray PATH...` removes a file git reports untracked only when a tool call in the session's own transcript named PATH before the file was born, so a session clears a stray it left itself, such as a failed edit's temporary copy in a primary checkout.
