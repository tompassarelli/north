- Buck2 after a landing (north#1115): beside each after-landing run the lander starts `north land crate-tests after-landing` on the landed head, in its own offload slot on a build host the offload chooses and never on the lander's host, with `NORTH_LAND_TEST=buck2-after-landing` set on the job. It runs `buck2 test` of every crate that host lists, with no Cargo line and no host case, and its exit status alone is its verdict: 0 green, 1 red, 75 none (a host with no list or no store generation, or a record it cannot read). It records one row per head (head, host, exit, seconds, crates passed) in `check-timings/buck2-after-landing.tsv` and the crates it passed, one per line, in `check-timings/buck2-after-landing/HEAD.crates`; nothing decides on either, and the Cargo run after the landing, which reverts, runs as before. The job runs under its own offload owner (`OWNER-buck2-after-landing`), so it never shares the lander's slots with that Cargo run, and admission never gives it a slot from the lander reserve. A lander restart while it runs leaves the job on the build host to its 1800 s timeout, and that head gets no row. `buck2_after_landing = "off"` in `harness/defaults.toml` starts nothing.
