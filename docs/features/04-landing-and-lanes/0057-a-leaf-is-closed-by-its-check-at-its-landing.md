- A leaf is closed by its check at its landing: an issue with no checkbox and no open child is a leaf, and a lane names it with an `Item: REPO#N` trailer and no `Box:` line. `north finish` records the acceptance command that passed on the lane's tree, and safe-push puts that command on the land ticket when the tree it queues is the tree the command passed on. When the lander lands the lane it checks that the lane's commit is an ancestor of origin/main, refuses an `Item:` that names an issue of another repository than the one being landed, and reads the threads ledger itself (`north threads list --json`): it goes on only for an issue the ticket's session holds a claim on, so a line in a commit closes nothing by itself. It then queues a close in the issue-body outbox, carrying the command only when the landed commit has the tree the command passed on; a lane the lander rebased or stacked on another has a different tree, and its leaf waits. `north after-landing` drains the outbox: it reads the issue again and closes it, with a comment naming the commit and the command, only when the command on the entry is the issue's own ``Done when: `CMD` ``. A leaf whose command has not passed on the landed tree (it needs the live runtime, a native client or a date, the lane was handed in with another check or with none, or main moved under it) stays open and is labelled `waits:runtime`. An issue with checkboxes keeps the box path of the landing tick, and an issue with an open child or one already closed is left as it is; the lander's line and the after-landing line name what happened to each. Why is in docs/rationale/sub-issue-cutover.md, departure 1 (north#1137).
