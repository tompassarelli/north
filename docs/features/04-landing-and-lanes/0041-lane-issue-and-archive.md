- Lane issue, archive and restore: `north lane new --issue REPO#N LANE` creates a lane under the project's `worktrees/` on a new branch from origin/main and records the issue it serves, and `north lane gc` judges each lane by git state alone, never by the issue (north#995, north#1650). A lane landed by ancestry or by content is removed. An unlanded lane or local branch that no live Fleet session or peer host holds is bundled to `~/archive/lanes/<project>/` once it has been idle 24 hours, whatever issue it names; the bundle holds the lane's commits and, when the lane was dirty, one snapshot commit carrying its uncommitted and untracked changes, and the bundle must verify and hold that head before the worktree (build output included) and the branch go. `north lane restore BRANCH` brings the newest archived copy back to a worktree with those changes unstaged, as they were. A lane something still holds is kept and listed, and `north lane gc --unlanded` prints that list. gc also drops the branch config of deleted branches and archives the worktree directories a failed removal leaves behind (north#1028, north#1054, north#892, north#1600).
