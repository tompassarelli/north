- Lanes record their issue and stale ones are archived, then reaped (north#995): `north lane new --issue REPO#N LANE` creates the lane `~/code/<project>/worktrees/SLUG` on branch SLUG from origin/main without tracking it, so concurrent lane creation writes no shared git config, and records its issue in `.git/north/lane-issues/SLUG` under the project repository, which outlives the worktree. `north lane gc` reads that record first, or the older `branch.SLUG.north-issue` config key, else the issues the lane's commits cite (Refs/Fixes/Closes/Part of, or a trailing `(repo#N)` on a line). It counts a lane landed by content as well as ancestry: its tip's tree is a tree on main, or every patch it carries has a commit on main with the same stable patch-id, so a lane on rewritten history is not counted lost; a commit's stable patch-id never changes, so the patch-ids of main's commits are kept per repository in `.git/north/lane-gc-patch-ids` keyed by commit sha, and a run diffs only the commits main gained since the last (north#1028). An unlanded lane or local branch whose issues are all closed is bundled after 7 idle days, and one that names no issue and has no owner (no lock, process, live session, claim or peer-host hold) after 14; the bundle (`git bundle` of the branch, with uncommitted and untracked changes as one snapshot commit on top) goes to `~/archive/lanes/<project>/` with a line in its `index.tsv`, must verify and hold the lane's head before the lane and its branch are removed, and a lane holding ignored files beyond build output is kept. A lane on an open issue is kept and listed under that issue (`kept on open REPO#N: ...`). gc runs outside the worker sandbox and also removes the empty `worktrees/` directories a mistyped lane path leaves inside a main checkout.
