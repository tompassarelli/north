- `safe-push --to main` runs the lane's affected land checks from the committed `.safe-push` (`land.check`, `land.local-only`, `land.machine-bound`, `land.runner`, `land.workflow`, `land.publish`): on GitHub Actions through `north land actions`, on the build host, or here. Before its checks run, `north capacity offload verdict hit` asks this host and every build host for a pass recorded for the same inputs (the command, the pinned runtime, the check environment, the toolchain and the object ids of the paths the check selects on or names), and a hit returns that verdict without running; a pass is stored on the host that ran it, a failure deletes the record, and `north land profile` counts the reused checks. `safe-push --help` is the contract.
- A land check that needs a workflow run on another host names `north land dispatch NAME`, which reads `[dispatch "NAME"]` (command, optional fetch step, workflow, repository, workflow ref, allowed inputs with anchored patterns, deadline) from origin main's `.safe-push`, never the lane's. It runs the fetch step in `north depbox fetch` and the command in `north depbox run`, takes from the command's output exactly one `north land dispatch: {JSON}` line of declared string inputs that match their patterns, adds `ref` and `base` itself, and dispatches the workflow once per check with `gh` found outside the checkout. It follows only the run whose id the dispatch returned: a success passes, a failure is red, and a refused input, a refused dispatch, no returned run id, a second dispatch for the same check, any other conclusion or a run past the deadline (cancelled) reaches no verdict, exit 75 (north#1148).
