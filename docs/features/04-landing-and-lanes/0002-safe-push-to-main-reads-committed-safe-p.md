- `safe-push --to main` runs the lane's affected land checks from the committed `.safe-push` (`land.check`, `land.local-only`, `land.machine-bound`, `land.runner`, `land.workflow`, `land.publish`): on GitHub Actions through `north land actions`, on the build host, or here. Before its checks run, `north capacity offload verdict hit` asks this host and every build host for a pass recorded for the same inputs (the command, the pinned runtime, the check environment, the toolchain and the object ids of the paths the check selects on or names), and a hit returns that verdict without running; a pass is stored on the host that ran it, a failure deletes the record, and `north land profile` counts the reused checks. `safe-push --help` is the contract.
- A land check that needs a workflow run on another host names `north land dispatch NAME`, which takes the check's command, workflow, workflow ref and allowed inputs from `[dispatch "NAME"]` in origin main's `.safe-push`, never the lane's: the command prints at most one `north land dispatch: {JSON}` line of string inputs, each declared and matching its anchored pattern, the lander adds `ref` and `base` itself, dispatches once with its own `gh`, and keeps the run's state in the JSON file `SAFE_PUSH_LAND_DISPATCHED` names, which the command reads as data; a refused input, a failed dispatch, a run that never appears, a cancelled run or one past the declared deadline reaches no verdict (exit 75) whatever the command exits (north#1148).
