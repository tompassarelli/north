- Done-when boxes: an open box whose Done when is a command writes it as ``Done when: `CMD` `` on its line. `north task check --done-when [--dry-run] [--confined] [--main DIR] [--box TEXT] (--body-file FILE | REPO#N | --repo OWNER/REPO)` (`--box` keeps only open boxes containing TEXT, `--confined` runs each command in a new worker domain) fetches origin main, when a box is left to check, into the project's check lane `worktrees/done-when`, a detached temporary worktree where the project keeps no worktrees directory (or uses `--main DIR`), runs each such command there with a 10-minute limit, and prints a verdict line per box. A box passes only when the expectation written after its command holds: `passes`, `succeeds` or `exits N` checks the exit code, `prints nothing` or `finds no match` needs empty stdout and an exit below 2, and `prints X` or `shows X` needs X in the output. A box with no stated expectation, or with a threshold or comparison such as `at most`, `under` or `<`, gets `judge`, which is never ticked. Without `--dry-run` it re-reads the issue body, ticks each passing box that is still open with ``Evidence: `CMD` passed on main SHA on DATE, exit N.``, the one stamp the issue-cleanup guard, the landing tick and the climber all read as passing through `box_oracles::passed`, attaches its last 20 output lines, and edits the issue only when the body changed; failing boxes stay open. `--body-file` prints the ticked body instead. Asked from a worker session, `north task check --done-when --box TEXT REPO#N` is run by the outside broker's checker, which reads the command from the issue, runs it `--confined` on origin/main and alone writes the ledger record, the stamp and the tick (north#1137); `--dry-run` and `--body-file` write nothing and run in place, and any other form there is refused before it starts.
