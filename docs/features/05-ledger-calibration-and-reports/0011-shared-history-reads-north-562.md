- Shared history reads (north#562): `threads recommend`, `ledger summary` and every other rework read take each checkout's main history from `<git-dir>/north-history.json`, keyed by the origin/main sha it ends at. A read at that sha runs no `git log`, a read after main moves logs only the new commits, and concurrent callers queue on `north-history.lock`, so a burst of launches makes one `git log` between them. Rework verdicts live beside it in `north-rework.json`, keyed by landing sha and item with the main head they were judged at: a verdict whose 48 h window main has moved a day past is never judged again, and a read at an unchanged head that names no new landing reads no history. A proxied threads read that finds its ledger snapshot older than 15 minutes starts the pull in a detached child and answers without waiting on it.
