- Policy replay: `north policy-replay run SCENARIO.json... --arm ARM... [--trials N] [--jobs N] [--policy AGENTS.md] --out RESULTS.jsonl` runs scenarios from `south:agents/replay/` × arms × trials, at most 4 in parallel, through `claude -p` with each policy arm (`full`, `minus:PREFIX,...`, `minus-file:PATH` with one rule prefix per line, or a scenario arm name) appended in place of the live `~/.claude/CLAUDE.md` (`--setting-sources project`, empty cwd). It scores each run with the scenario's regex or tool-call detector, appends one jsonl row per run (pass, turns, input/output/cache tokens, model, effort, wall seconds, `leftover_processes` (processes carrying the run's `POLICY_REPLAY_RUN` tag still alive after scoring, then sent SIGTERM and SIGKILL after 3 s before the temp dir is removed) and `cost_api_usd_comparison` as an API list-price comparison only) and prints pass rate per scenario × arm. `north policy-replay sweep SCENARIO.json... --variants VARIANTS.toml [--variant NAME...] [--provisional]` instead runs every `[[variant]]` of `south:agents/replay/variants.toml` (built from the live AGENTS.md, or the file a `policy` key names, by `minus`, `minus_file`, `plus` text files and `placement` moves to a skill or hook) over the scenarios × trials, appends per-run rows to `~/.local/state/agents/replay/sweep-<UTC date>-runs.jsonl` and one row per variant to `south:agents/replay/sweep-<UTC date>.jsonl`, which lands with the policy so every host's `agents sync` finds it, (policy sha256, startup tokens on the `agents sync` session-start chars/4 basis, conformance, n, tokens per run, `usd_or_null`, wall seconds, model, effort), and writes the candidate `~/.local/state/agents/replay/operating-point-candidate.toml` (`--candidate PATH`): the fewest startup tokens among variants with no one-sided Fisher drop (alpha 0.05) from the best variant overall or per scenario and no 3/3 to 0/3 scenario flip, with its per-scenario counts; it never touches `south:agents/operating-point.toml`. Re-run it on a model release, a big policy change or weekly. `north policy-replay promote SCENARIO.json... [--candidate PATH] [--operating-point PATH]`, run in a south worktree and landed through `safe-push`, copies the candidate's point keys into the operating point and keeps every other key and comment (`weak_scenarios`); it refuses a candidate that misses a listed scenario, flips a scenario the current point passed every trial of to 0 passes, or whose conformance is significantly below the current point or the frozen anchor (`anchor_conformance`, `anchor_n`, `anchor_date`, the point the promotion chain started from), so small steps cannot compound. `--accept-drop REASON` on `promote` (a model release, a new scenario set) skips those checks, records `accepted_drop` and `accepted_drop_date` and re-anchors on the candidate. Per-run model arms: `--model sonnet|haiku|opus|<full id>` and `--effort low|medium|high|xhigh` override the scenario's model and effort, and `--advisor MODEL` passes `claude -p --advisor MODEL`; Fable is refused as either, and `--sweep` refuses all three. Each row then records `model`, `effort`, `advisor`, `advisor_calls` (distinct `server_tool_use` blocks named `advisor` in the stream), `advisor_model_resolved`, the advisor's input/output tokens and `advisor_usd` from the result's `modelUsage`, and `usd` with `usd_basis` (the result's list-price `total_cost_usd`, since the north worker-ledger rate needs weekly usage readouts bracketing the run). A `command` detector runs the scenario's shell command in the run's cwd after the agent finishes and before the leftover-process kill, passing on exit 0 within its `timeout_s` (default 120). A scenario may live in a subdirectory such as `south:agents/replay/coding/` and name its policy file with a `policy` field relative to itself; the `agents sync` gate reads only `agents/replay/*.json` and `sweep-*.jsonl`, so these arms write `--out ~/.local/state/agents/replay/advisor-*.jsonl`.
