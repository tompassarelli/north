- Goals as checks (north#641): each project (north, makgora, wisp) keeps `concerns.toml` at its root, one `[[concern]]` per goal drawn from its README or AGENTS.md, with the line it comes from, an oracle command that prints one number, a `max` or `min` bound, a class, and `reads`, `commit` when the oracle measures the checked-out tree or `host` (the default) when it reads this host's state. A `contract` goal is never red: the after-landing run reads the landed tree twice and the landing's base, bisects the range to the first commit at which a goal turned red, reads that commit and its parent twice each through `north_base::foundation::pair::compare` in one run, with the concern list and the `concern-revert` gate's mode (harness/gates.toml, shadow until it is set to enforce) read from the landing's base,, and queues the revert (`Concern-red:` trailer, naming both verdicts and the north that read them) ahead of the queue only when the parent reads green twice and the commit red twice the same way. An oracle that exits non-zero, times out or prints no number gives no verdict and reverts nothing, one that answers a tree two ways is named nondeterministic and blames no commit, a `host` goal never reverts, and a refused revert is filed with both verdicts and the oracle's own output. A `debt` goal may be red up to its `ceiling` while its `owner` and `revisit` trigger stand in for the `Target-debt:` record. `north check concerns [--root DIR] [PROJECT...]` runs every oracle prints value, source, oracle, class and verdict, and exits 1 on a red contract, a goal over its ceiling or an oracle with no number; `north land profile --metric landing-p50|landing-p90|landing-projected|verification-p50|verification-p90` measures landing times; landing-projected, the last landings' service time times 1 or 2, is what the debt ceiling reads. The fleet tick tells the proxy `goals red (N): ...` when the red set changes and every 6 h while it stays red.
