- Deferred checks: an issue closes when its work has landed, not when its last soak has run. A box whose code landed and whose only remaining check is dated (a `Not before ...` read, a day without an event, a keep-or-revert read over N ledger runs) moves to a `[[check]]` entry in the same registry, so no worker waits for it. `north check experiments defer ISSUE BOX --check CMD --by YYYY-MM-DD [--expect TEXT] [--id ID] [--lead SESSION] [--root DIR]` appends the entry (box text, command, optional expected output, review day, owner issue, and the lead told on a miss, by default the calling fleet session) under `--root` (default: the current directory, so it lands with the lane) and marks the box `(waits: DAY, ...)` with a `<!-- check ID@DAY -->` marker on its issue. Dispatch staffs no marked box. `north check experiments judge --file`, run every 5 minutes on the lander, closes an open issue once each unticked box carries the marker of a check the landed registry holds and each ticked box is proven; on the review day it runs the check from the repository root (pass: exit 0 and, with `expect`, that exact output; 120 s limit), ticks the box with `Evidence:` on a pass, and on a miss writes the output onto the box, reopens the issue and messages the lead. A command that cannot run (exit 126 or 127, or timeout) is tried again on the next tick. A lead closes a dated-only issue from a north lane: `north check experiments defer north#N "BOX TEXT" --check 'CMD' --by YYYY-MM-DD`, commit `docs/rationale/experiments.toml`, then `safe-push --to main`.
