- Buck2 targets from the Cargo manifests (north#1115): `north buck targets` writes `BUCK` at the repository root and in each `crates/<dir>` from `cargo metadata` and the manifests' `[lints]`, so the Buck2 graph cannot drift from Cargo's while both exist; `--check` writes nothing and exits 1 naming each `BUCK` that differs. `--check` also compares `third-party/BUCK` with the packages and features `cargo tree` says the Cargo build uses, naming each package without a target, built without a feature Cargo turns on, no longer built, or depended on by a workspace target under a name the file lacks; these are the `buck-targets-drift` gate of `harness/gates.toml`, which prints them as would-be refusals and logs them to `$XDG_STATE_HOME/north/gates/buck-targets-drift.jsonl` while in shadow and exits 1 once it enforces. Each library is `//crates/<dir>:<crate>`, each binary `:<bin>` (`:<bin>-bin` when it shares the library's name), each unit-test harness `:<target>-unittest`, each integration test `:<crate>-test-<name>` and each example `:<crate>-example-<name>`; third-party crates are `//third-party:<crate>`. Every test is a `north_rust_test` carrying its nextest binary id, every package has the `:files` its tests read at run time, dotfiles included, a package's tests also get the labels its manifest lists in `[package.metadata.north.buck] test-resources`, of which `//:tree` is every package's files for a test that scans the repository, and `CARGO_MANIFEST_DIR` is the package path from the repository root. A case no remote worker can run is a host case, named with its reason in its package's `[[package.metadata.north.buck.host-cases]]` (`test` names the integration test that holds it) and listed in the one reviewed file `build/host-cases.list`: its test target skips it, `north buck targets` refuses a manifest host case the file lacks, reading the file inside a land check from the landing base (`$SAFE_PUSH_LAND_BASE`) rather than the lane, so a case enters by a landed change to the file alone and its manifest entry follows in a later lane, and also a manifest host case the lane's own copy lacks, so a case leaves the file only after its manifest entry, and `north buck host-cases --filter [PACKAGE...]` prints the class as one nextest filter without spaces for the declared Cargo line's `-E`, which runs it on the host. `north land crate-tests` likewise runs the class of the landing base's list, so a lane that edits or deletes its own copy still runs every case main lists. Every target of a crate carries its workspace-unified features, Cargo's lint and `--check-cfg` flags, and the `CARGO_*` variables its sources read. A file a crate reads through `include_str!`, `include_bytes!`, `include!` or a `#[path]` module outside its own source directory is exported by the package that owns it and mapped into the crate's source tree at its repository path. `north buck compare-cases NAME...` tests each named crate with Buck2 at the checked-out commit and prints the count of cases Buck2 ran, read from its own record of the run, beside the count `cargo nextest list` gives for the crate's library, binaries and integration tests, ignored cases left out, then each case on one side only; it exits 1 on any difference or a crate with no case (north#1299). A host case of `build/host-cases.list` counts as Cargo's rather than as a difference, and a listed one nextest does not list is a difference. Design and the feature decision in `docs/rationale/compile-reuse.md`.
