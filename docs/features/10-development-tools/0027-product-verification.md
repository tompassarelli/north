- Product verification: `verify-north` builds north from the checkout around the current directory (or takes `--north PATH`), then walks the spine end to end on a scratch repository with a bare origin and a scratch state root: every north call runs with `XDG_STATE_HOME` and `NORTH_TEST_ROOT` set to that root, so the worker's `north fleet launch --test` session, its safe-push landing queue, the `north land serve` that runs while the worker hands in with `safe-push --to main --wait`, and every notification stay inside it while account profiles and host policy are only read from the real home; that root also keeps the scratch lander and safe-push from naming the fleet's real ssh outbox hosts, and a host whose outbox holds no ticket gains no queue from a pull, so no scratch queue reaches another host. A separate cleanup process forgets the worker, removes the scratch repository, its landing queue and the state root, and asserts none of its processes survive, even when the run is interrupted. One line per step with wall ms; nonzero exit on any failure.
- A failed verify-north step keeps its evidence: the walk first copies its scratch `threads.db` and its `-wal` and `-shm`, and the lander's `pushes.tsv`, to `${XDG_STATE_HOME:-$HOME/.local/state}/north/verify-north/failed/STAMP` before cleanup removes the scratch root, and step 4 names the run row's role, outcome, landed, ended and landed_sha in its failure, so a ledger-settle regression is readable afterwards (north#1103).
