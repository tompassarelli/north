- Code health: `north code-health` measures hand-written TypeScript, JavaScript, Rust and C against the repo's `structure.toml` through `ast-grep`: size, nesting-weighted cognitive complexity, import cycles, layer violations, fan-in and fan-out, co-change and churn hotspots. `gate BASE HEAD` refuses new debt and reports each changed module's cognitive complexity as reduced, moved or raised with its fan-in and fan-out, so a split that only relocates complexity earns nothing, and `file_lines` is a warning that never refuses a lane; `check FILE` applies the rules to one dirty file, and `signal` says when a review is due; the `code-health-review` flow detector (`north ledger flow detect`) then reads it hourly for each enrolled repository, records the `code-health-review` loop and files one review box per repository on its owner. `budget [REV]` prints each crate against its cap, module pairs that change together with no `may_use` edge, imports of a more volatile module, special cases per module and files touched per feature commit since the last review; `signal` also fires on growth in those. `north health` reports a failing `capacity-watchdog` timer and opens an issue for it. `crate-lines [BASE HEAD]` (bare `north code-health` runs it) prints each crate's non-test Rust lines against its `[crate_lines]` cap and, given BASE HEAD, refuses growth past a cap already crossed unless a `Code-health-allow: crate-lines <crate>` trailer says why (`docs/rationale/crate-split.md`, `architectural-drift.md`).
