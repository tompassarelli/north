- Code health: `code-health report [--save]|gate BASE HEAD|check FILE|signal|review-done [--sha SHA]` (in `harness/code-health/`, `--repo DIR`, `--config FILE`, `--json`) measures hand-written TypeScript, JavaScript, Rust and C against the repo's committed `structure.toml` through `ast-grep`: file and function size, cyclomatic complexity, import cycles, layer violations against module `may_use`, fan-in/out, co-change pairs and churn x complexity hotspots. `gate` exits 1 with one line per new debt (cycle, layer, file-size, function, hotspot, generated), 0 when existing debt only stays put, and fails open without `structure.toml` or `ast-grep`; `check` applies the same rules to one dirty file against HEAD; `signal` prints `FIRE` reasons for the recurring review: commits, hand lines added, test lines added plus removed under test paths (`[review] test_lines_changed`, default 3000), days with landings, or a hotspot score. The hourly `code-health-tick` (north, makgora, wisp, padbridge, makgora-client) starts a `code-health-review-REPO-YYYYMMDD-HHMM` session (a name unique per run, so a parked earlier review never blocks it) whose brief declares `Tier:`, `Surface:` and `Needs: local-state`, takes the account placement picks, and whose review also walks the verification skill's delete-on-sight classes and names a canary per kept check family. State lives in `~/.local/state/code-health/<repo>/`. `north health` also judges each `capacity-watchdog` user timer's service: one that failed two runs in a row (`code-health-review` one run) is a failing check, and its first alert opens (or comments on) the open north issue `Harness unit NAME keeps failing`.
