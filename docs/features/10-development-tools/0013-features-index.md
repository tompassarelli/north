- Features index: `north docs features-index` regenerates `docs/features.md` from the one-file-per-feature tree under `docs/features/` (`_header.md` for the text above the first section, one `NN-name` directory per section holding `_title.md` and one `NNNN-name.md` file per entry, all joined in name order with a blank line between entries unless both are list items); to add a feature, add a file under the section's directory, never edit `docs/features.md` by hand. `north docs rationale-index` writes `docs/rationale/README.md`, one line per note with its title, link and first sentence. `--check` fails when the index is stale (a land check for `docs/features.md`), and `--root DIR` names the checkout. Both indexes are `regenerate` entries in `harness/merge-sets.toml`: when a rebase or cherry-pick stops on one, `north merge-driver continue` runs its generator on the merged sources, stages it and continues, which safe-push and the lander do on their own; the lander also regenerates an index after each lane that changes its sources (`sources` in that file) without committing it, folded into that lane, so batch-mates never make each other stale.
