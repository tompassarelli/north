- Features index: `north docs features-index` regenerates the features index from the one-file-per-feature tree under `docs/features/`, showing each entry's first sentence with a link to its file when the entry says more. The tree is `_header.md` for the text above the first section, one `NN-name` directory per section holding `_title.md` and one `NNNN-name.md` file per entry, joined in name order with a blank line between entries unless both are list items; to add a feature, add a file under the section's directory, never edit the features index by hand; the file is not tracked (`.gitignore` names it), so the lander and `north docs features-index` write it and no lane can commit it. A first sentence over 600 characters is clipped in the index and the generator prints its overage when it writes; the entry body has no length cap, so no lane is refused for a long entry (north#729). `north docs rationale-index` writes `docs/rationale/README.md`, one line per note with its title, link and first sentence. `north docs help-index` writes `src/cli/help.txt` from `src/cli/help/`: `_header.txt` and `_footer.txt` around one `NN-name` directory per help section holding `_title.txt` and one file per listed command with its name on the first line and its summary after, laid out in the summary column `north --help` uses; to change a listed command, edit its file under the section, never edit `src/cli/help.txt` by hand. `north docs reference-index` writes `src/cli/reference.txt` from `src/cli/reference/`: `_header.txt` and `_footer.txt` around one file per command, holding that command's reference line verbatim and joined in name order. `north docs verbs-index` writes `src/cli/verbs.rs` from `src/cli/verbs/`: one file per verb holding its `VerbKinds` line, sorted by that line. `north docs structure-index` writes `structure.toml` from `structure/`: one file per table (`[[module]]`, `[[crate_dag.crate]]`, an allow entry) in name order, each holding its table and the blank line that follows it, so a module, crate or allow change edits its own file. `build.rs` writes `src/cli/reference.txt`, `src/cli/verbs.rs` and `structure.toml` from those trees before the crate compiles, so a lane's own build and checks read the fresh registry without committing it; `north code-health` renders `structure.toml` from `structure/` at the commit it judges too, so a lane's layer and habit checks see a module it adds before the lander writes the generated file. `--check` fails when an index is stale, which is also a land check for each, and `--root DIR` names the checkout. The five tracked indexes are `regenerate` entries in `harness/merge-sets.toml` (the features index is gitignored and needs none): when a rebase or cherry-pick stops on one, `north merge-driver continue` runs its generator on the merged sources, stages it and continues, which safe-push and the lander do on their own. The lander also regenerates an index after each lane that changes its sources (`sources` in that file) and folds the result into that lane's picked commit, so the generated file is written at land time and never enters a worker's diff; `north land scan generated-registry` refuses a lane that commits one and names the per-unit file to edit instead.
