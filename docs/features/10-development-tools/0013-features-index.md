- Features index: `north docs features-index` regenerates `docs/features.md` from the one-file-per-feature tree under `docs/features/`, showing each entry's first sentence with a link to its file when the entry says more. The tree is `_header.md` for the text above the first section, one `NN-name` directory per section holding `_title.md` and one `NNNN-name.md` file per entry, joined in name order with a blank line between entries unless both are list items; to add a feature, add a file under the section's directory, never edit `docs/features.md` by hand. A first sentence over 600 characters is clipped in the index and the generator prints its overage when it writes; the entry body has no length cap, so no lane is refused for a long entry (north#729). `north docs rationale-index` writes `docs/rationale/README.md`, one line per note with its title, link and first sentence. `--check` fails when the index is stale, which is also a land check for each, and `--root DIR` names the checkout. Both indexes are `regenerate` entries in `harness/merge-sets.toml`: when a rebase or cherry-pick stops on one, `north merge-driver continue` runs its generator on the merged sources, stages it and continues, which safe-push and the lander do on their own. The lander also regenerates an index after each lane that changes its sources (`sources` in that file) and folds the result into that lane's picked commit, so the generated file is written at land time and never enters a worker's diff; `north land scan generated-registry` refuses a lane that commits one and names the per-unit file to edit instead.
