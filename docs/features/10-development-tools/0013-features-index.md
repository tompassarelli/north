- Features index: `north docs features-index` regenerates `docs/features.md` from the one-file-per-feature tree under `docs/features/`, showing each entry's first sentence with a link to its file when the entry says more. The tree is `_header.md` for the text above the first section, one `NN-name` directory per section holding `_title.md` and one `NNNN-name.md` file per entry, joined in name order with a blank line between entries unless both are list items; to add a feature, add a file under the section's directory, never edit `docs/features.md` by hand. A first sentence over 600 characters is clipped in the index and the generator prints its overage when it writes; the entry body has no length cap, so no lane is refused for a long entry (north#729). `north docs rationale-index` writes `docs/rationale/README.md`, one line per note with its title, link and first sentence. `north docs help-index` writes `src/cli/help.txt` from `src/cli/help/`: `_header.txt` and `_footer.txt` around one `NN-name` directory per help section holding `_title.txt` and one file per listed command with its name on the first line and its summary after, laid out in the summary column `north --help` uses; to change a listed command, edit its file under the section, never edit `src/cli/help.txt` by hand. `north docs reference-index` writes `src/cli/reference.txt` from `src/cli/reference/`: `_header.txt` and `_footer.txt` around numbered files holding contiguous runs of `north --help-all`'s reference lines verbatim, joined in name order; a new command adds its own `NNNN-command.txt` numbered above every existing file, and to change a line, edit the file that holds it, never edit `src/cli/reference.txt` by hand. `--check` fails when the index is stale, which is also a land check for each, and `--root DIR` names the checkout. Each index is a `regenerate` entry in `harness/merge-sets.toml`: when a rebase or cherry-pick stops on one, `north merge-driver continue` runs its generator on the merged sources, stages it and continues, which safe-push and the lander do on their own. The lander also regenerates an index after each lane that changes its sources (`sources` in that file) and folds the result into that lane's picked commit, so the generated file is written at land time and never enters a worker's diff; `north land scan generated-registry` refuses a lane that commits one and names the per-unit file to edit instead.
