- Dependency sandbox: `depbox fetch|run -- CMD...` runs installs, builds and tests in bwrap with the home directory masked except the checkout (read-write), the package and build caches it needs and the immutable firn and north pins (read-only), a scrubbed environment that keeps the fleet session variables, no sudo and, under `run`, no network; a fleet session's compile goes to a build host before the sandbox starts (north#671). Each checkout builds into its own `target/`, because cargo hashes a path package by its workspace-relative path and worktrees sharing a target directory would run each other's outputs. Before the sandbox starts, depbox roots the checkout's `nix develop` shell so `nix-collect-garbage` cannot delete it and break offline runs. It mounts the checkout a second time at `~/code/<project>/sandbox` and runs there, so every lane of a project builds at one path and a seeded `target/`'s incremental state stays valid (a one-line north-core change built in 14 s seeded this way against 112 s from another lane's path, 2026-11-05). The exact mounts are in `crates/north-capacity-host/src/capacity/depbox.rs`; `bin/depbox` forwards to `north depbox`. A depbox a worker command hands work to gets the worker's removal roots from the outside broker and applies them again inside the namespace with `north --worker-sandbox --hand-off`, so dependency code cannot remove a path outside the worker's trees even though the sandbox is built outside its Landlock domain (north#975). The broker starts a caller's run inside the caller's capacity lease scope, so a leased compile counts against its lease rather than escaping into the broker's service (north#1036).
