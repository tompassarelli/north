- Dependency sandbox: `depbox fetch|run -- CMD...` runs installs, builds and tests in bwrap with the home directory masked except the checkout (read-write), the package and build caches it needs and the immutable firn and north pins (read-only), a scrubbed environment that keeps the fleet session variables, no sudo and, under `run`, no network; a fleet session's compile goes to a build host before the sandbox starts (north#671). Each checkout builds into its own `target/`, because cargo hashes a path package by its workspace-relative path and worktrees sharing a target directory would run each other's outputs. Before the sandbox starts, depbox roots the checkout's `nix develop` shell so `nix-collect-garbage` cannot delete it and break offline runs. It mounts the checkout a second time at `~/code/<project>/sandbox` and runs there, so every lane of a project builds at one path and a seeded `target/`'s incremental state stays valid (a one-line north-core change built in 14 s seeded this way against 112 s from another lane's path, 2026-11-05). The exact mounts are in `bin/depbox`.
