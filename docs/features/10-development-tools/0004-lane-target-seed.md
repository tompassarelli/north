- Lane target seed: `north lane seed [DIR]` gives a checkout with no `target/` a `cp -a --reflink=always` copy of the newest idle sibling `target/` and deletes the fingerprints of packages that must rebuild, so a new lane's first build starts warm. It is run by the devShell hook, by `depbox` before its sandbox (which hides `north` and the sibling checkouts) and by `harness/scripts/canary.sh` for the scratch lane it makes in `worktrees/`, and acts only on a checkout with no `CARGO_TARGET_DIR` other than its own `target`, as the land checks set it. The source is the newest idle `target/` of the same container's `main` or `worktrees/*` that holds a `CACHEDIR.TAG` and a byte-identical `Cargo.lock`, copied with `incremental/` included; on btrfs the copy is made into a new subvolume, and a checkout with no source gets an empty `target/` subvolume holding cargo's `CACHEDIR.TAG`, because a btrfs snapshot leaves nested subvolumes out, so the hourly and daily `/home` snapshots never hold a lane's build output after it is deleted (`btrfs subvolume show target` lists it); the deleted fingerprints are those of every `Cargo.lock` package without a registry or git source. A sibling whose `.cargo-lock` is held mid-build is skipped (compile-times.md, "Measured: a new lane's first build"). A sibling on a filesystem that cannot share extents with the checkout (ext4 build hosts, tmpfs) seeds nothing and the lane builds cold, because a full copy there wrote 30 to 50 GiB per lane and took over 14 minutes on gex45, filling its disk on 2026-11-11 (north#1036). The copy is staged in `target.seeding-<pid>` and removed on every exit path the seeder catches before it is renamed into place, so only a killed process leaves one; `north lane reclaim` and the disk pass (`north capacity disk keep`) delete any `target.seeding-<pid>` in `~/code/*/main` or `~/code/*/worktrees/*` whose process is gone and whose directory is over an hour old. On a host whose `[hosts.NAME]` table in orchestration.toml sets `build_system = "buck2"`, it copies no `target/` and makes only an empty `buck-out/` beside the outermost `.buckconfig`, its own subvolume on btrfs and staged the same way in `buck-out.seeding-<pid>`, because the shared Buck2 action cache replaces the seed (compile-reuse.md, "Lanes and the laptop"); no host sets it before north#1115 box 7c.
