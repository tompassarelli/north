- North depbox: `north depbox fetch|run -- CMD...` is depbox in Rust, in `crates/north-capacity-host/src/capacity/depbox.rs`, with the same mounts, carried variables and same-mode pass-through; a `run` compile against a Cargo.lock this host never fetched first runs `cargo fetch --locked` in `fetch` mode. A build host runs each offloaded command other than a landing through `north depbox run`, and a landing runs `bun install --frozen-lockfile` and `cargo fetch --locked` through `north depbox fetch` (south#93).
- Agent toolchain calls: the capacity-gate shims (`bin/cargo` and its links rustc, cargo-nextest, bun, bunx, node, npm, npx, pnpm and yarn) send each call into `north depbox run`, or `fetch` for the verbs that download, so a lane's build scripts and package scripts never run outside depbox (`crates/north-capacity-host/src/capacity/gate.rs`). A depbox admitted by the heavy-command guard marks its sandbox with `DEPBOX_LEASED`, so the gate inside keeps that admission though depbox left the guard's scope. Each promoted runtime adds its tree's shims to the Nix store and roots them at the runtime's `shims`, and firn links those names into `~/.local/bin`, so the operator's terminal runs the same shims (`crates/north-runtime/src/runtime/store.rs`; south#93).
- Store entries for a land check: the land checks set `SAFE_PUSH_LAND_HOST_INPUTS` to the host inputs a check declares, each `STORE@PINS` input expanded to the store entries its head pins (a sharded family's pin is a directory with one file per shard, each naming its entry), and a `run` sandbox binds read-only each that is a link-free directory named by a 64-hex hash below a `*-build-inputs` folder of `~/.local/share`, never the store's root. Run from a worker sandbox, the outside broker keeps only the entries the caller's own domain reads, so a lane-only session's sandbox binds none (north#1148).
