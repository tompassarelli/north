- Two-rung routes (north#1233): `north fleet launch --route FAMILY[:EFFORT],FAMILY[:EFFORT]` of a Claude worker on a named issue starts the box on the first rung, a model family (haiku, sonnet or opus) and an optional effort, under a tier override; `small-first` names `haiku,opus`, and `opus:low,opus:medium` holds the model equal. Only the flag routes a launch: a `Route:` line in a brief's text routes nothing. The first rung's brief tells it to end its turn when its finish call's check fails, and to make the finish call even when it cannot finish. `north finish` writes each acceptance verdict as the session's finish record (session, command, head, passed, time). When a first rung's completed turn has a failed finish record written since the session started, the session watcher claims a once-only receipt and starts `north fleet launch --route after:NAME:RUNG` on the second rung from the project's main checkout. The failed check's output and diff the lane kept fill the second brief as quoted, bounded data and never decide whether the second rung starts. When the first rung's directory is in no git checkout, the second rung is refused and the parent told. An `after:` route never escalates, so a box starts at most twice without a person or the coordinator. Both launches write their route, model and session name to the dispatch launch record, which the tier loop joins to each session's usage in the run ledger.
