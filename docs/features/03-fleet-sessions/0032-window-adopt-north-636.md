- Window adopt (north#636): `north fleet adopt --name NAME`, run inside an interactive Claude window (it reads `CLAUDE_CODE_SESSION_ID`; a fleet session is refused) or a Pi window (it reads `PI_SESSION_ID`, see the Pi window adopt entry), finds that conversation among the live sessions every Claude account's profile lists, takes the name over in the fleet store as `--take-over` does, ends and archives the session that held it, and binds the name to the window: the record carries `adopted_ms` and no host. A message to the name, a backlog the old holder never took included (the window takes every message sent since the old holder began), goes into the window as one turn over its Claude Code session inbox (the socket and peer key its `sessions/PID.json` names), and the window's `north fleet send` signs as NAME. While the window lives the name reads `idle` and a second proxy launch is refused; revive, relaunch and the fleet tick start no host under the name, so the archived holder never wakes again. Adopting from another window ends the first window's hold; a closed window reads `exited` and a message to it fails naming the fix. Proxy name follows a live window: no one runs `north fleet adopt` for the proxy. Every interactive window's SessionStart hook runs `north fleet adopt --name proxy --if-free`, which binds the name to that window only when no live session holds it (a parked or exited holder does not); fleet sessions, subagents and a start whose session id is not its own Claude process's conversation never run it. A message to `proxy` whose holder is dead, and a launch naming it as the parent, first bind the name to a live interactive window (`entrypoint` `cli` in `sessions/PID.json`) that no other session holds, the one on the holder's own conversation first and else the newest; the window takes the name over and the message is delivered to it, so a message never revives the dead holder. Adoption leaves a `host.sock` directory in the name's session directory that an older session host cannot bind, and the fleet refuses every launch, take-over, revive and start on a conversation a live interactive window holds. Pi window adopt: `north fleet adopt --name proxy` run inside a Pi session binds the name to `PI_SESSION_ID`, records the window's Pi process, and installs the `north-fleet.ts` extension so a later Pi start or `/reload` loads it; the registry under `<state>/north/pi-windows` makes dispatch and the fleet tick count the name live while its Pi process runs, and a report to the name reaches the session as a user message over `<state>/north/pi-sessions/<pid>.sock`, queued as a follow-up while the session streams. A Pi window whose process is gone reads `exited`, and a second proxy launch is refused as for a Claude window.
