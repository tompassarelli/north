- Fleet gates: each fleet tick publishes this host's open decision gates to the store's `fleet_gates` table and caches it, so `north gate list` and the issue-gate guard behind `north fleet launch` and dispatch see the gates every host holds, answerable as `HOST:ID`. `north gate answer HOST:ID N` spools the answer for the asking session's host to apply once on its tick (north#184); that host admits the row from a peer only when its sender is the owner or the asking session's parent, the same check `north gate answer` makes before it spools (north#747), and `north gate open` for a session another host runs spools a GATE row that host opens as its own gate (north#416). `north gate open --issue OWNER/REPO#N --box TEXT` holds only launches whose `Item:` or `Box:` line carries TEXT, and in dispatch only the open boxes carrying TEXT, so one box of an umbrella issue does not hold its others (north#568, north#872); once the issue shows that box ticked, the next fleet command on the gate's host closes the gate with the ticked line as its answer, by `ticked` (north#872). `north gate --help` gives the forms.
- Ask-once gates: a gate without `--default` must name the ask-once category of its recommended option with `--ask-once CATEGORY` (cost, accounts, credentials, public, deletion, tom_name, direction: the `ask_once_*` classes of `harness/defaults.toml`), and it waits for the owner's answer; a gate that names a category and a default is refused, and so is a default whose recommended option names an ask-once word (north#1048). The category is stored with the gate and printed in the digest. `--issue` without `--box` is refused when the issue has several open boxes (north#670).
