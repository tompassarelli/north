- Placement gate: `north fleet launch` and `revive` of a Claude session first print one verdict line per account, open with its headroom or out on the window that stops it, so a box never starts on an account at its provider's limit; only the spend rule (north#702) refuses a start on usage grounds. A box whose model names Fable is ranked and refused by its `weekly_scoped/Fable` meter beside the shared five-hour and weekly windows, and a coordinator launch starts on the account with the most Fable headroom; when none has headroom above the subscription floor it starts Opus high instead, and the same fallback hands a running coordinator over when no account is left above its Fable floor (north#1065). A code-only box on a public repository is sent to `north cloud launch`, while the cloud credit is usable, under the best account whose profile on its host is signed in through claude.ai (`north fleet accounts --claude-ai` lists those, the ones with a `.credentials.json`; a token-only account cannot start `claude --cloud`), else it falls through to a local account as if cloud were absent (north#691), unless `--local "REASON"`, and a box with local needs goes to the first `[hosts.NAME]` machine that serves them and has room. A box that would run here also meets the spawn gate's CPU line (north#259). The reasons are recorded on the session and shown in `north fleet list`; the thresholds are the `dispatch_agent_memory_mib` and `build_disk_free_gib` keys in `harness/defaults.toml`.
