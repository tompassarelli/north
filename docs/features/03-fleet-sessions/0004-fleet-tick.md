- Fleet tick: `north fleet tick`, run on each fleet host by the `fleet-tick` timer, makes one `north fleet row exchange` with the ledger host. It commits this host's spool and those it takes from the far machines whose CLIs it runs (`north fleet spool take`), publishes this host's registry into `fleet_sessions`, and delivers each row addressed to its sessions through `hand_in` once by row id, reviving a parked recipient. A failed pull is reported per machine, and a row the store refuses is set aside with a notice; a prompt's uuid derives from its row id, so a killed tick redelivers at most once (north#429).
- Tick probes: the tick then runs its probe jobs in order (ended waits, parking limited sessions, the spend breaker, the hand-over scan), timing each by name in the `tick took` line. They share a 15 s budget: a job still running when it is spent, and the ones after it, are named in a `deferred NAME to the next tick` line, so no probe holds the tick (north#637).
