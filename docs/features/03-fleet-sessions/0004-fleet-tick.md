- Fleet tick: `north fleet tick`, run every 30 s on each fleet host by the `fleet-tick` timer, makes one `north fleet row exchange` with the ledger host (over the threads ssh remote, or the local ledger on the host that holds it): it commits every row in this host's spool and withdraws a spooled row only once that exchange answered, and also takes the spool of every far machine whose CLIs this host runs (`north fleet spool take` over ssh on each machine a live session of this registry is placed on, plus each `[hosts.NAME]` with `pulls_spool = true` in the orchestration policy, never this host) and puts those rows through the same exchange, dropping on a machine (`north fleet spool drop`) only the ids that exchange committed (ids go on the command's stdin, so any count fits); a row the store refuses or this build cannot decode is set aside on its machine (`north fleet spool set-aside`) with a notice and never fails the pull, and a pull or drop that fails is recorded under the machine's name in the tick's `pull_failed` and printed as `not pulled from NAME` other machines are still pulled, and the ssh helper is `fleet/ssh.rs`, publishes this registry into `fleet_sessions` and caches the whole table in `fleet/.fleet-sessions.json`, and fetches the MESSAGE, GATE, GATE-ANSWER and JOB-EXIT rows addressed to this host's unstopped sessions (and its CONTROL rows, below) sent since each session's creation and within the 7-day row window. Each goes through `hand_in`, which skips an id already in the session's `delivered` journal, so a second tick delivers nothing; a parked session is revived under its start lock. The row id fixes the prompt's uuid (a hash of the id), so the CLI echo and the session host's unaccepted-prompt replay match the row by id whatever signing or urgent prefix the text carries; a `delivered/ID.handing` marker left by a tick killed mid-delivery is redelivered once unless the session host journaled or echoed that uuid. A row from this host is signed by its sender alone and one from another host as `sender@host`. Journal entries older than 14 days are pruned. The TUI desk, wait results, reboot notices and a closed gate's answer to its session send through the spool and `hand_in` too: the answer is a spooled MESSAGE row handed in by id at once, and one whose hand-in failed is delivered by a later tick (north#429).
