- Fleet tick: `north fleet tick`, run on each fleet host by the `fleet-tick` timer, makes one `north fleet row exchange` with the ledger host. On the host `[placement] dispatch_host` names it also runs one `north fleet dispatch` when the last ran five minutes ago and dispatch is not paused, so the review-and-land loop needs no proxy step (north#1020). It commits this host's spool and those it takes from the far machines whose CLIs it runs (`north fleet spool take`), publishes this host's registry into `fleet_sessions`, retires the `fleet_sessions` rows of every host the ledger host's orchestration config no longer lists under `[hosts]` (north#794) and pulls no far machine its own config no longer lists, and delivers each row addressed to its sessions through `hand_in` once by row id, reviving a parked recipient. A failed pull is reported per machine, and a row the store refuses is set aside with a notice; a prompt's uuid derives from its row id, so a killed tick redelivers at most once (north#429). The host that settles the fleet also starts `north runtime checkouts` in a scope of its own and prints the moves and refusals that run left, so every host it ships runtimes to fast-forwards its `~/code/<project>/main` checkouts onto origin/main and a build host reads the same south `agents/orchestration.toml` as the fleet within one tick of a landing (north#872).
- Tick stages: each stage that calls another host (placement, take_far, ledger.exchange, drop_far, cache_far, deliver_far, settle) has its own budget; one still running at it is named in a `deferred STAGE to the next tick` line and its rows wait for the next tick. The rebooted stage revives each stranded session on its own thread against what is left of the tick's budget, naming one still running in a `deferred NAME to the next run` line. A deferred ledger.exchange skips hand-in and far delivery, not the probes, which run in order under a shared 14 s budget, each timed by name. The budgets sum to at most 38 s, inside the 50 s start timeout (north#637). Launch-queue admission reads, drops and starts queued launches in one pass that begins no launch after its 5 s share or what is left of those 38 s, whichever is less: the launches left are counted in one `deferred N queued launches to the next tick` line, a launch started on one tick is not read again ahead of them on the next, and a read still running when the 38 s end is left by a `deferred launch_queue to the next tick` line (north#637).
- Pulled-host probes: on a host marked `pulls_spool`, whose spool and registry the pulling host already exchanges, `north fleet tick` makes no exchange and runs only the probes that act on its own registry (waits, usage park, api credit move, budget notices, hand-over, reap) on the same 30 s timer, leaving placement and the fleet-wide probes (goals, scoreboard, corrections, records mirror, host checkouts) to the hosts that exchange; `north fleet waits` there runs the same set (north#770).
- Fleet reports: a host whose `[hosts.NAME]` entry sets `fleet_reports = false` (nexus, whose 3 cores the scoreboard read of 52 CPU seconds saturated) runs the same tick without the goals, scoreboard and corrections probes, which the other exchanging host's tick still runs; every host runs them by default (north#1036).
