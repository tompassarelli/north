- Proxy window (north#733, north#1048): the proxy runs only in a window Tom types into. Every path that starts a proxy host (`north fleet launch --role proxy`, with or without `--take-over`, the fleet tick's hand-over, `north fleet revive`, a message or report that wakes a stopped proxy, an account move by the API pool or a relaunch) opens a terminal window titled `north NAME` that runs `north fleet interactive NAME --after-turn`, so the proxy is on screen at once. The registry asks one port (`ProxyDesk`) at its single host start, with niri and ghostty as the adapter; the compositor spawns the window, so it is no child of north, and niri's socket is found in the runtime directory when `NIRI_SOCKET` is unset. Before the host starts, a proxy on another machine, one whose account profile would stop its window at a trust or bypass-permissions prompt, or a host with no niri socket (gex45, cloud) is refused with the reason, and no headless host starts; a window that then fails to open ends the host it was opened for. The window waits for a turn the host is running, and for any background task its CLI started, to end before it stops that host (stopping it kills them), and on an idle host it waits a few looks first, so the message that woke the proxy starts its turn before the window takes the conversation; it runs under the HOME of the fleet that opened it, since the compositor starts it with its own environment. A window still open on the conversation of a proxy that a take-over archived no longer counts as Tom's directing window, so the new proxy messages and launches at once; a window on any other conversation still holds direction until it has been idle for 30 minutes.
