- Launch claims: `north fleet launch` claims every issue its session holds before it starts (`--task REF`, else the issues the brief's first `Item:` line names), claiming only those no session in its parent chain already holds, so a lead that holds an issue keeps it while the children it staffs work its boxes, refusing on a live claim and taking one a stopped session left, and releases them when the session ends or fails to start; `north fleet list --json` shows them as `tasks`. With `--box TEXT`, or a `Box:` line in the brief, the claim covers that one box of the first issue: a second launch on another box of the same issue is admitted, a second launch on the same box or on the whole issue beside it is refused, and the run row records the issue and the box. An issue whose body says `Workers: N` is staffed box by box by dispatch, up to N workers at once.
- Filed claims: when a fleet worker files an issue, on whichever host it runs, the PostToolUse filing hook runs `north threads claim REPO#N --by SESSION` as soon as `gh issue create` returns the URL, so north dispatch, which reads every host's `threads list` (the laptop's through its copy on nexus), never staffs a second session on it. A blocker it files (a `Blocks:` line) and an issue the proxy files stay unclaimed for dispatch to staff, except an issue the worker files as its own item (its brief's `Item:` line says to file it first), which it keeps whatever it names as blocked. Before this, dispatch staffed north#736, north#737, north#738 and north#739 beside the sessions that had just filed them.
