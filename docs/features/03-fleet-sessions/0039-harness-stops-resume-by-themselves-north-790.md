- A first try the harness continued is scored by where its chain ends (north#790): the scoreboard's first-try bar folds a failed run that a `resume` cause row or a `Follows: SESSION (Stop: host NEED)` relaunch continued into the run its chain ends in, leaves a chain not yet ended out, and ends the chain at a message from Tom or the proxy, so the stopped run stays lost; `Stop: host` relaunches follow the stopped run and start from its report; a resume cause row never replaces the stopped run's own recorded cause (`north dash`, `docs/rationale/attribution.md`).
- One owner wakes a stop (north#790): the fleet resume pass owns a stopped session on this machine whose turn ended on `Stop: capacity`, waking it when the capacity host admits its queued run; `north fleet dispatch` revives only capacity stops on other machines and sessions that ended on a pending wait, and revives nothing the fleet already woke since the report, because `north fleet stranded --json` carries `resumed` (found by the `[north: ...]` opener every wake message starts with, dispatch's own included). A box waiting on a registered wait stays held while its session is parked on it (`north fleet list --json` `waiting`).
