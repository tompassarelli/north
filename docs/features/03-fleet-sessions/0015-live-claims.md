- Live claims: `threads claim`, `threads list [--json]` and north dispatch share one rule in `crates/north-core/src/threads/claims` (run in Rust as `north threads claim|list` on the ledger host; bin/threads hands both verbs to it). A claim is void, so `list` omits it, dispatch holds nothing and `claim` replaces it with a `claim` event naming it, when it was made before its GitHub issue was opened, its issue is closed or does not exist (native items read the ledger's item table), or its owner is not a session alive in the fleet (a name, conversation or provider:conversation of a non-exited session here or relayed by the caller; an unreadable fleet voids nothing). A claim with no event from its owner for 24 h past `since` plus its ETA (none counts as 0), or past `overdue_ratio` times its ETA with no event from its owner since the ETA, shows `STALE`; dispatch does not hold it and `claim` takes it over with a `handoff` event whose `takeover` names why. Any other claim is live: `claim` refuses another owner and dispatch holds the issue. An unreadable GitHub reply leaves only the ETA rule. `threads ready`, `threads unowned` and `north work list` read `north threads list --json` too, so a void claim leaves its issue ready and unowned and a live claim holds it; `north work list` shows only a live claim as its holder. `threads list --json --all` also lists void claims (standing `void`), and `threads release ITEM --held-by NAME` clears the claim only while NAME still owns it; every `north fleet` command clears the claims of exited sessions this way (parked, idle and working sessions keep theirs), so `threads show` stops naming an exited owner within one fleet command.
