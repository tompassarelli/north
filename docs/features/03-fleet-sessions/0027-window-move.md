- Window move: `north proxy move [--to ACCOUNT] [--auto] [--dry-run]` moves the window holding the conversation the fleet record names for the coordinator, whatever other interactive `claude` windows are open, when its account's outlook is under 45 minutes (or out), or when `--to` names an account with week headroom, to the account with the most week headroom whose own outlook is not under 45 minutes; it refuses when that conversation has no live window on a terminal and names the windows it saw (north#636, north#1238). The caller only starts the user unit `north-window-move` and prints its result, so a sandboxed shell, the coordinator's own included, can run it: the unit reads the windows, runs the terminal test and prints the plan, which `--dry-run` stops at. Otherwise it starts the unit `north-window-move-swap`, which waits for the old window's turn to end and runs the steps in order: carry the session's transcript, subagent files, file history and session environment into the target profile; open a ghostty window running `claude-ACCOUNT --resume SESSION` with the old window's flags and wait until it runs under the target profile's `CLAUDE_CONFIG_DIR`; change the fleet record's account and bind the coordinator's name to the new window; deliver its undelivered messages with a fleet tick; and only then stop the old daemon-hosted session, hang up the old window's shell and put the new window in the old one's workspace and column with focus restored. A failure, or a turn taken in the old window, before that last step closes only the new window and binds the name back to the old one, which stays as it was. The fleet tick runs `--auto`, which reads the coordinator's account from the fleet record and starts the swap unit at most once in 20 minutes.
