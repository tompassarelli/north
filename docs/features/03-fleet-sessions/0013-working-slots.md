- Working slots: a host slot and the working target count only sessions in `starting` or `working`; an `idle` session, or one `parked` on a registered run, holds its issue and its claims but no slot (`north resident-cap` also leaves an idle session's CLI out of the count). `north fleet wait RUN [NAME]` registers a run (`job:NAME[@HOST]`, `farm:RUN_ID`, `branch:BRANCH`, `capture:PATH`) in `~/.local/state/north/fleet/.waits`, shows it as `waiting` in `north fleet list --json`, and parks the session as soon as its turn ends; the fleet tick (every 30 s, or `north fleet waits` by hand) revives each session whose run is over with a message naming the run and its result, and drops the waits of stopped sessions. A run the session detached from its CLI (`setsid`, `nohup`, `job-run --notify`), seen as a live process in its `north-session-*.scope` outside the host's own process tree (a revival stops only the old host's tree and records its scope in `host.priors` beside `host.scope`, so runs detached under an earlier host stay alive and the new host counts them too until they end; stopping or forgetting the session stops those scopes), is registered as a `pid:PID@START` wait as soon as the host sees it, and the session parks 30 seconds after its turn ends; the tick settles that wait once the process is gone, messaging the session with the run. An idle session with no registered wait or detached run parks at the idle limit (10 minutes) and is revived by its next message. The tick retries a store settlement that failed on the next tick, and no longer wakes a worker on its waiting prose, a passed wait deadline or a lapsed job lease, and the silent notice to the parent is the one silence check.
