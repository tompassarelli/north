- Working slots: a host slot and the working target count only sessions `starting` or `working`; an idle session, or a parked one, keeps its issue, its box and claims but no slot, and dispatch staffs nothing beside it until it is revived or retired (north#1054). `north fleet wait RUN` registers a run (`job:`, `farm:`, `branch:` or `capture:`) and parks the session when its turn ends; the fleet tick, or `north fleet waits` by hand, revives it with the run's result once the run is over. A run the session detached from its CLI is found in its session scope and registered as a `pid:` wait on its own, surviving revivals until it ends. A session whose last turn ended on its account's usage limit is parked by the tick on `usage:ACCOUNT@TIME`, the reset the stream event or message names (else the account's window reset from the usage table), even if the host stopped it; `north fleet waits` revives it once that time passes, a worker holding a lane no queued ticket will land first, with a message to fetch, rebase and re-enqueue the lane or report Done with the landed sha. A session `north fleet stop` ended is never revived, and a parked session accrues no spend. An idle session with nothing to wait on parks at its idle limit and its next message revives it.
