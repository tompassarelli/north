- Claim holder reads (north#562): `threads holder REPO#N ...` and `threads holder --owner NAME ...` print the claim rows, as JSON `{item, owner}`, on those items or held by those owners, through one lookup per item on the claims table's item key or per owner, and read neither GitHub nor any fleet, so a read stays cheap on a loaded ledger host. `north fleet launch`, `--test` included, asks the ledger only who holds the items it names and clears any claim an exited session left on them; every other mutating `north fleet` verb leaves exited sessions' claims to the exited-claims sweep. Neither reads `threads list --json --all`. A launch whose holder read does not answer within 2 s says so, naming the read that timed out, and starts anyway: its claim, bounded the same way, refuses it if a live session holds the task, and one the ledger cannot take yet is made once the session runs.
