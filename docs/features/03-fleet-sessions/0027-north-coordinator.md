- North coordinator: `north coordinator` opens north's fleet TUI on the fleet session `coordinator`, attaching when it is live, reviving it when it is parked or stopped, and otherwise launching it through `north fleet launch`'s own account routing with `--role coordinator`, so `harness/claude/agents/coordinator.md` is its agent definition from the first turn; the launch also passes the `model:` and `effort:` that definition names under a `--tier-reason`, because the session record `north fleet show coordinator` prints takes its model from the launch request and not from the agent file. Where the fleet's desk can open a window, the coordinator starts in a client window as Coordinator window below says; where it cannot, `north coordinator` prints why no window opened (`north coordinator: no window opened for coordinator, so the fleet screen holds it: WHY`), starts the coordinator held by the screen (`--screen` on `north fleet launch`, or the record marked so before a revive): no window, an ordinary fleet host that the screen types into, and opens the fleet screen on it. Only `north coordinator` makes that choice, and only when the operator runs it on a coordinator that is not live; every start the operator did not type (a wake by a message or report, a relaunch, a take-over, the fleet tick's hand-over) inherits the surface on the record (`surface`, `window` or `screen`, in `north fleet show coordinator --json`), so a coordinator in a window never drops to the screen by itself, and a coordinator the screen held goes back to a window when the operator runs `north coordinator` on it, not live, where a window can open. In a fresh state, where the usage gate holds no Claude sample, `north coordinator` takes one usage reading, the one `north fleet usage --refresh` takes, before it places the coordinator. `north coordinator --interactive` stops the fleet coordinator and resumes the same conversation in `claude`, its record keeping its surface, and the coordinator is not revived while that UI holds it. When the coordinator's account is out, the fleet tick takes it over under its name onto an account with headroom and resumes its conversation, so there is always exactly one live coordinator (north#112). Coordinator window: a coordinator held in a window runs only in a window the operator types into. Every path that starts a window-held coordinator (`north fleet launch --role coordinator`, with or without `--take-over`, the fleet tick's hand-over, `north fleet revive`, an account move by the API pool or a relaunch) starts no fleet host: it opens a terminal window running the provider's interactive client on the coordinator's conversation (`claude --session-id ID` with the first prompt for a fresh one, `claude --resume ID` otherwise), and once the window is up binds the name to that conversation as `north fleet adopt` would, so messages to the coordinator reach that window from its first turn (north#1427). The window carries no fixed title; the client titles it as it does any other. The registry asks one port (`CoordinatorDesk`) with the client's command, with niri and ghostty as the adapter; the compositor spawns the window, so it is no child of north, and niri's socket is found in the runtime directory when `NIRI_SOCKET` is unset. Before the window opens, a coordinator on another machine, one whose account profile would stop its window at a trust or bypass-permissions prompt, or a host with no niri socket (a build host, the cloud) is refused with the reason, and nothing starts. A coordinator held by the screen keeps only the refusal of a coordinator on another machine and opens no window. The client runs in the coordinator's working directory, with its environment, under the HOME of the fleet that opened it, since the compositor starts it with its own environment. A window still open on the conversation of a coordinator that a take-over archived no longer counts as the operator's directing window, so the new coordinator messages and launches at once; a window on any other conversation still holds direction until it has been idle for 30 minutes.
