- Dispatch: `north dispatch`, run on Nexus by a timer (south `modules/north-dispatch.nix`), keeps free worker slots busy. It prints each host's cap and running sessions, each account as open or out, the free slots per host and account, and every open issue in the staffed repositories with why it is or is not ready: a label holding it for Tom, a live session, gate, claim or recent launch on it, an open predecessor, or a box gated `(not before TIME)`. Each ready box gets a generated brief and goes, in project priority order, to the cloud lane when it is code-only in an Autoland repository, else to the host that serves its needs and would start it soonest, on the open account that ranks first by pace. Attempts are logged in `~/.local/state/agents/dispatch/launches.jsonl`. An item tried twice without progress is left to the proxy (a session no registry lists spends no try), issues with no box go once a day to the triage lead or else the proxy, ready work with nothing launched raises one `nexus-alert`, and a launch queued behind an in-flight lane is held, not failed. `--dry-run` launches nothing. A box's needs are read before placement: its brief's `Needs:` line joins the issue's own `Needs:`, what its takeable boxes name (the laptop or its niri desktop, a host by name, every host, another repository's checkout as `checkout:REPO`, which only a host serving some need of that repository holds), the last report's `Stop: host` and every earlier `Stop: host` kept in the dispatch record's host-needs.jsonl while a box it was named for stays unticked, so no host lacking one is chosen; a report is the newest message opening with `Done:`, `Not done:`, `Split:` or `Blocked:`, not a later reply to a notice. A box is gated by its dated check, `(not before TIME)` or a date it is `after`, `from`, `due` or `reviewed on`, which `north graph ready` also holds it behind, and by the last report's `Stop: wait until`. Each launch first rereads its issue on GitHub and is skipped when the issue closed or its last box was ticked after the mirror copied it, and a claim on the laptop holds its issue through the claim list the laptop copies to Nexus (north#706).
