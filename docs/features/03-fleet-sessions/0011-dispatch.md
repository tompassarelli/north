- Dispatch: `north dispatch [--dry-run]` (Nexus timer every 5 minutes, south `modules/north-dispatch.nix`) keeps free worker slots busy. It prints each `[hosts.NAME]` (the laptop only while `north laptop status` says available, counting its sessions from the fleet list it copies to Nexus) with its resident cap and running sessions, each pace-control account as open or out with the hosts `[accounts.PROVIDER] profiles` signs it in on (less this host when its roster has no login of its own for the account), and per host and account the free slots: cap − running for an open account, none for one the out-rule holds (5h at 95%, 5h burn over its cap or the week exhausted; pace's allowed workers and projections never hold). A ready box is an open issue in a staffed repository (the `dispatch_repos` of each `[projects.NAME]` in South's orchestration, else its `repos`, less `[placement] private_repos`, in project `priority` order) with an unticked box, not in a project whose `dispatch_paused_until` (an RFC 3339 time in its `[projects.NAME]` table) is still ahead, which skips with `project NAME paused until TIME`, not labelled `evidence:tom`, `needs:tom`, `decision:tom`, `roadmap` or `native:running`, held by no running fleet session (each ref its `--task` names, else each number of an `sc-N`, `sc-N-M` or `wisp-N` name, on this host, any ssh host or the laptop), open north gate naming it (its `--issue`, its question or the asking session's name) on any host, NorthThreads claim or dispatch launch of the last two hours (six for a cloud launch), whose newest comment does not say it waits on Tom or the laptop, whose `Follows:`, `Blocked by`, GitHub blocked-by and plan `Order of work` predecessors are closed, and with at least one unticked box measurable now: an issue author gates a Done-when line on a time by writing `(not before YYYY-MM-DDTHH:MMZ)` in it, and while every unticked box carries a marker still in the future the issue skips as `only open box waits until <earliest>`; every other issue prints with its reason. Each ready box gets a generated brief (Item, Category and facets from the issue or defaulted, the generic Done when); its category is the first word of the body's `Category:` line, else a `category:NAME` label, else `feature` for `enhancement`, `debugging-unknown-cause` for `bug` and `docs-policy` for `documentation`, and a box none of those categorise skips as `ready, not placed: no category: ...`, which the alert line names when nothing else launched, and goes, in priority order, straight to the cloud lane (`north cloud launch`, no courier; Autoland lands the `claude/land-NAME` branch the session pushes) when it is code-only in an Autoland repository (makgora or wisp; other repositories have no courier, so they run on hosts), the credit is usable, this is `[placement] cloud_host` and fewer than 6 cloud boxes it started in the last 6 h are still open, else to the host that serves its needs, has a free slot and would start it soonest (`--local` records the cloud fallback): dispatch reads each host it reaches (here or over ssh) for `nproc`, `/proc/loadavg` and `/proc/meminfo`, classes a box verified by `local-test` or `native` as heavy (`dispatch_heavy_memory_mib`, else `dispatch_agent_memory_mib`), refuses a host whose total memory could never admit that class under unattended admission, and ranks the rest by the run queue past the cores plus one run when memory headroom would defer it now, `[placement] order` breaking ties and an unmeasured host (the laptop) counting as no wait (north#259), through `north fleet launch`, as a laptop job on the laptop. On that host it takes the open signed-in account that ranks first: a live pace spend target, then the week's room per hour until that week resets, scaled per window by the five-hour and weekly multipliers the model catalog gives its `[accounts.PROVIDER] plans` entry over those of `max-5x` (Max 20x is 4 times Max 5x in the five-hour window and 2 times in the week) so capacity that expires sooner is spent first, then scaled five-hour room, and a pick that is not the account with the most headroom (its tightest window's percent left, which `north fleet launch` placement compares) launches with a `--pin` reason naming both (north#297); each planned launch charges its account `reservation_fallback_points` divided by its plan size in each window before the next box ranks, and an account that charge would take past a window's stop takes no more boxes that run. Each attempt is a line in `~/.local/state/agents/dispatch/launches.jsonl`; sessions start in `~/code/REPO/main`; an item tried twice in 24 h is left to the proxy, where a try counts only when its session (read with `north fleet show`) committed, ran a check or reported something other than a capacity wait: a session that only waited on admission (`DEFER_*`, a pool or pair queue), hit a usage limit or failed before any report spends none, and the skip line names the tries that counted and those that did not. An open issue with no box at all, ticked or not, and no Tom, `roadmap` or `native:running` label skips as `needs a box`; the run prints them on one `needs a box:` line and, at most once a day, sends their list to the session `[dispatch] triage_lead` names through `north fleet send`. When ready work and free slots coexist and nothing launched it sends one `nexus-alert normal` line naming why, repeated only after 6 h or when the reason changes.
