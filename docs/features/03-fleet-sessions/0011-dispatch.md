- Dispatch: `north fleet dispatch`, run by the fleet tick on the host `[placement] dispatch_host` names every five minutes while dispatch is not paused, keeps free worker slots busy. `north fleet tick` on that host runs it when the last run is five minutes old, or at least 20 s old once this host's resident session count has fallen below the count recorded after that run, so a freed slot is staffed on the next tick (north#1102), and runs it nowhere else; a pause recorded by `north fleet dispatch pause --reason TEXT --by WHO (--until TIME | --check COMMAND)` holds it whatever the tick until its check exits 0 or its expiry comes (north#1136), since the `north-dispatch.timer` unit left the firn config at the North-catalog cutover (north#1020). It prints each host's cap and running sessions, each account as open or out, the free slots per host and account, and every open issue in the staffed repositories with why it is or is not ready: a label holding it for Tom, a live session, gate, claim or recent launch on it, an open predecessor, or a box gated `(not before TIME)`. Each ready issue is staffed box by box: every open, unheld, undated box gets its own launch, up to the free slots or the issue's `Workers: N` line, with a brief whose `Box:` line names it and whose Done when is that box, and an issue the survey read twice is staffed once, so a run never launches a box under a name it just created; a box whose named paths, or its issue's `Files:` line when it names none, overlap a path a running or just-launched box holds (one path the same as or inside the other) waits, printed as held for that box, so two workers never edit one module at once (north#835, north#1054). Each brief goes, in project priority order, to the cloud lane when it is code-only in an Autoland repository, else to the host that serves its needs and would start it soonest, on the open account that ranks first by pace. Attempts are logged in `~/.local/state/agents/dispatch/launches.jsonl`. An item tried twice without progress is left to the proxy, and so is a box launched twice in 24 h without being ticked, which holds only that box while its issue's other boxes still launch (a session no registry lists spends no try), issues with no box go once a day to the triage lead or else the proxy, ready work with nothing launched raises one `nexus-alert`, and a stretch of `dispatch_freeze_alarm_min` minutes of such runs sends the proxy one urgent message naming each spend guard that refuses an account and the first refusal (kept in the dispatch record's freeze.json; north#838), and a launch queued behind an in-flight lane is held, not failed. A run, dry or real, started on any host but the dispatch host runs there over ssh, so one set of dispatch records decides every plan, and the freeze page names the guard or failure that stopped each launch it planned (north#1054). `--dry-run` launches nothing and prints each category's live cells, its leader and at most two challengers, so no category shows more than three (north#939). A box's needs are read before placement: its brief's `Needs:` line joins the issue's own `Needs:`, what its takeable boxes name (the laptop or its niri desktop, a host by name, every host, another repository's checkout as `checkout:REPO`, which only a host serving some need of that repository holds), every need a worker recorded with `north fleet need HOST REASON` (a row in the dispatch record's host-needs.jsonl on the ledger host, written for the calling session and its issue) kept there while a box it was named for stays unticked, so no host lacking one is chosen; a session that opened a gate for Tom is held by that open gate, never by its report's words (north#872). A box is gated by its dated check, `(not before TIME)` or a date it is `after`, `from`, `by`, `due` or `reviewed on`, which `north graph ready` also holds it behind, or `after the next N landings` (landings on origin/main citing the issue since its last report); a report's `Stop: wait until`, a window or a relative wait its prose names (`over 3 h`, `7 days after`, `after 20 decisions`) and a report saying it waits on Tom hold nothing, so a box that waits carries its `(not before TIME)` stamp (north#872). Each launch first rereads its issue on GitHub and is skipped when the issue closed or its last box was ticked after the mirror copied it, and a claim on the laptop holds its issue through the claim list the laptop copies to Nexus (north#706). A box whose check command reads the lander's own records (`north land missed`, `profile`, `gate-stats`, `doctor`, `promote`, `replay` or `serve`, or `north loops check --role lander`) is placed on the lander host its repository names in `landing.lander-host` on origin/main, and keeps the `lander` need and waits when that host cannot be read, so a worker never judges it against a mirror elsewhere (north#990). A box whose last run shows a spin signal — a run the ledger settled not done with no harness cause recorded, the same land refusal twice with no falling error count, a missed check that reopened its box, or a run past twice the ETA its brief stated — launches one rung of the escalation ladder with the failed report as `Prior report:`, and its launch record keeps that signal in `signal` beside the tier and effort it climbed to (north#940). A dispatch alert nexus-alert cannot deliver pages the proxy instead and makes that run exit non-zero, and three failed launches of one cause in ten minutes page the proxy once with that cause and the first launch's stderr log (north#1071). A box whose backticked `north` verb is missing from origin/main's CLI reference, or that names a source path a landed commit deleted, is held with "check retired: WHAT" in `north fleet dispatch --dry-run` and never launched.
