- Dispatch: `north fleet dispatch`, run on Nexus by a timer (south `modules/north-dispatch.nix`), keeps free worker slots busy. It prints each host's cap and running sessions, each account as open or out, the free slots per host and account, and every open issue in the staffed repositories with why it is or is not ready: a label holding it for Tom, a live session, gate, claim or recent launch on it, an open predecessor, or a box gated `(not before TIME)`. Each ready issue is staffed box by box: every open, unheld, undated box gets its own launch, up to the free slots or the issue's `Workers: N` line, with a brief whose `Box:` line names it and whose Done when is that box, and a box whose named paths, or its issue's `Files:` line when it names none, overlap a path a running or just-launched box holds (one path the same as or inside the other) waits, printed as held for that box, so two workers never edit one module at once (north#835). Each brief goes, in project priority order, to the cloud lane when it is code-only in an Autoland repository, else to the host that serves its needs and would start it soonest, on the open account that ranks first by pace. Attempts are logged in `~/.local/state/agents/dispatch/launches.jsonl`. An item tried twice without progress is left to the proxy, and so is a box launched twice in 24 h without being ticked, which holds only that box while its issue's other boxes still launch (a session no registry lists spends no try); a box naming a window over readings (`over 3 h`) waits until that window has passed since the newest landing the issue cites, else its last report, issues with no box go once a day to the triage lead or else the proxy, ready work with nothing launched raises one `nexus-alert`, and a stretch of `dispatch_freeze_alarm_min` minutes of such runs sends the proxy one urgent message naming each spend guard that refuses an account and the first refusal (kept in the dispatch record's freeze.json; north#838), and a launch queued behind an in-flight lane is held, not failed. `--dry-run` launches nothing. A box's needs are read before placement: its brief's `Needs:` line joins the issue's own `Needs:`, what its takeable boxes name (the laptop or its niri desktop, a host by name, every host, another repository's checkout as `checkout:REPO`, which only a host serving some need of that repository holds), every need a worker recorded with `north fleet need HOST REASON` (a row in the dispatch record's host-needs.jsonl on the ledger host, written for the calling session and its issue) kept there while a box it was named for stays unticked, so no host lacking one is chosen; a report is the newest message opening with `Done:`, `Not done:`, `Split:` or `Blocked:`, not a later reply to a notice. A box is gated by its dated check, `(not before TIME)` or a date it is `after`, `from`, `by`, `due` or `reviewed on`, which `north graph ready` also holds it behind, or `after the next N landings` (landings on origin/main citing the issue since its last report), and by the last report's `Stop: wait until` and every earlier `Stop: wait until` kept in the dispatch record's wait-stops.jsonl while a box it was learned for stays unticked. Each launch first rereads its issue on GitHub and is skipped when the issue closed or its last box was ticked after the mirror copied it, and a claim on the laptop holds its issue through the claim list the laptop copies to Nexus (north#706). A box whose check command reads the lander's own records (`north land missed`, `profile`, `gate-stats`, `doctor`, `promote`, `replay` or `serve`, or `north loops check --role lander`) is placed on the lander host its repository names in `landing.lander-host` on origin/main, and keeps the `lander` need and waits when that host cannot be read, so a worker never judges it against a mirror elsewhere (north#990).
