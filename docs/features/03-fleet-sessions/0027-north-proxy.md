- North proxy: `north proxy` opens north's fleet TUI on the fleet session `proxy`, attaching when it is live, reviving it when it is parked or stopped, and otherwise launching it through `north fleet launch`'s own account routing with `--role proxy`, so `harness/claude/agents/proxy.md` is its agent definition from the first turn; the launch also passes the `model:` and `effort:` that definition names under a `--tier-reason`, because the session record `north fleet show proxy` prints takes its model from the launch request and not from the agent file. Where the fleet's desk can open a window, the proxy starts in a client window as Proxy window below says; where it cannot, `north proxy` prints why no window opened (`north proxy: no window opened for proxy, so the fleet screen holds it: WHY`), starts the proxy held by the screen (`--screen` on `north fleet launch`, or the record marked so before a revive): no window, an ordinary fleet host that the screen types into, and opens the fleet screen on it. Only `north proxy` makes that choice, and only when the operator runs it on a proxy that is not live; every start the operator did not type (a wake by a message or report, a relaunch, a take-over, the fleet tick's hand-over) inherits the surface on the record (`surface`, `window` or `screen`, in `north fleet show proxy --json`), so a proxy in a window never drops to the screen by itself, and a proxy the screen held goes back to a window when the operator runs `north proxy` on it, not live, where a window can open. In a fresh state, where the usage gate holds no Claude sample, `north proxy` takes one usage reading, the one `north fleet usage --refresh` takes, before it places the proxy. `north proxy --interactive` stops the fleet proxy and resumes the same conversation in `claude`, its record keeping its surface, and the proxy is not revived while that UI holds it. When the proxy's account is out, the fleet tick takes it over under its name onto an account with headroom and resumes its conversation, so there is always exactly one live proxy (north#112). Proxy window: a proxy held in a window runs only in a window the operator types into. Every path that starts its host (`north fleet launch --role proxy`, with or without `--take-over`, the fleet tick's hand-over, `north fleet revive`, a message or report that wakes a stopped proxy, an account move by the API pool or a relaunch) opens a terminal window titled `north NAME` that runs `north fleet interactive NAME --after-turn`, so the proxy is on screen at once. The registry asks one port (`ProxyDesk`) at its single host start, with niri and ghostty as the adapter; the compositor spawns the window, so it is no child of north, and niri's socket is found in the runtime directory when `NIRI_SOCKET` is unset. Before the host starts, a proxy on another machine, one whose account profile would stop its window at a trust or bypass-permissions prompt, or a host with no niri socket (a build host, the cloud) is refused with the reason, and no headless host starts; a window that then fails to open ends the host it was opened for. A proxy held by the screen keeps only the refusal of a proxy on another machine and opens no window. The window waits for a turn the host is running, and for any background task its CLI started, to end before it stops that host (stopping it kills them), and on an idle host it waits a few looks first, so the message that woke the proxy starts its turn before the window takes the conversation; it runs under the HOME of the fleet that opened it, since the compositor starts it with its own environment. A window still open on the conversation of a proxy that a take-over archived no longer counts as the operator's directing window, so the new proxy messages and launches at once; a window on any other conversation still holds direction until it has been idle for 30 minutes.
