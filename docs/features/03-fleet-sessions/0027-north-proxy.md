- North proxy: `north proxy` opens north's fleet TUI on the fleet session `proxy`, attaching when it is live, reviving it when it is parked or stopped, and otherwise launching it through `north fleet launch`'s own account routing with `--role proxy`, so `harness/claude/agents/proxy.md` is its agent definition from the first turn; the launch also passes the `model:` and `effort:` that definition names under a `--tier-reason`, because the session record `north fleet show proxy` prints takes its model from the launch request and not from the agent file. `north proxy --interactive` stops the fleet proxy and resumes the same conversation in `claude`, and the proxy is not revived while that UI holds it. When the proxy's account is out, the fleet tick takes it over under its name onto an account with headroom and resumes its conversation, so there is always exactly one live proxy (north#112). Proxy window: the proxy runs only in a window the operator types into. Every path that starts a proxy host (`north fleet launch --role proxy`, with or without `--take-over`, the fleet tick's hand-over, `north fleet revive`, a message or report that wakes a stopped proxy, an account move by the API pool or a relaunch) opens a terminal window titled `north NAME` that runs `north fleet interactive NAME --after-turn`, so the proxy is on screen at once. The registry asks one port (`ProxyDesk`) at its single host start, with niri and ghostty as the adapter; the compositor spawns the window, so it is no child of north, and niri's socket is found in the runtime directory when `NIRI_SOCKET` is unset. Before the host starts, a proxy on another machine, one whose account profile would stop its window at a trust or bypass-permissions prompt, or a host with no niri socket (a build host, the cloud) is refused with the reason, and no headless host starts; a window that then fails to open ends the host it was opened for. The window waits for a turn the host is running, and for any background task its CLI started, to end before it stops that host (stopping it kills them), and on an idle host it waits a few looks first, so the message that woke the proxy starts its turn before the window takes the conversation; it runs under the HOME of the fleet that opened it, since the compositor starts it with its own environment. A window still open on the conversation of a proxy that a take-over archived no longer counts as the operator's directing window, so the new proxy messages and launches at once; a window on any other conversation still holds direction until it has been idle for 30 minutes.
