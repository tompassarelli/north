- Ops check (north#112): `north ops check [--dry-run | --synthetic]` (timer every 5 minutes on Nexus, and on one other host for the dead-man) reads `north-data/expectations.toml`, built into the binary: each `[[expectation]]` names a measure (`cloud_launches`, `launch_failures` from the dispatch record, `closed_boxes` from the ledger, `heartbeat_age_minutes`), a threshold and `breach_when` direction, a window, an owner, the deterministic fix it should become, the host role it runs on (`nexus` or `elsewhere`) and optionally an `until` date. A new breach pushes the phone through `nexus-alert` and messages the `[notify] proxy` session once, a standing breach stays quiet, and the clear sends one `cleared`; a failed phone push is tried again next tick, and an unreadable measure fails the tick and leaves that state alone. Each tick writes `ops/heartbeat.json` under the agents state directory; `nexus-heartbeat` breaches when Nexus's is older than 15 minutes, and `nexus-dead-man` reads it over ssh from another host. `--dry-run` prints every expectation's state and sends and writes nothing. `--synthetic` (a weekly timer) sends one `north ops BREACH synthetic` and one `cleared` through both channels, keeps no state, and exits 1 if either channel missed. Every expectation has a breach fixture under `crates/north-core/src/ops/check/fixtures/<name>.toml` holding a breaching and a clearing value; the tests replay each through the alert path and fail on an expectation without a fixture or a fixture without an expectation.
