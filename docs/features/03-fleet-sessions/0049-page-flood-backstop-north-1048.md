- Page-flood backstop (north#1048): the fleet store's send path, which every service message passes, bounds what reaches the proxy. A service names a standing condition with `north fleet send --from service:UNIT --key CONDITION`, and the store delivers one message per key per episode, holding the repeats for `north fleet digest`, which prints a repeated held message once with its count; an episode ends at `--cleared`, at a new text key under the same condition (its first sentence with numbers and commit-shaped tokens blanked), or after 30 minutes in which the sender did not send it. An alarm service that names no key is keyed by its cause the same way. Whatever its keys, a service past 3 messages to the proxy in 10 minutes is folded into one line carrying the count, which goes out in place of the 4th; the rest of the window waits in the digest, and `north fleet send` records the flood as a `page-flood` incident (`north ledger incident report`). Messages from sessions, from Tom and gate messages pass unchanged. The lander's link hold, dispatch's launch failure causes and north-health's failed starts send under keys, and the lander's build-lag page is gone, since the lander doctor's link-behind bound owns a lagging lander, so the senders' own once-marks (`lander-build-alarmed`, the hold file's `alarmed` word, `failure-pages.json`, the per-cause windows in `unit-failures.json`) are gone. On 2026-11-10 one lander condition reached the proxy several hundred times in 15 minutes because nothing below the senders bounded the rate.
