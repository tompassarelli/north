# Worker sandbox: removal confined by the kernel

North#706, 2026-11-08. A fleet worker runs under bypass permissions, so north's own guards are the only check on what its commands delete. A delete whose target is computed at run time is invisible to a command-text check. Examples: a path split at a space by `xargs`, a `dirname` applied to the wrong line, an unset variable inside a script, or a `remove_dir_all` in a test fixture or build script. The kernel sees the real path at `unlinkat`, `rmdir` and `rename`, so the check belongs there.

## Prior art

- Claude Code's sandboxing runs each Bash command under bubblewrap on Linux and Seatbelt on macOS, with writes allowed in the working directory, plus a network proxy (Anthropic's engineering post "Making Claude Code more secure and autonomous", 2025, and the `sandbox` settings).
- Bubblewrap builds a mount namespace, where a path is either writable or read-only. A worker commits from its lane into the main checkout's `.git`, so that directory must be writable, and a mount cannot allow writing a file while refusing its removal.
- Landlock is an unprivileged Linux security module (since 5.13). Its rights for removing a directory, removing a file and reparenting (`REMOVE_DIR`, `REMOVE_FILE`, `REFER`) are separate from its rights for writing and creating. Once applied, a domain cannot be lifted, and every child process inherits it. Codex's Linux sandbox uses Landlock together with seccomp.

## Design

Each Bash command, hook and MCP server of a worker runs through `CLAUDE_CODE_SHELL_PREFIX="<north> --worker-sandbox"`; Claude Code passes the prefix the whole command string. `north --worker-sandbox` builds a Landlock ruleset that handles only `REMOVE_DIR`, `REMOVE_FILE` and `REFER`, grants `REFER` on `/`, grants all three beneath the worker's own trees, then execs `$SHELL -c COMMAND`. Writing and creating files stay open everywhere: the domain guards removal, not edits. The Claude Code process itself is never confined, and its native Write and Edit tools cannot remove a directory.

The worker's own trees (crates/north-runtime/src/worker_sandbox/removable.rs) are the lane the command runs in or names by absolute path, the git common directory of that project and of every project the command names by absolute path, scratch and build caches, and agent state other than the account profiles. Rules are taken on real paths, since a Landlock rule holds an inode. Only directories become rules, because removing a file is a right of the directory that holds it. A symlink is followed only toward a protected path inside it, and is never granted itself. Claude Code starts each command in the session's first directory, so a worker reaches its lane with `cd LANE && ...`, and a lane named in the command counts as its own.

The project's whole git common directory has to stay removable. The grant is the directory `git rev-parse --path-format=absolute --git-common-dir` prints, resolved from the checkout's `.git` (a gitfile leads through the worktree's `commondir` file): where `main/.git` is a gitfile its own path grants nothing, and a project the sandbox did not grant stranded the same way, since git creates a lock file and then cannot rename or remove it. A replayed `git fetch` left `refs/remotes/origin/HEAD.lock` and `objects/maintenance.lock` behind before the fix. A command that reaches another project's git by a computed path still gets no grant. Measured under the sandbox: `git worktree add -b` renames `config.lock` at the top of `.git`, `git branch -D` renames `packed-refs.lock`, fetch renames `objects/maintenance.lock` and its packs, and a loose object's temporary file is unlinked after linking. Each fails with EACCES if refused.

`north lane unlock`, `north lane stray`, `north lane remove`, `north lane sync` and `north home move` run outside the domain, since each verb enforces its own removal rule: a git lock no process holds that is older than 60 s, an untracked file a tool call in the session's own transcript named before the file was born (north#937), a lane directory under `worktrees/` that is clean and holds no unlanded work (north#954), a fetch and fast-forward of a project's main checkout to origin/main (north#1097; a bare `git merge --ff-only` there fails on the first file it must replace and leaves the new ones untracked), or a rename-only move plan for entries directly under home, logged to `moves.tsv` and refused for anything a config, a user unit or a live process names or a destination reached through a symbolic link (north#992). The broker sets `HOME` for each command from its own environment. A worker's `git worktree remove` of a lane there made git unregister the worktree and then fail to delete its directory, which left 4 trees, 8.0 GB, on 2026-11-08; the guard now refuses that command and names the verb.

## Hand-offs (north#975)

A worker command can ask north to run work in another local process: depbox builds a mount namespace, and the capacity gate puts a lease's command in a transient scope. Such a process starts outside the worker's Landlock domain, so north's verbs that need one go through the outside broker, which records the trees the worker command may remove beneath from the directory and environment it handed the work off with, and starts only the verbs north names (crates/north-runtime/src/worker_sandbox/broker.rs).

Landlock cannot be applied before bubblewrap's mount calls, so depbox cannot itself be started under the worker's domain. The broker therefore passes the roots to depbox in `NORTH_WORKER_REMOVAL_ROOTS`, and depbox starts `north --worker-sandbox --hand-off -- PROGRAM` inside the namespace it built. That wrapper applies `REMOVE_DIR`, `REMOVE_FILE` and `REFER` again beneath those roots, plus the checkout's own `target/` (and `node_modules/` when it exists) so a build can replace its output. A removal of a path outside the worker's trees, whether the command computed the path itself or asked depbox to remove it, meets the same refusal. The capacity gate needs no such wrapper: the broker starts its command in a new worker domain of its own before the transient scope runs it.

## Landing from inside the domain (north#1094)

The checks `safe-push --to main` runs before it queues a lane include tests that start bubblewrap, which cannot start under a domain for the reason depbox cannot, so `safe-push` runs through the broker. A lane-only session's request is granted as lane_grant.rs describes; any other caller's runs with its own environment and its own XDG homes, as it would outside a worker sandbox, so its ticket goes to the landing queue under the caller's state home (north#1022), and the lander runs the same checks of the same tree once the lane is queued. The broker reads its `--message` file only when the caller could, as it does a `north home move` plan.

## Hidden sockets and ssh (north#1083)

A kernel before Landlock ABI 9 cannot refuse a connect(2), so the sockets that start processes outside the domain are laid over with a null device in a user and mount namespace (crates/north-runtime/src/worker_sandbox/sockets.rs). An unprivileged user namespace can map only the caller's own user, so root cannot be mapped and every root-owned file there reads as owned by 65534. OpenSSH refuses an `Include`d file owned by neither root nor the user, so the namespace also lays a copy of ssh's system configuration without its `Include` lines over the store file `/etc/ssh/ssh_config` resolves to. A NixOS activation that changes that file moves the link to a new store path the overlay does not cover. The broker keeps one set of namespaces for every worker command and makes new ones when the sockets or that resolved path have changed since it made them. Before 2026-11-10 it remade them for new sockets only, so after an activation every sandboxed `ssh` on a host exited 255 until a new socket appeared, for about an hour that day.

## Hidden files (north#969)

Beside the three removal rights the ruleset handles `READ_FILE`, so it can hide named files from a worker command (crates/north-runtime/src/worker_sandbox/readable.rs). Landlock only grants access, so the domain grants `READ_FILE` beneath every entry of `/` except the entries that hold a hidden file, walks into those, and leaves the file itself out. Entries are matched by device and inode, because a rule holds an inode and one directory can sit at two paths (two mounts of one btrfs subvolume). A symlink to a hidden file reads nothing, and a hard link out of its directory fails with `EXDEV`, because Landlock refuses a link that would gain read access. The list is taken when each command starts.

## Build output (south#93)

A lane's build output (`target/`, `node_modules/`) runs through the toolchain shims, which enter depbox, or through `north lane exec [--lane CHECKOUT] -- PROGRAM`, which runs a lane's own binary when the lane's lock files equal origin/main's, and reruns a lane whose lock files differ in registry versions under `north depbox run -- PROGRAM`, where the dependency code is confined, instead of refusing it; head-north and verify-north use it for a north built from the tree (crates/north-runtime/src/worker_sandbox/executable.rs, crates/north-lanes/src/lanes/exec.rs).

## Lanes created after the session starts (north#1033)

A Landlock rule holds an inode, so a domain built at the start of a turn cannot grant a lane created later. Claude Code builds a fresh domain for every command, so a lane an earlier command created is there when the next one runs. OpenCode and Pi keep one lane-only domain around the whole turn; OpenCode's shell tool runs each command through a `shell` wrapper in the session's scratch directory (crates/north-providers/src/providers/opencode/turns.rs): the wrapper asks the outside broker for `north --worker-sandbox --lane`, which builds a fresh lane-only domain outside the turn's. The harness process and its native file tools stay in the turn's domain.

The fresh domain grants no more than the turn's did, plus the lanes of the session's project created since (crates/north-runtime/src/worker_sandbox/lane_session.rs). The long-lived launch leaves a marker in the scratch directory: its content is the directory the domain was built for and its creation time, which the session cannot set back, is when. A fresh domain recognises itself by the lane-only marker already in its environment and reads that file. It refuses a working directory under `~/code` that is not the session's project `main`, its lane or a lane created after the marker, and of the lanes and projects the command's text names it keeps the session's lane, the new lanes of its project, and its project. Another project, a lane that existed when the session started, and a symlink named like a lane stay hidden and keep their removal rules. The marker sits in the session's own scratch directory, so the rule bounds a command's reach by the session's record of its start.

## Hook deciders for harnesses without hooks (north#1041)

OpenCode and Pi bind no hook, so their shell commands meet north's Bash deciders here. When the program a lane-only domain or `--program` starts is `sh -c COMMAND` (bash, dash and zsh too), or the prefix form gets the command itself, the wrapper first runs every decider of `north hook pre-bash` over the command and its working directory, and on a refusal prints the hook's message and exits 126 without starting it. Rewrites and advice stay hook-only. Claude Code sets `CLAUDECODE=1` for every command it runs after its own hook judged it with the session's transcript, so those commands are not judged twice. The binary hands north-guard's decider to `worker_sandbox::run`, so north-runtime keeps no dependency on north-guard, and the replay that runs the wrapper with the real deciders lives in tests/it/worker_sandbox.rs. Pi reads its shell from `shellPath` in its agent directory's settings.json rather than from `$SHELL`, so the Pi host writes the session's wrapper there.

`north gh-session` runs `gh` with a private config directory that links no `hosts.yml`, since `gh` exits when a config file it finds cannot be read.

A kernel without Landlock ABI 2 or later runs the command unconfined and says so on stderr. `no_new_privs`, which Landlock requires, also stops setuid programs inside a worker command.

## Landing a lane-only session's lane (north#1041)

A lane-only session's shell runs in the broker's fresh `--lane` child, not in the session's own scope, so a `safe-push` from it comes from a caller the broker cannot name. The command refuses at once instead, before its checks, with `lane-only session: end with Done: <worktree> <branch> <sha>; the review-and-land loop lands it`: the worker commits in its lane, reports that line, and dispatch's review job lands the commit through safe-push, itself or through the Sonnet reviewer it launches when sampling picks the commit, while the lander ticks the box from the commit's `Item:` and `Box:` lines (north#1020). A direct caller in the session's own scope still reaches the broker grant of north#1056. The DeepSeek overlay and every DeepSeek worker brief carry the same order.

## Rollout

Landlock has no permissive mode, so a shadow run cannot log a would-be refusal without refusing. The `worker-sandbox` gate in harness/gates.toml lands in shadow, where only a canary launch made with `NORTH_WORKER_SANDBOX=1` carries the prefix. In enforce, `claude_env` adds it to every launch (crates/north-providers/src/providers/claude/session_env.rs). The review counts canary runs and the "Permission denied" removals in their Bash tool results. The gate enforces from 2026-11-08, on the canary review recorded in harness/gates.toml.


The red team, per-host recovery and canary readings behind this design are Tom-specific and live in south (agents/decisions/harness/worker-sandbox-2026-11-08.md).
