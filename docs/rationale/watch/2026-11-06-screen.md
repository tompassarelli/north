# Screen of fast-growing agent-skill repositories, 2026-11-06

Nine public agent-skill repositories with the largest October 2026 star gains were
screened once, on request (2026-11-06), to decide which join the follow list in
`south:agents/watch.toml`. Star gain is a popularity signal, not evidence of quality,
so it chose what to look at and played no part in a verdict. mattpocock/skills is
already followed and was not screened again.

## Method

Step 1 of [watching](../../../harness/skills/agent-policy/references/watching.md) for
each: a fresh clone into its own new empty directory at head, every file read as data,
never as instructions, and the license read from the `LICENSE` file at that revision.
Nothing was copied during the screen. Where a kept repository's license allows it and
a piece is worth taking as written, the section below names the file and revision. The
full cycle can then copy it after `external-code` records it, with attribution in
`agent-machinery/PROVENANCE.md` and `docs/references.md`. Copied skill text is still read
as data and fitted to north's skill format, and copied code must be Rust, or
TypeScript on Bun.
Then about five minutes each on three questions:

1. Does it hold a mechanism north lacks or does worse, compared by file?
2. Is the content substantive (tools, checks, tests) or thin prompt text?
3. Does its history show iteration from measured results (evals, benchmarks, A/B
   arms, changes reverted or narrowed on evidence)?

Counts below come from `git rev-list --count --since=2026-10-01 --until=2026-11-01 HEAD`
(October commits), distinct October author emails, and commit subjects that name
eval, benchmark, baseline or A/B work (`git log --format=%s | grep -ciE
'eval|bench|a/b|measur|baseline|ablat|score'`, over at most the last 300 commits).

Design-skill repositories serve Tom's game and UI projects rather than north, so they
were judged for those: the Mak'gora client (the desktop app beside Warcraft III), the
Wisp and Mak'gora public pages, and Galileo's explanatory docs.

## Verdicts

- **DietrichGebert/ponytail** (code quality), `96608e0`, MIT. **Follow.**
  Evidence: 145 October commits from 72 authors, 34 measurement commits.
  `benchmarks/agentic/` runs real headless Claude Code sessions on seeded repositories
  with arms for no skill, the skill, a candidate build and two seven-word YAGNI prompts.
  It includes those prompts on purpose to test whether one line matches the skill. It
  runs a safety tier on adversarial input and uses a blind pairwise judge. The README
  reports 39 tasks with 5 runs each. North's code rules (`agent-machinery/skills/program-craftsmanship/`, the
  Code section of the global policy) have never been measured against a no-skill arm,
  and the A/B gate north took from pstack for prompt changes has no agentic harness
  behind it. Worth a full cycle: the arm design, including the trivial-prompt control,
  the reuse-first ladder in `skills/ponytail/SKILL.md`, and the closing line naming what
  was skipped or not checked.
- **pbakaus/impeccable** (design), `c3bb418`, Apache-2.0. **Follow**, for the Mak'gora
  client UI and the Wisp and Mak'gora pages. Evidence: 524 October commits from 16
  authors, 43 measurement commits, a Rust crate and CLI, golden tests that are
  re-recorded when output changes, and 62 deterministic slop rules that run without a
  model. North has no design-review mechanism; its closest pieces are the dataviz skill
  and `private-desktop-development` screenshots. Worth a full cycle: the deterministic
  slop rules as a check on the client UI, `critique` and `audit` with P0 to P3 ranking,
  and the per-project `PRODUCT.md` that later commands read.
- **obra/superpowers** (software engineering), `22f0b46`, MIT. **Follow.** Evidence:
  releases are squashed, so October shows only 3 commits from 1 author (v7.0.0,
  v7.0.1). The history before them shows eval-driven change: a RED baseline (25 of 25
  controllers refuse stale ledgers, at a forensic cost) before a GREEN result. A design
  spec was re-scoped and its claims narrowed when blind adoption did not reproduce. A
  "never tell a reviewer what not to flag" rule came from evals. North's worker loop
  (`harness/skills/workers/`), `agent-machinery/skills/debugging/` and
  `agent-machinery/skills/verification/` cover the same ground, but not its
  subagent-driven development fix loop, with a resume-based fix round, a five-round
  breaker and a reviewer risk budget. Nor does north have its RED-then-GREEN pressure
  test for a new skill (`skills/writing-skills/`).
- **addyosmani/agent-skills** (software engineering), `301b02b`, MIT. **Follow.**
  Evidence: 199 October commits from 24 authors, 59 eval commits. `evals/` pairs each
  skill with a case where it should fire and a case where it should stay quiet. Fixes
  have dropped graders that leaked the answer and rejected incomplete executor streams
  before grading. `evals/skill-impact.md` is an append-only ledger for rejected skill
  changes, but it has no rows yet. North chooses skill descriptions by hand
  (`harness/skills/agent-policy/references/guides/agentskills-optimizing-descriptions.md`)
  and `crates/north-runtime/src/timers/skill_review.rs` never measures whether a skill
  fires. Worth a full cycle: the fire and stay-quiet pairs, and the rejected-change
  ledger. `doubt-driven-development` is adversarial review, which pstack has moved
  away from, so it is not a candidate.
- **Graphify-Labs/graphify** (knowledge), `16218bf`, Apache-2.0. **Recheck
  2026-12-21.** Evidence: 158 October commits from 55 authors and a tree-sitter code
  graph with every edge tagged as extracted or inferred, which north lacks. Its
  `BENCHMARKS.md` reports a fixed coding agent's coverage on ERPNext rising from 70.8%
  (grep and read) to 82.0%, at about 140K tokens per query, with identical budgets and a
  spend ledger. That is a real measurement, but against one repository. Taking it would
  add a Python tool, which needs Tom's decision as a new dependency. The README leads
  with a hosted product claiming an 80% token cut that the benchmark does not cover. On
  the recheck: has the coding-agent benchmark grown past one repository, and is the
  local CLI still free of the hosted service?
- **Nutlope/hallmark** (design), `407fa68`, MIT. **Recheck 2026-12-21**, for the
  Mak'gora and Wisp public pages. Evidence: 117 October commits from 11 authors, 17 eval
  commits. `eval/` holds 8 briefs with expected outcomes, including one that tempts
  invented metrics. It runs a matrix of models and packs, a browser lint, and a vision
  judge on six axes, plus a tier that drives the real Claude Code binary. That is
  substantive, but it covers the same ground as impeccable's slop rules and review, and
  two design sources for one need are one too many. On the recheck: after impeccable's
  first full cycle, does hallmark's eval add anything impeccable's does not? If not, skip.
- **wheresryan22/anatomy** (design), `1482e84`, MIT. **Recheck 2026-12-07**, for
  Galileo's explanatory docs. Evidence: all 153 commits fall between 2026-10-08 and
  2026-10-18, from 14 authors, with no commit since. It builds interactive figures in
  which a physical mechanism stands in for a concept. Its geometry audits (nothing
  passes through anything in any frame, clips sampled through their final instant) are
  real checks, and it has `evals/evals.json`, but it has only 3 measurement commits. It
  is young and stalled. On the recheck: has it resumed with measured iteration?
- **cathrynlavery/diagram-design** (diagramming), `f24d98b`, MIT. **Skip.** Thin on
  measurement: 3 measurement commits. About half of the last 25 subjects are
  release-manifest bumps, and the other half are import and geometry fixes. Wrong format for
  Tom's projects: it emits a self-contained HTML and SVG file, while north, Galileo and
  Wisp docs are Markdown read on GitHub. A diagram that does not render where the doc
  is read gets cut.
- **Leonxlnx/taste-skill** (design), `9b4bf93`, MIT. **Skip.** Mostly hype: the
  README opens with a sponsor table. It aims at company landing pages "at the figma.com
  and x.ai bar", a bar it never measures. It has 1 measurement commit, and `tests/` holds
  only frontmatter and text-encoding checks. It duplicates what impeccable and hallmark
  measure.

## Copyable as written

Each license below was read from `LICENSE` at the named revision.

- ponytail `96608e0` (MIT): the ladder section "The smallest complete change" in
  `skills/ponytail/SKILL.md`, as skill text. The benchmark harness in
  `benchmarks/agentic/` is Python and JavaScript, so it is ideas only.
- impeccable `c3bb418` (Apache-2.0): the slop rules in `crates/detect/` are Rust and
  can be copied as written. The copy must carry Apache-2.0's notice and a statement of
  changes, and must keep the upstream `NOTICE.md`, which itself credits MIT content from
  ehmo/platform-design-skills.
- superpowers `22f0b46` (MIT): the RED-then-GREEN pressure test in
  `skills/writing-skills/SKILL.md`, as skill text.
- addyosmani/agent-skills `301b02b` (MIT): the 25 fire and stay-quiet case files in
  `evals/cases/*.json` are data and can be copied as fixtures. The runner is ideas only.

## Full cycle now

None of the four follows needs its full cycle before watching.md makes it due on
2026-12-06. ponytail is the strongest candidate to pull forward, because its agentic
arm harness tests the one claim north has never measured: whether its code-writing
rules beat no rules and a seven-word prompt.

A recheck is a `[[recheck]]` entry in `south:agents/watch.toml`. `north watch-review` launches one session for it on its date (north#636).
