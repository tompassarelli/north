What pstack added since 2026-10-15:

- `create-formal-verification-skill` and `maintain-formal-verification-skill`. They pick the promise where a bug
  costs most and tests reach least, and check it over every ordering in a stated scope, with TLA+ as the default for
  ordering questions. They require each property to be shown failing on a broken variant ("a check you've never seen
  fail proves nothing"). The generated skill records the files it covers and the commit at which it last matched
  them, and the maintain skill sorts each later failure into drift or bug.
- `statechart`: renders a checked TLA+ model as a Mermaid chart for the person who owns the behavior.
- `ketchup`: now lists every item waiting on the user, each decidable from the reply alone, even when that makes
  the reply long. `ketchup-video` renders the same thing as slides.
- `sharpen`: its prompt changed twice in four days. The rewritten-prompt ban was dropped (#712), then the original
  prompt was restored (#729).
- Claude Code packaging: a generated install tree, a name-mapping adapter (`docs/harness/claude-code.md`), and a CI
  check that fails when the generated copy or the docs fall out of step with the tree (#637, #704).
- `autopilot-full`: a rebase or minor fix after the swarm verdict gets one fresh verifier, not a full new round.
- Deletions: the `interrogate` lead-judgment calibration section, the migrate-callers rule list, and the
  "don't lie to the type system" bullets from the type-discipline principle.

## How we evaluated

1. Each of the 13 adopted rules was checked against north's tree and ledger, with file or command evidence.
2. Each new pstack mechanism was ranked by expected effect on landing speed, quality and usage per closed box. Each
   rank has a basis, either measured on north (git, ledger, a count over the tree) or marked as reasoned.
3. Each of the top three got an experiment with a frozen input, one metric and a keep or revert rule fixed in
   advance. One cost under 30 minutes and was run. The rest are filed.

## 80/20: what in pstack would move north most

1. <a id="able-to-fail"></a>**Checks that have been shown to fail, on north's most-churned state machine.** From the
   formal-verification skills. Basis, measured: dispatch was added on 2026-10-25 (f7d7c0040). In the next three days 28 more commits touched
   `src/ops/dispatch`, and 14 of them fixed how it claims, holds, counts tries or skips a box (fd445065f, 2f13801f8, 82c320284, b8f453fb7, d16b43b1f, b3f45b8b7, 0d5f66993, e6ca01dd9, b33e451a6, 1d97b57ee, e20875584, 6c8f1ba1a, 1e730115c, f30f5650c). Each fix added the next
   case someone thought of. Dispatch staffs every automatic box, so a wrong hold or try count costs whole boxes.
   Effect: quality and landing speed.
2. <a id="docs-vs-tree"></a>**A check that docs and prompts match the tree.** From pstack's docs-vs-tree CI check and
   its sync commits. Basis, measured on `fd445065f`: 9 of the 28 distinct `north <subcommand>` citations in `*.md`
   name a command the CLI does not have. Eight are in `harness/codex/prompts/`, and the ninth is `north pace refusal` in
   `docs/features.md`. By path instead, only
   3 of 23 skills cite north files that changed after the skill's last edit, so command names drift and paths
   mostly don't. Effect: usage per closed box, because an agent following a dead command loses a turn. This is the
   lint rung of rule 4.
3. <a id="sharpen-and-vanilla"></a>**A deeper brief before launch, and an A/B for the fleet prompt itself.** From
   `/sharpen`. Basis, reasoned: first-pass landing depends on the brief, and dispatch briefs today carry no trace or
   rationale (rule 13). The evidence for sharpen's own wording is weak, since its author changed it twice in four
   days. The vanilla arm closes the rule 5 gap. Effect: landing on the first pass, at a token cost to be measured.

Considered and left out:

- `ketchup`'s every-waiting-item format. North's gates already require options, recommendation and default (rule 8).
- `statechart`. It has no reader in north until a TLA+ model exists.
- The Claude Code packaging. North drives Claude Code headless and owns its own prompt.
- One fresh verifier per minor fix. It refines rule 2, whose larger gaps (no checks, no reviewer identity) come first.

## Experiments

- <a id="experiment-vanilla-ledger"></a>**Ledger comparison, north prompt vs vanilla, run 2026-10-27.**
  - Frozen input: every Claude run in the laptop host's `ledger.db` with a system prompt hash, 2026-10-15 to 2026-10-27.
  - Metric: landed tasks per arm.
  - Result: the vanilla arm (empty system prompt, `e3b0c442`) has 75 sessions, 68 of them Haiku, all from
    Terminal-Bench smoke runs and single-turn replay scenarios, and none tied to a task. The north arm has 727
    sessions on the current prompt (`ee9dbf8b`).
  - Decision: inconclusive by construction. The ledger cannot pair the arms, so the comparison moved into the
    frozen-set A/B in north#264 as arm V.
  - Also found: only 39 of 147 landed tasks have linked runs, so usage per closed box is measurable on about 27% of
    landings. Every ledger experiment inherits that gap.
- **Dispatch property check (north#262).** Frozen input: the parents of the 14 fix commits listed above.
  Metric: how many of them the check fails on. Keep the check if it fails on at least 5, otherwise revert it.
  - Result, run 2026-10-27: the check (`src/ops/dispatch/order_tests.rs`) ran at 9 of the 14 parents and failed on all 9.
    It failed on its own fix's rule at 6: the usage-limit wording (fd445065f), a session that did no work counting as a
    try (2f13801f8), a stopped session's claim holding (82c320284), a hand-made claim not holding (d16b43b1f), a failed
    launch holding past 15 minutes (0d5f66993) and a launch counting as resident past 15 minutes (e6ca01dd9). The other
    3 failed on rules that later fixes added. The other 5 parents (b33e451a6, 1d97b57ee, e20875584, 6c8f1ba1a,
    1e730115c) predate `Record.cloud`, so the check does not compile there; they are not counted. Kept.
- **Dead-command lint (north#263).** Frozen input: north history since 2026-10-15. Metric: citations flagged at the
  commit that introduced them or at the commit that removed their command. Keep the lint if it flags at least one,
  otherwise revert it. Filed.
- **Sharpen and vanilla A/B (north#264).** Frozen input: 20 closed boxes from 2026-10-20 to 2026-10-27, briefs as
  launched. Metrics: first-pass rate with a paired interval, and tokens per closed box. Keep sharpen only if the
  interval excludes zero and tokens rise by at most 10%. Filed.
