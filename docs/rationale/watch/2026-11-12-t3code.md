## What this range changes in how T3 Code runs, for the evals

Pins in play: the harness text and MCP tool list Eval T reads are at release `v0.1.9` (`24e77473ecf4`, 2026-11-11 01:11
-08:00), which is 554 commits behind this head. These points are from the diffs, not from running T3 Code.

**Harness text, the first request: almost unchanged, since the pin one rule.**
- `agentContextBudget.json` at the pin and at this head: Claude system append 5,597 bytes and Codex additional context
  7,327 bytes at both. The MCP tool list went from 48,217 to 48,126 bytes.
- Since the pin, one commit changed instruction text, `4599e55bdd` (2026-11-11 11:53 -08:00): the rule "asked to settle
  a thread, `t3_thread_organize` too", plus contractions removed across the runtime and orchestration text to hold the
  byte budget. Since the base, the instruction files changed in 3 commits in all: that one, `3051b32502` (chat file
  links) and `0c832589a0` (requested WebMCP writes).
- Codex's first request changed in two ways, both in `12b29eb71d` (2026-11-12 02:39 -08:00): `turn/start` no longer
  forces `summary: "detailed"`, which `de34391427` set on 2026-10-02 for every turn. It reads the user's
  `model_reasoning_summary` from the Codex config and sends that, else `auto`, and it makes one `config/read` call
  before each turn. A reasoning-summary setting changes how many summary tokens the model is asked for, not the answer.
- Claude's first request after a resume changed: `9e716b694a` stops a resumed session sending its first request before
  its MCP servers connect, which made Claude Code tell the agent they had disconnected (it leaves
  `MCP_CONNECTION_NONBLOCKING` unset on resume). `86e2cb21c9` fixes Claude turns on busy hosts timing out registering
  MCP tools. `c085a0aa5d` caps the baseline checkpoint a prompt waits on at 5 seconds, where a slow workspace held every
  prompt up to 30.

**Model and effort: now applied to the running turn.**
- `d6e5f2e06f` (effort) and `5984bbb36e` (model sent with a steer) apply a Claude change to the turn in flight.
  `669aa32e0d` keeps Codex loaded when only the effort changes. Before, a change took effect at the next turn.
- `5922408c3b`: a custom Claude model whose id equals a Claude Code alias (`opus`, `sonnet`, `haiku`, `fable`) is pinned
  to itself with `ANTHROPIC_DEFAULT_<ALIAS>_MODEL`, since Claude Code expands a bare alias to its own model.
- `60efd7c869`: `t3_thread_launch` refuses a model the provider does not advertise, matching aliases
  case-insensitively. `04be2b365f`: Codex and Pi runs report the model the provider ran, not the model requested.
- None of these changes which model or effort a fresh eval sample runs: the runner names the model itself
  (`--model claude-sonnet-5-5 --shell-model gpt-6.1-terra`).

**Session run and recovery.**
