## The evals framework

### What it is

An eval runs a real model against T3 Code's real model-facing text and scores what the model does. This covers agent
instructions, MCP tool descriptions and schemas, tool results, generated titles and PR bodies. There are five evals:

- **`mcp-tool-use`.** About 180 cases in `evals/mcp-tool-use/cases/*.ndjson`: 79 bad, 67 guard and 35 control.
- **`thread-titles` and `voice-cleanup`.** Blind A/B review of generated text, with an answer key opened after scoring.
- **`pr-content`.** Instructions in the repository that try to redirect a PR body.
- **`test-signal`.** Tunes the cheap-model test reviewer's prompt to the fewest words that still flag 6 bad tests and
  leave 4 good ones alone (`evals/test-signal/cases.ts`).

The rules in `evals/README.md`, and how each works:

- **Text comes from the source.** An eval imports the code under test from source and never copies a prompt, tool
  description or schema. `mcp-tool-use/run.ts` imports the server's toolkits, instructions and adapters directly.
- **Cases come from real failures.**
  - Each case has an `id`, a `kind` and a `source` (a PR, issue or thread).
  - `bad` reproduces a mistake, `guard` protects correct behavior, and `control` is ordinary work, which catches a fix
    that overcorrects.
  - The case is added before the fix, and must fail on the old text and pass on the new.
  - A changed case must still fail on the text it was written against.
- **Fidelity.**
  - A trimmed capture of a real harness turn supplies the harness's own system prompt and native tools
    (`templates/*.json.gz`). User instructions, skills and home paths are stripped by `trim-capture.ts`.
  - A cheap model plays the shell and the CLIs, so nothing runs on the machine. Shell mocks and real tool handlers
    over scripted state answer the facts a decision turns on. Each README states its fidelity gaps.
- **Sampling.**
  - Two samples per case, and a third when they disagree. A case fails when half or more of its samples fail.
  - Results are compared with a baseline on the same model and shell simulator, never with an absolute score.
  - `--baseline ... --stop-on-regression` stops a run once a case that passed every baseline sample fails.
  - `regrade.ts` grades saved rows again when a grader changes, at no model cost.
- **Paid runs stay out of CI.** CI typechecks the package and runs the graders' unit tests, which are plain logic and
  hold most of the code: 7,501 of the 15,686 TypeScript lines in `evals/` are tests. A full run costs about $9 on Sonnet and
  $17 on Opus. Each summary records its token cost.
- **How results decide.** A PR that changes model-facing text reports per-case pass counts from main's text to the
  PR's text, per model. The README records them, for example the device-routing fix #25661 and the request_secret
  guidance. AGENTS.md tells agents to run the evals that cover any change to that text, and to add a failing case
  for any model-behavior fix.
- **A budget for agent context.**
  - `AgentContextBudget.test.ts` measures the bytes of the system-prompt append, the Codex additional context and the
    MCP tool list. It keeps `agentContextBudget.json` equal to those measurements.
  - A workflow fails any PR that raises a value above main's, unless a maintainer adds a label.
  - Today the file reads 5,366, 7,096 and 48,119 bytes.

**Adherence, measured.** Since `evals/` landed on 2026-10-26, 33 commits changed model-facing text. That count covers
`runtimeInstructions.ts`, `orchestrationInstructions.ts`, `CodexDeveloperInstructions.ts`, the MCP toolkits' `tools.ts`
and `packages/contracts/src/*Mcp.ts`. 17 of the 33 also changed `evals/`. No eval file was reverted in that window.

### The smallest eval harness in north's stack

The design is in north#714. It has three parts.

**Cases come from north's own corrections, not new synthetic scenarios.**
- `harness/corrections.toml` already classes the owner's corrections (17 classes), and `north convo` holds each one's
  session transcript.
- A case names a session and the message before the corrected turn, its kind (bad, guard or control), and a detector
  over the next turn's tool calls and text.

**The runner forks the real conversation, so fidelity needs no simulator.**
- It runs `claude -p --resume ID --fork-session` on a copy of the transcript cut at that turn.
- Skills, hooks and the agent definition come from a worktree at the arm's revision.
- The flag that makes this work is `--system-prompt-snapshot off`. Claude Code 2.1.318 records the system prompt on a
  conversation's first request and resends it verbatim on every resume. Without the flag, an arm's text would never
  reach the model.
- This replaces T3 Code's simulated shell and trimmed captures, because the transcript already holds the real harness
  prompt, real tool results and real context.

**It extends `north policy-replay`; no new crate.**
- Arms are two git revisions of the text, on the same model and effort.
- Sampling is 2 samples plus a 3rd on disagreement, with a per-case verdict that fails at half or more.
- A changed detector regrades the saved rows.
- A lane that fixes an agent behavior through harness text adds its case, and shows it failing on the base and
  passing on the lane.
- Paid runs stay out of land checks.

The adaptive sampling was measured on north's own rows. Across the 15 stored sweeps, 160 of 166 three-trial cells
agreed on their first two trials. Two samples plus a third on disagreement would have run 338 trials instead of 498,
32% fewer. Every per-case majority verdict stays the same by construction.

## Experiments

### E1, real-transcript replay fidelity (north#714): not run

This experiment needs the case runner described above, so it costs more than 30 minutes.

- **Frozen input:** for each class in `harness/corrections.toml` at `7595245ae5`, the newest correction row dated
  before 2026-11-07T00:00Z whose transcript `north convo` still holds.
- **Metric:** the number of classes whose corrected behavior reproduces in at least 2 of 3 samples on the harness text
  of the session's date.
- **Keep:** 6 or more, then build the case requirement. Fewer than 6, then close it as not built.
- **Verdict on main (2026-12-07):** the weekly recurrence of the fixed classes, over 4 weeks before and after. Keep if
  it falls by at least half.

### E2, stay-quiet controls for a refusing guard (north#715): ran, kept

- **Keep rule,** fixed before classifying: adopt controls and a measured false-refusal rate for refusing guards if any
  top refusing rule's sample is at least 10% false.
- **Frozen input:**
  - Every PreToolUse denial whose text says the command would act "inside the PRIMARY checkout", in Claude transcripts
    under the north profiles modified 2026-11-04 to 2026-11-07.
  - That gave 294 distinct commands. Every tenth by sorted command, starting at the third, gave a sample of 30.
- **Classification:** true when the command would change a primary checkout's working tree, index or HEAD.
- **Result:** 24 false, 4 true and 2 unclear, so 80% false. Kept.
  - The true refusals were in-place edits and new files written under main's tree.
  - The false refusals fall into four classes:
    - lane cleanup run from main (`git worktree remove`, `git branch -D`, `git push origin --delete`): 5;
    - `git -C main worktree add`, the command the denial itself recommends, or a worktree added and then worked in:
      5;
    - interpreter or heredoc scripts run with main as the working directory but writing only under /tmp or state
      directories: 9;
    - commands that first `cd` into a worktree or a temporary directory: 5.
- **Scale:** `north hook stats --since 7d` counts 899 launch-critical refusals, 173 repeats and a 52 s median loss. At
  80% false, that is about 700 wrong refusals and 10 agent-hours a week.
- **Verdict on main:** a fresh 30-row sample from the week after north#715's fix lands. Keep the fix if at most 3 of
  30 are false and no true class is lost.

### E3, non-hermetic tests behind flaky verdicts (north#716): ran, kept

- **Keep rule,** fixed before counting: adopt the check if at least half of the incidents involve the wall clock, a
  sleep or real host state.
- **Frozen input:** the flaky or false-culprit incidents named in north commit messages from 2026-11-04 to 2026-11-07.
  These were read from the messages only.
- **Result:** 4 of 5. Kept.
  - `capacity_agent_compile` read real free disk space (83efe919e4).
  - Room readings differed from the pinned readings admission uses (344cf09f8).
  - Capacity timing tests raced the clock (1bafcf47f6).
  - Fleet router tests ran on a wall clock (5ad2175e7a).
  - The fifth, release-gate shell cases failing on the build host (fee222a979), names no cause.
- **Shipped:** the `ambient-test-input` rule of the Rust habits check (`structure.toml`, `[rust_habits.ambient_inputs]`).
  - It names `thread::sleep`, `tokio::time::sleep` (outside a test on tokio's paused clock), `Instant::now`,
    `SystemTime::now`, `statvfs`, `available_space`, `available_parallelism` and `"/proc` reads in test code, and the
    message names the fixture to use: tokio's paused clock, `DrivenClock` and `Host::until`, or the pinned
    `AGENT_CAPACITY_*` readings in `tests/it/capacity_host/mod.rs`, which is itself exempt.
  - `ambient-test-inputs.tsv` lists the 188 uses in 69 files on 2026-11-07 as a count per file. A file above its count
    is named at every site and, in refuse mode, a count above what the file holds is refused, so the list only shrinks.
  - It starts with `mode = "advisory"`, where only the edit-time code-health guard reports it. It becomes `mode =
    "refuse"`, which the landing test `the_north_tree_keeps_its_rust_habits` enforces, after a week with no false hit.
- **Verdict on main (2026-12-07):** false culprits and flaky verdicts in the sheriff's decision log, over 4 weeks
  before and after the check starts refusing. Keep if they fall by at least half.

## Where north is better

- **Test admission is enforced, not advised.** North refuses a lane whose added tests kill no mutant of its own diff
  (760f712aa9), requires a bug test seen failing on the old code, and runs added tests 8 times under load
  (c7060fa6f3). T3 Code's test-signal reviewer is advisory (`conclusion: neutral`), and its failing-test-first rule is
  prose.
- **Policy changes get a dated verdict.** `docs/rationale/experiments.toml` gives each change a metric, a bar and a
  review date, and `north check experiments judge` keeps or reverts it. T3 Code records eval results in README tables
  and never returns to them.
- **The replay runner uses real tools.** North's boxed coding scenarios run real Claude Code with real tools in a
  scratch directory, and record tokens and cost per run. T3 Code's shell is simulated by a model, and its own READMEs
  list results that are artifacts of that simulation.
- **Injected context is small.** North's sessions start with 3,283 tokens of policy, and the lead median total is
  4,297 tokens (`north context audit --since 7d`). T3 Code's budget file holds 60,581 bytes of instructions and tool
  list.
- **Landing is guarded and measured end to end.** The lander bisects culprits, its sheriff now confirms a culprit twice
  on each side before reverting, and the landing spans are traced. T3 Code relies on PR CI with one aggregate check
  that fails open.
