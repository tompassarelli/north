What pstack changed:

- `interrogate` was rewritten from opinion review to proof by run (`ab1f702`). Before: one reviewer per model, a
  rubric, a lead sorting findings into act-on, consider, noted and dismissed, and an agreement map across models.
  After: adversaries are told to break the change and to report only what a command showed, with the command, its
  output and the output the intent requires; the lead reruns each command and keeps only findings the rerun
  reproduces. Style, naming and future-change risks are excluded. `SKILL.md` went from 74 to 31 lines, and its four
  references (rubric, reviewer prompt, lead judgment, code-quality lens; 225 lines) were deleted.
- The autopilot playbooks now block a PR only for a problem shown by a failing run at the head or a doc line the PR
  made wrong; a wording-only change gets no verifier; everything else goes to a follow-up.
- `principle-explain-the-number` gained "write the decision before you run": name the result that would change a
  decision and the noise floor, and stop when the run-to-run spread is larger than the effect.
- `orchestrate` was made agentic (`c742dd6`): the coordinator uses its own task, tracker and event tools, and the
  orchestration CLI and store (3,066 lines of TypeScript with tests, added 2026-08-02) were deleted. The playbook
  went from 112 to 25 lines.
- `arena`: the cross-judge is now never from the parent's model family, and the judge is skipped when no other
  family runs. `autopilot-stack` became autopilot-full without the merge, dropping its one-writer chain section.
- `poteto-mode`: restate the user's goal in the first message, each brief, each PR and each final report.
- The formal-verification skills added before `519d36a` are unchanged.

Reverts and flip-flops: `autopilot-stack` was added on 2026-08-01 and has 12 commits; this rewrite drops the
topology rules it was built around. The orchestration store lived three months. The judge rule tightened from
"prefer another family" to "never the parent's family". `interrogate` has 10 commits since 2026-09-07, and this one
reverses its premise that model diversity is the adversarial signal. None of these were undone twice inside this
window, so none is marked weak on that ground.

## Adversarial review versus running things

pstack's tree supports the headline in one specific form. It did not drop adversarial review; it kept the skill and
changed what counts as a finding: only a reproduced run survives, and opinion, style and agreement between models
were deleted. Separately, its autopilot blocks only on a shown failure, and it ships formal-verification skills that
require each property to be seen failing on a broken variant.

North moved the same way on the same day, for its own measured reasons. The retire-review-gate lane found 280
`Reviewed` trailers on main that checked only a string, two `changes-needed` verdicts that landed, and a forced review
of a two-line fixture that found nothing, while triggered judgment reviews found real defects. It keeps a fresh
reviewer only for plans, trust-boundary code and judged cross-module lanes, and adds proptest properties, a
cargo-mutants sweep and a stateright model of the landing protocol. The difference is that north's triggered reviews
still accept findings without a run. pstack's rule is the piece north lacks.

The 2026-10-15 adoption rested on two adversarial reviews and imported what both held, which is agreement between
models; the same record rejects that as proof of correctness. Since then 7 of the 13 rules (1, 3, 4, 7, 8, 11, 12)
and both 2026-10-27 checks have been shown live with file or command evidence, so they stand on that evidence, not
on the reviews. Three should be revisited:

- Rule 2's "given by someone other than the author". The trailer gate that enforced it bought a string. A pass is
  already an exit code fleet captured; independence matters only for judgment reviews, and E1 tests whether those
  should also require a run.
- Rule 5. Its A/B gate holds for policy files through `agents sync`, but the fleet prompt has never been compared
  with vanilla. Keep the rule and run the test, or drop the claim that the fleet prompt earned its place.
- Rule 13. Still prose only. pstack's goal-restating rule is a lighter version of the same idea and is just as
  unmeasured, so neither is added until north#247 measures briefs.

## Experiments

All three are filed on north#524 with their frozen inputs, metrics and keep rules. None ran in this cycle: each
reads a lane that had not landed on 2026-11-04.

- E1, run-proven review findings. Frozen input: the 16 findings of the three 2026-11-04 judgment reviews. Metric:
  acted-on code-review findings that had no run behind them. Keep: require a command and output per code-review
  finding only if that count is 0.
- E2, properties and models seen failing. Frozen input: the cargo-mutants list for the proptest-decisions modules at
  that lane's merge base. Metric: surviving mutants each new property kills. Keep each property that kills at least
  one; keep the stateright model only if it fails on a seeded broken variant.
- E3, no verifier for wording-only changes. Frozen input: 20 policy-only landings before the gate's retirement and
  20 after. Metric: median last-commit-to-main time, with reverts within 48 h as a guard. Keep the retirement if the
  median falls and reverts rise by at most 1.
