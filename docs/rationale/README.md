# Rationale notes

Why north is built the way it is, one note per decision. `north docs rationale-index` writes this list from each note's title and first sentence; edit the notes, not this file.

- [Account usage: one reserve, placement that manages work in flight, and a spend breaker](account-capacity.md): Plan of 2026-11-04 (laptop time), revised the same day to Tom's design of 2026-11-05.
- [Agent push identity: agents push as the North Fleet app, Tom keeps his login](agent-push-identity.md): Tom approved on 2026-11-06 moving agent pushes off his admin login, so that GitHub itself refuses an agent's stray tag instead of safe-push alone (north#619).
- [Agent user: agents run under a Unix user of their own](agent-user.md): Decided 2026-11-09 under north#977.
- [Architectural drift: a measured loop, not only a periodic review](architectural-drift.md): Decided 2026-11-06 under north#636, after Tom shared a community skill for untangling a codebase in one pass and a model's rewrite of it, and asked how it should fold into north.
- [Attribution: which side each worker outcome belongs to](attribution.md): A worker run can fail because of the worker or because of the harness that staffed, placed, landed or gated it.
- [Backlog ranking: north's open issues ranked by leverage, with the edges between them](backlog-ranking.md): North's open issues on 2026-11-06, ranked by how much other work each one unblocks or speeds up, then by cost, with the waits between them as an edge list.
- [Betterleaks: one secret scanner, tuned for the guarded secrets and fast landings](betterleaks.md): Tom asked on 2026-11-06 for betterleaks (MIT, https://github.com/betterleaks/betterleaks) in place of the previous scanner wherever a repository or host scans for secrets, configured so it adds as little time as possible to builds and landings (north#642).
- [Build cost: where north's compiles burn cores, and what to cut first](build-cost.md): Plan of 2026-11-04 (laptop time), revised the same day after review.
- [Capacity scheduler: elastic, learned, fleet-wide placement by predicted finish time](capacity-scheduler.md): Owner: north#259
- [Change graph replay: carry-over, missed tests and blame on 2026-11-08's queue](change-graph-replay.md): The change graph (north#917) answers three questions about a lane: which tests its change can reach (`north graph ask affected`), which lanes share a reachable test (`overlap`), and which lanes a failed test or compile error points at (`blame`).
- [Change graph: which tests a lane can affect, built over Git](change-graph.md): Tom asked on 2026-11-08 to build the change graph for landing now, alongside the lander fixes (north#917): edges in north-graph from a change to the tests it can affect, so the lander runs only those tests, scopes the check of a merged tree to where lanes' cones overlap, and blames a failure on one lane.
- [Command usage, 30 days to 2026-11-10](command-usage-2026-11.md): Measured for north#970 cut 13 (docs/rationale/leaner-north.md): one 30-day use count for every command line in `src/cli/reference.txt` (308 commands at commit 14871e01b3), read before any command is proposed for retirement.
- [Compile reuse: every compile input is built once across the fleet](compile-reuse.md): North moves from Cargo to Buck2 with remote execution and one shared content-addressed store, so that no rustc invocation, link or test runs twice for the same inputs on any host (north#1115, decided 2026-11-11).
- [Concerns: standing judgments with history, one registry and four views](concerns.md): Design of 2026-11-07 for north#709, which asks that north be supervised as standing concerns, things managed indefinitely, rather than as tickets that close and are forgotten.
- [Conflict-free landing: no lane starves, no author round-trip for a mechanical conflict](conflict-free-landing.md): On 2026-11-05 Tom asked for a fix by construction after the lane that puts every repository on the lander (s18-integrated) lost the race to main four times in 20 minutes while its author rebased by hand.
- [Context economics: what a worker's context costs, and where it compacts](context-economics.md): Decided 2026-11-06 under north#636.
- [Coverage test selection: the tests a change reaches](coverage-test-selection.md): North lands first and verifies after the push, so a failing test costs a revert.
- [Crate split: why a leaf edit rebuilt 141k lines](crate-split.md): Owner: north#722
- [Credentials registry: no agent work depends on a human sign-in](credentials-registry.md): Decided 2026-11-06 under north#522.
- [Dispatch spread: one run bounded by spend, sessions, builds and disk on every host](dispatch-spread.md): At 12:05 PM on 2026-11-06 (laptop time) one `north fleet dispatch` run launched 17 boxes, all on gex45, several times what the account bound allowed.
- [Docs architecture](docs-architecture.md): Owner: north#523
- [Estimation audit, 2026-11-05: what north predicts about work, and whether it learns](estimation-audit-2026-11-05.md): Tom asked on 2026-11-05 for an audit of the estimates north makes about work: which model and effort can do which category, how long a box takes, what it costs, what CPU and memory a command needs, how long a check may run, when a goal finishes, and how much account room a launch needs.
- [Failing-first rationale](failing-first.md): Cold-path reasoning behind the rule that a bug fix lands with a test seen failing on the code before the fix, and a refactor declares `Behavior: unchanged` with its changed tests passing on the old code.
- [Frontier scoreboard: north against plain Claude Code on the same boxes](frontier.md): The owner asked on 2026-11-07 for a scoreboard that shows whether north is at the frontier of agent harnesses, by how much and where it is not (north#730).
- [Graph blame: the graph names the culprit, bisection is the fallback](graph-blame.md): Tom set the direction on 2026-11-11 (north#1039): blame for a red after-landing run should be near-instant, bisection retired wherever the change graph can answer and informed by it where it cannot.
- [Guard false refusals, measured 2026-11-08](guard-false-refusals.md): Every PreToolUse guard that refused a tool call from 2026-11-01 to 2026-11-08 has a labelled sample in `crates/north-guard/src/guard/hook_refusal_samples.toml`.
- [First tries lost to the harness, 24 h to 2026-11-08 03:15 UTC](harness-losses-2026-11-08.md): The readiness bar "first tries lost to the harness" (ceiling 0.1%, `ready-harness-loss` in concerns.toml) read 6% over 24 h on 2026-11-08 at 03:08 UTC, with n=323.
- [Dissolving agent-machinery into harness](harness-skill-roots.md): Decided 2026-11-08 (north#868) after an outside assessment proposed it.
- [The holdlist: what north must not lose, each with a guard](holdlist.md): In the week before 2026-11-11, 67 reverts and repeated incidents came back after their fix, because nothing stopped a later lane from removing the guard that fix had added (north#1127).
- [Hooks against the runtime](hooks-and-runtime.md): Audited 2026-11-04 against Claude Code 2.1.317, for the 18 hook entries installed in the `claude-d` profile (`jq '.hooks' ~/.local/state/north/profiles/claude-d/settings.json`).
- [Lander doctor: every known stuck state has a bound and a remedy](lander-doctor.md): On 2026-11-06 the lander was stuck or degraded five ways, each found by a person or the proxy: gex45's disk at 99% queueing builds, offload slots held by hung jobs, the lander link held for three hours, a missing registered worktree failing checks, and runtime switches failing checks.
- [Lander drill: every remedy is proven nightly against a scratch lander](lander-drill.md): `north land drill` injects each of the six stuck states the lander met on 2026-11-06 into a scratch lander every night and requires its remedy to clear it with nobody paged (north#634).
- [Landing by construction](landing-by-construction.md): On the morning of 2026-11-08 north's lander and fleet lost about two hours of landings, from 7:00 to 9:45 AM +07, to failures that a person noticed and fixed by hand.
- [Landing latency: where a worker's commit waits before main](landing-latency.md): Measured on Mak'gora, 2026-10-28, while about 15 workers waited on their landings during a live playtest.
- [Landing queue p90: where 38 minutes went on 2026-11-08, by stage](landing-queue-p90.md): North's landing queue p90 target is 60 s.
- [Landing refusals in shadow: only a broken build, failing checks, secrets and privacy refuse a lane](landing-refusals-shadow.md): `north land gate-stats --since 7d` on the lander, read on 2026-11-07, showed most landing refusals protecting nothing: test admission refused 136 lanes and 127 of them landed later (20 worker-hours), the debt ceiling 46 (43 later, 33 with the same patch, 31.8 worker-hours), the language gate 46 (42 later), the revert guard 33 (21 unchanged after a rebase), the runtime-floor gate 14 (13 unchanged) and the coverage test 8.
- [Landing train: main never red, finished work never waits on someone else's break](landing-train.md): Owner: north#360
- [Leaner north: a measured plan to cut the code toward half](leaner-north.md): Tom asked on 2026-11-09 for a leaner north, possibly half its lines, and north#970 asks for the cuts to be planned by measurement before any lane starts.
- [Learned routing and goal ETA measurements](learned-routing-and-goal-eta.md): Dated measurements behind two routing decisions: the learned tier-routing backtest that kept the cell-rate rule, and the replay that set how the goal ETA reads box durations.
- [Learning loops: the registry of every automatic decision north makes](learning-loops.md): The loop registry, `harness/loops.toml`, lists each decision north makes without a person (the tier a box gets, the ETA and budget its brief states, the cores a lease charges, the deadline a land check gets, which machine a launch runs on) and states for each what it learns from, what updates it and how often.
- [Measured no gain: what to retire](measured-no-gain.md): Audited 2026-11-04 on north origin/main `7c2a76350`.
- [Nearest-box routing: start each box where boxes like it finished, and climb on worker-caused failure](nearest-routing.md): Decided 2026-11-07 under north#705.
- [Current Nix practice, November 2026, against how Tom's repositories use Nix](nix-current-practice.md): Research of 2026-11-04 for north#553.
- [Nix and dev-shell footguns: every failure class and the guard that closes it](nix-footguns.md): Plan of 2026-11-05 (laptop time) for north#553.
- [Nix leverage and agent sandboxing: an adversarial review of "fix everything with a Nix overlay"](nix-leverage.md): Review of 2026-11-09 for north#968: Geoffrey Huntley's post on Nix ([ghuntley-nix](../references.md#ghuntley-nix), 2026-10-07) and its companion repository ([ghuntley-nix-demo](../references.md#ghuntley-nix-demo)), tested claim by claim against how north, firn and south use Nix, plus the question of whether agents need Docker or a microVM.
- [Non-Rust inventory](non-rust-inventory.md): Every non-Rust code file left in North on 2026-11-08 for north#88 (the rows of files since ported or deleted are dropped; git history has them): shell, Python, TypeScript and JavaScript files, and shebang scripts in `bin/` and `harness/`.
- [One landing per change](one-landing-per-change.md): A change lands on main as one commit.
- [Operator views: one read model, three layers](operator-views.md): Tom said on 2026-11-10 that north's operator views overlap and confuse him: the same facts are computed and printed by separate code, nothing discloses detail progressively, and nothing is layered by concern (north#1063).
- [Outcome watchdog](outcome-watchdog.md): On 2026-11-07 four flows stopped for hours while their own checks passed: finished runs stopped reaching the ledger host while the recorder exited 0 and `north health` printed `snapshot: ok`; every host's policy generation was held from 6:16 AM with an alert that named no cause; a gex45 profile launched sessions with no settings.json; and a host deploy restarted the dispatch timer the proxy had stopped.
- [Page floods: bound the rate where every page passes, not in each sender](page-flood.md): On 2026-11-10 one lander condition reached the coordinator several hundred times in 15 minutes, because the only thing deciding "already paged" was a per-sender mark and the one that failed had no ceiling below it (north#1048).
- [Placement: one function places every session and heavy run from each host's recorded reading](placement.md): Plan of 2026-11-11 for north#1036 (the box "One scheduler places every session and heavy run across the laptop, gex45, cpx62 and cpx62b").
- [The policy climber: north improves its own staffing policy](policy-climber.md): Retired 2026-11-10 by north#970 (bce9c60404): `north-climb`, `north ops climb run` and the archive's rule file are gone, so nothing on main runs this design.
- [Private text judge: kinds of text kept off public repositories by construction](private-text-judge.md): Tom asked on 2026-11-06 for one rule that keeps private kinds of text out of every public repository and in south (south#73).
- [Propagation: build each artifact once and move it to every host](propagation.md): A landed change that must reach every machine (the north runtime, and firn's system closures for whiterabbit, gex45, cpx62 and nexus) should cost one build on one host plus a network copy per host.
- [Provider parity: one owner for every guarantee only a Claude hook holds](provider-parity.md): North#1041, 2026-11-10.
- [The proxy's role: route and judge, delegate the rest, and measure it](proxy-role.md): Tom asked on 2026-11-05 for the orchestrating session to act as one: do brief cross-cutting work itself and delegate everything that takes several steps, with a deterministic mechanism behind each rule wherever one can carry it.

- [Pull hand-over of queued agent builds (north#634)](pull-hand-over.md): gex45's admission queue held agent heavy runs (a worker's `cargo test`) while the laptop or ccx33 had free slots, because the only way off a full host was a push: the full host opened ssh to a peer, shipped the lane and ran the command there.
- [Worker read isolation](read-isolation.md): Measured 2026-10-30 for north#59 step 1 (north#361): which Claude Code settings stop a worker session from reading session credentials (`~/.claude/sessions`) and reaching peer session sockets (`/run/user/1000/cc-socks`), whatever command it runs.
- [Repeat runs, 2026-11-06: why a box takes more than two worker runs](repeat-runs-2026-11-06.md): Tom asked on 2026-11-06 that north's own staffing and oversight be fixed rather than capacity added, after the worker ledger showed 6 to 30 mean attempts per box and a 9% to 40% first-pass rate over the week from 2026-10-30.
- [Replay divergence: a declared change promotes, an undeclared one is reverted](replay-divergence.md): The lander runs from its own runtime link and `north land promote` moves it only when the candidate runtime replays the latest recorded rounds to the verdicts the lander recorded (docs/features/04-landing-and-lanes/0015-lander-promote.md).

- [Runtime directory writes: one lock per sha](runtime-install-lock.md): On 2026-11-07 at 17:15:40Z nexus's `north runtime update` reused the live binaries for the docs-only 9dc5d445 and was part-way through exporting the tree when the laptop's staging push of the same sha ran its install on nexus.

- [Scoreboard: north's weekly numbers against published figures](scoreboard.md): Tom asked on 2026-11-06 for a weekly scoreboard that shows, by measurement rather than by feeling, how north compares with the best published systems (north#657).
- [Semantic physics review: how much of north's state comes from git and checks, and how much from what agents say](semantic-physics-review.md): An outside design proposal, reviewed on 2026-11-07, argues that a coding harness should keep its own model of the work and treat each agent as a stateless worker that only proposes a change.
