# North features

What each harness command and app feature does, grouped by job. The commands live in [bin/](../bin/);
[harness.md](harness.md) shows how they fit together. Each command's `--help`, its code and
[harness/defaults.toml](../harness/defaults.toml) are authoritative for flags, defaults and thresholds;
a number quoted below describes the behaviour when it was written.

CPU offload: [`north nexus-run`](nexus-run.md) sends an owned working tree over SSH, runs its command under Nexus capacity admission, and retrieves selected outputs. The private stock asset cache stays outside Git on Nexus.

## The `north` app

- Interactive fleet screen: `north` or `north fleet` opens the fleet list, transcript and digest.
- Work items: `north work list`, `north work search TEXT`, and `north work show REPO#N`. Search includes matching open and closed issues. Work edits use `north work claim REPO#N [--by NAME] [--eta MINUTES]`, `release REPO#N [--to NAME]`, `need REPO#N BLOCKER#N`, `unneed REPO#N BLOCKER#N`, and `close REPO#N --comment RESULT`. Changes are recorded on the GitHub issue.
- Where work state lives: GitHub holds titles, bodies, checklist, state and blockers. NorthThreads holds current holders, elapsed time and ETA, handoffs and worker runs. North reads both and writes through their commands.
- Skills and hooks: `agents status`, `stale`, `inspect ID`, `path ID`, `on ID`, `off ID` and `sync` (each also `north config agents ...`) list, toggle and publish the catalog's skills and hooks; [harness.md](harness.md#install) describes what `agents sync` publishes.

## Staffing and routing

 - Claude account profiles: `north fleet launch --provider claude --account LABEL --name NAME PROMPT` uses the account's local profile and records its label for restarts. Omitting `--account` on a Claude launch (not `--test`) runs it on the account placement picks, the target `agents plan --place` prints, and a held placement refuses with `held: REASON` and exit 1 like every launch refusal; a named account that placement refuses stays refused, and a Codex launch still needs `--account`. South owns account IDs, host profiles, plan selections and required plans for automatic routing. `agents sync` projects the default Claude harness files into those profiles while credentials and session history stay separate. A profile awaiting its required plan is available explicitly but is excluded from automatic routing until its OAuth tier confirms that plan.
- Interactive Claude and Codex: `claude` and `codex` are the installed vendor runtimes (`~/.local/lib/{claude,codex}/current`) on their default homes; sessions on other accounts run through `north fleet launch --provider claude|codex --account LABEL`.
- Fleet accounts: each `~/.local/state/north/profiles/claude-LABEL` with credentials is one account unless it is logged in to the same account as another label (the sha256 prefix of the `oauthAccount.accountUuid` in its `.claude.json`, over the fleet profiles and this host's `[accounts.claude] profiles`); the label `[accounts.claude] labels` declares for that login keeps it, else the first label by name. A duplicate is left out of `north fleet accounts` and the fleet TUI's launch form (named on stderr with the label it shares a login with), refused by every launch and revive (CLI or TUI, even with `--pin` or `--test`), and unavailable to placement, which also skips any pace-control account with no fleet profile.
- Account owner hosts: a label that `[accounts.claude] profiles` declares only for other hosts is foreign here (north#177): a copied `.credentials.json` shares one OAuth refresh token, so a refresh on either host revokes the other copy. A foreign label is left out of `north fleet accounts` (named on stderr with its owner hosts), refused by every launch and revive naming the owners, and unavailable to placement; placement may still put it on an owner machine, and `north fleet launch --cwd HOST:/PATH` names that machine and its directory. Pace sampling reads its usage through ssh on the owner host instead of starting `claude` here. It starts a provider's local usage adapter only on a host its `[accounts.PROVIDER]` table admits (one its `profiles` name, or any host when it declares no `profiles`), so a provider with no such table, such as Gemini, is not read. A label with no declared profile hosts runs anywhere. A launch whose first turn answers `Not logged in` restarts once, and one that answers `OAuth session expired` is refused naming the account and host; both are recorded in `fleet/.credential-failures.jsonl`.
- Routing: `agents plan` prints one difficulty band table from scalar tier starts, with account usage and project priority, share and target. `agents plan` shows each account’s used percentage, linear pace, available weekly dollars and reset timestamp, and routes each tier to the soonest-expiring under-pace account. Claude drains to 5% left at its reset. `--json` exposes the same metrics and routes; `--at FILE` replays recorded routing decisions. Project `share` is a percentage of rolling seven-day available dollars; `target` is its deadline.
- No pace hold: `north fleet launch` placement and the Agent-tool spawn gate (`north pace reserve` and the refusal it prints) refuse a new worker on an account only when its 5h window is at or over 95%, its measured 5h burn is over `five_hour_burn_cap_pct_h` (50%/h), or the provider reports its week (`week` or `LIMIT:week`) exhausted; the pace controller's held, over and allowed workers, pace lines, projections and drain grants never refuse. `agents plan` (north pace plan, crates/north-core/src/router/choose.rs) still routes by pace and drain grant at a Claude account's week drain floor (north#185). Each hold names its measured reason and when that window resets, in local 12-hour time. The spawn gate keeps its CPU and landing-flow checks and the usage-gate money refusal for an account whose overflow can bill money; it holds no calibrated reservation.
- Resident cap: `north resident-cap gate claude|codex ARG...` refuses a new resident session on a host whose `[hosts.<hostname>] resident_cap = N` in orchestration.toml is reached, counting live claude/codex CLIs listed by `north fleet list --json` plus unregistered top-level interactive ones, and print `Hold: <host> has N/N resident agent CLIs; place this worker on laptop|cloud` (exit 3). `--cloud`, `-p` and codex exec/app-server launches are not resident; `CASE=URGENT` with a FACT passes; hosts without the key are never held; `north resident-cap status` prints the live count and cap.
- Token-only usage: a Claude account this host declares a `token_file` for and holds no login of, which has no `~/.claude.json` usage cache to read, is sampled by `north pace sample` with one one-token Messages request on that token, whose `anthropic-ratelimit-unified-5h-*` and `7d-*` headers give its `session` and `weekly_all` windows. `agents usage` names an account's plan from its refreshed `.claude.json` `organizationRateLimitTier`, else its sign-in credential's tier, else `[accounts.claude] plans`.
- Usage resets: `agents usage` publishes fresh readouts through `threads ingest` to the authoritative ledger, with its existing offline spool. Remote clients read history from the mirrored snapshot and overlay fresh readouts in memory. A stale plan readout fails loudly. `agents usage` keeps each account's used percentages and reset times and appends reset availability and its source. `usage-web-read` reads the Claude usage page and account UUID inside automation Chrome, caches per-kind counts and expiry by hashed account in `~/.local/state/agents/usage/claude-web.json`, and preserves other accounts and the previous cache on failure.
- Usage read: `agents usage` is served by `north usage`: the latest reading of each account window from the threads ledger, as a per-account table of windows, billing, resets, burn, plan and cost, or with `--json` as JSON carrying a `stale` flag. `--refresh` reads every usage and billing adapter here and, unless `--local`, on each other machine holding a labelled account, records the readings and rewrites the pace gate; `--write-pace-gate` rewrites only the gate, `--fast PROVIDER` answers through its exit code whether fast mode is on, and `--gate PROVIDER` is `north pace gate PROVIDER`. The flags are in `agents --help`.
- Worker estimates: `north worker-ledger --recommend 'FACETS'` chooses the cheapest tier meeting the 80% measured success threshold and adds the recommended tier’s eta from the sample cell, backing off Surface, Verify, Scope, then Spec until three samples are available (or Category alone): `eta active <median>m (p25 <a>–p90 <b>, n=<N>) wall p75 <W>m wait median <X>m` from the runs that recorded active minutes, or `eta wall <W>m (p75 of n=<N>, ...)` when too few did; no samples prints `eta n/a (n=0)`.
- Follows boxes: `threads queue follow REF --tier T --parent NAME` queues a brief from stdin, whose `Follows:` line names the predecessor commit subject, SHA or issue ref. `follows-release` releases a box when its predecessor reaches origin/main, then sends the assignment to its Fleet parent with `north fleet send`.
- Project quote: `agents plan --quote --project P --boxes N` reads the project target from `south:agents/orchestration.toml` and the worker ledger, prints the measured completion date and dollars, and asks one date-and-budget decision for dated projects; undated projects ask none. `agents flow` prints the needed closure rate for each project target.
- Fleet idle (north#252): a session host parks an idle session after its idle limit (`north fleet launch --idle-exit`), and a wake while the prompt cache is warm resumes on it. A large unfinished session is sent a bare `/compact` frame shortly before its cache expires and is parked after it. A session whose last report opens Done, Not done, Split, Stop or Blocked, that has a parent or task and parents no live session, exits instead of parking; its transcript and worktree stay, and `north fleet send` or `north fleet revive` brings it back. A host journals each prompt until Claude echoes it into a turn, so a prompt queued just before a host restart is written again by the next host instead of lost, and `north fleet list` calls a session working while its journal holds a prompt (north#245).
- Handoff arms (north#252): `north dispatch` writes `Arm: handoff-150k` (`handoff_arm_ctx`) or `Arm: no-handoff` as the first `Arm:` line of each fleet box's brief, alternating per tier until each arm has 30 launches there, and records it in the dispatch record; `north fleet launch` keeps the threshold on the session record, so a revived worker stays on its arm. On `handoff-150k` the session host messages the worker to land and hand off when its context reaches 150k, again per further 50k; `no-handoff` leaves it to Claude Code's compaction; the worker-handoff hook and `bin/capacity-watchdog` stay at 350k (`handoff_ctx`). `north worker-ledger --summary --by arm` compares the arms per tier. Once both arms hold 30 launches on a tier and each has a closed box in `north ledger summary --since 7d`, dispatch launches that tier on the arm with the lower cost per closed box (a tie keeps the handoff arm) and prints a north#57 recommendation note naming both costs.
- Pace notices: a pace hold or resume goes to the phone only (`PACE-HELD`, `PACE-RESUMED`); no fleet session is messaged, so a notice never wakes a session and never reads as an instruction to stop spawning (north#186, north#249). An idle session sees each account's pace in its next prompt through the grounding hook.
- Goal ETA: `agents plan` prints, per project target, the critical path over the goal's open boxes at the spawn gate's width with landing overhead, predicted finish against the target and n per box, and records it as a `goal_eta` calibration row ([feedback-loop.md](feedback-loop.md#goal-eta-north35-box-7)).
- `agents plan --score PROJECT` scores a passed project target from the open issue backlog, linked issue boxes and rolling seven-day run costs, prints on-date, in-budget and spec-pass, and appends one row to `~/.local/state/agents/goal-scores.jsonl`. Missing issue or spending evidence is unmeasured. Project share applies to available account dollars. Projected misses offer one budget/date/scope decision with recorded non-AI service costs and speedups.

## Fleet sessions

- Fleet sessions: `north fleet launch` registers the session's row in the fleet store's `fleet_sessions` table on the ledger host (`north fleet row register`) before it starts anything: a launch claims a name that no live session on another host holds, `--take-over` replaces the row under the name, and the launch refuses with the reason when the store refuses the name or the ledger host does not answer (a send never refuses for that). A host marked `pulls_spool` in `[hosts.NAME]` runs only the CLIs other hosts place on it and refuses every launch. `north fleet send` and `ask` message a session, `north fleet tree` shows parent links, and `north fleet revive` restarts a session. A send, report, gate notice or host-death alarm for a session another host runs is spooled and carried by the fleet ticks (see Fleet spool), and a launch may name as its parent any session in this registry or the cached fleet table. `north fleet tree`, `north fleet list` and `north fleet list --json --all` read the cached `fleet_sessions` copy the tick refreshes (never waiting on the ledger host) and list each session another host runs beside this host's own live records, which win over this host's own table rows, with their `host`, `machine` and `tasks` (marked stale after 5 minutes without an update and left out after 7 days), every tick also publishes this host's open decision gates into the store's `fleet_gates` table and caches the table beside the sessions, so `north gate list [--json]` and the issue-gate guard behind `north fleet launch` and dispatch show this host's gates beside the open gates other hosts hold (rows with their `host` and an id answerable as `HOST:ID`, read from the cached copy and never waiting on the ledger host), and `north gate answer HOST:ID N` (`--session NAME` only when the cached table lacks the gate) spools a GATE-ANSWER row naming the gate, the session (which the table must hold on HOST) and the calling session, which the asking session's host applies once by row id on its tick, so the answer reaches the asking session on its own host (north#184). `north gate open` for a session this registry lacks but the fleet table names spools a GATE row, which that session's host opens as a gate of its own, once by row id, on its `north fleet tick` (north#416); until a tick runs on the opening host the row waits in its spool. Each tick also revives the sessions a host reboot stranded: `north fleet rebooted [--revive]` lists this host's recently active sessions that are parked (not stopped, host process gone), were last written before the machine's boot time (`/proc/stat` btime), had been active within their idle limit at the boot (an older stream means the host parked itself) and did not end on a `Done:` report, and with `--revive` runs each through `north fleet revive` (placement kept, `--local` for a conversation on this host) and sends it `host H rebooted at T; resume from your last checkpoint`; `north fleet tick` runs it for its own host, so a rebooted host's sessions resume on the first tick after it boots, a revived session's record being written again so the next tick lists it no more, one that cannot be revived retries each tick, and a tick starts no new revive past 15 s so the 50 s unit is not killed between a revive and its message.
- Fleet store: `north fleet row put` reads one fleet row or an array of them as JSON on stdin and commits them to the threads ledger in one transaction, once per row id, printing `committed ID` per row; where this machine does not hold the ledger it forwards the rows over the threads ssh remote and answers the remote exit code. The ledger also holds `fleet_sessions`, one row per session name with the provider, account, cwd, parent, placement, machine and tasks `fleet list` shows, which a launch claims only while no session of that name is live fleet-wide (north#429).
- Fleet spool: every `north fleet send`, parent notice (`Fleet::tell`) and `ask` first writes a MESSAGE row to `fleet/spool/ID.json` (renamed into place). A recipient in this host's registry also gets the row handed in at once through `hand_in`, the one path that delivers a row into a session: it takes an exclusive lock on the session's `delivered` directory and creates `delivered/ID` before delivering, so a row id already there (the same row from a later tick) is a no-op, and a failed delivery clears the entry and withdraws the row from the spool. A name neither in the registry nor in `fleet/.fleet-sessions.json` (the cached copy of `fleet_sessions`, which each `fleet tick` writes on its own host and, through `north fleet spool cache`, on every far machine it pulls) fails at once; a name only in the cache is spooled for the ticks to carry, and the send names the host that runs it. A `job-run --notify` exit for a session on this host is handed in at once and otherwise waits in the spool. The tick delivers every MESSAGE, GATE, GATE-ANSWER and JOB-EXIT row addressed to a session on its host, a JOB-EXIT as the session's wake prompt, once by row id; JOB-START and JOB-BEAT rows stay in the store as wait leases. Each tick also marks exited every row of its host that its registry no longer holds, so a forgotten name is free again. A tick that pulls a far machine also asks it for its own registry (`north fleet spool registry`; gex45 keeps the legacy sessions launched there), publishes those sessions under that machine's host name, and hands the rows addressed to them in on that machine over ssh (`north fleet spool deliver`), once by row id in that machine's delivery journal. A JOB-EXIT that reached the store more than a day ago is no longer delivered. A session cannot be named `spool` (north#429).
- Fleet tick: `north fleet tick`, run every 30 s on each fleet host by the `fleet-tick` timer, makes one `north fleet row exchange` with the ledger host (over the threads ssh remote, or the local ledger on the host that holds it): it commits every row in this host's spool and withdraws a spooled row only once that exchange answered, and also takes the spool of every far machine whose CLIs this host runs (`north fleet spool take` over ssh on each machine a live session of this registry is placed on, plus each `[hosts.NAME]` with `pulls_spool = true` in the orchestration policy, never this host) and puts those rows through the same exchange, dropping on a machine (`north fleet spool drop`) only the ids that exchange committed (ids go on the command's stdin, so any count fits); a row the store refuses or this build cannot decode is set aside on its machine (`north fleet spool set-aside`) with a notice and never fails the pull, and a pull or drop that fails is recorded under the machine's name in the tick's `pull_failed` and printed as `not pulled from NAME` other machines are still pulled, and the ssh helper is `fleet/ssh.rs`, publishes this registry into `fleet_sessions` and caches the whole table in `fleet/.fleet-sessions.json`, and fetches the MESSAGE, GATE, GATE-ANSWER and JOB-EXIT rows addressed to this host's unstopped sessions (and its CONTROL rows, below) sent since each session's creation and within the 7-day row window. Each goes through `hand_in`, which skips an id already in the session's `delivered` journal, so a second tick delivers nothing; a parked session is revived under its start lock. The row id fixes the prompt's uuid (a hash of the id), so the CLI echo and the session host's unaccepted-prompt replay match the row by id whatever signing or urgent prefix the text carries; a `delivered/ID.handing` marker left by a tick killed mid-delivery is redelivered once unless the session host journaled or echoed that uuid. A row from this host is signed by its sender alone and one from another host as `sender@host`. Journal entries older than 14 days are pruned. The TUI desk, wait results, reboot notices and a closed gate's answer to its session send through the spool and `hand_in` too: the answer is a spooled MESSAGE row handed in by id at once, and one whose hand-in failed is delivered by a later tick (north#429).
- Fleet control (north#433, box 1d of north#429): `north fleet forget`, `stop` and `interrupt` of a name this registry lacks but the cached `fleet_sessions` table names write one CONTROL row (the verb in its text) to the spool and print `spooled CONTROL row ID`; a name in neither fails with `no session named NAME`. The tick on the host that holds the session fetches CONTROL rows for its stopped sessions as well as its running ones (a stopped session still receives no MESSAGE), and applies each once: `stop` and `interrupt` are journaled by row id in the session's `delivered` directory, and `forget` needs no journal because the session leaves the registry. `show` stays local-or-error.
- Placement gate: `north fleet launch` and `revive` of a Claude session run Claude-only placement first and print one verdict line per account (available with its headroom, or out at 95% 5h, a measured 5h burn over the 50%/h cap, or a provider-exhausted week; the pace controller's held or over never refuses). A code-only public box (declared `Surface:`, no local `Needs:`, repository north, wisp or makgora) is refused with the `north cloud launch` command for the account with the most headroom, run on the host where that account is signed in with that profile's `CLAUDE_CONFIG_DIR` (cloud compute has no separate charge and draws the account's plan limits; the credit is only an extra balance spent first), unless `--local "REASON"`, which a laptop discharging its battery refuses unless `--pin "REASON"` too; an account other than the one placement picks (the most headroom among the accounts that can run on the chosen machine, or here) is refused unless `--pin "REASON"` or it ranks with that account given 5 more points of its own week room under the same spend target, so a near-tie keeps the named account (north#389).. A box needing something local (private stores, native clients) runs on the first `[hosts.NAME]` machine with `ssh` whose `serves` covers each need, a `NEED` for every repository or a `NEED:REPO` for one, and that is below its resident cap and not saturated (a host is skipped, with the reason printed, when its available memory leaves no room for a session (the unattended memory floor beside the agent class's 768 MiB request) or its root disk is under `build_disk_free_gib`, never for its build queue or its load, because sessions are admitted on memory and slot room only; the reading is taken over the same ssh and cached for 60 s, and `agents plan --place` applies the same rule; `--cwd HOST:PATH` onto a saturated host is refused unless `--pin "REASON"`); failing that it stays here when this host's own `[hosts.NAME] serves` covers its needs, and is refused as unserved when it doesn't. The reasons are recorded on the session and shown in `north fleet list`. `--test` sessions skip the gate. A launch claims, before it starts, every issue it holds (`--task REF`, else all those the first `Item:` line names up to a word such as `follows` or `see`, in the prompt or the brief it points at; the first is the session's task and `fleet list --json` shows all as `tasks`), refusing on a live claim and taking one a stopped session left, and releases them when the session ends or fails to start. A `--task REF` or `Item:` launch is refused while a running fleet session on this host, any other host (over ssh, or the laptop's copied list) or a dispatch launch of the last two hours already holds REF, unless `--force-dup "REASON"`, which is recorded as `dup: REASON`.
- Launch tier (north#242): `north fleet launch` of a Claude session that holds an issue (`--task REF`, else the brief's first `Item:` line) reads the brief's `Category:` and facets (`Spec`, `Surface`, `Verify`; a missing Category is `feature`), routes them as dispatch does (art on sonnet-high, mechanical on worker-haiku with its miss retried on sonnet-high, feature, tooling, native-check, balance-tuning and bug-known-cause alternating the Sonnet and Opus arms until the ledger holds 15 runs of each and then taking the arm with the lower `north ledger summary --since 7d` cost per closed box, everything else on worker), starts the session with that tier's `--model` and `--effort` from South's `[tiers]` table, and writes the `Tier:`, `Arm:` and `Follows:` lines into the prompt's brief header (a Haiku pick also gets the wait-on-Monitor rule). A brief that already carries `Tier:` (a dispatched box's, or an escalation's `worker-sonnet`, `worker-high` or `worker-xhigh`) keeps it, and a `Tier:` naming no tier is refused. A `--model` of another family than the pick is refused unless `--tier-reason TEXT` is given or the brief carries a `Tier-reason:` line, and a Claude launch that holds no issue is refused any `--model` without one, since no issue's routing can check it. Such a launch with no `--model` is routed the same way on the `Category:` (or `Tier:`) line in the header block (the lines before the first blank line) of its system prompt, prompt or named brief, with the session name standing in for the item; a header that marks a worker (`Delegation: role=worker`, or a `Spec:`, `Scope:`, `Surface:` or `Verify:` line) but declares neither and names no `Item:` is refused, and a brief whose header does neither keeps the account's default, so a plan's per-box lines below the header route nothing; the reason is recorded on the session as `tier: TEXT` beside `--local` and `--pin`, shown in `north fleet list` and kept by `revive`. Each launch is appended to the launching host's `launches.jsonl` as a hand launch, which dispatch on that host counts for arm alternation, Haiku retries and `Stop: decision` reports and which holds nothing; a hand launch on another host reaches dispatch only through the ledger's runs.
- Learning tick (north#112): `north tune [--dry-run]` prints the `north ledger summary --since 7d` dashboard line, then decides from the ledger's closed boxes of the last 7 days the cells briefs and routing take: `route CATEGORY` (the arm dispatch takes once both arms hold 15 runs and a cost per closed box), and `eta_minutes FAMILY CATEGORY` and `budget_usd FAMILY CATEGORY` (the ceiling of the p75 run wall and twice the median cost per closed box, as briefs print them). It writes them to `~/.local/state/north/tune/cells.json`, whose `route` cells dispatch and `north fleet launch` follow while the file is under 36 h old, and appends one line per new, changed or dropped cell to `provenance.jsonl` there with its from and to values, the ledger rows and closed boxes behind it, the 95% order-statistic interval of its figure and the rerun command. Each tier and category whose cost per closed box rose more than 25% over the 7 days before, on a tier that started a worker run in the last 7 days (a box is labeled by its first run's tier, so a retired tier's late closers file nothing), gets one north issue titled `Cost per closed box rose more than 25% week on week in TIER CATEGORY` (never for `unknown`, whose boxes move to a labeled cell once `north threads label-runs` reads their issue, north#528), unless an open issue of that title holds it, and the last line is the open north issue count. `--dry-run` writes and files nothing.
- Bet dividends (north#112): `north ops dividend [--dry-run]` reads each open issue labelled `bet`, takes the `north ops dividend CHECK` commands its Dividend section names, evaluates them over the last 7 days, comments `north ops dividend DATE: PAYING` or `DECAYED` on the issue once a day, and sends the proxy a fleet message for each bet that comments DECAYED. The checks are `cloud-lane` (a cloud placement in the last day while the cloud credit lives), `laptop-share` (the laptop under 80% of measured CPU-hours from each host's capacity usage log), `game-share` (makgora and wisp at least 60% of safe-push landings) and `release-closed` (makgora `priority:now` issues closed at least one a day). `north ops dividend CHECK` prints one verdict and exits 0 paying, 1 decayed, 3 unread; a check whose input cannot be read is UNREAD and comments nothing.
- Ops check (north#112): `north ops check [--dry-run]` (timer every 5 minutes on Nexus, and on one other host for the dead-man) reads `north-data/expectations.toml`, built into the binary: each `[[expectation]]` names a measure (`cloud_launches`, `launch_failures` from the dispatch record, `closed_boxes` from the ledger, `heartbeat_age_minutes`), a threshold and `breach_when` direction, a window, an owner, the deterministic fix it should become, the host role it runs on (`nexus` or `elsewhere`) and optionally an `until` date. A new breach pushes the phone through `nexus-alert` and messages the `[notify] proxy` session once, a standing breach stays quiet, and the clear sends one `cleared`; a failed phone push is tried again next tick, and an unreadable measure fails the tick and leaves that state alone. Each tick writes `ops/heartbeat.json` under the agents state directory; `nexus-heartbeat` breaches when Nexus's is older than 15 minutes, and `nexus-dead-man` reads it over ssh from another host. `--dry-run` prints every expectation's state and sends and writes nothing. Tests replay a breach and a clear for every shipped expectation.
- Dispatch: `north dispatch [--dry-run]` (Nexus timer every 5 minutes, south `modules/north-dispatch.nix`) keeps free worker slots busy. It prints each `[hosts.NAME]` (the laptop only while `north laptop status` says available, counting its sessions from the fleet list it copies to Nexus) with its resident cap and running sessions, each pace-control account as open or out with the hosts `[accounts.PROVIDER] profiles` signs it in on (less this host when its roster has no login of its own for the account), and per host and account the free slots: cap − running for an open account, none for one the out-rule holds (5h at 95%, 5h burn over its cap or the week exhausted; pace's allowed workers and projections never hold). A ready box is an open issue in a staffed repository (the `dispatch_repos` of each `[projects.NAME]` in South's orchestration, else its `repos`, less `[placement] private_repos`, in project `priority` order) with an unticked box, not in a project whose `dispatch_paused_until` (an RFC 3339 time in its `[projects.NAME]` table) is still ahead, which skips with `project NAME paused until TIME`, not labelled `evidence:tom`, `needs:tom`, `decision:tom`, `roadmap` or `native:running`, held by no running fleet session (each ref its `--task` names, else each number of an `sc-N`, `sc-N-M` or `wisp-N` name, on this host, any ssh host or the laptop), open north gate naming it (its `--issue`, its question or the asking session's name) on any host, NorthThreads claim or dispatch launch of the last two hours (six for a cloud launch), whose newest comment does not say it waits on Tom or the laptop, whose `Follows:`, `Blocked by`, GitHub blocked-by and plan `Order of work` predecessors are closed, and with at least one unticked box measurable now: an issue author gates a Done-when line on a time by writing `(not before YYYY-MM-DDTHH:MMZ)` in it, and while every unticked box carries a marker still in the future the issue skips as `only open box waits until <earliest>`; every other issue prints with its reason. ## Landing and lanes

- `safe-push --to main` lands the lane as one commit: before its land checks and the Autoland queue push, `north lane-squash` folds the lane's unpublished commits (none an origin ref reaches) into one commit on the newest published commit, with the first commit's author, every trailer kept once and the message from `--message FILE` or the first commit with the other subjects listed; `--several-commits REASON` keeps them apart and logs to `several-commit-landings.tsv` (docs/rationale/one-landing-per-change.md).
- `safe-push --to main` runs the lane's affected land checks from the committed `.safe-push` (`land.check`, `land.local-only`, `land.machine-bound`, `land.runner`, `land.workflow`, `land.publish`): on GitHub Actions through `north land-actions`, on the build host, or here. Before each check it asks `north land-cache hit` and reuses a pass recorded for the same inputs (the command, the host class that ran it, the toolchain and the object ids of the check's paths), so an unchanged check never runs twice; a failure deletes the record. `safe-push --help` and `north land-cache --help` are the contract.
- Red main event: when a land check fails on Actions, `north land-red-check` reads the failed cargo (`---- NAME stdout ----`, `test NAME ... FAILED`) and harness (`land check: FILE exited`, `FAIL`) tests and asks whether they fail on main's own tree, from a result recorded for that tree under `safe-push/red-check/` or by rerunning only them there through `north capacity offload run --host gex45`; if they do it records the `main is red` issue, sends the proxy and the session's Fleet parent one line naming the tests and the newest main commit since the last green run that changed their inputs, and the lane prints `blocked by red main, not this lane` and `north land-red-wait` retries it once a `Main-red:` lane lands; main CI runs on main are never cancelled in progress.
- Landing tempo (north#255, B12 and B13): safe-push and the lander record each lane they decide through `north land-train record|check|red` (in the background, never under the land lock) as `landings`, `land_checks` and `main_red` rows in the threads ledger, and `north flow` reads them back per repository as landings per hour, finished-to-landed and first-commit-to-landed percentiles, batch size, re-lands, check runs thrown away because main moved, bisect depth and red-main minutes, with `--json` for the same under `landing`. The row schema and why each field exists are in docs/rationale/landing-train.md.
- `north capacity offload choose|run`: while this host is in game-reserve, `safe-push` ships the lane by git bundle to the first other `[hosts.NAME]` with an `ssh` destination and room (free cores, the heavy memory request, 20 GiB free where its offload slot lives) and runs the land checks there in `~/.cache/land-offload/<checkout>`, whose `target` persists between runs; `land.local-only` entries in `.safe-push` and a missing host keep the checks on this host (`land.machine-bound` ones may ship); a repository whose `.safe-push` names a `land.workflow`, north among them, runs its checks on GitHub Actions instead and never offloads.
- Fleet capacity rows: `north capacity pull [--host NAME]` reads each other `[hosts.NAME]` ssh host's `capacity_runs` rows newer than the last one pulled for that host (read-only `sqlite3` over ssh) into this machine's capacity.db under a `host` column (this machine's own rows carry its name), and `north capacity actions-pull` records each started job of the north, makgora and wisp Actions runs (first pull: 7 days) as an `actions:LABEL` row with `queuedSeconds` (created to started) and `wallSeconds` (started to completed), then prints the p50 queue per runner label and an `incident: REPO main is red` line (exit 3) for each repository whose latest push-to-main run failed; a second run of either adds no rows. Sizing reads only this machine's own rows (`capacity_history`), so pulled rows feed placement and reports, never its estimates.
- `mutant record <id>` (`north mutant record`) saves the scratch copy's non-empty diff against HEAD to `~/.local/state/agents/mutants/<repo>/<id>.patch`; `north mutant verify BASE HEAD`, run on demand (no landing gate runs it since 2026-11-04), refuses a claim whose patch is missing or applies to neither side and, when the base `.safe-push` sets `mutant.run`, runs that runner once under one capacity lease over the change tree and every mutant tree, requiring each named test to pass on the change and fail on its mutant; verified kills are cached by change patch-id and mutant.
- Fails-first gate: `north land-fails-first [BASE HEAD]`, a `.safe-push` land check, runs the tests a lane adds or changes against base with the head's test files: a lane that changes code needs at least one of them to fail on base, and a lane marked `Behavior: unchanged` needs all of them to pass. It then runs those tests concurrently several times (the `[flake]` section of `.safe-push`) on the lane head and refuses a lane naming any test that fails a run as flaky, never retrying to green. The contract is `north land-fails-first --help` and why is in docs/rationale/failing-first.md.
- Provenance: `north provenance check BASE HEAD` lists each bar (a comparator such as under, within or `<=`, a number and a unit) added to a PLAN*.md table row, a Done when line, a `- [ ]` box or a test path without a `Provenance: <claim>; origin <...>; pointer <...>; rationale <path#anchor | not recorded>; revisit <...>` trailer whose claim names its number and unit and whose origin is not `none` (allowed only with `; soft`); a reworded line keeping its bar passes; it runs on demand and no landing gate runs it since 2026-11-04. `north provenance debt [--due] [--repo PATH]...` lists `Target-debt` trailers on origin/main of each `~/code/*/main` not named by a later `Target-paid: <commit>`, with `--due` keeping rows whose revisit date passed, whose `closed REPO#N` issue closed, or whose trigger is event text.

[--stall-alarm]` caches pending landings, landing rate, push-to-land latency, main idle time, oldest landing job and runner, stall verdict, project throughput, and Actions, Wisp and Autoland capacity signals. `--stall-alarm` sends notices to the active Fleet parent and Plato, and mentions Tom after 60 minutes until main moves and jobs recover. ## Issues and native items

- Native items: `threads new life|accounts|travel|ops TITLE [--due D] [--body -]` captures an item that lives only in threads.db (`life#1`), with `threads note`, `close` and `reopen`; `need`/`unneed` involving a native item are recorded locally, and `ready`, `show`, `list` and claims treat native items like GitHub issues without calling gh. Native items never reach GitHub: NorthThreads' gh calls, `safe-push` (commit messages, branch and tag names) and the `native-item-guard` hook (gh writes naming a native ref or quoting an item's title (20+ characters, 3+ words)) refuse them; `new` and `note` refuse text `gitleaks stdin` flags. ## Machines, capacity and scheduled jobs

- Product verification: `verify-north` builds north from the checkout around the current directory (or takes `--north PATH`), then in a 160x45 tmux terminal opens `north fleet`, launches a Claude haiku session from the Ctrl+N form, checks an Alt+U urgent answer within 10 s during a running `sleep 120`, a Ctrl+G deepen run in the ledger, a Codex `fleet ask`, and a `north task check` verdict; a separate cleanup process forgets its sessions, kills its terminal and asserts none of its session hosts or app-servers survive, even when the run is interrupted. One line per step with wall ms; nonzero exit on any failure.

- Fleet receipts: `north fleet launch` makes the calling session the new session's parent, or the `proxy` session for a launch from outside the fleet, unless `--parent` says otherwise. When a child ends a turn that landed a commit or whose reply opens Done, Not done, Split, Stop or Blocked, its host queues one `[from NAME · turn N · exit E · landed SHA]` message with the reply to the parent; other turns stay in `north fleet show NAME` without waking it, a failed turn arrives with its transcript tail and a host death arrives urgently. The ledger claims each notice once, so a restart never resends one, and `--test` sessions keep their gates out of Tom's digest.
- Runtime promotion: after a north landing safe-push runs `north runtime follow`, which starts `north runtime promote` in the background, and every host also runs `north runtime update` from its `north-runtime-follow` timer. - Landing watch: safe-push appends one JSON line per stage end, known wait, retry, failure, refusal and landing to `~/.local/state/safe-push/events.jsonl` and starts `north watch --once` on any failure or refusal; the `north-watch` user timer runs it too. - Orphan lease reaper: `north capacity reap-orphans` stops the scope of every run lease whose wrapper process is gone, so no Warcraft client or run outlives its runner and the lease's slot frees; it is the stop half of the laptop's `laptop-auto` tick and needs no `laptop` command, so gex45, which has no such tick, runs it from the `lease-reaper` user timer every 30 s (south `modules/lease-reaper.nix`, imported by `hosts/gex45/configuration.nix`) (north#191, north#335).
- Capacity estimates: `machine-capacity estimate -- CMD ARG...` predicts a command's cores, peak memory, I/O and disk busy share from its newest matching measured runs (`capacity_sizing_runs`), falling back from the exact signature through owner, family and repository to the declared class, and prints the match level and confidence (`capacity_high_confidence_runs`). An expensive target with no history of its own stays heavy at low confidence. Admission reserves from these estimates with `capacity_memory_margin`, and status and probe publish the committed totals the spawn gate reads.
- Resource model: every finished capacity run records its command key, host, cache state, queue wait, memory peak and stall, whether its memory cap censored it, and what admission predicted. Successful runs feed a per-host model at three levels (exact command and cache state, exact command, owner and shape), and admission sizes a command's memory from the answering level once it has enough runs (`capacity_memory_margin`); a key with no level reports `unknown` instead of borrowing a wider estimate, and a censored run only raises the key's memory floor. `north capacity model [KEY]` prints the levels and `north capacity calibration` prints predicted against actual wall time and memory per key and host, flagging drift.
- Nexus RAM and CPU stalls: `north nexus-ram record` (Nexus minutely timer, nixos-config `modules/nexus-ram`) appends one row to `$NEXUS_RAM_DIR/YYYY-MM-DD.jsonl` (UTC day, default `~/.local/state/nexus-ram`): MemAvailable, swap, zram used and compressed, memory PSI some/full avg60, resident agent CLIs (top-level interactive claude and codex; `-p`/`--print`, codex `exec`/`app-server`/`mcp-server`/`cloud` and `--cloud` excluded) and their process-tree PSS, plus since the previous row `gap_s` (wall seconds), `steal_pct` (steal share of `/proc/stat` cpu jiffies), and `cpu_psi`/`io_psi` (avg10, cumulative `total` microseconds and their deltas); the first row and a counter reset after a reboot record null. `north nexus-ram report [--days N]` (default 7) prints p50/p95/max agent CLIs and PSS, min MemAvailable, PSI-full minutes, minutes with steal over 20%, the longest row gap, OOM kills from the journal and one verdict: UPGRADE when on 3 or more days MemAvailable stayed under 600 MiB or PSI full avg60 over 1% for over 10 minutes, or an OOM kill hit an agent; otherwise STAY. Test inputs: `NEXUS_RAM_DIR`, `NEXUS_RAM_PROC`, `NEXUS_RAM_ZRAM`, `NEXUS_RAM_NOW`, `NEXUS_RAM_JOURNAL`.
- Rest check: `capacity-watchdog rest-check [--seconds N] [--expected FILE] [--observed FILE] [--save FILE]` compares running system and user services and scopes, active timers and listening sockets (`PROTO ADDR:PORT UNIT`, `-` for a gone creator such as kernel WireGuard) with the host's expected-at-rest set (`~/.config/capacity-watchdog/rest.json`, declared in firn as `myConfig.modules.capacity-watchdog.rest`), measures each unit's CPU and context switches over N s (default 30), prints extra units, sockets and over-budget units, lists claude/codex/tmux sessions as agents, and exits 1 when anything is not at rest.
- Poll loops: `poll-loop-guard` (Rust PreBash, Claude Bash and Codex exec) refuses a foreground call that can wait over 60 s in `sleep` or in an `until`/`while` loop that sleeps, unless `timeout` or the tool's own timeout bounds it at 60 s; the refusal names `job-run --notify` and Monitor. Background calls pass, since their exit notifies the session.

Each `[[command]]` declares leading `pattern` words (mode flags match in any order after the verb), `narrowing` flags that permit local work, and a `farm` command with `why`. Whole-roster matches are refused even inside `machine-capacity run`; missing or malformed declarations leave existing capacity checks in place. Claude Bash and Codex exec payloads share this identity.
- Scheduled job runs: `job-run [--path DIRS] [--user USER] [--notify] NAME -- CMD...` wraps a timer's command, records its start and finish (name, host, started, finished, rc) through `threads job-run` (spooled while the remote ledger is unreachable) and exits with the command's code; `--notify` instead detaches the command into its own session with its output in `~/.local/state/north/jobs/`, returns at once and sends `job-run: NAME exited RC` to the fleet session `$NORTH_FLEET_SESSION` when it ends (the session host reads the job's JOB-START lease with `north fleet row leased SESSION` to know a quiet child waits on it, and `bin/job-run` writes no `.job` record), so an agent ends its turn and wakes on the result, and the job outlives a subagent's teardown; `threads job-runs` shows runs, failures and the last rc per name and host. Firn's `jobRun` helper wraps every registry timer.
- Overdue jobs: `north job-watch run [--registry DIR] [--peers FILE] [--state FILE] [--dry-run]` (nexus, every 15 min) reads registry routines with a `placement` and `deadline`, `threads job-runs --json` and WireGuard presence from `/run/nexus/peers.json`, and sends one normal (priority 2) alert per job when it becomes overdue (a laptop job also when the laptop has been online period + 30 min with no success), repeats at most daily and sends a normal note on recovery; `JOB_WATCH_TOPIC` overrides the topic.
- Private checks: `north private-check` runs the checks of `north-data/private-checks.toml` that need a GPU or private art and so cannot run on hosted runners or in the farm-runner containers. Per check it fetches the repository's origin/main into its own locked worktree, skips a tip already judged or one whose diff touches none of the check's paths, runs each step under a machine-capacity lease and posts the verdict as a GitHub commit status; a step capacity never admitted posts nothing and is retried on the next run. `--dry-run` prints the status requests instead of posting. ## Wisp payoff

`north wisp payoff [--since YYYY-MM-DD] [--json]` reads retained Mak'gora evidence, Wisp state, and Wisp evidence/build directories without creating a store. It prints per-kind UTC Monday weeks, completed comparison agreement, invalid native attempts, native client-minutes, Wisp main commit counts, retirement candidates, and disagreement evidence paths. JSON includes each contributing run for audit. The fleet Ctrl+T digest refreshes its summary in background upkeep.

Pad families use their script directory (standalone pads use their name). Pad client-minutes count two clients over game, reset, reload and run time; Wisp, comparison and wait time are excluded. Acceptance report elapsed time is divided equally over checks and marked estimated. Batch dates use file modification time because the format has no timestamp. PASS and FAIL count as comparisons only when both headless and comparison ran; INVALID never counts as disagreement.

Retire candidates have at least ten agreeing comparisons and zero disagreements across the last fourteen days, independent of the display filter. They select Wisp-only evidence with a one-in-ten native sample. The weekly projected sample saving is 90% of those kinds’ historical native minutes, a counterfactual estimate. Actual avoided minutes, closed Public 0.1 boxes, native minutes per closure and Wisp-only closure shares remain unknown when retained evidence lacks closure provenance and skipped-run records. Do not equate projected savings with observed payoff. The command never files issues or sends messages; its evidence paths support deduplicated issue filing and planner handoff.

The planner contract is `schema_version: 1`. `families[]` is computed from the full rolling fourteen-day window even with `--since`. Each entry has `id`, `match_rule: {kind, values}`, `verdict` (`wisp-only` or `native`), `native_sample_rate` (0.1 or 1.0), `counts`, and inclusive `window_start_unix` / `window_end_unix`. `parent-directory` matches an immediate POSIX dirname in `values` and a `.pad` basename; `exact-path` matches a whole path in `values`; `none` applies to accept checks, not scripts. Unknown or ambiguous matches select native. Paths are repo-relative POSIX strings; reject absolute paths, backslashes, and dot segments. Headless-session batches are excluded regardless of their comparison message.

Sampler `sha256-first-u32be-mod10-v1` hashes UTF-8 `scriptPath + "\n" + fullSourceRevision`, without a trailing newline. Interpret the first four SHA-256 bytes as an unsigned big-endian integer and take modulo ten. Select native when the verdict is `native` or that bucket is zero. JSON `sampler` carries the identity, exact input description and a test vector. This gives identical reruns the same sample and prevents display filtering from changing routing.
