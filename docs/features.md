# North features

What each harness command and app feature does, grouped by job. The commands live in [bin/](../bin/);
[harness.md](harness.md) shows how they fit together. Each command's `--help`, its code and
[harness/defaults.toml](../harness/defaults.toml) are authoritative for flags, defaults and thresholds;
a number quoted below describes the behaviour when it was written.

CPU offload: [`nexus-run`](nexus-run.md) sends an owned working tree over SSH, runs its command under Nexus capacity admission, and retrieves selected outputs. The private stock asset cache stays outside Git on Nexus.

## The `north` app

- Interactive fleet screen: `north` or `north fleet` opens the fleet list, transcript and digest.
- Work items: `north work list`, `north work search TEXT`, and `north work show REPO#N`. Search includes matching open and closed issues. Work edits use `north work claim REPO#N [--by NAME] [--eta MINUTES]`, `release REPO#N [--to NAME]`, `need REPO#N BLOCKER#N`, `unneed REPO#N BLOCKER#N`, and `close REPO#N --comment RESULT`. Changes are recorded on the GitHub issue.
- Where work state lives: GitHub holds titles, bodies, checklist, state and blockers. NorthThreads holds current holders, elapsed time and ETA, handoffs and worker runs. North reads both and writes through their commands.
- Skills and hooks: `agents status`, `stale`, `inspect ID`, `path ID`, `on ID`, `off ID` and `sync` (each also `north config agents ...`) list, toggle and publish the catalog's skills and hooks; [harness.md](harness.md#install) describes what `agents sync` publishes.

## Staffing and routing

 - Claude account profiles: `north fleet launch --provider claude --account LABEL --name NAME PROMPT` uses the account's local profile and records its label for restarts. Omitting `--account` keeps the current default. South owns account IDs, host profiles, plan selections and required plans for automatic routing. `agents sync` projects the default Claude harness files into those profiles while credentials and session history stay separate. A profile awaiting its required plan is available explicitly but is excluded from automatic routing until its OAuth tier confirms that plan.
- Interactive Claude and Codex: `claude` and `codex` are the installed vendor runtimes (`~/.local/lib/{claude,codex}/current`) on their default homes; sessions on other accounts run through `north fleet launch --provider claude|codex --account LABEL`.
- Fleet accounts: each `~/.local/state/north/profiles/claude-LABEL` with credentials is one account unless it is logged in to the same account as another label (the sha256 prefix of the `oauthAccount.accountUuid` in its `.claude.json`, over the fleet profiles and this host's `[accounts.claude] profiles`); the label `[accounts.claude] labels` declares for that login keeps it, else the first label by name. A duplicate is left out of `north fleet accounts` and the fleet TUI's launch form (named on stderr with the label it shares a login with), refused by every launch and revive (CLI or TUI, even with `--pin` or `--test`), and unavailable to placement, which also skips any pace-control account with no fleet profile.
- Account owner hosts: a label that `[accounts.claude] profiles` declares only for other hosts is foreign here (north#177): a copied `.credentials.json` shares one OAuth refresh token, so a refresh on either host revokes the other copy. A foreign label is left out of `north fleet accounts` (named on stderr with its owner hosts), refused by every launch and revive naming the owners, and unavailable to placement; placement may still put it on an owner machine, and `north fleet launch --cwd HOST:/PATH` names that machine and its directory. Pace sampling reads its usage through ssh on the owner host instead of starting `claude` here. It starts a provider's local usage adapter only on a host its `[accounts.PROVIDER]` table admits (one its `profiles` name, or any host when it declares no `profiles`), so a provider with no such table, such as Gemini, is not read. A label with no declared profile hosts runs anywhere. A launch whose first turn answers `Not logged in` restarts once, and one that answers `OAuth session expired` is refused naming the account and host; both are recorded in `fleet/.credential-failures.jsonl`.
- Routing: `agents plan` prints one difficulty band table from scalar tier starts, with account usage and project priority, share and target. `agents plan` shows each account’s used percentage, linear pace, available weekly dollars and reset timestamp, and routes each tier to the soonest-expiring under-pace account. Claude drains to 5% left at its reset. `--json` exposes the same metrics and routes; `--at FILE` replays recorded routing decisions. Project `share` is a percentage of rolling seven-day available dollars; `target` is its deadline.
- No pace hold: `north fleet launch` placement and the Agent-tool spawn gate (`north pace refusal` and `reserve`) refuse a new worker on an account only when its 5h window is at or over 95%, its measured 5h burn is over `five_hour_burn_cap_pct_h` (50%/h), or the provider reports its week (`week` or `LIMIT:week`) exhausted; the pace controller's held, over and allowed workers, pace lines, projections and drain grants never refuse. `agents plan` (north pace plan, src/router/choose.rs) still routes by pace and drain grant at a Claude account's week drain floor (north#185). The spawn gate keeps its CPU checks and its plan-stop and money reservation cap.
- Resident cap: `north resident-cap gate claude|codex ARG...` refuses a new resident session on a host whose `[hosts.<hostname>] resident_cap = N` in orchestration.toml is reached, counting live claude/codex CLIs listed by `north fleet list --json` plus unregistered top-level interactive ones, and print `Hold: <host> has N/N resident agent CLIs; place this worker on laptop|cloud` (exit 3). `--cloud`, `-p` and codex exec/app-server launches are not resident; `CASE=URGENT` with a FACT passes; hosts without the key are never held; `north resident-cap status` prints the live count and cap.
- Token-only usage: a Claude account this host declares a `token_file` for and holds no login of, which has no `~/.claude.json` usage cache to read, is sampled by `north pace sample` with one one-token Messages request on that token, whose `anthropic-ratelimit-unified-5h-*` and `7d-*` headers give its `session` and `weekly_all` windows. `agents usage` names an account's plan from its refreshed `.claude.json` `organizationRateLimitTier`, else its sign-in credential's tier, else `[accounts.claude] plans`.
- Usage resets: `agents usage` publishes fresh readouts through `threads ingest` to the authoritative ledger, with its existing offline spool. Remote clients read history from the mirrored snapshot and overlay fresh readouts in memory. A stale plan readout fails loudly. `agents usage` keeps each account's used percentages and reset times and appends reset availability and its source. `usage-web-read` reads the Claude usage page and account UUID inside automation Chrome, caches per-kind counts and expiry by hashed account in `~/.local/state/agents/usage/claude-web.json`, and preserves other accounts and the previous cache on failure.
- Usage read: `agents usage` and `agents usage --json` are served by `north usage`: the latest reading of each account window from the threads ledger (the mirrored snapshot on a remote client, refreshed once over ssh when it fails its integrity check), as the per-account table with its windows, billing, reset availability, burn, plan and the cost lines, or as JSON with a `stale` flag, byte for byte as harness/lib/usage.py printed them; the claude rows of accounts this host does not hold, and providers outside the model catalog, are left out. `agents usage --write-pace-gate` (the pace sampler's call) rewrites `usage-gate.json` from Rust, building the router's context in process: its money refusals, per-account refusals, window projections and pace reading equal those usage.py wrote. `agents usage --refresh [--local]` reads every `usage_*.py` and `billing_*.py` adapter beside harness/lib in parallel (30 s each) and, unless `--local`, each labelled account signed in on another machine over ssh (45 s), records the readings in the usage table (a mirrored client publishes them to the ledger host first), rewrites `usage-gate.json` under the pace-control lock, and sends one desktop notice per promotion ending within seven days. `agents usage --fast PROVIDER [--cached]` prints `on` (exit 0) or `off` (exit 1) from routing, refreshing that provider first unless cached; `agents usage --gate PROVIDER` is `north pace gate PROVIDER`. Only `--reservation-json` still runs harness/lib/usage.py.
- Worker estimates: `worker-ledger --recommend 'FACETS'` chooses the cheapest tier meeting the 80% measured success threshold and adds the recommended tier’s nearest-rank p75 actual duration and sample cell, backing off Surface, Verify, Scope, then Spec until three samples are available (or Category alone); no samples prints `eta n/a (n=0)`.
- Follows boxes: `threads queue follow REF --tier T --parent NAME` queues a brief from stdin, whose `Follows:` line names the predecessor commit subject, SHA or issue ref. `follows-release` releases a box when its predecessor reaches origin/main, then sends the assignment to its Fleet parent with `north fleet send`.
- Project quote: `agents plan --quote --project P --boxes N` reads the project target from `south:agents/orchestration.toml` and the worker ledger, prints the measured completion date and dollars, and asks one date-and-budget decision for dated projects; undated projects ask none. `agents flow` prints the needed closure rate for each project target.
- Fleet idle (north#252): a session host parks an idle session after its idle limit (`--idle-exit`, default 10 minutes), and a wake within the hour resumes on the warm prompt cache. A session at 200k context tokens or more that is not finished stays up instead, and at 55 idle minutes, before the 1-hour cache expires, the host writes a bare `/compact` frame to it (headless Claude Code runs it as the command) and parks it after its idle limit; past 60 idle minutes it parks uncompacted, since the cache is cold. A session whose last report opens Done, Not done, Split, Stop or Blocked, has a parent or a task and parents no live session exits instead of parking, by 60 idle minutes even with a background task still out; its transcript and worktree stay and `north fleet send` or `revive` brings it back. A host told to end (SIGTERM at a host restart) passes that signal to its runtime and marks such a finished session exited too, so a restart leaves it stopped instead of parked for a notice to revive. A host journals each prompt it writes to Claude until Claude echoes it into a turn (`unaccepted.jsonl` in the host directory), and a host ended with a prompt still unechoed leaves its worker parked, not exited; the worker's watchdog (any session with a parent or task) then revives it (if that watchdog outlives the restart), and `north fleet stop` discards the journal, and the new host writes the journaled prompt once more, so a message queued just before a restart runs without a new `send` or `revive`. A prompt that is not echoed on that second host is dropped. The host journals a prompt before it acknowledges the write, and `north fleet list` and `show` call a running session working while its journal holds a prompt: a revived Claude echoes a queued prompt only once it has loaded the resumed conversation, several seconds on, so until then its stream still ends on the old turn (north#245). Every Claude profile compacts on size at 500k (`autoCompactWindow`).
- Handoff arms (north#252): `north dispatch` writes `Arm: handoff-350k` or `Arm: no-handoff` as the first `Arm:` line of each fleet box's brief, alternating per tier until each arm has 30 launches there, and records it in the dispatch record; `north fleet launch` keeps the threshold on the session record, so a revived worker stays on its arm. On `handoff-350k` the session host messages the worker to land and hand off when its context reaches 350k (`handoff_ctx`), again per further 50k; `no-handoff` leaves it to Claude Code's compaction. `worker-ledger --summary --by arm` compares the arms per tier.
- Pace notices: a pace hold or resume goes to the phone only (`PACE-HELD`, `PACE-RESUMED`); no fleet session is messaged, so a notice never wakes a session and never reads as an instruction to stop spawning (north#186, north#249). An idle session sees each account's pace in its next prompt through the grounding hook.
- Goal ETA: `agents plan` prints, per project target, the critical path over the goal's open boxes at the spawn gate's width with landing overhead, predicted finish against the target and n per box, and records it as a `goal_eta` calibration row ([feedback-loop.md](feedback-loop.md#goal-eta-north35-box-7)).
- `agents plan --score PROJECT` scores a passed project target from the open issue backlog, linked issue boxes and rolling seven-day run costs, prints on-date, in-budget and spec-pass, and appends one row to `~/.local/state/agents/goal-scores.jsonl`. Missing issue or spending evidence is unmeasured. Project share applies to available account dollars. Projected misses offer one budget/date/scope decision with recorded non-AI service costs and speedups.

## Fleet sessions

- Fleet sessions: `north fleet launch` starts a headless session, `north fleet send` and `ask` message it, `north fleet tree` shows parent links, and `north fleet revive` restarts a session. A send on a host without the named session posts it to that host's outbox once a fleet host has relayed from it; the fleet host's `fleet-relay` timer runs `north fleet relay HOST...`, which takes each host's letters over ssh (`north fleet outbox take`), delivers them, drops the delivered ones, and fails (once per letter) for a letter it cannot deliver. A session launched on another host (`--parent NAME` over ssh) may name a parent registered only on the fleet host once that host has relayed from it; its reports, gate notices and host-death alarms then post to the same outbox. The relay also reads each host's sessions and open gates (`north fleet outbox snapshot`) into `fleet/.remote`, so `north fleet list` and `tree` show them (with their parent, host-qualified, marked stale after 5 minutes unseen), `north gate list` shows its open gates as `HOST:ID`, and `north gate answer HOST:ID N` answers one over ssh as the calling session, so the answer reaches the asking session on its own host (north#184).
- Placement gate: `north fleet launch` and `revive` of a Claude session run Claude-only placement first and print one verdict line per account (available with its headroom, or out at 95% 5h, a measured 5h burn over the 50%/h cap, or a provider-exhausted week; the pace controller's held or over never refuses). A code-only public box (declared `Surface:`, no local `Needs:`, repository north, wisp or smashcraft) is refused with the Nexus `north cloud launch` command while the cloud credit is unexpired and unspent, unless `--local "REASON"`; an account other than the one placement picks (the most headroom among the accounts that can run on the chosen machine, or here) is refused unless `--pin "REASON"`. A box needing something local (private stores, native clients) runs on the first `[hosts.NAME]` machine with `ssh` whose `serves` covers each need, a `NEED` for every repository or a `NEED:REPO` for one, and that is below its resident cap; failing that it stays here when this host's own `[hosts.NAME] serves` covers its needs, and is refused as unserved when it doesn't. The reasons are recorded on the session and shown in `north fleet list`. `--test` sessions skip the gate. A `--task REF` launch is refused while a running fleet session on this host, any other host (over ssh, or the laptop's copied list) or a dispatch launch of the last two hours already holds REF, unless `--force-dup "REASON"`, which is recorded as `dup: REASON`.
- Launch tier (north#242): `north fleet launch` of a Claude session that holds an issue (`--task REF`, else the brief's first `Item:` line) reads the brief's `Category:` and facets (`Spec`, `Surface`, `Verify`; a missing Category is `feature`), routes them as dispatch does (art on sonnet-high, mechanical on worker-haiku with its miss retried on sonnet-high, feature, tooling, native-check, balance-tuning and bug-known-cause alternating the Sonnet and Opus arms until the ledger holds 15 runs of each and then taking the arm with the lower `north ledger summary --since 7d` cost per closed box, everything else on worker), starts the session with that tier's `--model` and `--effort` from South's `[tiers]` table, and writes the `Tier:`, `Arm:` and `Follows:` lines into the prompt's brief header (a Haiku pick also gets the wait-on-Monitor rule). A brief that already carries `Tier:` (a dispatched box's, or an escalation's `worker-sonnet`, `worker-high` or `worker-xhigh`) keeps it, and a `Tier:` naming no tier is refused. A `--model` of another family than the pick is refused unless `--tier-reason TEXT` is given or the brief carries a `Tier-reason:` line, and a Claude launch that holds no issue is refused any `--model` without one, since no issue's routing can check it. Such a launch with no `--model` is routed the same way on the `Category:` (or `Tier:`) line in the header block (the lines before the first blank line) of its system prompt, prompt or named brief, with the session name standing in for the item; a header that marks a worker (`Delegation: role=worker`, or a `Spec:`, `Scope:`, `Surface:` or `Verify:` line) but declares neither and names no `Item:` is refused, and a brief whose header does neither keeps the account's default, so a plan's per-box lines below the header route nothing; the reason is recorded on the session as `tier: TEXT` beside `--local` and `--pin`, shown in `north fleet list` and kept by `revive`. Each launch is appended to the launching host's `launches.jsonl` as a hand launch, which dispatch on that host counts for arm alternation, Haiku retries and `Stop: decision` reports and which holds nothing; a hand launch on another host reaches dispatch only through the ledger's runs.
- Learning tick (north#112): `north tune [--dry-run]` prints the `north ledger summary --since 7d` dashboard line, then decides from the ledger's closed boxes of the last 7 days the cells briefs and routing take: `route CATEGORY` (the arm dispatch takes once both arms hold 15 runs and a cost per closed box), and `eta_minutes FAMILY CATEGORY` and `budget_usd FAMILY CATEGORY` (the ceiling of the p75 run wall and twice the median cost per closed box, as briefs print them). It writes them to `~/.local/state/north/tune/cells.json` and appends one line per new, changed or dropped cell to `provenance.jsonl` there with its from and to values, the ledger rows and closed boxes behind it, the 95% order-statistic interval of its figure and the rerun command. Each tier and category whose cost per closed box rose more than 25% over the 7 days before gets one north issue titled `Cost per closed box rose more than 25% week on week in TIER CATEGORY`, unless an open issue of that title holds it, and the last line is the open north issue count. `--dry-run` writes and files nothing.
- Dispatch: `north dispatch [--dry-run]` (Nexus timer every 5 minutes, south `modules/north-dispatch.nix`) keeps free worker slots busy. It prints each `[hosts.NAME]` (the laptop only while `laptop status` says available, counting its sessions from the fleet list it copies to Nexus) with its resident cap and running sessions, each pace-control account as open or out with the hosts `[accounts.PROVIDER] profiles` signs it in on (less this host when its roster has no login of its own for the account), and per host and account the free slots: cap − running for an open account, none for one the out-rule holds (5h at 95%, 5h burn over its cap or the week exhausted; pace's allowed workers and projections never hold). A ready box is an open issue in a staffed repository (the `dispatch_repos` of each `[projects.NAME]` in South's orchestration, else its `repos`, less `[placement] private_repos`, in project `priority` order) with an unticked box, not in a project whose `dispatch_paused_until` (an RFC 3339 time in its `[projects.NAME]` table) is still ahead, which skips with `project NAME paused until TIME`, not labelled `evidence:tom`, `needs:tom`, `decision:tom`, `roadmap` or `native:running`, held by no running fleet session (each ref its `--task` names, else each number of an `sc-N`, `sc-N-M` or `wisp-N` name, on this host, any ssh host or the laptop), open north gate naming it on any host, NorthThreads claim or dispatch launch of the last two hours (six for a cloud launch), whose newest comment does not say it waits on Tom or the laptop, whose `Follows:`, `Blocked by`, GitHub blocked-by and plan `Order of work` predecessors are closed, and with at least one unticked box measurable now: an issue author gates a Done-when line on a time by writing `(not before YYYY-MM-DDTHH:MMZ)` in it, and while every unticked box carries a marker still in the future the issue skips as `only open box waits until <earliest>`; every other issue prints with its reason. Each ready box gets a generated brief (Item, Category and facets from the issue or defaulted, the generic Done when); its category is the first word of the body's `Category:` line, else a `category:NAME` label, else `feature` for `enhancement`, `debugging-unknown-cause` for `bug` and `docs-policy` for `documentation`, and a box none of those categorise skips as `ready, not placed: no category: ...`, which the alert line names when nothing else launched, and goes, in priority order, straight to the cloud lane (`north cloud launch`, no courier; Autoland lands the `claude/land-NAME` branch the session pushes) when it is code-only in an Autoland repository (smashcraft or wisp; other repositories have no courier, so they run on hosts), the credit is usable, this is `[placement] cloud_host` and fewer than 6 cloud boxes it started in the last 6 h are still open, else to the host that serves its needs, has a free slot and would start it soonest (`--local` records the cloud fallback): dispatch reads each host it reaches (here or over ssh) for `nproc`, `/proc/loadavg` and `/proc/meminfo`, classes a box verified by `local-test` or `native` as heavy (`dispatch_heavy_memory_mib`, else `dispatch_agent_memory_mib`), refuses a host whose total memory could never admit that class under unattended admission, and ranks the rest by the run queue past the cores plus one run when memory headroom would defer it now, `[placement] order` breaking ties and an unmeasured host (the laptop) counting as no wait (north#259), through `north fleet launch`, as a laptop job on the laptop. On that host it takes the open signed-in account that ranks first: a live pace spend target, then the week's room per hour until that week resets, scaled per window by the five-hour and weekly multipliers the model catalog gives its `[accounts.PROVIDER] plans` entry over those of `max-5x` (Max 20x is 4 times Max 5x in the five-hour window and 2 times in the week) so capacity that expires sooner is spent first, then scaled five-hour room; each planned launch charges its account `reservation_fallback_points` divided by its plan size in each window before the next box ranks, and an account that charge would take past a window's stop takes no more boxes that run. Each attempt is a line in `~/.local/state/agents/dispatch/launches.jsonl`; sessions start in `~/code/REPO/main`; an item tried twice in 24 h is left to the proxy, where a try counts only when its session (read with `north fleet show`) committed, ran a check or reported something other than a capacity wait: a session that only waited on admission (`DEFER_*`, a pool or pair queue), hit a usage limit or failed before any report spends none, and the skip line names the tries that counted and those that did not. An open issue with no box at all, ticked or not, and no Tom, `roadmap` or `native:running` label skips as `needs a box`; the run prints them on one `needs a box:` line and, at most once a day, sends their list to the session `[dispatch] triage_lead` names through `north fleet send`. When ready work and free slots coexist and nothing launched it sends one `nexus-alert normal` line naming why, repeated only after 6 h or when the reason changes.
- Cloud sessions: `north cloud launch REPO SLUG BRIEF` refreshes a sparse, depth-1 checkout of the public repository under `/tmp/cloud/src/REPO`, marks it trusted in the login's `~/.claude.json` just before launching, and starts BRIEF plus the cloud safety line and the steps that push `claude/land-SLUG` through `claude --cloud` from it, printing the session, the branch and the checkout. `north cloud list | events ID OUT | sweep DIR | send ID FILE | wait ID OUT [--after UUID] [--timeout SECS]` reads, messages, waits on and sweeps the Anthropic cloud sessions of the host's `~/.claude` login through `curl`, with the token on curl's stdin config, never in argv ([cloud.md](../harness/skills/workers/references/cloud.md)). `send` posts FILE as a user message to an idle session and prints the HTTP status and the message uuid; `wait` writes the transcript once the session is idle and its newest turn event ends the turn, after that uuid when `--after` is given, and exits 1 on timeout; `sweep` archives only `anthropic_cloud` sessions in `requires_action`, never bridges.
- Live claims: `threads claim`, `threads list [--json]` and north dispatch share one rule in `src/threads/claims` (run in Rust as `north threads claim|list` on the ledger host; bin/threads hands both verbs to it). A claim is void, so `list` omits it, dispatch holds nothing and `claim` replaces it with a `claim` event naming it, when it was made before its GitHub issue was opened, its issue is closed or does not exist (native items read the ledger's item table). A claim with no event from its owner for 24 h past `since` plus its ETA (none counts as 0) shows `STALE`; dispatch does not hold it and `claim` takes it over with a `handoff` event whose `takeover` names why. Any other claim is live: `claim` refuses another owner and dispatch holds the issue. An unreadable GitHub reply leaves only the ETA rule. `threads ready`, `threads unowned` and `north work list` read `north threads list --json` too, so a void claim leaves its issue ready and unowned and a live claim holds it; `north work list` shows only a live claim as its holder.
- Live holders: `threads ready` and `threads unowned` keep a stale claim held when its exact owner matches an active Fleet session; a registered launcher PID must still be alive. A proxying client relays proven local owner identifiers to the remote ledger; PIDs are checked only on their own host. Finished or dead holders' stale claims no longer hold.
- Resuming archived work: `threads show REPO#N` reads origin's `archive/*` tags in `~/code/<repo>/main` (or the current lane) and lists tags whose commit messages say `Refs REPO#N`, with `git push origin archive/<branch>:refs/heads/<branch>` to restore each. The SessionStart unlanded-work hook lists the same archives when the session's Fleet task brief has an `Item:` ref.

## Landing and lanes

- `safe-push --to main` reads committed `.safe-push` `land.check` entries (`pathspec[,pathspec] :: command`) and runs affected checks; Main is red confirms a failed job once and reverts a culprit after a green parent.
- `north capacity offload choose|run`: while this host is in game-reserve, `safe-push` ships the lane by git bundle to the first other `[hosts.NAME]` with an `ssh` destination and room (free cores, the heavy memory request, 20 GiB free where its offload slot lives) and runs the land checks there in `~/.cache/land-offload/<checkout>`, whose `target` persists between runs; `land.local-only` entries in `.safe-push` and a missing host keep the checks on this host.
- `mutant record <id>` (`north mutant record`) saves the scratch copy's non-empty diff against HEAD to `~/.local/state/agents/mutants/<repo>/<id>.patch`; `safe-push` runs `north mutant verify BASE HEAD`, which refuses a claim whose patch is missing or applies to neither side and, when the base `.safe-push` sets `mutant.run`, runs that runner once under one capacity lease over the change tree and every mutant tree, requiring each named test to pass on the change and fail on its mutant; verified kills are cached by change patch-id and mutant.
- Provenance: `north provenance check BASE HEAD` lists each bar (a comparator such as under, within or `<=`, a number and a unit) added to a PLAN*.md table row, a Done when line, a `- [ ]` box or a test path without a `Provenance: <claim>; origin <...>; pointer <...>; rationale <path#anchor | not recorded>; revisit <...>` trailer whose claim names its number and unit and whose origin is not `none` (allowed only with `; soft`); a reworded line keeping its bar passes, and `safe-push` refuses the rest. `north provenance debt [--due] [--repo PATH]...` lists `Target-debt` trailers on origin/main of each `~/code/*/main` not named by a later `Target-paid: <commit>`, with `--due` keeping rows whose revisit date passed, whose `closed REPO#N` issue closed, or whose trigger is event text.
- Landing flow: `agents flow [--json] [--repo NAME]... [--stall-alarm]` caches pending landings, landing rate, push-to-land latency, main idle time, oldest landing job and runner, stall verdict, project throughput, and Actions, Wisp and Autoland capacity signals. `--stall-alarm` sends notices to the active Fleet parent and Plato, and mentions Tom after 60 minutes until main moves and jobs recover. Fleet sessions use the same one-hour landing WIP limit (floor 2), with landing-path and `CASE=URGENT` exceptions.
- CI diagnosis: `ci-diagnose [--dry-run OWNER/REPO RUN_ID]` runs after `agents flow --stall-alarm` (laptop, every five minutes); for each open "main is red" issue in north, firn and smashcraft it takes the newest still-failing main run, has Claude Haiku extract the failing step, first error lines and culprit `path:line` from `gh run view --log-failed` (refusing JSON whose step or errors are not in the log), has Claude Opus medium judge the cause and smallest fix from that plus the compare diff stat, and posts one comment marked `<!-- ci-diagnose:RUN -->`; it never changes code, reverts or closes anything.

## Ledger, calibration and reports

- Worker delivery costs: `worker-ledger --summary` includes median brief-to-landed minutes, dollars per done box and observed completed-worker concurrency by model/effort/fast and project. NorthThreads stores account, model, effort, fast and included-plan dollars; weekly readout deltas allocate dollars to token samples from active runs (input 1, cache write 1.25, cache read Opus 0.05/others 0.1, output 5). Missing measured intervals print unknown costs. `--backfill --since 2026-10-11` rereads prior runs; remote ledger reads use its snapshot, never a frozen local database. `threads ingest` accepts `type=usage` readout rows and refreshes the mirror after publishing them, using the existing remote spool during outages. Senders reach the ledger host through `north threads ingest`, which reads its input and then takes an exclusive `ingest.lock` beside the ledger, waiting up to 5 s; a second ingest that cannot get it exits 75 (retry) and the sender spools the batch instead of piling up a process on the host. `worker-ledger`'s own ingest goes through it too, so it waits behind a held lock like any sender.

## Policy measurement

- Policy regression gate: `agents sync` measures the candidate policy's startup tokens (chars/4 of global and code-root policy, the Claude skill and agent listings and the largest SessionStart role output; the harness-bundled listing and project AGENTS.md files are not counted) and the sha256 of `south:agents/AGENTS.md`, and compares them with `south:agents/operating-point.toml` and the newest `sweep-*.jsonl` row for that sha256 in `south:agents/replay/` or `~/.local/state/agents/replay/` with 3 or more trials on every scenario the operating point's row measured (a later 1-trial row or a newly added scenario does not displace it). Re-run it on a model release, a big policy change or weekly. `SCENARIO.json... --promote [--candidate PATH] [--operating-point PATH]`, run in a south worktree and landed through `safe-push`, copies the candidate's point keys into the operating point and keeps every other key and comment (`weak_scenarios`); it refuses a candidate that misses a listed scenario, flips a scenario the current point passed every trial of to 0 passes, or whose conformance is significantly below the current point or the frozen anchor (`anchor_conformance`, `anchor_n`, `anchor_date`, the point the promotion chain started from), so small steps cannot compound. `--accept-drop REASON` (a model release, a new scenario set) skips those checks, records `accepted_drop` and `accepted_drop_date` and re-anchors on the candidate. ## Machines, capacity and scheduled jobs

- Product verification: `verify-north` builds north from the checkout around the current directory (or takes `--north PATH`), then in a 160x45 tmux terminal opens `north fleet`, launches a Claude haiku session from the Ctrl+N form, checks an Alt+U urgent answer within 10 s during a running `sleep 120`, a Ctrl+G deepen run in the ledger, a Codex `fleet ask`, and a `north task check` verdict; a separate cleanup process forgets its sessions, kills its terminal and asserts none of its session hosts or app-servers survive, even when the run is interrupted. One line per step with wall ms; nonzero exit on any failure.
- Fleet landings: fleet exports `NORTH_FLEET_SESSION` to every command a session runs, `safe-push` logs that name in `pushes.tsv` with the default-branch commit it landed, and north records that commit as the landing of the session's task (its `--task`, else the session name) when each turn ends and every 30 s while the fleet screen is open, so `north task landed` is optional.
- Fleet receipts: `north fleet launch` makes the calling session (`NORTH_FLEET_SESSION`) the parent unless `--parent NAME|none` says otherwise. When a child ends a completed turn that landed a commit or whose reply starts with Done, Not done, Split, Stop or Blocked, its session host queues one message to the parent: `[from NAME · turn N · exit E · landed SHA]` and the child's reply, cut at 4,000 characters with a pointer to `north fleet show NAME`. Other completed turns (progress lines, questions) stay in the child's transcript and ledger without waking the parent; `north fleet show NAME` shows them. A failed turn is queued like any receipt with the last 5 transcript lines, while a host death mid-task is sent urgently, which a per-child `fleet watchdog` process notices. A gate the child opens also goes to the parent as one line. The parent or Tom can close it with `north gate answer ID N [--note TEXT]`; the ledger records the answering session name (or `tom`), and the child receives a `[gate ID]` fleet message with the chosen option and optional note. A closed gate never defaults later. A stale answer shows the stored answer and answerer as information. Launch test sessions with `north fleet launch --test`; their children inherit the marker and their gates stay out of Tom’s decisions digest. `verify-north` marks its sessions automatically. The ledger's `receipts` table claims each notice once, so restarts never resend one; a stopped parent is never revived for a notice.
- Runtime promotion: `north runtime update` (run by `agent-runtime-update`'s 02:00 pass) fetches north main and, when `~/.local/state/north/current` is behind origin/main, builds it in a detached `worktrees/runtime-<short>` under a heavy capacity lease (while this host is in game-reserve it instead prints `north runtime: building <short> on HOST while this host is in game-reserve`, runs `north runtime update` on the first other `[hosts.NAME]` with room by the `north capacity offload` rule and rsyncs that host's programs back, so the game never waits out a build), installs `runtimes/<sha>/north`, `verify-north` and `tree/` (a `git archive` of that commit, which scheduled jobs run harness code from), swaps `current` atomically, runs `agents sync` (which projects skills, scripts and hooks from the new `tree/`, so they change only when `current` does) and swaps back if that fails; it keeps the previous runtime plus the 3 newest others and holds `runtime-update.lock`. Promotion roots each store path the binaries name as `runtimes/<sha>/gcroot-<store name>` (`nix-store --add-root --indirect`), so Nix garbage collection never removes what a promoted runtime loads and pruning a runtime releases its roots. `north runtime deploy HOST...` builds that runtime on the machine it runs on (the laptop, so Nexus's 3 cores never compile north), runs `nix-store --realise` over its store references on each HOST, rsyncs the programs into the HOST's `runtimes/<sha>/` and runs `north runtime update` there, which skips its build and promotes.
- Orphan lease reaper: `north capacity reap-orphans` stops the scope of every run lease whose wrapper process is gone, so no Warcraft client or run outlives its runner and the lease's slot frees; it is the stop half of the laptop's `laptop-auto` tick and needs no `laptop` command, so hosts without that tick (gex45, nexus) run it from the `lease-reaper` user timer every 30 s (nixos-config `modules/laptop-runner`, off the laptop placement) (north#191).
- Capacity estimates: `machine-capacity estimate [--json] [--class CLASS] [--owner OWNER] -- CMD ARG...` uses the current directory and the last 20 matching measured runs, with exact signature, full owner/shape, owner prefix/shape/class, family/repo, family (none for unrecognized `other` commands), and declared-class fallbacks. Imported rows without exact targets cannot establish that a target is known. Owner levels require an explicit owner; the prefix is its leading ASCII letters. It prints p50/p90 cores, peak memory, I/O bytes, disk busy share, sample count, match level, and confidence. Disk busy share is the maximum physical whole-disk `/proc/diskstats` I/O-millisecond delta divided by run wall milliseconds (host-wide; partitions and virtual devices excluded). Stored cgroup I/O pressure is reference data only. Runs without a class reserve rounded-up p90 cores and p90 memory plus 20%; running batch CPU accounting uses the greater of measured two-minute use and estimate p50, plus 25%. ## Wisp payoff

`north wisp payoff [--since YYYY-MM-DD] [--json]` reads retained Smashcraft evidence, Wisp state, and Wisp evidence/build directories without creating a store. It prints per-kind UTC Monday weeks, completed comparison agreement, invalid native attempts, native client-minutes, Wisp main commit counts, retirement candidates, and disagreement evidence paths. JSON includes each contributing run for audit. The fleet Ctrl+T digest refreshes its summary in background upkeep.

Pad families use their script directory (standalone pads use their name). Pad client-minutes count two clients over game, reset, reload and run time; Wisp, comparison and wait time are excluded. Acceptance report elapsed time is divided equally over checks and marked estimated. Batch dates use file modification time because the format has no timestamp. PASS and FAIL count as comparisons only when both headless and comparison ran; INVALID never counts as disagreement.

Retire candidates have at least ten agreeing comparisons and zero disagreements across the last fourteen days, independent of the display filter. They select Wisp-only evidence with a one-in-ten native sample. The weekly projected sample saving is 90% of those kinds’ historical native minutes, a counterfactual estimate. Actual avoided minutes, closed Public 0.1 boxes, native minutes per closure and Wisp-only closure shares remain unknown when retained evidence lacks closure provenance and skipped-run records. Do not equate projected savings with observed payoff. The command never files issues or sends messages; its evidence paths support deduplicated issue filing and planner handoff.

The planner contract is `schema_version: 1`. `families[]` is computed from the full rolling fourteen-day window even with `--since`. Each entry has `id`, `match_rule: {kind, values}`, `verdict` (`wisp-only` or `native`), `native_sample_rate` (0.1 or 1.0), `counts`, and inclusive `window_start_unix` / `window_end_unix`. `parent-directory` matches an immediate POSIX dirname in `values` and a `.pad` basename; `exact-path` matches a whole path in `values`; `none` applies to accept checks, not scripts. Unknown or ambiguous matches select native. Paths are repo-relative POSIX strings; reject absolute paths, backslashes, and dot segments. Headless-session batches are excluded regardless of their comparison message.

Sampler `sha256-first-u32be-mod10-v1` hashes UTF-8 `scriptPath + "\n" + fullSourceRevision`, without a trailing newline. Interpret the first four SHA-256 bytes as an unsigned big-endian integer and take modulo ten. Select native when the verdict is `native` or that bucket is zero. JSON `sampler` carries the identity, exact input description and a test vector. This gives identical reruns the same sample and prevents display filtering from changing routing.
