# North features

What each harness command and app feature does, grouped by job. The commands live in [bin/](../bin/);
[harness.md](harness.md) shows how they fit together. Each command's `--help`, its code and
[harness/defaults.toml](../harness/defaults.toml) are authoritative for flags, defaults and thresholds;
a number quoted below describes the behaviour when it was written.

CPU offload: [`nexus-run`](nexus-run.md) sends an owned working tree over SSH, runs its command under Nexus capacity admission, and retrieves selected outputs. The private stock asset cache stays outside Git on Nexus.

## The `north` app

- Interactive coding workspace: `north`, or `north --resume ID`.
- Work items: `north work list`, `north work search TEXT`, and `north work show REPO#N`; in the app, `/work` opens the list and Enter opens the selected item. Type in the list to filter open issues, or use `/work search TEXT` to include closed issues. Escape returns to the composer.
- Work edits: `north work claim REPO#N [--by NAME] [--eta MINUTES]`, `release REPO#N [--to NAME]`, `need REPO#N BLOCKER#N`, `unneed REPO#N BLOCKER#N`, and `close REPO#N --comment RESULT`. In the app use `/work` followed by the same arguments. Changes are recorded on the GitHub issue.
- Where work state lives: GitHub holds titles, bodies, checklist, state and blockers. NorthThreads holds current holders, elapsed time and ETA, handoffs and worker runs. North reads both and writes through their commands.
- Skills and hooks: `agents status`, `stale`, `inspect ID`, `path ID`, `on ID`, `off ID` and `sync` (each also `north config agents ...`) list, toggle and publish the catalog's skills and hooks; [harness.md](harness.md#install) describes what `agents sync` publishes.

## Staffing and routing

- Claude account profiles: `agents lead start --provider claude --account LABEL --domain DOMAIN --brief FILE` uses the account's local profile and records its label for restarts. Omitting `--account` keeps the current default. South owns account IDs, host profiles, plan selections and required plans for automatic routing. `agents sync` projects the default Claude harness files into those profiles while credentials and session history stay separate. A profile awaiting its required plan is available explicitly but is excluded from automatic routing until its OAuth tier confirms that plan.
- Interactive Claude: `claude --account LABEL` selects a signed-in profile; plain `claude` chooses the greatest remaining weekly capacity in plan units, excluding windows at 95% or above. Cached profile usage and the usage ledger provide the newest readings without a network request. `--resume` and `-c` select the profile owning the current directory's session. Harness `-p` calls and launches with an explicit profile keep their account.
- Routing: `agents plan` prints one difficulty band table from scalar tier starts, with account usage and project priority, share and target. `agents plan` shows each account’s used percentage, linear pace, available weekly dollars and reset timestamp, and routes each tier to the soonest-expiring under-pace account. Claude drains to 5% left at its reset; Codex drains to 15% left Friday 23:59 America/New_York, prints its projection from the last three hours of burn against the 10–20% band, and flags drain behind on Thursday or later above 20%. `--json` exposes the same metrics and routes; `--at FILE` replays recorded routing decisions. Project `share` is a percentage of rolling seven-day available dollars; `target` is its deadline.
- Pace hold: the spawn gate holds a new worker when the account routing picks for its provider is at or over its pace line and the project (the brief's `Item: repo#N`, else the spawner's org domain) has no live `target` with a `drain = { <account or provider> = "tom: <date> <quote>" }` grant for that account in orchestration.toml, printing `Hold: <account> is at or over its pace line (used U% vs pace P%); <project> has no approved deadline. ...`. It denies once now reaches that account's `[pace] enforce_from` time in orchestration.toml and only warns before it or without one, and `agents plan` (routing.choose) admits by the same rule, routing an at-or-over-pace account and printing a warning before its enforce_from; `CASE=URGENT` passes, and a stale or unknown usage readout prints its stale warning instead of holding.
- Resident cap: `bin/claude`, `bin/codex` and `agents lead start|restart` refuse a new resident session on a host whose `[hosts.<hostname>] resident_cap = N` in orchestration.toml is reached, counting live claude/codex CLIs registered in `agents org` plus unregistered top-level interactive ones, and print `Hold: <host> has N/N resident agent CLIs; place this worker on laptop|cloud` (exit 3). `--cloud`, `-p` and codex exec/app-server launches are not resident; `CASE=URGENT` with a FACT passes; hosts without the key are never held; `python3 harness/lib/resident_cap.py status` prints the live count and cap.
- Usage resets: `agents usage` publishes fresh readouts through `threads ingest` to the authoritative ledger, with its existing offline spool. Remote clients read history from the mirrored snapshot and overlay fresh readouts in memory. A stale plan readout fails loudly. `agents usage` keeps each account's used percentages and reset times and appends reset availability and its source. `usage-web-read` reads the Claude usage page and account UUID inside automation Chrome, caches per-kind counts and expiry by hashed account in `~/.local/state/agents/usage/claude-web.json`, and preserves other accounts and the previous cache on failure.
- Worker estimates: `worker-ledger --recommend 'FACETS'` chooses the cheapest tier meeting the 80% measured success threshold and adds the recommended tier’s nearest-rank p75 actual duration and sample cell, backing off Surface, Verify, Scope, then Spec until three samples are available (or Category alone); no samples prints `eta n/a (n=0)`.
- Follows boxes: `threads queue follow REF --tier T --lead L` queues a brief from stdin whose `Follows:` line names a commit subject, SHA or issue ref; `follows-release` (run by `safe-push` after a landing on the default branch, and by each `worker-sweep` pass for landings made elsewhere) releases each box whose predecessor is on origin/main, passes it through the spawn gate as its lead and runs `$FOLLOWS_RELEASE_START TIER LEAD BRIEF` (default `codex-lead send`), and a box the gate denies or that has not started 5 minutes after release gets one `FOLLOWS` line in `<lead>-inbox.md` and `proxy-inbox.md`.
- Project quote: `agents plan --quote --project P --boxes N` reads the project target from `south:agents/orchestration.toml` and the worker ledger, prints the measured completion date and dollars, and asks one date-and-budget decision for dated projects; undated projects ask none. `agents flow` prints the needed closure rate for each project target.
- Goal ETA: `agents plan` prints, per project target, the critical path over the goal's open boxes at the spawn gate's width with landing overhead, predicted finish against the target and n per box, and records it as a `goal_eta` calibration row ([feedback-loop.md](feedback-loop.md#goal-eta-north35-box-7)).
- `agents plan --score PROJECT` scores a passed project target from the open issue backlog, linked issue boxes and rolling seven-day run costs, prints on-date, in-budget and spec-pass, and appends one row to `~/.local/state/agents/goal-scores.jsonl`. Missing issue or spending evidence is unmeasured. Project share applies to available account dollars. Projected misses offer one budget/date/scope decision with recorded non-AI service costs and speedups.

## Leads, ticks and sessions

- Headless leads: `agents attach NAME` opens a tmux pane; closing the terminal detaches. `agents lead restart NAME` resumes its saved transcript. `AGENTS_SESSION_HOST=tmux|ghostty` overrides `[sessions] host` in orchestration.toml; the default uses ghostty on a Wayland desktop and tmux elsewhere.
- Agent names in status bars: `agent-statusline` is Claude Code's statusLine command. It prints the org name in bold (AGENT_ORG_NAME, `← parent` below a lead; Plato for Tom's top-level session), then role, domain and model. `codex-lead start` names the Codex thread after the org node and shows the thread title first in the TUI status line, leaving the window title to spawn-quiet.
- Agent events: `agents event KIND [ITEM] --from-node NAME --to-node NAME --body TEXT` records an addressed row in the canonical threads ledger and mirrors it to human records; `--lane`, `--sha`, `--repo` and `--packet` retain the work context. `agents supervise` (user service `agents-supervise`) delivers rows to live Claude sockets and Codex threads and applies the stall rules in [harness.md](harness.md#events-between-agents). `agents event list` shows unanswered rows. `agents org set proxy [--pid N]` registers the proxy's actual Claude process for delivery. Bootstrap or hand off a Claude proxy with `agents org start proxy --brief FILE [--account LABEL] [--cwd DIR]`: it uses the lead launcher, copies existing project trust into the selected profile and reports success only after the new transcript records its first completed turn. `--timeout SECONDS` defaults to 120; expiry closes the replacement session and reports failure.
- Tick precheck: `agents tick-precheck --session ID --status FILE` runs a lead tick's commands (`threads unowned`, `worker-sweep`, `capacity-watchdog report`, and `agents flow` plus `worker-ledger --summary` every third tick) in parallel within 2 minutes, reduces them to flag keys with volatile numbers normalised out and diffs them against `~/.local/state/agents/tick-precheck/<session>.json`; with nothing new it prints and appends `quiet tick=<n>: <counts>` to FILE and exits 0, otherwise prints only the new rows with their source and exits 10; raw outputs go to `<session>-last.txt` for audit. A session sees only the capacity and flow flags its lead owns: a lease flag carries `org=<node>` from `capacity-watchdog`'s process-tree attribution of the lease holder, a flow row belongs to the lead whose domain or `repos` include the repo (goal flags: closures below the needed rate, land-to-close over 30 minutes, land ratio below 1.0, any failed unowned lane), an untranscribed or unnamed lead row goes to that lead and the proxy, and flags no lead owns go to the proxy (any session not in `agents org`). Each tick it also finishes the caller's active children whose newest status or `-peer.md` file ends in `FINISHED <name>` written after they started: it runs `agents org finish NAME`, which closes the child's tmux session or verified launcher process tree and deregisters it, and prints `FINISHED <name>` (exit 10). A trailing `DONE` line finishes nothing: it becomes the flag row `DONE seen for <name>: run agents org finish <name> if its queue is empty`, keyed by the line's text, so it wakes the parent once per new DONE line.
- Tick tokens: `tick-tokens [--hours 24] TRANSCRIPT...` prints Opus tokens, output tokens and model calls per `[routine:tick]` turn in Claude transcripts, deduplicated by message id.
- Live holders: `threads unowned` keeps an expired claim held when its exact owner matches an active org node or session; a registered launcher PID must still be alive. A proxying client relays proven local owner identifiers to the remote ledger; PIDs are checked only on their own host. Finished or dead holders still expire after twice their ETA.
- Resuming archived work: `threads show REPO#N` reads origin's `archive/*` tags in `~/code/<repo>/main` (or the current lane) and lists tags whose commit messages say `Refs REPO#N`, with `git push origin archive/<branch>:refs/heads/<branch>` to restore each. The SessionStart unlanded-work hook lists the same archives when the session's registered org brief has an `Item:` ref.
- Matrix agent rooms: `socrates-chat run` reconciles this machine's org rooms under the Socrates Space and drains `~/.local/state/socrates-chat/outbox`; it wakes on org, outbox, status-file and pending-transcript changes, watched session exits (util-linux `waitpid`) and synced space state, re-reads space layout only when a room opens or closes or space state changes, and otherwise ticks every 5 minutes (1 minute with open watches, 2 s with queued inbound messages); workers post into their parent's room. Socrates orders Plato, alerts, then the Smashcraft, Wisp, Nexus, North, Tooling and Mail sub-spaces. Leads and sub-leads go into their org domain's sub-space; other domains stay directly in Socrates. Spaces and rooms resolve by alias before creation, and an unchanged hierarchy sends no state updates. `post --as NODE [--kind reply|result|notice] [--tag TAG] TEXT|-` writes the v1 spool without network access; `rooms [--json]` includes each room's parent space alias. `avatar ROOM FILE` uploads an image as Socrates and sets the room or space avatar; ROOM is an alias or room id. `log NODE --last N`, `latency --last N`, `probe NODE TEXT` and `replay [FILE]` inspect or exercise the bridge. Text over 4,000 characters or 40 lines becomes a file with three summary lines. Network commands use `SOCRATES_CHAT_HOMESERVER`, `SOCRATES_CHAT_TOM_USER_ID` and `SOCRATES_CHAT_TOKEN_FILE`, or decrypt `matrix-appservice-as-token` from `SOCRATES_CHAT_SOPS_FILE` at runtime; tokens stay out of argv and the database. `SOCRATES_CHAT_ADMIN_ROOM` overrides the admin alias, and `SOCRATES_CHAT_PROXY_PANE` enables proxy output. Only events whose sender exactly matches Tom's configured id enter sessions: Claude uses a bracketed tmux paste; Codex uses `codex-lead send` for its recorded session. C0/C1 controls and bracketed-paste escapes are stripped; message line breaks become Unicode line separators. Dialogs and absent sessions queue messages in order; an absent session wakes its live parent, or posts the wake in Plato's room. Other rooms also copy a `Tom → NODE` notice into Plato's room. `SOCRATES_CHAT_PROXY_PANE=socket:session` enables proxy delivery. `latency --last N [--json]` reports transcript-received minus sent and reply-posted minus turn end. `probe` sends as Tom through a temporary password login using `matrix-tom-password` in the existing encrypted Matrix file and logs out afterward. Posts default to silent `m.notice`; Plato remains `m.text`, and long posts remain files. Exactly one relay sets `SOCRATES_CHAT_WATCHES=1` to persist timeline ETAs and watches: Tom writes `watch <repo>#<n>|this|<node>|<box> [done] [if over <n>m|<n>min|<n>h|<n>d]` or `unwatch <target>` in any managed room (case-insensitive). Watch commands stay out of panes, receive a silent acknowledgement, and ping once each for done, blocked and overdue; done ends the watch. The deadline is the explicit duration from the command time, else the latest target ETA, else none. Issue watches poll `tompassarelli/<repo>` at most once per minute; node and box watches use posts from the synced timeline.

## Landing and lanes

- `safe-push --to main` reads committed `.safe-push` `land.check` entries (`pathspec[,pathspec] :: command`) and runs affected checks; Main is red confirms a failed job once and reverts a culprit after a green parent.
- `mutant record <id>` saves the scratch copy's non-empty diff against HEAD to `~/.local/state/agents/mutants/<repo>/<id>.patch`; `safe-push` checks each new `Test-kind: <name> <kind> kills <id>` claim against its landing base or head.
- Provenance: `north provenance check BASE HEAD` lists each bar (a comparator such as under, within or `<=`, a number and a unit) added to a PLAN*.md table row, a Done when line, a `- [ ]` box or a test path without a `Provenance: <claim>; origin <...>; pointer <...>; rationale <path#anchor | not recorded>; revisit <...>` trailer whose claim names its number and unit and whose origin is not `none` (allowed only with `; soft`); a reworded line keeping its bar passes, and `safe-push` refuses the rest. `north provenance debt [--due] [--repo PATH]...` lists `Target-debt` trailers on origin/main of each `~/code/*/main` not named by a later `Target-paid: <commit>`, with `--due` keeping rows whose revisit date passed, whose `closed REPO#N` issue closed, or whose trigger is event text.
- Landing flow: `agents flow [--json] [--repo NAME]... [--stall-alert]` caches pending landings, landing rate, push-to-land latency, main idle time, oldest landing job and runner, the stall verdict, project throughput (issues closed per hour over 3 h against open issues per hour left to its orchestration target, median landing-commit-to-close minutes over 24 h preferring the sha in Autoland's auto-close comment, main landings per `claude/land-*` push over 3 h, failed lanes whose issue has no NorthThread claim for 15 minutes, oldest pending lane wait), and three capacity guards (account Actions jobs busy, idle Wisp pairs while `needs:native-*` issues wait, Autoland census reuse over the last 20 landings) for five minutes; `--stall-alert` notifies the repository lead and Plato, writes the lead inbox, and mentions Tom after 60 minutes until main moves and jobs recover; Claude and Codex refuse new code workers above one hour of landings (floor 2), except landing-path or `CASE=URGENT` briefs. Every run also reads the status file of each active lead and sub-lead of a project with a `target` (Running/Blocked/Next sections) and prints `agents flow: box waiting over 10m with no running worker: LEAD BOX (Nm)` for a box under Next or blocked on capacity or hold with no Running worker for more than `box_idle_min` minutes (first seen kept in `agents/flow/boxes.json`), and `agents flow: box staffed by N running workers: LEAD BOX (WORKERS)` for a box with more than one; the tick precheck routes both to that lead's lead and the proxy.
- CI diagnosis: `ci-diagnose [--dry-run OWNER/REPO RUN_ID]` runs after `agents flow --stall-alert` (laptop, every five minutes); for each open "main is red" issue in north, firn and smashcraft it takes the newest still-failing main run, has Claude Haiku extract the failing step, first error lines and culprit `path:line` from `gh run view --log-failed` (refusing JSON whose step or errors are not in the log), has Claude Opus medium judge the cause and smallest fix from that plus the compare diff stat, and posts one comment marked `<!-- ci-diagnose:RUN -->`; it never changes code, reverts or closes anything.
- Stale lane proposals: `lane-shepherd propose [--repo NAME]...` records Haiku verdicts with Git evidence; `lane-shepherd apply FILE [--only ROW...]` archives approved fold/archive rows locally before retirement and prints lead landing commands for land rows. `lane-shepherd apply --safe [--repo NAME]... [--exclude FILE]` needs no approval or Haiku: it archives to `refs/archive/lanes/<slug>`, verifies, then retires clean merged lanes idle 3h and unlocked, unused lanes idle 24h, skips `*-land` and excluded lanes, and writes the rest (land commands, conflicts, kept) to a proposals TSV.

## Ledger, calibration and reports

- Worker delivery costs: `worker-ledger --summary` includes median brief-to-landed minutes, dollars per done box and observed completed-worker concurrency by model/effort/fast and project. NorthThreads stores account, model, effort, fast and included-plan dollars; weekly readout deltas allocate dollars to token samples from active runs (input 1, cache write 1.25, cache read Opus 0.05/others 0.1, output 5). Missing measured intervals print unknown costs. `--backfill --since 2026-10-11` rereads prior runs; remote ledger reads use its snapshot, never a frozen local database. `threads ingest` accepts `type=usage` readout rows and refreshes the mirror after publishing them, using the existing remote spool during outages.
- Split outcome: a worker report starting `Split:` is recorded as `split`, counts in no tier rate, lends its `Arm:` to its parts (runs whose `Follows:` names it), and `worker-ledger --summary` adds a per-category table of splits, parts, parts closure, summed part minutes and minutes from the split to the last part.
- Recurring recalibration: every recording `worker-ledger` run (the 15-minute timer) ends with `harness/lib/recalibrate.py`: on the ledger host (no `~/.config/threads/remote`, Nexus) it runs `threads calibrate --write` when the newest calibration row is over `calibrate_after_min` (55) minutes old, and on the host holding the Codex rollouts (the laptop) its first run from Monday 00:00Z each week runs `defaults-measure.py --priors` and records one `prior` calibration row per provisional default through `threads record-priors` (cell the default, n its settling count, value the count it needs).
- Loop report: `agents report` prints the latest `calibration` batch per kind with its age, n and `(uncalibrated: <reason>)` for cells under n=5 or older than 7 days, the latest `prior` batch as `SETTLED` or `WAIT <default> n=<n>/<need>`, the 7-day stall recovery line `worker-ledger --summary` prints, spawn-gate denials over 7 days by gate (capacity, flow, pace), and each project's latest goal score (on-date, in-budget with spent against budget, spec).
- Test health: `test-health [--now ISO] [--out FILE] [--html FILE] [--no-fetch]` writes one JSON row per active repo (latest main CI wall per landing gate against its budget, five-kind census share from the T5 TSVs and wisp#120, unique-kill share, a 30-day test-file and CI-wall trend, and spot-check verdicts from `handoffs/test-health-spotcheck/<repo>.json`) and renders it as a self-contained HTML page; every number links to its run, commit or file, and a fixed `--now` gives identical output. Completed run jobs are cached in `~/.cache/test-health`.

## Policy measurement

- Policy regression gate: `agents sync` measures the candidate policy's startup tokens (chars/4 of global and code-root policy, the Claude skill and agent listings and the largest SessionStart role output; the harness-bundled listing and project AGENTS.md files are not counted) and the sha256 of `south:agents/AGENTS.md`, and compares them with `south:agents/operating-point.toml` and the newest `~/.local/state/agents/replay/sweep-*.jsonl` row for that sha256 with 3 or more trials on every scenario the operating point's row measured (a later 1-trial row or a newly added scenario does not displace it). It refuses to publish with no operating point, when the live policy has no such sweep row, when that row ran on another model than the point, flips a scenario the point passed every trial to 0 passes, or shows a conformance drop (one-sided Fisher exact, alpha 0.05), or when startup tokens grew without a significant conformance gain; otherwise it prints `session start N tokens (operating point M at DATE, conformance C)`, the token breakdown, SKILL body lines and Codex listing characters, and `sweep due` when tokens differ from the operating point by more than 15%. It never runs replays; `policy-replay.py --sweep` does, weekly from the Monday tick and on each new model release `model-watch` reports. The `agent-config-check` rules group requires every `rules.toml` entry to carry a `placement` (`global`, `merged:<id>`, `skill:<name>`, `hook:<name>` or `dropped`), matches the `global` entries 1:1 and in order with the AGENTS.md bullets, and fails an entry added since the landed `origin/main` copy unless it cites at least 2 ids in `incidents.jsonl`.
- Skill prune: `skill-prune [--measure]` (laptop timer, Sundays 09:00) runs one Claude Opus medium session that prunes the shared SKILL.md bodies toward the 60-line playbook target and shrinks duplicated or stale rules, logs each moved or removed line in `skill-prune-moves.md`, folds `codex-lessons.md` into the skills and `codex-lessons-folded.md`, lands each repository through `safe-push` and runs `agents sync`; it writes the before and after body and lesson counts to `~/.local/state/agents/handoffs/skill-prune.md`. `--measure` prints each shared skill's body lines, marks domain skills and reports the total beside the operating point in `south:agents/operating-point.toml`, with no cap.
- Policy replay: `python3 harness/scripts/policy-replay.py SCENARIO.json... --arm ARM... [--trials N] [--jobs N] [--policy AGENTS.md] --out RESULTS.jsonl` runs scenarios from `south:agents/replay/` × arms × trials, at most 4 in parallel, through `claude -p` with each policy arm (`full`, `minus:PREFIX,...`, `minus-file:PATH` with one rule prefix per line, or a scenario arm name) appended in place of the live `~/.claude/CLAUDE.md` (`--setting-sources project`, empty cwd). It scores each run with the scenario's regex or tool-call detector, appends one jsonl row per run (pass, turns, input/output/cache tokens, model, effort, wall seconds, `leftover_processes` (processes carrying the run's `POLICY_REPLAY_RUN` tag still alive after scoring, then sent SIGTERM and SIGKILL after 3 s before the temp dir is removed) and `cost_api_usd_comparison` as an API list-price comparison only) and prints pass rate per scenario × arm. `--sweep VARIANTS.toml [--variant NAME...] [--provisional]` instead runs every `[[variant]]` of `south:agents/replay/variants.toml` (built from the live AGENTS.md, or the file a `policy` key names, by `minus`, `minus_file`, `plus` text files and `placement` moves to a skill or hook) over the scenarios × trials, appends per-run rows to `sweep-<UTC date>-runs.jsonl` and one row per variant to `~/.local/state/agents/replay/sweep-<UTC date>.jsonl` (policy sha256, startup tokens on the `agents sync` session-start chars/4 basis, conformance, n, tokens per run, `usd_or_null`, wall seconds, model, effort), and writes the candidate `~/.local/state/agents/replay/operating-point-candidate.toml` (`--candidate PATH`): the fewest startup tokens among variants with no one-sided Fisher drop (alpha 0.05) from the best variant overall or per scenario and no 3/3 to 0/3 scenario flip, with its per-scenario counts; it never touches `south:agents/operating-point.toml`. Re-run it on a model release, a big policy change or weekly. `SCENARIO.json... --promote [--candidate PATH] [--operating-point PATH]`, run in a south worktree and landed through `safe-push`, copies the candidate's point keys into the operating point and keeps every other key and comment (`holdout_from`, `weak_scenarios`); it refuses a candidate that misses a listed scenario, flips a scenario the current point passed every trial of to 0 passes, or whose conformance is significantly below the current point or the frozen anchor (`anchor_conformance`, `anchor_n`, `anchor_date`, the point the promotion chain started from), so small steps cannot compound. `--accept-drop REASON` (a model release, a new scenario set) skips those checks, records `accepted_drop` and `accepted_drop_date` and re-anchors on the candidate. `--provider codex --arm full` instead runs each scenario through `codex exec --json --ephemeral` (gpt-6.1-sol medium) from an empty temp cwd with the normal Codex home `~/.local/state/north/codex-pooled`, so it measures Codex conformance to the live policy and skill listing as deployed; it refuses a `--policy` that differs from the home's `AGENTS.md`, runs tool-less scenarios in a read-only sandbox, maps shell commands to `Bash` and a before/after diff of the cwd to `Edit` calls, records `model_resolved` from Codex's turn log and `codex_version`, retries a model-at-capacity failure after 1, 2 and 4 minutes counting each as an outage, and prints conformance with its Wilson 95% interval. Per-run model arms: `--model sonnet|haiku|opus|<full id>` and `--effort low|medium|high|xhigh` override the scenario's model and effort (with `--provider codex` they replace gpt-6.1-sol medium), and `--advisor MODEL` passes `claude -p --advisor MODEL`; Fable is refused as either, and `--sweep` refuses all three. Each row then records `model`, `effort`, `advisor`, `advisor_calls` (distinct `server_tool_use` blocks named `advisor` in the stream), `advisor_model_resolved`, the advisor's input/output tokens and `advisor_usd` from the result's `modelUsage`, and `usd` with `usd_basis` (the result's list-price `total_cost_usd`, since the worker-ledger rate needs weekly usage readouts bracketing the run; null for Codex). A `command` detector runs the scenario's shell command in the run's cwd after the agent finishes and before the leftover-process kill, passing on exit 0 within its `timeout_s` (default 120). A scenario may live in a subdirectory such as `south:agents/replay/coding/` and name its policy file with a `policy` field relative to itself; the `agents sync` gate reads only `agents/replay/*.json` and `sweep-*.jsonl`, so these arms write `--out ~/.local/state/agents/replay/advisor-*.jsonl`.
- Harness tuner (north#47): `python3 harness/scripts/harness-tuner.py sets TUNE_DIR JUDGE_DIR` refuses when the tuning and judging scenario sets share a file stem, box commit or normalized prompt or brief; `propose --runs RUNS.jsonl --surface skill|prompt|hook-message --target PATH --out BRIEF.md` writes the proposer's brief (failed, errored and slow tuning runs, the target's text, the rules) and `BRIEF.schema.json`; `record ANSWER.json` refuses more than 5 edits, an edit without one `fixes` and one `may_break` line, an `old` text not found exactly once, or a target that is a test, fixture, replay set, scoring script or the adoption rule, and writes `~/.local/state/agents/replay/harness-tuner-<UTC date>.jsonl` once; `apply EDITS.jsonl --id eN [--base AGENTS.md]` writes a `baseline` and `eN` `[[variant]]` pair (`plus` the original and edited surface, a hook edit cut to its message lines) that `policy-replay.py --sweep` reads, and with `--base` the full `--policy` files, never touching the repo file; `replay JUDGE/*.json --variants DIR... --base AGENTS.md [--provider codex|claude] --out RESULTS.jsonl --cap-usd X [--cap-week-pct P]` runs baseline and edits paired per scenario and trial (Codex through a scratch home whose `AGENTS.md` is the variant policy), prices Codex runs at the model catalog's list price, skips runs already in `--out`, and stops starting runs at the cap with exit 3; `judge RESULTS.jsonl [--edits EDITS.jsonl]` prints per edit the paired task-cluster difference with its 95% interval, Wilson interval, list $ per success and median wall, the north#36 verdict (BEATS on non-overlapping Wilson intervals, MATCHES-FOR-LESS when the difference's lower bound is at least minus `noninferiority_margin` and list $ per success is lower, else NO-GAIN or UNDECIDED), total list spend and whether a second round is worth it.

## Issues and native items

## Machines, capacity and scheduled jobs

- Runtime promotion: `north-runtime-update` (run by `agent-runtime-update`'s 02:00 pass) fetches north main and, when `~/.local/state/north/current` is behind origin/main, builds it in a detached `worktrees/runtime-<short>` under a heavy capacity lease, installs `runtimes/<sha>/north`, swaps `current` atomically, runs `agents sync` and swaps back if that fails; it keeps the previous runtime plus the 3 newest others and holds `runtime-update.lock`.
- Capacity estimates: `machine-capacity estimate [--json] [--class CLASS] [--owner OWNER] -- CMD ARG...` uses the current directory and the last 20 matching measured runs, with exact signature, full owner/shape, owner prefix/shape/class, family/repo, family, and declared-class fallbacks. An expensive target absent from exact family/repo/package history stays heavy (native for native clients) with low confidence, even when other targets have family history; known targets and cheap families retain nearest matching. Imported rows without exact targets cannot establish that a target is known. Owner levels require an explicit owner; the prefix is its leading ASCII letters. It prints p50/p90 cores, peak memory, I/O bytes, disk busy share, sample count, match level, and confidence. Disk busy share is the maximum physical whole-disk `/proc/diskstats` I/O-millisecond delta divided by run wall milliseconds (host-wide; partitions and virtual devices excluded). Stored cgroup I/O pressure is reference data only. Runs without a class reserve rounded-up p90 cores and p90 memory plus 20%; running batch CPU accounting uses the greater of measured two-minute use and estimate p50, plus 25%. Native CPU accounting uses live measured use; missing or stale measurements use the estimate (or the reservation for older leases). Status and probe publish the same committed CPU totals for the spawn gate.
- Rest check: `capacity-watchdog rest-check [--seconds N] [--expected FILE] [--observed FILE] [--save FILE]` compares running system and user services and scopes, active timers and listening sockets (`PROTO ADDR:PORT UNIT`, `-` for a gone creator such as kernel WireGuard) with the host's expected-at-rest set (`~/.config/capacity-watchdog/rest.json`, declared in firn as `myConfig.modules.capacity-watchdog.rest`), measures each unit's CPU and context switches over N s (default 30), prints extra units, sockets and over-budget units, lists claude/codex/tmux sessions as agents, and exits 1 when anything is not at rest.
- Farm-only commands: `heavy-command-guard` reads `.agents/farm-only.toml` at each command's Git root. Each `[[command]]` declares leading `pattern` words (mode flags match in any order after the verb), `narrowing` flags that permit local work, and a `farm` command with `why`. Whole-roster matches are refused even inside `machine-capacity run`; missing or malformed declarations leave existing capacity checks in place. Claude Bash and Codex exec payloads share this identity.
- Scheduled job runs: `job-run [--path DIRS] [--user USER] NAME -- CMD...` wraps a timer's command, records its start and finish (name, host, started, finished, rc) through `threads job-run` (spooled while the remote ledger is unreachable) and exits with the command's code; `threads job-runs` shows runs, failures and the last rc per name and host. Firn's `jobRun` helper wraps every registry timer.
- Overdue jobs: `job-watch run` (nexus, every 15 min) reads registry routines with a `placement` and `deadline`, `threads job-runs --json` and WireGuard presence from `/run/nexus/peers.json`, and pushes one urgent alert per job when it becomes overdue (a laptop job also when the laptop has been online period + 30 min with no success), repeats at most daily and sends a normal note on recovery; `JOB_WATCH_TOPIC` overrides the topic. `job-watch self-test [--post]` runs the scenario fixtures, posting to socrates-test.
- Queued laptop jobs: `threads queue add PLACEMENT REF|- -- CMD...` queues work for a machine that may be asleep; `threads queue take PLACEMENT[,PLACEMENT...]` claims the oldest job of those placements atomically and prints it as JSON; `threads queue msg ID done|failed TEXT` records the result and comments it on the job's issue (a note on a native item); `threads queue msg ID requeued TEXT` puts a taken job back at its original position as `requeued`, which `take` claims like `queued`; `threads queue drop ID REASON` drops a queued or requeued job (taken, done and failed jobs are refused), recording REASON as its result and a ledger note; `threads queue` lists jobs with their wait from queued to taken (to now while queued) and their `queue-ID` job run's host, start and rc, and the tick precheck flags a job queued and untaken past `queue_wait_flag_min` (30) minutes. `laptop-runner` (laptop timer each minute and on wake) takes jobs for `$LAPTOP_RUNNER_PLACEMENT` (default `laptop`; nexus runs it as `nexus`), plus the shared `pool` placement while on AC power (or with no battery) and `machine-capacity probe --class heavy` would grant a heavy lease, one at a time under flock and runs each through `job-run queue-ID` in its own process group, keeping its full output at `~/.local/state/laptop-runner/queue-ID.log` on the host that ran it (the ledger result names host and path, plus the last 3000 characters). Laptop availability: `laptop open|close|drain|toggle [until HH:MM] [REASON...]`, `laptop status [--json]` and `laptop tick` are the single writer of `~/.local/state/placement/laptop.json` (`{state, since, reason, by, until?, grace?}`, written atomically with a ledger note on an `ops` item) on the ledger host, forwarding over ssh where `~/.config/threads/remote` exists; `open` is available, `close` drains with a 2-minute grace and `drain` with 15 minutes (`LAPTOP_GRACE` seconds overrides), and a word holds until its `until`, else until the next window edge. The `laptop-window` timer runs `laptop tick` each minute on Nexus: it opens at the window's open time and drains at its close (`/etc/placement/laptop-window.json`: tz, open, close), returns to the window state when a word's `until` passes, and turns draining into unavailable once no laptop job is taken. With placement `laptop`, `laptop-runner` takes nothing unless the state is available (read through `laptop status --json`, keeping the last cached state while the ledger host is unreachable), and past a drain's grace it SIGTERMs the running job's process group and records it `requeued`. `agents org show` (second line) and `agents flow` (first line) print `laptop status`, and the tick precheck flags each state change once.
