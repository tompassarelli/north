# North features

- Headless leads: `agents attach NAME` opens a tmux pane; closing the terminal detaches. `agents lead restart NAME` resumes its saved transcript. `AGENTS_SESSION_HOST=tmux|ghostty` overrides `[sessions] host` in orchestration.toml; the default uses ghostty on a Wayland desktop and tmux elsewhere.
- Interactive coding workspace: `north`, or `north --resume ID`.
- Capacity estimates: `machine-capacity estimate [--json] [--class CLASS] [--owner OWNER] -- CMD ARG...` uses the current directory and the last 20 matching measured runs, with exact signature, full owner/shape, owner prefix/shape/class, family/repo, family, and declared-class fallbacks. An expensive target absent from exact family/repo/package history stays heavy (native for native clients) with low confidence, even when other targets have family history; known targets and cheap families retain nearest matching. Imported rows without exact targets cannot establish that a target is known. Owner levels require an explicit owner; the prefix is its leading ASCII letters. It prints p50/p90 cores, peak memory, I/O bytes, disk busy share, sample count, match level, and confidence. Disk busy share is the maximum physical whole-disk `/proc/diskstats` I/O-millisecond delta divided by run wall milliseconds (host-wide; partitions and virtual devices excluded). Stored cgroup I/O pressure is reference data only. Runs without a class reserve rounded-up p90 cores and p90 memory plus 20%; running batch CPU accounting uses the greater of measured two-minute use and estimate p50, plus 25%. Native CPU accounting uses live measured use; missing or stale measurements use the estimate (or the reservation for older leases). Status and probe publish the same committed CPU totals for the spawn gate.
- Skills and hooks: `north config agents help`.
- Landing flow: `agents flow [--json] [--repo NAME]... [--stall-alert]` caches pending landings, landing rate, push-to-land latency, main idle time, oldest landing job and runner, the stall verdict, and three capacity guards (account Actions jobs busy, idle Wisp pairs while `needs:native-*` issues wait, Autoland census reuse over the last 20 landings) for five minutes; `--stall-alert` notifies the repository lead and Plato, writes the lead inbox, and mentions Tom after 60 minutes until main moves and jobs recover; Claude and Codex refuse new code workers above one hour of landings (floor 2), except landing-path or `CASE=URGENT` briefs.
- Usage resets: `agents usage` keeps each account's used percentages and reset times and appends reset availability and its source. `usage-web-read` runs the approved read-only Claude Chrome prompt from `~/.local/state/agents/handoffs/usage-web-read-prompt.txt`, caches per-kind counts and expiry by hashed account in `~/.local/state/agents/usage/claude-web.json`, and preserves other accounts and the previous cache on failure.
- Agent names in status bars: `agent-statusline` is Claude Code's statusLine command. It prints the org name in bold (AGENT_ORG_NAME, `← parent` below a lead; Plato for Tom's top-level session), then role, domain and model. `codex-lead start` names the Codex thread after the org node and shows the thread title first in the TUI status line, leaving the window title to spawn-quiet.
- Matrix agent rooms: `socrates-chat run` reconciles this machine's org rooms under the Socrates Space and drains `~/.local/state/socrates-chat/outbox`; workers post into their parent's room. Socrates orders Plato, alerts, then the Smashcraft, Galileo, Wisp, Nexus, North, Tooling and Mail sub-spaces. Leads and sub-leads go into their org domain's sub-space; other domains stay directly in Socrates. Spaces and rooms resolve by alias before creation, and an unchanged hierarchy sends no state updates. `post --as NODE [--kind reply|result|notice] [--tag TAG] TEXT|-` writes the v1 spool without network access; `rooms [--json]` includes each room's parent space alias. `avatar ROOM FILE` uploads an image as Socrates and sets the room or space avatar; ROOM is an alias or room id. `log NODE --last N`, `latency --last N`, `probe NODE TEXT` and `replay [FILE]` inspect or exercise the bridge. Text over 4,000 characters or 40 lines becomes a file with three summary lines. Network commands use `SOCRATES_CHAT_HOMESERVER`, `SOCRATES_CHAT_TOM_USER_ID` and `SOCRATES_CHAT_TOKEN_FILE`, or decrypt `matrix-appservice-as-token` from `SOCRATES_CHAT_SOPS_FILE` at runtime; tokens stay out of argv and the database. `SOCRATES_CHAT_ADMIN_ROOM` overrides the admin alias, and `SOCRATES_CHAT_PROXY_PANE` enables proxy output. Only events whose sender exactly matches Tom's configured id enter sessions: Claude uses a bracketed tmux paste; Codex uses `codex-lead send` for its recorded session. C0/C1 controls and bracketed-paste escapes are stripped; message line breaks become Unicode line separators. Dialogs and absent sessions queue messages in order; an absent session wakes its live parent, or posts the wake in Plato's room. Other rooms also copy a `Tom → NODE` notice into Plato's room. `SOCRATES_CHAT_PROXY_PANE=socket:session` enables proxy delivery. `latency --last N [--json]` reports transcript-received minus sent and reply-posted minus turn end. `probe` sends as Tom through a temporary password login using `matrix-tom-password` in the existing encrypted Matrix file and logs out afterward. Posts default to silent `m.notice`; Plato remains `m.text`, and a line beginning `Needs Tom:` sends a text mention of Tom (attachments remain files). Exactly one relay sets `SOCRATES_CHAT_WATCHES=1` to persist timeline ETAs and watches: Tom writes `watch <repo>#<n>|this|<node>|<box> [done] [if over <n>m|<n>min|<n>h|<n>d]` or `unwatch <target>` in any managed room (case-insensitive). Watch commands stay out of panes, receive a silent acknowledgement, and ping once each for done, blocked and overdue; done ends the watch. The deadline is the explicit duration from the command time, else the latest target ETA, else none. Issue watches poll `tompassarelli/<repo>` at most once per minute; node and box watches use posts from the synced timeline.
- Farm-only commands: `heavy-command-guard` reads `.agents/farm-only.toml` at each command's Git root. Each `[[command]]` declares leading `pattern` words (mode flags match in any order after the verb), `narrowing` flags that permit local work, and a `farm` command with `why`. Whole-roster matches are refused even inside `machine-capacity run`; missing or malformed declarations leave existing capacity checks in place. Claude Bash and Codex exec payloads share this identity.
- Work items: `north work list`, `north work search TEXT`, and `north work show REPO#N`; in the app, `/work` opens the list and Enter opens the selected item. Type in the list to filter open issues, or use `/work search TEXT` to include closed issues. Escape returns to the composer.
- Work edits: `north work claim REPO#N [--by NAME] [--eta MINUTES]`, `release REPO#N [--to NAME]`, `need REPO#N BLOCKER#N`, `unneed REPO#N BLOCKER#N`, and `close REPO#N --comment RESULT`. In the app use `/work` followed by the same arguments. Changes are recorded on the GitHub issue.
- GitHub as the Socrates Agent app: `gh-app-token` prints a cached installation token (decrypted from south's `secrets/github-app.yaml`), and `gh-as-app ARGS` runs `gh` with it.

GitHub holds titles, bodies, checklist, state and blockers. `threads` holds current holders, elapsed time and ETA, handoffs and worker runs. North reads both and writes through their commands.

- Resuming archived work: `threads show REPO#N` reads origin's `archive/*` tags in `~/code/<repo>/main` (or the current lane) and lists tags whose commit messages say `Refs REPO#N`, with `git push origin archive/<branch>:refs/heads/<branch>` to restore each. The SessionStart unlanded-work hook lists the same archives when the session's registered org brief has an `Item:` ref.
- Worker estimates: `worker-ledger --recommend 'FACETS'` adds the recommended tier’s nearest-rank p75 actual duration and sample cell, backing off Surface, Verify, Scope, then Spec until three samples are available (or Category alone); no samples prints `eta n/a (n=0)`.
- Live holders: `threads unowned` keeps an expired claim held when its exact owner matches an active org node or session; a registered launcher PID must still be alive. A proxying client relays proven local owner identifiers to the remote ledger; PIDs are checked only on their own host. Finished or dead holders still expire after twice their ETA.

Follow the [testing skill](../socrates/skills/testing/SKILL.md) for retention and evidence. Check a changed Rust feature with `depbox run -- nix develop -c cargo check --locked --offline` and its affected tests with `depbox run -- nix develop -c cargo test --locked --offline --bin north FILTER`. Build the app with `depbox run -- nix develop -c cargo build --locked --offline`, then run `target/debug/north`.

- Public watch: `model-watch [--interests PATH] [--feedback PATH] [--topic normal]` snapshots model/release sources, Hacker News and game-development feeds. Only new candidates invoke one plan-billed Claude ranking with fast mode disabled; up to 8 kept items are sent through nexus-alert. Use `--topic socrates-test` for checks. Model events and proposed catalog rows remain in the existing stores.
- Scheduled job runs: `job-run [--path DIRS] [--user USER] NAME -- CMD...` wraps a timer's command, records its start and finish (name, host, started, finished, rc) through `threads job-run` (spooled while the remote ledger is unreachable) and exits with the command's code; `threads job-runs` shows runs, failures and the last rc per name and host. Firn's `jobRun` helper wraps every registry timer.
- Overdue jobs: `job-watch run` (nexus, every 15 min) reads registry routines with a `placement` and `deadline`, `threads job-runs --json` and WireGuard presence from `/run/nexus/peers.json`, and pushes one urgent alert per job when it becomes overdue (a laptop job also when the laptop has been online period + 30 min with no success), repeats at most daily and sends a normal note on recovery; `JOB_WATCH_TOPIC` overrides the topic. `job-watch self-test [--post]` runs the scenario fixtures, posting to socrates-test.
- Queued laptop jobs: `threads queue add PLACEMENT REF|- -- CMD...` queues work for a machine that may be asleep; `threads queue take PLACEMENT` claims the oldest job atomically and prints it as JSON; `threads queue msg ID done|failed TEXT` records the result and comments it on the job's issue (a note on a native item); `threads queue` lists jobs with their `queue-ID` job run. `laptop-runner` (laptop timer each minute and on wake) takes jobs for `$LAPTOP_RUNNER_PLACEMENT` (default `laptop`; nexus runs it as `nexus`) one at a time under flock and runs each through `job-run queue-ID`, keeping its full output at `~/.local/state/laptop-runner/queue-ID.log` on the host that ran it (the ledger result names host and path, plus the last 3000 characters). `galileo-full-suite SHA` runs Galileo's full suite at SHA in a fixed worktree under a heavy machine-capacity lease (all 4 nexus CPUs), keeping its target directory in `~/.cache/galileo-full-suite` between runs, building once and running the test binaries four at a time slowest first, and prints wall time and result; queue it with `threads queue add nexus - -- galileo-full-suite SHA`. `galileo-land-check [--base REF] [REV]` runs, in one persistent worktree `~/code/galileo/worktrees/land-check` checked out at REV under a lock so its target stays incremental across lanes, under a heavy machine-capacity lease, only the tests the change from BASE (default the merge-base with origin/main) touched: changed crate sources select the crate and its workspace reverse dependents, test files their test targets, `SPEC.md` galileo-cli's help_syntax, and files read by path the crates naming them; anything unmapped runs the workspace, docs-only changes exit at once, and it prints passed/failed, binaries and build, test and wall seconds. `galileo-mutants list|run [--rev REV] [--per-function] [--shard K/N] [--sample N] [--limit N] [--timeout-multiplier M] OUT.jsonl` runs Galileo's mutation campaign: cargo-mutants lists mutants over galileo-core, galileo-syntax and galileo-cli, and each mutant of shard K of N is applied in the fixed scratch worktree `~/code/galileo/worktrees/mutants-run` (added lines marked `MUTANT:<id>`, target kept so rebuilds are incremental) and tested with `cargo test --workspace --no-fail-fast` under heavy leases of under an hour each, appending a kill-matrix row (id, file:line, function, diff, killed/survived/unviable/timeout, where a run past M (default 2) times the host baseline is timeout and names no test, failing tests beyond the baseline's, seconds, host) to OUT and resuming from rows already there. `--per-function` keeps one mutant per function (file, name and span) in list order, sharding and sampling by function; `list --per-function` prints those and their count, and `run` tries the function's next mutant, up to 3, while the chosen one is unviable or unapplied.
- Test health: `test-health [--now ISO] [--out FILE] [--html FILE] [--no-fetch]` writes one JSON row per active repo (latest main CI wall per landing gate against its budget, five-kind census share from the T5 TSVs, `test-lean-galileo.md` and wisp#120, unique-kill share, a 30-day test-file and CI-wall trend, and spot-check verdicts from `handoffs/test-health-spotcheck/<repo>.json`) and renders it as a self-contained HTML page; every number links to its run, commit or file, and a fixed `--now` gives identical output. Completed run jobs are cached in `~/.cache/test-health`.
- Native items: `threads new life|accounts|travel|ops TITLE [--due D] [--body -]` captures an item that lives only in threads.db (`life#1`), with `threads note`, `close` and `reopen`; `need`/`unneed` involving a native item are recorded locally, and `ready`, `show`, `list` and claims treat native items like GitHub issues without calling gh. Native items never reach GitHub: threads' gh calls, `safe-push` (commit messages, branch and tag names) and the `native-item-guard` hook (gh writes naming a native ref or quoting 12+ characters of an item's text) refuse them; `new` and `note` refuse text `gitleaks stdin` flags. Under `THREADS_NO_NATIVE` (exported by `agy`) or `CLAUDE_CODE_REMOTE` (cloud workers), threads hides native items and refuses to show them or the snapshot.
- Dependency sandbox: `depbox fetch|run -- CMD...` runs installs, builds and tests in bwrap with the home directory masked except the git toplevel (rw), its common dir and ~/.gitconfig (ro), the bun, cargo and nix caches (rw) ~/.rustup, the firn CLI runtime and the immutable firn and north pins (ro); /run/user, /run/secrets.d and /tmp are empty, the environment keeps only PATH, HOME, USER, LANG, TERM, NIX_PATH and the SSL cert variables, no_new_privs blocks sudo, and `run` has no network.
- Supply alert: `supply-alert normal|urgent TEXT [TITLE]` posts one phone alert through `ssh nexus nexus-alert`, so the ntfy publisher token stays on nexus.
- Supply scan: `supply-chain-scan` (daily user timer `supply-chain-scan.timer`) runs osv-scanner on origin/main lockfiles of smashcraft, wisp, north, nixos-config and galileo, alerts through `supply-alert` on new malware (urgent) or new fixable advisories (normal), and records seen IDs in `~/.local/state/supply-chain/seen.json`.
- Digest feedback: `agents news [--days 7]` shows the last delivered kept items. `agents news --noise ID` or `--more ID` appends private feedback under south; `--feedback PATH` overrides the log. The next ranking includes that log and a deterministic source/title adjustment. Interests default to the private `~/code/south/main/config/interests.md`, with `--interests PATH` as the override.
- Watch scenario: `python3 socrates/scripts/watch-digest-scenario.py` replays public fixture inputs against an isolated ledger and the `socrates-test` topic; it never posts to production topics.
- Runtime promotion: `north-runtime-update` (run by `agent-runtime-update`'s 02:00 pass) fetches north main and, when `~/.local/state/north/current` is behind origin/main, builds it in a detached `worktrees/runtime-<short>` under a heavy capacity lease, installs `runtimes/<sha>/north`, swaps `current` atomically, runs `agents sync` and swaps back if that fails; it keeps the previous runtime plus the 3 newest others and holds `runtime-update.lock`.

- `agents plan --json` exposes resolved bands, usable providers, escalation tiers and account states; `--at FILE` exposes the recorded routing decisions.
- `safe-push --to main` reads committed `.safe-push` `land.check` entries (`pathspec[,pathspec] :: command`), runs affected checks, and records time, commands and result in `~/.local/state/agents/land-checks.tsv`; Main is red confirms a failed job once and reverts a culprit after a green parent.
- `mutant record <id>` saves the scratch copy's non-empty diff against HEAD to `~/.local/state/agents/mutants/<repo>/<id>.patch`; `safe-push` checks each new `Test-kind: <name> <kind> kills <id>` claim against its landing base or head.

- Recorded Chrome sessions: `chrome-tabs run -- claude --chrome [args]` serves Chrome MCP calls through a recording proxy that writes the initial group tab and `tabs_create_mcp` receipts under `~/.local/state/agents/chrome-tabs/`, and a per-session systemd user reaper, outside the session's scope so SIGKILL cannot take it down, closes only those recorded tabs once the session ends. `spawn-quiet` and `usage-web-read` use this launcher. Browser batches are unavailable because tab creation must be recorded before returning its result. Tabs opened by page popups have no creation receipt and remain unrecorded. A changed native host leaves the record for inspection rather than risking reused tab IDs.
