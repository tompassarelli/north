# North features

- Stale lane proposals: `lane-shepherd propose [--repo NAME]...` records Haiku verdicts with Git evidence; `lane-shepherd apply FILE [--only ROW...]` archives approved fold/archive rows locally before retirement and prints lead landing commands for land rows. `lane-shepherd apply --safe [--repo NAME]... [--exclude FILE]` needs no approval or Haiku: it archives to `refs/archive/lanes/<slug>`, verifies, then retires clean merged lanes idle 3h and unlocked, unused lanes idle 24h, skips `*-land` and excluded lanes, and writes the rest (land commands, conflicts, kept) to a proposals TSV.
- Headless leads: `agents attach NAME` opens a tmux pane; closing the terminal detaches. `agents lead restart NAME` resumes its saved transcript. `AGENTS_SESSION_HOST=tmux|ghostty` overrides `[sessions] host` in orchestration.toml; the default uses ghostty on a Wayland desktop and tmux elsewhere.
- Interactive coding workspace: `north`, or `north --resume ID`.
- Capacity estimates: `machine-capacity estimate [--json] [--class CLASS] [--owner OWNER] -- CMD ARG...` uses the current directory and the last 20 matching measured runs, with exact signature, full owner/shape, owner prefix/shape/class, family/repo, family, and declared-class fallbacks. An expensive target absent from exact family/repo/package history stays heavy (native for native clients) with low confidence, even when other targets have family history; known targets and cheap families retain nearest matching. Imported rows without exact targets cannot establish that a target is known. Owner levels require an explicit owner; the prefix is its leading ASCII letters. It prints p50/p90 cores, peak memory, I/O bytes, disk busy share, sample count, match level, and confidence. Disk busy share is the maximum physical whole-disk `/proc/diskstats` I/O-millisecond delta divided by run wall milliseconds (host-wide; partitions and virtual devices excluded). Stored cgroup I/O pressure is reference data only. Runs without a class reserve rounded-up p90 cores and p90 memory plus 20%; running batch CPU accounting uses the greater of measured two-minute use and estimate p50, plus 25%. Native CPU accounting uses live measured use; missing or stale measurements use the estimate (or the reservation for older leases). Status and probe publish the same committed CPU totals for the spawn gate.
- Rest check: `capacity-watchdog rest-check [--seconds N] [--expected FILE] [--observed FILE] [--save FILE]` compares running system and user services and scopes, active timers and listening sockets (`PROTO ADDR:PORT UNIT`, `-` for a gone creator such as kernel WireGuard) with the host's expected-at-rest set (`~/.config/capacity-watchdog/rest.json`, declared in firn as `myConfig.modules.capacity-watchdog.rest`), measures each unit's CPU and context switches over N s (default 30), prints extra units, sockets and over-budget units, lists claude/codex/tmux sessions as agents, and exits 1 when anything is not at rest.
- Skills and hooks: `north config agents help`.
- Landing flow: `agents flow [--json] [--repo NAME]... [--stall-alert]` caches pending landings, landing rate, push-to-land latency, main idle time, oldest landing job and runner, the stall verdict, goal throughput (issues closed per hour over 3 h against open issues per hour left to the goal deadline, median landing-commit-to-close minutes over 24 h preferring the sha in Autoland's auto-close comment, main landings per `claude/land-*` push over 3 h, failed lanes whose issue has no `threads` claim for 15 minutes, oldest pending lane wait), and three capacity guards (account Actions jobs busy, idle Wisp pairs while `needs:native-*` issues wait, Autoland census reuse over the last 20 landings) for five minutes; `--stall-alert` notifies the repository lead and Plato, writes the lead inbox, and mentions Tom after 60 minutes until main moves and jobs recover; Claude and Codex refuse new code workers above one hour of landings (floor 2), except landing-path or `CASE=URGENT` briefs.
- Usage resets: `agents usage` keeps each account's used percentages and reset times and appends reset availability and its source. `usage-web-read` runs the approved read-only Claude Chrome prompt from `~/.local/state/agents/handoffs/usage-web-read-prompt.txt`, caches per-kind counts and expiry by hashed account in `~/.local/state/agents/usage/claude-web.json`, and preserves other accounts and the previous cache on failure.
- Agent names in status bars: `agent-statusline` is Claude Code's statusLine command. It prints the org name in bold (AGENT_ORG_NAME, `← parent` below a lead; Plato for Tom's top-level session), then role, domain and model. `codex-lead start` names the Codex thread after the org node and shows the thread title first in the TUI status line, leaving the window title to spawn-quiet.
- Matrix agent rooms: `socrates-chat run` reconciles this machine's org rooms under the Socrates Space and drains `~/.local/state/socrates-chat/outbox`; it wakes on org, outbox, status-file and pending-transcript changes, watched session exits (util-linux `waitpid`) and synced space state, re-reads space layout only when a room opens or closes or space state changes, and otherwise ticks every 5 minutes (1 minute with open watches, 2 s with queued inbound messages); workers post into their parent's room. Socrates orders Plato, alerts, then the Smashcraft, Galileo, Wisp, Nexus, North, Tooling and Mail sub-spaces. Leads and sub-leads go into their org domain's sub-space; other domains stay directly in Socrates. Spaces and rooms resolve by alias before creation, and an unchanged hierarchy sends no state updates. `post --as NODE [--kind reply|result|notice] [--tag TAG] TEXT|-` writes the v1 spool without network access; `rooms [--json]` includes each room's parent space alias. `avatar ROOM FILE` uploads an image as Socrates and sets the room or space avatar; ROOM is an alias or room id. `log NODE --last N`, `latency --last N`, `probe NODE TEXT` and `replay [FILE]` inspect or exercise the bridge. Text over 4,000 characters or 40 lines becomes a file with three summary lines. Network commands use `SOCRATES_CHAT_HOMESERVER`, `SOCRATES_CHAT_TOM_USER_ID` and `SOCRATES_CHAT_TOKEN_FILE`, or decrypt `matrix-appservice-as-token` from `SOCRATES_CHAT_SOPS_FILE` at runtime; tokens stay out of argv and the database. `SOCRATES_CHAT_ADMIN_ROOM` overrides the admin alias, and `SOCRATES_CHAT_PROXY_PANE` enables proxy output. Only events whose sender exactly matches Tom's configured id enter sessions: Claude uses a bracketed tmux paste; Codex uses `codex-lead send` for its recorded session. C0/C1 controls and bracketed-paste escapes are stripped; message line breaks become Unicode line separators. Dialogs and absent sessions queue messages in order; an absent session wakes its live parent, or posts the wake in Plato's room. Other rooms also copy a `Tom → NODE` notice into Plato's room. `SOCRATES_CHAT_PROXY_PANE=socket:session` enables proxy delivery. `latency --last N [--json]` reports transcript-received minus sent and reply-posted minus turn end. `probe` sends as Tom through a temporary password login using `matrix-tom-password` in the existing encrypted Matrix file and logs out afterward. Posts default to silent `m.notice`; Plato remains `m.text`, and long posts remain files. Exactly one relay sets `SOCRATES_CHAT_WATCHES=1` to persist timeline ETAs and watches: Tom writes `watch <repo>#<n>|this|<node>|<box> [done] [if over <n>m|<n>min|<n>h|<n>d]` or `unwatch <target>` in any managed room (case-insensitive). Watch commands stay out of panes, receive a silent acknowledgement, and ping once each for done, blocked and overdue; done ends the watch. The deadline is the explicit duration from the command time, else the latest target ETA, else none. Issue watches poll `tompassarelli/<repo>` at most once per minute; node and box watches use posts from the synced timeline.
- Farm-only commands: `heavy-command-guard` reads `.agents/farm-only.toml` at each command's Git root. Each `[[command]]` declares leading `pattern` words (mode flags match in any order after the verb), `narrowing` flags that permit local work, and a `farm` command with `why`. Whole-roster matches are refused even inside `machine-capacity run`; missing or malformed declarations leave existing capacity checks in place. Claude Bash and Codex exec payloads share this identity.
- Work items: `north work list`, `north work search TEXT`, and `north work show REPO#N`; in the app, `/work` opens the list and Enter opens the selected item. Type in the list to filter open issues, or use `/work search TEXT` to include closed issues. Escape returns to the composer.
- Work edits: `north work claim REPO#N [--by NAME] [--eta MINUTES]`, `release REPO#N [--to NAME]`, `need REPO#N BLOCKER#N`, `unneed REPO#N BLOCKER#N`, and `close REPO#N --comment RESULT`. In the app use `/work` followed by the same arguments. Changes are recorded on the GitHub issue.
- GitHub as the Socrates Agent app: `gh-app-token` prints a cached installation token (decrypted from south's `secrets/github-app.yaml`), and `gh-as-app ARGS` runs `gh` with it.

GitHub holds titles, bodies, checklist, state and blockers. `threads` holds current holders, elapsed time and ETA, handoffs and worker runs. North reads both and writes through their commands.

- Resuming archived work: `threads show REPO#N` reads origin's `archive/*` tags in `~/code/<repo>/main` (or the current lane) and lists tags whose commit messages say `Refs REPO#N`, with `git push origin archive/<branch>:refs/heads/<branch>` to restore each. The SessionStart unlanded-work hook lists the same archives when the session's registered org brief has an `Item:` ref.
- Worker delivery costs: `worker-ledger --summary` includes median brief-to-landed minutes, dollars per done box and observed completed-worker concurrency by model/effort/fast and project. `threads` stores account, model, effort, fast and included-plan dollars; weekly readout deltas allocate dollars to token samples from active runs (input 1, cache write 1.25, cache read Opus 0.05/others 0.1, output 5). Missing measured intervals print unknown costs. `--backfill --since 2026-10-11` rereads prior runs; remote ledger reads use its snapshot, never a frozen local database. `threads ingest` accepts `type=usage` readout rows and refreshes the mirror after publishing them, using the existing remote spool during outages.
- Worker estimates: `worker-ledger --recommend 'FACETS'` adds the recommended tier’s nearest-rank p75 actual duration and sample cell, backing off Surface, Verify, Scope, then Spec until three samples are available (or Category alone); no samples prints `eta n/a (n=0)`.
- Split outcome: a worker report starting `Split:` is recorded as `split`, counts in no tier rate, lends its `Arm:` to its parts (runs whose `Follows:` names it), and `worker-ledger --summary` adds a per-category table of splits, parts, parts closure, summed part minutes and minutes from the split to the last part.
- Live holders: `threads unowned` keeps an expired claim held when its exact owner matches an active org node or session; a registered launcher PID must still be alive. A proxying client relays proven local owner identifiers to the remote ledger; PIDs are checked only on their own host. Finished or dead holders still expire after twice their ETA.

Follow the [testing skill](../socrates/skills/testing/SKILL.md) for retention and evidence. Check a changed Rust feature with `depbox run -- nix develop -c cargo check --locked --offline` and its affected tests with `depbox run -- nix develop -c cargo test --locked --offline --bin north FILTER`. Build the app with `depbox run -- nix develop -c cargo build --locked --offline`, then run `target/debug/north`.

- Public watch: `model-watch [--interests PATH] [--feedback PATH] [--topic normal]` snapshots model/release sources, Hacker News and game-development feeds. Only new candidates invoke one plan-billed Claude ranking with fast mode disabled; up to 8 kept items are sent through nexus-alert. Use `--topic socrates-test` for checks. Model events and proposed catalog rows remain in the existing stores.
- Cross-project scan: `cross-project-scan [--print-bundle]` (laptop timer, daily 07:30) bundles open issues, open `threads list` rows, 24 h first-parent landings and `agents org show` for smashcraft, wisp, galileo, north and firn, asks Claude Opus medium (Codex medium without claude) for at most 3 overlap findings with projects, evidence and acting lead, writes `~/.local/state/agents/handoffs/cross-project-scan.md` and posts it to Plato's room (falling back to `proxy-inbox.md`); it files nothing.
- CI diagnosis: `ci-diagnose [--dry-run OWNER/REPO RUN_ID]` runs after `agents flow --stall-alert` (laptop, every five minutes); for each open "main is red" issue in north, firn and smashcraft it takes the newest still-failing main run, has Claude Haiku extract the failing step, first error lines and culprit `path:line` from `gh run view --log-failed` (refusing JSON whose step or errors are not in the log), has Claude Opus medium judge the cause and smallest fix from that plus the compare diff stat, and posts one comment marked `<!-- ci-diagnose:RUN -->`; it never changes code, reverts or closes anything.
- Goal: `agents goal set --deadline ISO --projects A,B TEXT` writes `~/.local/state/agents/goal.json`, which `agents flow` reads for needed closures per hour; `agents goal clear` removes it.
- Tick precheck: `agents tick-precheck --session ID --status FILE` runs a lead tick's commands (`threads unowned`, `worker-sweep`, `capacity-watchdog report`, and `agents flow` plus `worker-ledger --summary` every third tick) in parallel within 2 minutes, reduces them to flag keys with volatile numbers normalised out and diffs them against `~/.local/state/agents/tick-precheck/<session>.json`; with nothing new it prints and appends `quiet tick=<n>: <counts>` to FILE and exits 0, otherwise prints only the new rows with their source and exits 10; raw outputs go to `<session>-last.txt` for audit. A session sees only the capacity and flow flags its lead owns: a lease flag carries `org=<node>` from `capacity-watchdog`'s process-tree attribution of the lease holder, a flow row belongs to the lead whose domain or `repos` include the repo (goal flags: closures below the needed rate, land-to-close over 30 minutes, land ratio below 1.0, any failed unowned lane), an untranscribed or unnamed lead row goes to that lead and the proxy, and flags no lead owns go to the proxy (any session not in `agents org`).
- Tick tokens: `tick-tokens [--hours 24] TRANSCRIPT...` prints Opus tokens, output tokens and model calls per `[routine:tick]` turn in Claude transcripts, deduplicated by message id.
- Issue box lint: `issue-box-lint [REPO#N...] [--repo REPO]` prints each unchecked Done when box that hands Tom a mechanical check (input, sizes, frames, sounds, menus, launches), which agents verify on VM pairs and native capture instead; it exits 1 when any box is flagged.
- Policy regression gate: `agents sync` measures the candidate policy's startup tokens (chars/4 of global and code-root policy, the largest registered project AGENTS.md, the Claude skill and agent listings and the largest SessionStart role output; the harness-bundled listing is not counted) and the sha256 of `south:agents/AGENTS.md`, and compares them with `south:agents/operating-point.toml` and the newest `~/.local/state/agents/replay/sweep-*.jsonl` row for that sha256. It refuses to publish when a sweep row shows conformance below the operating point by more than one binomial standard error, or when startup tokens grew without a sweep row above it by more than one standard error; otherwise it prints `session start N tokens (operating point M at DATE, conformance C)`, the token breakdown, SKILL body lines and Codex listing characters, and `sweep due` when tokens differ from the operating point by more than 15%. With no operating point it prints `no operating point yet` and passes. It never runs replays; `policy-replay.py --sweep` does, weekly from the Monday tick and on each new model release `model-watch` reports. The `agent-config-check` rules group also fails a `rules.toml` entry added since the landed `origin/main` copy unless it cites at least 2 ids in `incidents.jsonl`.
- Skill prune: `skill-prune [--measure]` (laptop timer, Sundays 09:00) runs one Claude Opus medium session that prunes the shared SKILL.md bodies to the 60-line playbook cap and shrinks duplicated or stale rules, logs each moved or removed line in `skill-prune-moves.md`, folds `codex-lessons.md` into the skills and `codex-lessons-folded.md`, lands each repository through `safe-push` and runs `agents sync`; it writes the before and after body and lesson counts to `~/.local/state/agents/handoffs/skill-prune.md`. `--measure` prints each shared skill's body lines, marks domain skills and reports the total beside the operating point in `south:agents/operating-point.toml`, with no cap.
- Scheduled job runs: `job-run [--path DIRS] [--user USER] NAME -- CMD...` wraps a timer's command, records its start and finish (name, host, started, finished, rc) through `threads job-run` (spooled while the remote ledger is unreachable) and exits with the command's code; `threads job-runs` shows runs, failures and the last rc per name and host. Firn's `jobRun` helper wraps every registry timer.
- Overdue jobs: `job-watch run` (nexus, every 15 min) reads registry routines with a `placement` and `deadline`, `threads job-runs --json` and WireGuard presence from `/run/nexus/peers.json`, and pushes one urgent alert per job when it becomes overdue (a laptop job also when the laptop has been online period + 30 min with no success), repeats at most daily and sends a normal note on recovery; `JOB_WATCH_TOPIC` overrides the topic. `job-watch self-test [--post]` runs the scenario fixtures, posting to socrates-test.
- Queued laptop jobs: `threads queue add PLACEMENT REF|- -- CMD...` queues work for a machine that may be asleep; `threads queue take PLACEMENT` claims the oldest job atomically and prints it as JSON; `threads queue msg ID done|failed TEXT` records the result and comments it on the job's issue (a note on a native item); `threads queue` lists jobs with their `queue-ID` job run. `laptop-runner` (laptop timer each minute and on wake) takes jobs for `$LAPTOP_RUNNER_PLACEMENT` (default `laptop`; nexus runs it as `nexus`) one at a time under flock and runs each through `job-run queue-ID`, keeping its full output at `~/.local/state/laptop-runner/queue-ID.log` on the host that ran it (the ledger result names host and path, plus the last 3000 characters). `galileo-full-suite SHA` runs Galileo's full suite at SHA in a fixed worktree under a heavy machine-capacity lease (all 4 nexus CPUs), keeping its target directory in `~/.cache/galileo-full-suite` between runs, building once and running the test binaries four at a time slowest first, and prints wall time and result; `--only NAME,...` runs just those test binaries without the doc tests and `--skip NAME,...` the rest, so the suite splits into two nexus jobs: `threads queue add nexus - -- galileo-full-suite SHA --skip differential_1` and `... --only differential_1`. `galileo-land-check [--base REF] [REV]` runs, in one persistent worktree `~/code/galileo/worktrees/land-check` checked out at REV under a lock so its target stays incremental across lanes, under a heavy machine-capacity lease, only the tests the change from BASE (default the merge-base with origin/main) touched: changed crate sources select the crate and its workspace reverse dependents, test files their test targets, `SPEC.md` galileo-cli's help_syntax, and files read by path the crates naming them; anything unmapped runs the workspace, docs-only changes exit at once, and it prints passed/failed, binaries and build, test and wall seconds. `galileo-mutants list|run [--rev REV] [--per-function] [--shard K/N] [--sample N] [--limit N] [--timeout-multiplier M] OUT.jsonl` runs Galileo's mutation campaign: cargo-mutants lists mutants over galileo-core, galileo-syntax and galileo-cli, and each mutant of shard K of N is applied in the fixed scratch worktree `~/code/galileo/worktrees/mutants-run` (added lines marked `MUTANT:<id>`, target kept so rebuilds are incremental) and tested with `cargo test --workspace --no-fail-fast` under heavy leases of under an hour each, appending a kill-matrix row (id, file:line, function, diff, killed/survived/unviable/timeout, where a run past M (default 2) times the host baseline is timeout and names no test, failing tests beyond the baseline's, seconds, host) to OUT and resuming from rows already there. `--per-function` keeps one mutant per function (file, name and span) in list order, sharding and sampling by function; `list --per-function` prints those and their count, and `run` tries the function's next mutant, up to 3, while the chosen one is unviable or unapplied.
- Test health: `test-health [--now ISO] [--out FILE] [--html FILE] [--no-fetch]` writes one JSON row per active repo (latest main CI wall per landing gate against its budget, five-kind census share from the T5 TSVs, `test-lean-galileo.md` and wisp#120, unique-kill share, a 30-day test-file and CI-wall trend, and spot-check verdicts from `handoffs/test-health-spotcheck/<repo>.json`) and renders it as a self-contained HTML page; every number links to its run, commit or file, and a fixed `--now` gives identical output. Completed run jobs are cached in `~/.cache/test-health`.
- Native items: `threads new life|accounts|travel|ops TITLE [--due D] [--body -]` captures an item that lives only in threads.db (`life#1`), with `threads note`, `close` and `reopen`; `need`/`unneed` involving a native item are recorded locally, and `ready`, `show`, `list` and claims treat native items like GitHub issues without calling gh. Native items never reach GitHub: threads' gh calls, `safe-push` (commit messages, branch and tag names) and the `native-item-guard` hook (gh writes naming a native ref or quoting 12+ characters of an item's text) refuse them; `new` and `note` refuse text `gitleaks stdin` flags. Under `THREADS_NO_NATIVE` (exported by `agy`) or `CLAUDE_CODE_REMOTE` (cloud workers), threads hides native items and refuses to show them or the snapshot.
- Dependency sandbox: `depbox fetch|run -- CMD...` runs installs, builds and tests in bwrap with the home directory masked except the git toplevel (rw), its common dir and ~/.gitconfig (ro), the bun, cargo and nix caches (rw) ~/.rustup, the firn CLI runtime and the immutable firn and north pins (ro); /run/user, /run/secrets.d and /tmp are empty, the environment keeps only PATH, HOME, USER, LANG, TERM, NIX_PATH and the SSL cert variables, no_new_privs blocks sudo, and `run` has no network.
- Supply alert: `supply-alert normal|urgent TEXT [TITLE]` posts one phone alert through `ssh nexus nexus-alert`, so the ntfy publisher token stays on nexus.
- Supply scan: `supply-chain-scan` (daily user timer `supply-chain-scan.timer`) runs osv-scanner on origin/main lockfiles of smashcraft, wisp, north, nixos-config and galileo, alerts through `supply-alert` on new malware (urgent) or new fixable advisories (normal), and records seen IDs in `~/.local/state/supply-chain/seen.json`.
- Digest feedback: `agents news [--days 7]` shows the last delivered kept items. `agents news --noise ID` or `--more ID` appends private feedback under south; `--feedback PATH` overrides the log. The next ranking includes that log and a deterministic source/title adjustment. Interests default to the private `~/code/south/main/config/interests.md`, with `--interests PATH` as the override.
- Watch scenario: `python3 socrates/scripts/watch-digest-scenario.py` replays public fixture inputs against an isolated ledger and the `socrates-test` topic; it never posts to production topics.
- Policy replay: `python3 socrates/scripts/policy-replay.py SCENARIO.json... --arm ARM... [--trials N] [--jobs N] [--policy AGENTS.md] --out RESULTS.jsonl` runs scenarios from `south:agents/replay/` × arms × trials, at most 4 in parallel, through `claude -p` with each policy arm (`full`, `minus:PREFIX,...`, `minus-file:PATH` with one rule prefix per line, or a scenario arm name) appended in place of the live `~/.claude/CLAUDE.md` (`--setting-sources project`, empty cwd). It scores each run with the scenario's regex or tool-call detector, appends one jsonl row per run (pass, turns, input/output/cache tokens, model, effort, wall seconds, and `cost_api_usd_comparison` as an API list-price comparison only) and prints pass rate per scenario × arm. `--sweep VARIANTS.toml [--variant NAME...] [--provisional]` instead runs every `[[variant]]` of `south:agents/replay/variants.toml` (built from the live AGENTS.md by `minus`, `minus_file`, `plus` text files and `placement` moves to a skill or hook) over the scenarios × trials, appends per-run rows to `sweep-<UTC date>-runs.jsonl` and one row per variant to `~/.local/state/agents/replay/sweep-<UTC date>.jsonl` (policy sha256, startup tokens on the `agents sync` session-start chars/4 basis, conformance, n, tokens per run, `usd_or_null`, wall seconds, model, effort), and writes `south:agents/operating-point.toml`: the fewest startup tokens among variants within one binomial standard error of the best conformance. Re-run it on a model release, a big policy change or weekly.
- Runtime promotion: `north-runtime-update` (run by `agent-runtime-update`'s 02:00 pass) fetches north main and, when `~/.local/state/north/current` is behind origin/main, builds it in a detached `worktrees/runtime-<short>` under a heavy capacity lease, installs `runtimes/<sha>/north`, swaps `current` atomically, runs `agents sync` and swaps back if that fails; it keeps the previous runtime plus the 3 newest others and holds `runtime-update.lock`.

- `agents plan --json` exposes resolved bands, usable providers, escalation tiers and account states; `--at FILE` exposes the recorded routing decisions.
- `safe-push --to main` reads committed `.safe-push` `land.check` entries (`pathspec[,pathspec] :: command`), runs affected checks, and records time, commands and result in `~/.local/state/agents/land-checks.tsv`; Main is red confirms a failed job once and reverts a culprit after a green parent.
- `mutant record <id>` saves the scratch copy's non-empty diff against HEAD to `~/.local/state/agents/mutants/<repo>/<id>.patch`; `safe-push` checks each new `Test-kind: <name> <kind> kills <id>` claim against its landing base or head.

- Recorded Chrome sessions: `chrome-tabs run -- claude --chrome [args]` serves Chrome MCP calls through a recording proxy that writes the initial group tab and `tabs_create_mcp` receipts under `~/.local/state/agents/chrome-tabs/`, and a per-session systemd user reaper, outside the session's scope so SIGKILL cannot take it down, closes only those recorded tabs once the session ends. `spawn-quiet` and `usage-web-read` use this launcher. Browser batches are unavailable because tab creation must be recorded before returning its result. Tabs opened by page popups have no creation receipt and remain unrecorded. A changed native host leaves the record for inspection rather than risking reused tab IDs.
- Effect kit: `effect-kit init|check|sync|upgrade|scan [ROOT]` (in `agent-machinery/scripts/effect-kit.mjs`) keeps one setup in every TypeScript project that depends on `effect`, configured by its `effect-kit.json`. `check` fails on drift between the vendored `repos/effect.json` version and the lockfile's `effect`, any Effect language-service diagnostic (all count at error severity), a plugin that ignores them in the exit code, or a raw spawn, timer, promise or fetch outside Effect in host tools, and prints the counts. `init` vendors upstream at the installed version and sets the plugin, `sync` moves the vendored copy, `upgrade` bumps Effect packages to the newest stable release at least 7 days old, and `scan` lists `ROOT/*/main` projects (default `~/code`) that depend on `effect` without `effect-kit.json`.
