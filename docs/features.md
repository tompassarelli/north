# North features

What each harness command and app feature does, grouped by job. The commands live in [bin/](../bin/);
[harness.md](harness.md) shows how they fit together. Each command's `--help`, its code and
[harness/defaults.toml](../harness/defaults.toml) are authoritative for flags, defaults and thresholds;
a number quoted below describes the behaviour when it was written.

CPU offload: [`north capacity nexus`](nexus-run.md) sends an owned working tree over SSH, runs its command under Nexus capacity admission, and retrieves selected outputs. The private stock asset cache stays outside Git on Nexus.

## The `north` app

- Interactive fleet screen: `north` or `north fleet` opens the fleet list, transcript and digest.
- Work items: `north work list`, `north work search TEXT`, and `north work show REPO#N`. [more](features/01-the-north-app/0002-work-items.md)
- Where work state lives: GitHub holds titles, bodies, checklist, state and blockers. [more](features/01-the-north-app/0003-where-work-state-lives.md)
- Skills and hooks: `agents status`, `stale`, `inspect ID`, `path ID`, `on ID`, `off ID` and `sync` (each also `north config agents ...`) list, toggle and publish the catalog's skills and hooks; [harness.md](harness.md#install) describes what `agents sync` publishes.
- Verb help: `north VERB --help` or `-h`, at any depth such as `north capacity watchdog sample --help`, is answered by the dispatcher before any verb runs, from the usage the verb publishes (safe-push, fleet, cloud, capacity watchdog, land serve, lane gc) or else from the verb's lines in `north --help`, so a probe never samples, posts or launches; every verb in the CLI verb table has a `north --help` line, and a test asks each for `--help` and `-h` under a 5 s deadline. [more](features/01-the-north-app/0005-verb-help.md)

## Staffing and routing

 - Claude account profiles: `north fleet launch --provider claude --account LABEL --name NAME PROMPT` uses the account's local profile and records its label for restarts. [more](features/02-staffing-and-routing/0001-claude-account-profiles.md)
- Interactive Claude and Codex: `claude` and `codex` are the installed vendor runtimes (`~/.local/lib/{claude,codex}/current`) on their default homes; sessions on other accounts run through `north fleet launch --provider claude|codex --account LABEL`.
- Fleet accounts: each `~/.local/state/north/profiles/claude-LABEL` with credentials is one account unless it is logged in to the same account as another label (the sha256 prefix of the `oauthAccount.accountUuid` in its `.claude.json`, over the fleet profiles and this host's `[accounts.claude] profiles`); the label `[accounts.claude] labels` declares for that login keeps it, else the first label by name. [more](features/02-staffing-and-routing/0003-fleet-accounts.md)
- Account owner hosts: a label that `[accounts.claude] profiles` declares only for other hosts is foreign here (north#177): a copied `.credentials.json` shares one OAuth refresh token, so a refresh on either host revokes the other copy. [more](features/02-staffing-and-routing/0004-account-owner-hosts.md)
- Routing: `agents plan` prints one difficulty band table from scalar tier starts, with account usage and project priority, share and target. [more](features/02-staffing-and-routing/0005-routing.md)
- Spend rule (north#702, docs/rationale/spend-rule.md): only the pooled reserve, the cap on active worker sessions, the burn tripwire, the provider's own limit and a missing reading stop a new worker, and each refusal names its rule. [more](features/02-staffing-and-routing/0006-spend-rule.md)
- Resident cap: `north resident-cap gate claude|codex ARG...` refuses a new resident session on a host whose `[hosts.<hostname>] resident_cap = N` in orchestration.toml is reached, counting live claude/codex CLIs listed by `north fleet list --json` plus unregistered top-level interactive ones, and print `Hold: <host> has N/N resident agent CLIs; place this worker on laptop|cloud` (exit 3). [more](features/02-staffing-and-routing/0007-resident-cap.md)
- Token-only usage: a Claude account this host declares a `token_file` for and holds no login of, which has no `~/.claude.json` usage cache to read, is sampled by `north fleet pace sample` with one one-token Messages request on that token, whose `anthropic-ratelimit-unified-5h-*` and `7d-*` headers give its `session` and `weekly_all` windows. [more](features/02-staffing-and-routing/0008-token-only-usage.md)
- Usage resets: `agents usage` publishes fresh readouts through `threads ingest` to the authoritative ledger, with its existing offline spool. [more](features/02-staffing-and-routing/0009-usage-resets.md)
- Usage read: `agents usage` is served by `north fleet usage`: the latest reading of each account window from the threads ledger, as a per-account table of windows, billing, resets, burn, plan and cost, or with `--json` as JSON carrying a `stale` flag. [more](features/02-staffing-and-routing/0010-usage-read.md)
- Worker estimates: `north ledger worker --recommend 'FACETS'` chooses the cheapest tier meeting the 80% measured success threshold and adds the recommended tier’s eta from the sample cell, backing off Surface, Verify, Scope, then Spec until three samples are available (or Category alone): `eta active <median>m (p25 <a>–p90 <b>, n=<N>) wall p75 <W>m wait median <X>m` from the runs that recorded active minutes, or `eta wall <W>m (p75 of n=<N>, ...)` when too few did; no samples prints `eta n/a (n=0)`.
- Follows boxes: `threads queue follow REF --tier T --parent NAME` queues a brief from stdin, whose `Follows:` line names the predecessor commit subject, SHA or issue ref. [more](features/02-staffing-and-routing/0012-follows-boxes.md)
- Project quote: `agents plan --quote --project P --boxes N` reads the project target from `south:agents/orchestration.toml` and the worker ledger, prints the measured completion date and dollars, and asks one date-and-budget decision for dated projects; undated projects ask none. [more](features/02-staffing-and-routing/0013-project-quote.md)
- Fleet idle (north#252): a session host parks an idle session after its idle limit (`north fleet launch --idle-exit`), and a wake while the prompt cache is warm resumes on it. [more](features/02-staffing-and-routing/0014-fleet-idle-north-252.md)
- Context arms (north#636): `north fleet dispatch` stamps a placed local Claude box that carries no tier or effort arm with `Arm: context-200k`, `context-300k`, `context-400k` or `context-500k`, drawn in equal shares by the seeded hash of its item and launch count, as the first `Arm:` line after `Tier:`. [more](features/02-staffing-and-routing/0015-context-arms-north-636.md)
- Goal ETA: `agents plan` prints, per project target, the critical path over the goal's open boxes at the spawn gate's width with landing overhead, predicted finish against the target and n per box, and records it as a `goal_eta` calibration row ([goal ETA measurements](rationale/learned-routing-and-goal-eta.md#goal-eta)).
- `agents plan --score PROJECT` scores a passed project target from the open issue backlog, linked issue boxes and rolling seven-day run costs, prints on-date, in-budget and spec-pass, and appends one row to `~/.local/state/agents/goal-scores.jsonl`. [more](features/02-staffing-and-routing/0018-agents-plan-score-project-scores-a-passe.md)
- Effort arms (north#112): an Opus box on no tier arm, in a category whose `north ledger worker --recommend` cell holds 15 Opus runs, runs on `Arm: effort-medium` or `Arm: effort-high` in turn, launched with that `--effort`, and the dispatch record keeps the arm so the next box takes the other; while a box carries an effort arm it carries no context arm, since the ledger records only the first `Arm:` line. [more](features/02-staffing-and-routing/0020-effort-arms-north-112.md)
- Review items by kind (north#255): `north work review PLAN [--author TIER]` splits a design review into line items. [more](features/02-staffing-and-routing/0020-review-items-by-kind-north-255.md)
- Tier success as a prediction (north#255): `north ledger worker --recommend` lists no Codex tier outside codex-only mode. [more](features/02-staffing-and-routing/0021-tier-success-brier-north-255.md)

## Fleet sessions

- Fleet sessions: `north fleet launch` starts a session and first registers its row in the fleet store's `fleet_sessions` table on the ledger host, so one live session holds a name fleet-wide (`--take-over` replaces the row), and the launch refuses with the reason when the store refuses the name or does not answer. [more](features/03-fleet-sessions/0001-fleet-sessions.md)
- Fleet store: `north fleet row put` reads one fleet row or an array of them as JSON on stdin and commits them to the threads ledger in one transaction, once per row id, printing `committed ID` per row; where this machine does not hold the ledger it forwards the rows over the threads ssh remote and answers the remote exit code. [more](features/03-fleet-sessions/0002-fleet-store.md)
- Fleet spool: every `north fleet send`, parent notice and `ask` first writes a MESSAGE row to this host's fleet spool. [more](features/03-fleet-sessions/0003-fleet-spool.md)
- Fleet tick: `north fleet tick`, run on each fleet host by the `fleet-tick` timer, makes one `north fleet row exchange` with the ledger host.
- Tick stages: each stage that calls another host (placement, take_far, ledger.exchange, drop_far, cache_far, deliver_far, settle) has its own budget; one still running at it is named in a `deferred STAGE to the next tick` line and its rows wait for the next tick.
- Pulled-host probes: on a host marked `pulls_spool`, whose spool and registry the pulling host already exchanges, `north fleet tick` makes no exchange and runs only the probes that act on its own registry (waits, usage park, api credit move, spend breaker and tripwire, hand-over, reap) on the same 30 s timer, leaving placement and the fleet-wide probes (goals, scoreboard, corrections, records mirror) to the hosts that exchange; `north fleet waits` there runs the same set (north#770). [more](features/03-fleet-sessions/0004-fleet-tick.md)
- Fleet control (north#433, box 1d of north#429): `north fleet forget`, `stop` and `interrupt` of a name this registry lacks but the cached `fleet_sessions` table names write one CONTROL row (the verb in its text) to the spool and print `spooled CONTROL row ID`; a name in neither fails with `no session named NAME`. [more](features/03-fleet-sessions/0005-fleet-control-north-433-box-1d-of-north.md)
- Placement gate: `north fleet launch` and `revive` of a Claude session first print one verdict line per account, open with its headroom or out on the window that stops it, so a box never starts on an account at its provider's limit; only the spend rule (north#702) refuses a start on usage grounds. [more](features/03-fleet-sessions/0006-placement-gate.md)
- Launch tier (north#242): `north fleet launch` of a Claude session routes it to a tier as dispatch does, from the brief's `Category:` and its `Spec`, `Surface` and `Verify` facets, starts it with that tier's model and effort from South's tiers table, and writes `Tier:`, `Arm:` and `Follows:` into the brief header. [more](features/03-fleet-sessions/0007-launch-tier-north-242.md)
- Learning tick (north#112): `north tune` decides, from recently closed boxes, the cells briefs and routing read: `route CATEGORY` (the arm dispatch takes once both arms hold enough runs) and `eta_minutes` and `budget_usd` per family and category. [more](features/03-fleet-sessions/0008-learning-tick-north-112.md)
- Budget scoring (north#255): each worker run stores the Budget its brief set at launch (the `at $X API-equivalent spend` line drawn at E's p90) in `runs.budget_usd`, kept through completion. [more](features/03-fleet-sessions/0008-learning-tick-north-255-budgets.md)
- Bet dividends (north#112): `north ops dividend [--dry-run]` reads each open issue labelled `bet`, takes the `north ops dividend CHECK` commands its Dividend section names, evaluates them over the last 7 days, comments `north ops dividend DATE: PAYING` or `DECAYED` on the issue once a day, and sends the proxy a fleet message for each bet that comments DECAYED. [more](features/03-fleet-sessions/0009-bet-dividends-north-112.md)
- Ops check (north#112): `north ops check`, on a five-minute timer on Nexus and on one other host as its dead-man, turns each expectation in `north-data/expectations.toml` (a measure, a threshold, a window, an owner and the fix it should become) into one phone push through `nexus-alert` and one message to the `[notify] proxy` session when it breaches, and one `cleared` when it clears; a standing breach stays quiet. [more](features/03-fleet-sessions/0010-ops-check-north-112.md)
- Dispatch: `north fleet dispatch`, run on Nexus by a timer (south `modules/north-dispatch.nix`), keeps free worker slots busy. [more](features/03-fleet-sessions/0011-dispatch.md)
- Paused projects (north#636): a `[projects.NAME]` table in orchestration.toml with `paused = true` sets that project aside: `north fleet dispatch` prints `paused NAME` once and launches none of its issues.
- Cloud sessions: `north cloud launch REPO SLUG BRIEF` refreshes a shallow checkout of the public repository under `/tmp/cloud/src/REPO`, trusts it for the login, and starts BRIEF with the cloud safety line and the steps that push `claude/land-SLUG` through `claude --cloud`, printing the session, the branch and the checkout. [more](features/03-fleet-sessions/0012-cloud-sessions.md)
- Working slots: a host slot and the working target count only sessions `starting` or `working`; an idle session, or one parked on a registered run, keeps its issue and claims but no slot. [more](features/03-fleet-sessions/0013-working-slots.md)
- Stranded lanes (north#333): `north fleet stranded --json` lists this host's exited or parked sessions that stopped on `Stop: capacity` or a wait, with each worktree their report names and what it holds that origin/main lacks. [more](features/03-fleet-sessions/0014-stranded-lanes-north-333.md)
- Live claims: `threads claim`, `threads list` and `north fleet dispatch` share one claim rule in `crates/north-threads/src/threads/claims`. [more](features/03-fleet-sessions/0015-live-claims.md)
- Live holders: `threads ready` and `threads unowned` keep a stale claim held when its exact owner matches an active Fleet session; a registered launcher PID must still be alive. [more](features/03-fleet-sessions/0016-live-holders.md)
- Placement reach: a `Needs:` word that names a `[hosts.NAME]` in orchestration.toml (a word that is not a local need) keeps the box off Anthropic cloud and off every machine that does not reach NAME. [more](features/03-fleet-sessions/0018-placement-reach.md)
- Fleet gates: each fleet tick publishes this host's open decision gates to the store's `fleet_gates` table and caches it, so `north gate list` and the issue-gate guard behind `north fleet launch` and dispatch see the gates every host holds, answerable as `HOST:ID`.
- Ask-once gates: a question naming a word of an `ask_once_*` class in `harness/defaults.toml` (cost, accounts, credentials, public, deletion, direction) is refused `--default` and `--default-after`, and waits for Tom's answer. [more](features/03-fleet-sessions/0019-fleet-gates.md)
- Fleet TUI switch: in the composer `Esc` interrupts the selected session when it is working (and moves focus to the list otherwise; `Ctrl+C` still interrupts), and `/model NAME` and `/effort LEVEL` are run by the TUI instead of being sent to the model: they stop the selected session and restart it on the same conversation through `north fleet relaunch NAME [--model M] [--effort LEVEL]`, which checks the model and effort as a launch does before it stops anything; with no argument they show the current value and the valid choices. [more](features/03-fleet-sessions/0019-fleet-tui-switch.md)
- Reboot revival: `north fleet rebooted` lists this host's sessions a reboot stranded (parked with their process gone, last written before the boot, active within their idle limit then, and not ended on a `Done:` report), and `--revive` restarts each through `north fleet revive` with a message telling it to resume from its last checkpoint. - Launch claims: `north fleet launch` claims every issue its session holds before it starts (`--task REF`, else the issues the brief's first `Item:` line names, else the issue its body opens with, as `north#855: run ...` does), claiming only those no session in its parent chain already holds, so a lead that holds an issue keeps it while the children it staffs work its boxes, refusing on a live claim and taking one a stopped session left, and releases them when the session ends or fails to start; `north fleet list --json` shows them as `tasks`.

## Landing and lanes

## Wisp payoff

`north wisp payoff [--since YYYY-MM-DD] [--json]` reads retained Mak'gora evidence, Wisp state, and Wisp evidence/build directories without creating a store. It prints per-kind UTC Monday weeks, completed comparison agreement, invalid native attempts, native client-minutes, Wisp main commit counts, retirement candidates, and disagreement evidence paths. JSON includes each contributing run for audit. The fleet Ctrl+T digest refreshes its summary in background upkeep.

Pad families use their script directory (standalone pads use their name). Pad client-minutes count two clients over game, reset, reload and run time; Wisp, comparison and wait time are excluded. Acceptance report elapsed time is divided equally over checks and marked estimated. Batch dates use file modification time because the format has no timestamp. PASS and FAIL count as comparisons only when both headless and comparison ran; INVALID never counts as disagreement.

Retire candidates have at least ten agreeing comparisons and zero disagreements across the last fourteen days, independent of the display filter. They select Wisp-only evidence with a one-in-ten native sample. The weekly projected sample saving is 90% of those kinds’ historical native minutes, a counterfactual estimate. Actual avoided minutes, closed Public 0.1 boxes, native minutes per closure and Wisp-only closure shares remain unknown when retained evidence lacks closure provenance and skipped-run records. Do not equate projected savings with observed payoff. The command never files issues or sends messages; its evidence paths support deduplicated issue filing and planner handoff.

The planner contract is `schema_version: 1`. `families[]` is computed from the full rolling fourteen-day window even with `--since`. Each entry has `id`, `match_rule: {kind, values}`, `verdict` (`wisp-only` or `native`), `native_sample_rate` (0.1 or 1.0), `counts`, and inclusive `window_start_unix` / `window_end_unix`. `parent-directory` matches an immediate POSIX dirname in `values` and a `.pad` basename; `exact-path` matches a whole path in `values`; `none` applies to accept checks, not scripts. Unknown or ambiguous matches select native. Paths are repo-relative POSIX strings; reject absolute paths, backslashes, and dot segments. Headless-session batches are excluded regardless of their comparison message.

Sampler `sha256-first-u32be-mod10-v1` hashes UTF-8 `scriptPath + "\n" + fullSourceRevision`, without a trailing newline. Interpret the first four SHA-256 bytes as an unsigned big-endian integer and take modulo ten. Select native when the verdict is `native` or that bucket is zero. JSON `sampler` carries the identity, exact input description and a test vector. This gives identical reruns the same sample and prevents display filtering from changing routing.
