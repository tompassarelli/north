# North features

What each harness command and app feature does, grouped by job. The commands live in [bin/](../bin/);
[harness.md](harness.md) shows how they fit together. Each command's `--help`, its code and
[harness/defaults.toml](../harness/defaults.toml) are authoritative for flags, defaults and thresholds;
a number quoted below describes the behaviour when it was written.

CPU offload: [`north nexus-run`](nexus-run.md) sends an owned working tree over SSH, runs its command under Nexus capacity admission, and retrieves selected outputs. The private stock asset cache stays outside Git on Nexus.

## The `north` app

- Interactive fleet screen: `north` or `north fleet` opens the fleet list, transcript and digest.
- Work items: `north work list`, `north work search TEXT`, and `north work show REPO#N`. Search includes matching open and closed issues. Work edits use `north work claim REPO#N [--by NAME] [--eta MINUTES]`, `release REPO#N [--to NAME]`, `need REPO#N BLOCKER#N`, `unneed REPO#N BLOCKER#N`, and `close REPO#N --comment RESULT`. Changes are recorded on the GitHub issue.
- Where work state lives: GitHub holds titles, bodies, checklist, state and blockers. NorthThreads holds current holders, elapsed time and ETA, handoffs and worker runs. North reads both and writes through their commands.
- Skills and hooks: `agents status`, `stale`, `inspect ID`, `path ID`, `on ID`, `off ID` and `sync` (each also `north config agents ...`) list, toggle and publish the catalog's skills and hooks; [harness.md](harness.md#install) describes what `agents sync` publishes.

## Staffing and routing

 - Claude account profiles: `north fleet launch --provider claude --account LABEL --name NAME PROMPT` uses the account's local profile and records its label for restarts. Omitting `--account` on a Claude launch (not `--test`) runs it on the account placement picks, the target `agents plan --place` prints, and a held placement refuses with `held: REASON` and exit 1 like every launch refusal; a named account that placement refuses stays refused, and a Codex launch still needs `--account`. South owns account IDs, host profiles, plan selections and required plans for automatic routing. `agents sync` projects the default Claude harness files into those profiles while credentials and session history stay separate. A profile awaiting its required plan is available explicitly but is excluded from automatic routing until its OAuth tier confirms that plan.
- Interactive Claude and Codex: `claude` and `codex` are the installed vendor runtimes (`~/.local/lib/{claude,codex}/current`) on their default homes; sessions on other accounts run through `north fleet launch --provider claude|codex --account LABEL`.
- Fleet accounts: each `~/.local/state/north/profiles/claude-LABEL` with credentials is one account unless it is logged in to the same account as another label (the sha256 prefix of the `oauthAccount.accountUuid` in its `.claude.json`, over the fleet profiles and this host's `[accounts.claude] profiles`); the label `[accounts.claude] labels` declares for that login keeps it, else the first label by name. A duplicate is left out of `north fleet accounts` and the fleet TUI's launch form (named on stderr with the label it shares a login with), refused by every launch and revive (CLI or TUI, even with `--pin` or `--test`), and unavailable to placement, which also skips any pace-control account with no fleet profile.
- Account owner hosts: a label that `[accounts.claude] profiles` declares only for other hosts is foreign here (north#177): a copied `.credentials.json` shares one OAuth refresh token, so a refresh on either host revokes the other copy. A foreign label is left out of `north fleet accounts` (named on stderr with its owner hosts), refused by every launch and revive naming the owners, and unavailable to placement; placement may still put it on an owner machine, and `north fleet launch --cwd HOST:/PATH` names that machine and its directory. Pace sampling reads its usage through ssh on the owner host instead of starting `claude` here. It starts a provider's local usage adapter only on a host its `[accounts.PROVIDER]` table admits (one its `profiles` name, or any host when it declares no `profiles`), so a provider with no such table, such as Gemini, is not read. A label with no declared profile hosts runs anywhere. A launch whose first turn answers `Not logged in` restarts once, and one that answers `OAuth session expired` is refused naming the account and host; both are recorded in `fleet/.credential-failures.jsonl`.
- Routing: `agents plan` prints one difficulty band table from scalar tier starts, with account usage and project priority, share and target. `agents plan` shows each account’s used percentage, linear pace, available weekly dollars and reset timestamp, and routes each tier to the soonest-expiring under-pace account. Claude drains to 5% left at its reset. `--json` exposes the same metrics and routes; `--at FILE` replays recorded routing decisions. Project `share` is a percentage of rolling seven-day available dollars; `target` is its deadline.
- No pace hold: `north fleet launch` placement and the Agent-tool spawn gate (`north pace reserve` and the refusal it prints) refuse a new worker on an account only when its 5h window is at or over 95%, its measured 5h burn is over `five_hour_burn_cap_pct_h` (50%/h), or the provider reports its week (`week` or `LIMIT:week`) exhausted; the pace controller's held, over and allowed workers, pace lines, projections and drain grants never refuse. `agents plan` (north pace plan, crates/north-pace/src/router/choose.rs) still routes by pace and drain grant at a Claude account's week drain floor (north#185). Each hold names its measured reason and when that window resets, in local 12-hour time. The spawn gate keeps its CPU and landing-flow checks and the usage-gate money refusal for an account whose overflow can bill money; it holds no calibrated reservation.
- Resident cap: `north resident-cap gate claude|codex ARG...` refuses a new resident session on a host whose `[hosts.<hostname>] resident_cap = N` in orchestration.toml is reached, counting live claude/codex CLIs listed by `north fleet list --json` plus unregistered top-level interactive ones, and print `Hold: <host> has N/N resident agent CLIs; place this worker on laptop|cloud` (exit 3). `--cloud`, `-p` and codex exec/app-server launches are not resident; `CASE=URGENT` with a FACT passes; hosts without the key are never held; `north resident-cap status` prints the live count and cap.
- Token-only usage: a Claude account this host declares a `token_file` for and holds no login of, which has no `~/.claude.json` usage cache to read, is sampled by `north pace sample` with one one-token Messages request on that token, whose `anthropic-ratelimit-unified-5h-*` and `7d-*` headers give its `session` and `weekly_all` windows. `agents usage` names an account's plan from its refreshed `.claude.json` `organizationRateLimitTier`, else its sign-in credential's tier, else `[accounts.claude] plans`.
- Usage resets: `agents usage` publishes fresh readouts through `threads ingest` to the authoritative ledger, with its existing offline spool. Remote clients read history from the mirrored snapshot and overlay fresh readouts in memory. A stale plan readout fails loudly. `agents usage` keeps each account's used percentages and reset times and appends reset availability and its source. `usage-web-read` reads the Claude usage page and account UUID inside automation Chrome, caches per-kind counts and expiry by hashed account in `~/.local/state/agents/usage/claude-web.json`, and preserves other accounts and the previous cache on failure.
- Usage read: `agents usage` is served by `north usage`: the latest reading of each account window from the threads ledger, as a per-account table of windows, billing, resets, burn, plan and cost, or with `--json` as JSON carrying a `stale` flag. `--refresh` reads every usage and billing adapter here and, unless `--local`, on each other machine holding a labelled account, records the readings and rewrites the pace gate; `--write-pace-gate` rewrites only the gate, `--fast PROVIDER` answers through its exit code whether fast mode is on, and `--gate PROVIDER` is `north pace gate PROVIDER`. The flags are in `agents --help`.
- Worker estimates: `north worker-ledger --recommend 'FACETS'` chooses the cheapest tier meeting the 80% measured success threshold and adds the recommended tier’s eta from the sample cell, backing off Surface, Verify, Scope, then Spec until three samples are available (or Category alone): `eta active <median>m (p25 <a>–p90 <b>, n=<N>) wall p75 <W>m wait median <X>m` from the runs that recorded active minutes, or `eta wall <W>m (p75 of n=<N>, ...)` when too few did; no samples prints `eta n/a (n=0)`.
- Follows boxes: `threads queue follow REF --tier T --parent NAME` queues a brief from stdin, whose `Follows:` line names the predecessor commit subject, SHA or issue ref. `follows-release` releases a box when its predecessor reaches origin/main, then sends the assignment to its Fleet parent with `north fleet send`.
- Project quote: `agents plan --quote --project P --boxes N` reads the project target from `south:agents/orchestration.toml` and the worker ledger, prints the measured completion date and dollars, and asks one date-and-budget decision for dated projects; undated projects ask none. `agents flow` prints the needed closure rate for each project target.
- Fleet idle (north#252): a session host parks an idle session after its idle limit (`north fleet launch --idle-exit`), and a wake while the prompt cache is warm resumes on it. A large unfinished session is sent a bare `/compact` frame shortly before its cache expires and is parked after it. A session whose last report opens Done, Not done, Split, Stop or Blocked, that has a parent or task and parents no live session, exits instead of parking; its transcript and worktree stay, and `north fleet send` or `north fleet revive` brings it back. A host journals each prompt until Claude echoes it into a turn, so a prompt queued just before a host restart is written again by the next host instead of lost, and `north fleet list` calls a session working while its journal holds a prompt (north#245).
- Handoff arms (north#252): `north dispatch` writes `Arm: handoff-150k` (`handoff_arm_ctx`) or `Arm: no-handoff` as the first `Arm:` line of each fleet box's brief, alternating per tier until each arm has 30 launches there, and records it in the dispatch record; `north fleet launch` keeps the threshold on the session record, so a revived worker stays on its arm. On `handoff-150k` the session host messages the worker to land and hand off when its context reaches 150k, again per further 50k; `no-handoff` leaves it to Claude Code's compaction; the worker-handoff hook and `north capacity watchdog` stay at 350k (`handoff_ctx`). `north worker-ledger --summary --by arm` compares the arms per tier. Once both arms hold 30 launches on a tier and each has a closed box in `north ledger summary --since 7d`, dispatch launches that tier on the arm with the lower cost per closed box (a tie keeps the handoff arm) and prints a north#57 recommendation note naming both costs.
- Pace notices: a pace hold or resume goes to the phone only (`PACE-HELD`, `PACE-RESUMED`); no fleet session is messaged, so a notice never wakes a session and never reads as an instruction to stop spawning (north#186, north#249). An idle session sees each account's pace in its next prompt through the grounding hook.
- Goal ETA: `agents plan` prints, per project target, the critical path over the goal's open boxes at the spawn gate's width with landing overhead, predicted finish against the target and n per box, and records it as a `goal_eta` calibration row ([goal ETA measurements](rationale/learned-routing-and-goal-eta.md#goal-eta)).
- `agents plan --score PROJECT` scores a passed project target from the open issue backlog, linked issue boxes and rolling seven-day run costs, prints on-date, in-budget and spec-pass, and appends one row to `~/.local/state/agents/goal-scores.jsonl`. Missing issue or spending evidence is unmeasured. Project share applies to available account dollars. Projected misses offer one budget/date/scope decision with recorded non-AI service costs and speedups.
- Lane overlap: `north fleet launch` (and so `north dispatch`) reads the `Files:` line of the box it is about to start, diffs each running session's lane (the worktree its recent output names most) and each ticket queued at the lander against origin/main, and prints `overlap: lane NAME also changes FILE` for every file both change. Files whose path has a `merge=` driver in `.gitattributes` are not counted. When two or more in-flight lanes changed the same file, the box is queued behind the earliest of them that holds an issue through `north threads queue follow` and the launch prints `queued:` instead of a session name; `--overlap-ok "REASON"` starts it anyway and records `overlap-ok: REASON` on the session. The `[staffing]` keys `follows-on-overlap` (default true) and `overlap-lanes` (default 2) in South's orchestration.toml change the rule.
- Effort arms (north#112): an Opus box on no tier arm, in a category whose `north worker-ledger --recommend` cell holds 15 Opus runs, runs on `Arm: effort-medium` or `Arm: effort-high` in turn, launched with that `--effort`, and the dispatch record keeps the arm so the next box takes the other; while a box carries an effort arm it carries no handoff arm, since the ledger records only the first `Arm:` line. Once both effort arms hold 15 stamped runs and 15 closed boxes in `north ledger summary --since 30d`, the effort with the lower spend per kept box (closed boxes not reworked within 48 h; medium on a tie) is the category's effort: `north tune` writes it as the `effort CATEGORY` cell with its evidence in the provenance file, and dispatch launches the category's Opus boxes at the cell's effort while it is under 36 h old, else at the ledger's settled effort.
- Review items by kind (north#255): `north review-items PLAN [--author TIER]` splits a design review of PLAN into line items. Fact items, every path or `path:line` the plan cites, every north verb it names and every pair of its numbered boxes whose `Files:` overlap, run here through citation-check and the staffing-overlap file check and print `holds` or `FAILS`; a box pair holds only when `Needs:` orders it. Scenario items, one per `Enforced by` claim, go to the other model family than the author (`sonnet-high` for an Opus author, `opus-medium` for a Sonnet one); architecture items, one per design part that makes such a claim, go to Opus at a tier the author is not (`opus-high` for an `opus-medium` author), with the lens `simpler-alternative` where the part rejects alternatives and `decomposition` elsewhere. It launches nothing; the author defaults to `opus-medium`.

## Fleet sessions

- Fleet sessions: `north fleet launch` starts a session and first registers its row in the fleet store's `fleet_sessions` table on the ledger host, so one live session holds a name fleet-wide (`--take-over` replaces the row), and the launch refuses with the reason when the store refuses the name or does not answer. `north fleet send` and `ask` message a session, `north fleet tree` shows parent links and `north fleet revive` restarts one; `north fleet list` and `tree` read the copy of the table the fleet tick caches, so they show every host's sessions without waiting on the ledger host. A message to a session on another host travels through the fleet spool. A host marked `pulls_spool` in its `[hosts.NAME]` entry only runs the CLIs other hosts place on it and refuses launches. `north fleet --help` gives every subcommand and flag.
- Fleet store: `north fleet row put` reads one fleet row or an array of them as JSON on stdin and commits them to the threads ledger in one transaction, once per row id, printing `committed ID` per row; where this machine does not hold the ledger it forwards the rows over the threads ssh remote and answers the remote exit code. The ledger also holds `fleet_sessions`, one row per session name with the provider, account, cwd, parent, placement, machine and tasks `fleet list` shows, which a launch claims only while no session of that name is live fleet-wide (north#429).
- Fleet spool: every `north fleet send`, parent notice and `ask` first writes a MESSAGE row to this host's fleet spool. A recipient on this host gets it at once through `hand_in`, the one path that delivers a row into a session, which journals each row id in the session's `delivered` directory so a row is delivered once. A name only in the cached fleet table is left for the fleet ticks to carry to its host, and a name in neither fails at once. The ticks deliver MESSAGE, GATE, GATE-ANSWER and JOB-EXIT rows by row id, and a tick that pulls a far machine delivers to that machine's sessions over ssh. `north fleet spool --help` lists the machine-side verbs. A session cannot be named `spool` (north#429).
- Fleet tick: `north fleet tick`, run on each fleet host by the `fleet-tick` timer, makes one `north fleet row exchange` with the ledger host. It commits this host's spool and the spools it takes from the far machines whose CLIs it runs (`north fleet spool take`, dropping only the ids the exchange committed), publishes this host's registry into `fleet_sessions` and caches the whole table, and fetches the rows addressed to its sessions, delivering each through `hand_in` once by row id and reviving a parked recipient. A failed pull is reported per machine without stopping the others, and a row the store refuses is set aside on its machine with a notice. A prompt's uuid derives from its row id, so a tick killed mid-delivery redelivers at most once (north#429).
- Fleet control (north#433, box 1d of north#429): `north fleet forget`, `stop` and `interrupt` of a name this registry lacks but the cached `fleet_sessions` table names write one CONTROL row (the verb in its text) to the spool and print `spooled CONTROL row ID`; a name in neither fails with `no session named NAME`. The tick on the host that holds the session fetches CONTROL rows for its stopped sessions as well as its running ones (a stopped session still receives no MESSAGE), and applies each once: `stop` and `interrupt` are journaled by row id in the session's `delivered` directory, and `forget` needs no journal because the session leaves the registry. `show` stays local-or-error.
- Placement gate: `north fleet launch` and `revive` of a Claude session first print one verdict line per account, open with its headroom or out on the window that stops it, so a box never starts on an account that is out or burning toward the five-hour stop; pace targets never refuse. A code-only box on a public repository is sent to `north cloud launch` unless `--local "REASON"`, an account other than placement's pick needs `--pin "REASON"` (north#389), and a box with local needs goes to the first `[hosts.NAME]` machine that serves them and has room. A box that would run here also meets the spawn gate's CPU line (north#259). The reasons are recorded on the session and shown in `north fleet list`; the thresholds are the `five_hour_burn_cap_pct_h`, `dispatch_agent_memory_mib` and `build_disk_free_gib` keys in `harness/defaults.toml`.
- Launch tier (north#242): `north fleet launch` of a Claude session routes it to a tier as dispatch does, from the brief's `Category:` and its `Spec`, `Surface` and `Verify` facets, starts it with that tier's model and effort from South's tiers table, and writes `Tier:`, `Arm:` and `Follows:` into the brief header. A brief that already names a known `Tier:` keeps it. A `--model` of another family than the pick, or any `--model` on a launch that holds no issue, is refused unless `--tier-reason TEXT` or a `Tier-reason:` line explains it; the reason is shown in `north fleet list` and kept by `revive`. Each launch is logged in the host's `launches.jsonl` as a hand launch, which dispatch on that host counts for arm alternation.
- Learning tick (north#112): `north tune` decides, from the ledger's recently closed boxes, the cells briefs and routing read: `route CATEGORY` (the arm dispatch takes once both arms hold enough runs) and `eta_minutes` and `budget_usd` per family and category. It writes them to `~/.local/state/north/tune/cells.json`, which dispatch and `north fleet launch` follow while it is fresh, and appends each changed cell with its evidence, interval and rerun command to `provenance.jsonl` beside it. Cells whose cost per closed box rose sharply week on week share one rolling issue behind the two-breach gate (opened on the second risen tick, edited only on change, closed when calm), a section per cell listing its closed boxes with their worker runs (north#579). It also prints, per tier and category, the median and p90 ratio of actual to estimated minutes and cost of the week's runs and the share inside their estimate (`n/a` for cost while runs record no expected spend), and files one north issue under the same rule for each whose median ratio left 0.67-1.5x over at least three runs. `--dry-run` writes and files nothing.
- Bet dividends (north#112): `north ops dividend [--dry-run]` reads each open issue labelled `bet`, takes the `north ops dividend CHECK` commands its Dividend section names, evaluates them over the last 7 days, comments `north ops dividend DATE: PAYING` or `DECAYED` on the issue once a day, and sends the proxy a fleet message for each bet that comments DECAYED. The checks are `cloud-lane` (a cloud placement in the last day while the cloud credit lives), `laptop-share` (the laptop under 80% of measured CPU-hours from each host's capacity usage log), `game-share` (makgora and wisp at least 60% of safe-push landings) and `release-closed` (makgora `priority:now` issues closed at least one a day). `north ops dividend CHECK` prints one verdict and exits 0 paying, 1 decayed, 3 unread; a check whose input cannot be read is UNREAD and comments nothing.
- Ops check (north#112): `north ops check`, on a five-minute timer on Nexus and on one other host as its dead-man, turns each expectation in `north-data/expectations.toml` (a measure, a threshold, a window, an owner and the fix it should become) into one phone push through `nexus-alert` and one message to the `[notify] proxy` session when it breaches, and one `cleared` when it clears; a standing breach stays quiet. `--dry-run` prints every expectation's state and sends nothing, and `--synthetic`, on a weekly timer, proves both channels still deliver. Every expectation has a breaching and a clearing fixture under `crates/north-dispatch/src/check/fixtures/`, and the tests fail on an expectation without one.
- Dispatch: `north dispatch`, run on Nexus by a timer (south `modules/north-dispatch.nix`), keeps free worker slots busy. It prints each host's cap and running sessions, each account as open or out, and the free slots per host and account, then every open issue in the staffed repositories with why it is or is not ready: a label holding it for Tom, a live session, gate, claim or recent launch on it, an open predecessor, or a Done-when box gated `(not before TIME)`. Each ready box gets a generated brief and goes, in project priority order, to the cloud lane when it is code-only in an Autoland repository, else to the host that serves its needs and would start it soonest (`dispatch_heavy_memory_mib`, `dispatch_agent_memory_mib`), on the open account that ranks first by pace (`reservation_fallback_points`). Attempts are logged in `~/.local/state/agents/dispatch/launches.jsonl`; an item tried twice without progress is left to the proxy, issues with no box go to the triage lead, and ready work with nothing launched raises one `nexus-alert`. `--dry-run` launches nothing.
- Cloud sessions: `north cloud launch REPO SLUG BRIEF` refreshes a shallow checkout of the public repository under `/tmp/cloud/src/REPO`, trusts it for the login, and starts BRIEF with the cloud safety line and the steps that push `claude/land-SLUG` through `claude --cloud`, printing the session, the branch and the checkout. `north cloud list`, `events`, `send`, `wait` and `sweep` read, message, wait on and archive the Anthropic cloud sessions of the host's login through `curl`, with the token on curl's stdin config and never in argv ([cloud.md](../harness/skills/workers/references/cloud.md)). `north cloud --help` gives every form and flag.
- Working slots: a host slot and the working target count only sessions `starting` or `working`; an idle session, or one parked on a registered run, keeps its issue and claims but no slot. `north fleet wait RUN` registers a run (`job:`, `farm:`, `branch:` or `capture:`) and parks the session when its turn ends; the fleet tick, or `north fleet waits` by hand, revives it with the run's result once the run is over. A run the session detached from its CLI is found in its session scope and registered as a `pid:` wait on its own, surviving revivals until it ends. A session whose last turn ended on its account's usage limit is parked by the tick on `usage:ACCOUNT@TIME`, the reset the stream event or message names (else the account's window reset from the usage table), even if the host stopped it; `north fleet waits` revives it once that time passes, a worker holding a lane no queued ticket will land first, with a message to fetch, rebase and re-enqueue the lane or report Done with the landed sha. A session `north fleet stop` ended is never revived, and a parked session accrues no spend. An idle session with nothing to wait on parks at its idle limit and its next message revives it.
- Stranded lanes (north#333): `north fleet stranded --json` lists this host's exited or parked sessions that stopped on `Stop: capacity` or a wait, with each worktree their report names and what it holds that origin/main lacks. Each `north dispatch` run reads it from every host: a session whose lanes hold nothing new is forgotten, and any other keeps its issues and is revived once per report, with a turn naming its lanes, when its machine and account have room. `north flow` lists each repository's stranded lanes, and `north flow --stall-alarm` reminds the Fleet parent and the proxy while any remain.
- Live claims: `threads claim`, `threads list` and `north dispatch` share one claim rule in `crates/north-core/src/threads/claims`. A claim is void when it predates its issue, its issue is closed or missing, or its owner is no live fleet session, and stale when its owner has been silent past its ETA (`overdue_ratio`); dispatch holds neither, and `claim` takes either over with an event naming why. Any other claim is live: `claim` refuses another owner and dispatch holds the issue. `threads ready`, `threads unowned` and `north work list` read the same list, and every `north fleet` command releases the claims of exited sessions.
- Live holders: `threads ready` and `threads unowned` keep a stale claim held when its exact owner matches an active Fleet session; a registered launcher PID must still be alive. A proxying client relays proven local owner identifiers to the remote ledger; PIDs are checked only on their own host. Finished or dead holders' stale claims no longer hold.
- Resuming archived work: `threads show REPO#N` reads origin's `archive/*` tags in `~/code/<repo>/main` (or the current lane) and lists tags whose commit messages say `Refs REPO#N`, with `git push origin archive/<branch>:refs/heads/<branch>` to restore each. The SessionStart guard in `north hook` (also `north archives REPO NUMBER`) lists the same archives when the session's Fleet task brief has an `Item:` ref.
- Placement reach: a `Needs:` word that names a `[hosts.NAME]` in orchestration.toml (a word that is not a local need) keeps the box off Anthropic cloud and off every machine that does not reach NAME. A machine reaches itself and each host in its `reaches = [...]` list, and a host with no `reaches` list reaches every host; `north fleet launch` prints `HOST skipped: cannot reach NAME` for a refused machine, and when this host cannot reach NAME either, the box is `unserved: no host reaches NAME` instead of launching blind.
- Fleet gates: each fleet tick publishes this host's open decision gates to the store's `fleet_gates` table and caches it, so `north gate list` and the issue-gate guard behind `north fleet launch` and dispatch see the gates every host holds, answerable as `HOST:ID`. `north gate answer HOST:ID N` spools the answer for the asking session's host to apply once on its tick (north#184), and `north gate open` for a session another host runs spools a GATE row that host opens as its own gate (north#416). `north gate --help` gives the forms.
- Fleet TUI switch: in the composer `Esc` interrupts the selected session when it is working (and moves focus to the list otherwise; `Ctrl+C` still interrupts), and `/model NAME` and `/effort LEVEL` are run by the TUI instead of being sent to the model: they stop the selected session and restart it on the same conversation through `north fleet relaunch NAME [--model M] [--effort LEVEL]`, which checks the model and effort as a launch does before it stops anything; with no argument they show the current value and the valid choices. `north fleet interactive NAME` hands a session to Claude Code's own UI: it stops the fleet host, waits until it has exited, marks the record stopped and execs `claude --resume CONVERSATION` in the session's directory under the account's credential and environment; `north fleet revive NAME` takes the same conversation back into the fleet and, like `relaunch` and `interactive`, refuses while an interactive `claude` still holds that conversation.
- Reboot revival: `north fleet rebooted` lists this host's sessions a reboot stranded (parked with their process gone, last written before the boot, active within their idle limit then, and not ended on a `Done:` report), and `--revive` restarts each through `north fleet revive` with a message telling it to resume from its last checkpoint. `north fleet tick` runs it for its own host, so a rebooted host's sessions resume on its first tick and one that cannot be revived is retried on the next.
- Launch claims: `north fleet launch` claims every issue its session holds before it starts (`--task REF`, else the issues the brief's first `Item:` line names), refusing on a live claim and taking one a stopped session left, and releases them when the session ends or fails to start; `north fleet list --json` shows them as `tasks`. A launch whose issue a running session on any host or a recent dispatch launch already holds is refused unless `--force-dup "REASON"`, recorded on the session as `dup: REASON`.
- Refused land branches: `north flow` reads the `autoland` commit status of every unlanded `claude/land-*` tip in a repository whose Autoland posts one (wisp and makgora) and lists a failed tip under `refused` with its pusher, the refusal and the run link. While that pusher is no live Fleet session, `north flow --stall-alarm` reminds the Fleet parent and the proxy until the branch is fixed or withdrawn; a live pusher hears the refusal from its own safe-push wait.
- Cloud handback landing: `north cloud land EVENTS` applies the latest patch handback in a cloud session's transcript with `git am --3way` in a fresh `worktrees/cloud-SESSION` lane off origin/main, folds it into one commit without session trailers, runs `north land checks` on it and enqueues it with `safe-push --to main`, printing `Done: queued`, or stops with the reason and the lane path and queues nothing; a handback already queued is a no-op. `north cloud wait` runs it when the finished session's transcript holds a handback, so a cloud worker's patch lands without a lead.
- Fleet sender: every message row carries a required `Sender` (`tom`, `session:NAME` or `service:UNIT`, on the wire as that text) and no send path defaults it. The fleet TUI composer sends as `tom`, which reaches the session unprefixed on any host; a session sends as itself (`[from NAME]`); a timer or daemon sends as `service:UNIT` (`[from service:UNIT]`), and fleet machinery (parent notices, wait settlements) as `service:north-fleet`. `north fleet send [--now] [--from service:UNIT] NAME TEXT...` and `north fleet ask NAME [--from service:UNIT] QUESTION...` outside a fleet session without `--from` are refused, `--from tom` is refused everywhere, and a source test in `fleet::sender_tests` fails any Rust or `bin/` shell-out to `north fleet send` that omits `--from` (north#112, box W1).
- Cloud reap (north#259): `north cloud launch` registers each session in `~/.local/state/agents/dispatch/cloud-launches.jsonl`, and `north cloud reap`, run every 2 minutes by the laptop's `north-cloud-reap` user timer (nixos-config), reads each session launched in the last 7 days that has not landed yet: one still running, or idle with its turn unended, is left alone; a finished one whose transcript holds a patch handback lands through the same `north cloud land` path as `north cloud wait`, from `~/code/REPO/main`, printing `Done: queued`. The session is then recorded as landed under `~/.local/state/north/cloud-handback/reap/` and never read again, and the landing's own queued record keeps a handback from being queued twice; a finished session with no handback is reread only once its `updated_at` changes. It exits 1 when a landing stopped or a session could not be read.
- Cloud stall wake: `north cloud wait` treats a finished turn with no `Done:`, `Not done:`, `Split:` or `Blocked:` line in its last reply and no patch handback as a stall, such as a worker that ended its turn on a background build; it posts a continue message telling the worker to run that work in the foreground, finish and hand back the patch with a report, then waits again after that message, at most twice, before printing that the worker stalled and exiting 1.
- Fleet role: every session record carries `role`, set by `north fleet launch`: `--role proxy|lead|worker` when given, else `worker` for a launch with a task (`--task` or an `Item:` line) and `lead` for any other. The host exports it as `NORTH_FLEET_ROLE` beside `NORTH_FLEET_SESSION`, and `fleet list --json` shows it. A proxy is named `proxy` and has no parent; while one proxy session is live a second proxy launch is refused unless it passes `--take-over` under the live proxy's name. The ledger's session role and the lead-timer guard read the field; a record written before roles infers it from its name, parent and task (north#112).
- North proxy: `north proxy` opens north's fleet TUI on the fleet session `proxy`, attaching when it is live, reviving it when it is parked or stopped, and otherwise launching it through `north fleet launch`'s own account routing with `--role proxy`, so `harness/claude/agents/proxy.md` is its agent definition from the first turn. `north proxy --interactive` stops the fleet proxy and resumes the same conversation in `claude`, and the proxy is not revived while that UI holds it. When the proxy's account is out, the fleet tick takes it over under its name onto an account with headroom and resumes its conversation, so there is always exactly one live proxy (north#112).

## Landing and lanes

- `safe-push --to main` lands the lane as one commit: before its land checks and the Autoland queue push, `north lane-squash` folds the lane's unpublished commits (none an origin ref reaches) into one commit on the newest published commit, with the first commit's author, every trailer kept once and the message from `--message FILE` or the first commit with the other subjects listed; `--several-commits REASON` keeps them apart and logs to `several-commit-landings.tsv` (docs/rationale/one-landing-per-change.md).
- `safe-push --to main` runs the lane's affected land checks from the committed `.safe-push` (`land.check`, `land.local-only`, `land.machine-bound`, `land.runner`, `land.workflow`, `land.publish`): on GitHub Actions through `north land-actions`, on the build host, or here. Before each check it asks `north land-cache hit` and reuses a pass recorded for the same inputs (the command, the host class that ran it, the toolchain and the object ids of the check's paths), so an unchanged check never runs twice; a failure deletes the record. `safe-push --help` and `north land-cache --help` are the contract.
- Red main event: when a land check fails on Actions, `north land-red-check` reads the failed cargo (`---- NAME stdout ----`, `test NAME ... FAILED`) and harness (`land check: FILE exited`, `FAIL`) tests and asks whether they fail on main's own tree, from a result recorded for that tree under `safe-push/red-check/` or by rerunning only them there through `north capacity offload run --host gex45`; if they do it keeps a box per red main commit in the rolling `main is red` issue from the first red verdict, which names the issue in its `Main-red:` marker (an unchanged red main posts nothing, a new red main commit edits it, never a comment), sends the proxy and the session's Fleet parent one line naming the tests and the newest main commit since the last green run that changed their inputs, and the lane prints `blocked by red main, not this lane` and `north land-red-wait` retries it once a `Main-red:` lane lands; main CI runs on main are never cancelled in progress.
- Landing tempo (north#255, B12 and B13): safe-push and the lander record each lane they decide through `north land-train record|check|red` (in the background, never under the land lock) as `landings`, `land_checks` and `main_red` rows in the threads ledger, and `north flow` reads them back per repository as landings per hour, finished-to-landed and first-commit-to-landed percentiles, batch size, re-lands, check runs thrown away because main moved, bisect depth and red-main minutes, with `--json` for the same under `landing`. The row schema and why each field exists are in docs/rationale/landing-train.md.
- `north capacity offload choose|run`: while this host is in game-reserve and its CPU split is not enforced (a playtest lease whose `game-reserve status` reports ENFORCED runs the checks here, confined to the agent CPUs), `safe-push` ships the lane by git bundle to the first other `[hosts.NAME]` with an `ssh` destination and room (free cores, the heavy memory request, 20 GiB free where its offload slot lives) and runs the land checks there in `~/.cache/land-offload/<checkout>`, whose `target` persists between runs; `land.local-only` entries in `.safe-push` and a missing host keep the checks on this host (`land.machine-bound` ones may ship); a repository whose `.safe-push` names a `land.workflow`, north among them, runs its checks on GitHub Actions instead and never offloads.
- Fleet capacity rows: `north capacity pull [--host NAME]` reads each other `[hosts.NAME]` ssh host's `capacity_runs` rows newer than the last one pulled for that host (read-only `sqlite3` over ssh) into this machine's capacity.db under a `host` column (this machine's own rows carry its name), and `north capacity actions-pull` records each started job of the north, makgora and wisp Actions runs (first pull: 7 days) as an `actions:LABEL` row with `queuedSeconds` (created to started) and `wallSeconds` (started to completed), then prints the p50 queue per runner label and an `incident: REPO main is red` line (exit 3) for each repository whose latest push-to-main run failed; a second run of either adds no rows. Sizing reads only this machine's own rows (`capacity_history`), so pulled rows feed placement and reports, never its estimates.
- `mutant record <id>` (`north mutant record`) saves the scratch copy's non-empty diff against HEAD to `~/.local/state/agents/mutants/<repo>/<id>.patch`; `north mutant verify BASE HEAD`, run on demand (no landing gate runs it since 2026-11-04), refuses a claim whose patch is missing or applies to neither side and, when the base `.safe-push` sets `mutant.run`, runs that runner once under one capacity lease over the change tree and every mutant tree, requiring each named test to pass on the change and fail on its mutant; verified kills are cached by change patch-id and mutant.
- Fails-first gate: `north land-fails-first [BASE HEAD]`, a `.safe-push` land check, runs the tests a lane adds or changes against base with the head's test files: a lane that changes code needs at least one of them to fail on base, and a lane marked `Behavior: unchanged` needs all of them to pass. It then runs those tests concurrently several times (the `[flake]` section of `.safe-push`) on the lane head and refuses a lane naming any test that fails a run as flaky, never retrying to green. The contract is `north land-fails-first --help` and why is in docs/rationale/failing-first.md.
- Provenance: `north provenance check BASE HEAD` lists each bar (a comparator such as under, within or `<=`, a number and a unit) added to a PLAN*.md table row, a Done when line, a `- [ ]` box or a test path without a `Provenance: <claim>; origin <...>; pointer <...>; rationale <path#anchor | not recorded>; revisit <...>` trailer whose claim names its number and unit and whose origin is not `none` (allowed only with `; soft`); a reworded line keeping its bar passes; it runs on demand and no landing gate runs it since 2026-11-04. `north provenance debt [--due] [--repo PATH]...` lists `Target-debt` trailers on origin/main of each `~/code/*/main` not named by a later `Target-paid: <commit>`, with `--due` keeping rows whose revisit date passed, whose `closed REPO#N` issue closed, or whose trigger is event text.
- Landing flow: `agents flow [--json] [--repo NAME]... [--stall-alarm]` caches pending landings, landing rate, push-to-land latency, main idle time, oldest landing job and runner, stall verdict, project throughput (the open count the goal needs closed weights each open `release` or `bet` issue by its `size:S`, `size:M` or `size:L` label as 1, 2 or 4), and Actions, Wisp and Autoland capacity signals. `--stall-alarm` sends notices to the active Fleet parent and Plato, and mentions Tom after 60 minutes until main moves and jobs recover. Fleet sessions use the same one-hour landing WIP limit (floor 2), with landing-path and `CASE=URGENT` exceptions.
- Red-main notice: `red-main-notify` runs beside `ci-diagnose` on the same tick; for each open "main is red" issue in wisp, north, firn and makgora it sends the live session whose worktree is the issue's `Culprit lane:` (the lane Autoland recorded for the first failing commit, wisp:host/checks/mainRed.ts) and the proxy one `north fleet send` naming the commit, its failing tests and the 15-minute revert time, once per culprit commit (state under `~/.local/state/north/red-main-notify`).
- CI diagnosis: `ci-diagnose [--dry-run OWNER/REPO RUN_ID]` runs after `agents flow --stall-alarm` (laptop, every five minutes); for each open "main is red" issue in north, firn and makgora it takes the newest still-failing main run, has Claude Haiku extract the failing step, first error lines and culprit `path:line` from `gh run view --log-failed` (refusing JSON whose step or errors are not in the log), has Claude Opus medium judge the cause and smallest fix from that plus the compare diff stat, and posts one comment marked `<!-- ci-diagnose:RUN -->`; it never changes code, reverts or closes anything.
- Runtime-floor gate: `north runtime-floor-gate`, which safe-push runs after the build-cache gate for every repository, refuses a landing whose added script or `.nix` lines call a `north` subcommand, or pass it a flag, that the oldest live runtime this host knows lacks; a subcommand call passes when the script probes it first with `north SUB --help`, and a flag waits until every host runs a runtime that accepts it. It exists because a landing that calls what an older runtime lacks breaks every host still on it: on 2026-11-01 every landing was refused for hours (north#482), and on 2026-11-05 the lander crash-looped on a new `--all` flag (north#360). How the floor is chosen, which source module must accept a flag, and the nixos-config and south case are pinned by the cases in crates/north-landing/src/runtime_floor_gate_tests.rs.
- Lander queue stall: each `north flow` row reads the lander's own queue (`~/.local/state/north/land-queue/<origin key>/`, the key shared with the lander through `platform::land_queue`) beside GitHub: tickets queued (counted in `pending`), the oldest ticket's age, minutes since the last `landed` ticket and the running candidate check's age against the p90 of its finished checks in 7 days. The stall verdict, and so `--stall-alarm`, reports a stall when tickets wait and main has not moved through the lander for `lander_idle_alarm_minutes`, or a check runs past `lander_check_p90_multiple` times its p90. A project target already past prints as passed with the policy line to change, not as a projected miss, and the stale-usage line moved to the silent-signal detector.
- Box trailers and the landing tick: a lane's commit carries `Item: REPO#N` and `Box: TEXT` trailers, the Done when box it closes, which `north brief new` prints and `north cloud land` keeps as one closing trailer block when it folds a handback. `north land scan boxes BASE..HEAD`, which `north cloud land` runs before the land checks, refuses a `Box:` with no `Item:` before it or one that matches no single unticked box on that issue. After a landing, `north after-landing` (run by safe-push's direct and train paths and by the lander's follow step) queues one tick per trailer in the issue-body outbox under the land queue and drains it through the one issue-body writer: the box is ticked with its landed sha, a parent box with it once every box under it is ticked, and the issue closes with a comment naming the sha once at least one box parsed and every box is ticked. A box marked `(observed)`, `(headless run)` or a Tom check, a box with unticked boxes under it, and an issue with no checkboxes get no edit and a refusal note naming why. Why is in docs/rationale/proxy-role.md section 4.
- Lander idle-slot SLO: no lane waits more than `lander_idle_slot_wait_minutes` (10) while one of the lander's `lander_check_slots` (4) check slots is idle. Each `north flow` row reads the lander queue's tickets, queued and decided under `done/`, and its `logs/`: a lane waits from the time in its ticket's name until its own precheck log, a batch candidate or speculative log, or its decision starts or ends the wait, and a check occupies a slot from the time in its log's name to the log's last write. A lane whose wait beside an idle slot passes the limit is a breach on the UTC day it passes it; `--json` lists today's under `idle_slot_wait_breaches` (lane, queue and breach times, wait minutes, idle minutes, most idle slots) with the day's count against `lander_idle_slot_breach_budget` (3) under `idle_slot_budget`, and the text row shows `idle-slot waits over 10m today N/3`. With `--stall-alarm`, the day the budget is spent sends lander-lead one `north fleet send` naming each breach, kept once per repository and day in `agents/flow/slo.json`. On 2026-11-05 lanes waited 15 to 22 minutes while check slots idled behind unleased worker builds (north#360).
- Lander promotion: the lander runs from its own runtime link, `~/.local/state/north/lander`, so a commit to main that changes the lander's inputs no longer retires it, and `north land promote` is the one way that link moves (north#360: on 2026-11-05 the lander retired on every such commit). Promotion has the runtime `current` points at replay the latest recorded rounds from each repository's land queue through `north land replay`, each refused lane on the main its ticket records under `decided_on`, then shadow the pending queue on current main for `--shadow-minutes`, and swaps the link and restarts the `north-land` units only when every replayed verdict matches and no error repeats; any mismatch leaves the link unchanged and exits 1, and `--dry-run` stops before the swap.
- Lander recheck: a green precheck lane lands its checked tree only while its base is still main. When main moved during its check, a lane whose changed files meet main's is checked again in full on the new main, and any other runs only the `[land] recheck` lines of `.safe-push` on the exact tree it would land (`NORTH_LAND_RECHECK=1` selects them in `north land checks`; north runs `cargo check --tests` on the crates the lane affects), or the full check where a repository has none. On 2026-11-05 a lane that added a struct field landed without a second check beside a lane that built the struct in another file, and main stopped compiling for 12 minutes (north#582).
- Lander watchdog: every lander round records slots, busy slots, waiting lanes and any error or transient wait in `<queue>/watchdog/rounds.json`, then checks four invariants: (a) no check slot idles while lanes wait for more than one round, (b) no repository repeats the same error three rounds in a row, (c) no lane waits longer than 20 minutes, (d) no branch is claimed by two worktrees. Repairs recreate or remove a broken lander worktree, quarantine a lane or a repository's lanes to `<queue>/quarantine/` with the reason as the verdict, or restart `north-land@PROJECT.service` when that user unit exists; each violated invariant pages `lander-lead` through `north fleet send` at most once per 15 minutes (`<queue-root>/watchdog-pages.json`). `north land watchdog --once [--queue-root DIR]` runs the same patrol over every queue under the root, prints each violation, its repair and its page, and exits 1 when any invariant was violated.
- One lander per repository: `north land serve --repo DIR` without `--all` serves only that repository's queue (`~/.local/state/north/land-queue/<origin key>/`) and takes an exclusive `flock` on `lander.lock` in it, writing `pid N serving DIR` there. A second lander on that queue, per-repository or `--all`, exits 1 with `queue ... is already served by pid N serving DIR; refusing to serve it twice`; `--all` instead skips a queue another lander holds, says `not serving` once, and retries it at the next discovery. Each lander reaps and tags its remote offload runs with its own owner, `north-land-<origin key>`, so a restart of one repository's lander never reaps another's checks, and a repository whose rounds error backs off 60, 120, then 240 seconds, alarming the proxy at the third, without delaying any other repository (north#360).
- Clippy first: `north land checks` runs the listed `cargo clippy` land check alone before every other land check, on the crates the lane affects (`SAFE_PUSH_LAND_PACKAGES`, the changed crates plus every workspace crate that depends on them, or `--workspace` for a workspace manifest, `Cargo.lock` or toolchain change), and a lint failure ends the land check there with the clippy output and none of the later checks run. A lane that changes no Rust input lists no clippy check and skips the step, inferred checks keep their fixed order, and the log prints the check order. The last 8 land-check failures before 2026-11-05 were lanes' own lints found after about 40 minutes in the queue (north#259).

## Ledger, calibration and reports

- Worker delivery costs: `north worker-ledger` records each finished worker as a run in the threads ledger and `--summary` reports brief-to-landed minutes, dollars per done box and completed-worker concurrency per model, effort and project; dollars come from weekly usage readouts allocated to the token samples of active runs, and a missing interval prints an unknown cost. A fleet session is reread while its transcript changes, so its latest decided report wins, and a session safe-push recorded landing counts as landed; a worker the ledger has not recorded whose transcript then sits over 2 hours on an unanswered message or a parked tool call is recorded finished at its latest decided report (north#255). `north ledger summary --since WINDOW` prints a `runs/closed` line with the worker runs per closed box in each category, and `--json` lists them under `runs_per_closed`. Senders reach the ledger host through `north threads ingest`, which holds an exclusive lock beside the ledger with no network call inside it, exits 75 for the sender to spool when the lock is busy, and logs each ingest's wait and hold to `ingest.log`. Flags are in `north worker-ledger --help`.
- Split outcome: a worker report starting `Split:` is recorded as `split`, counts in no tier rate, lends its `Arm:` to its parts (runs whose `Follows:` names it), and `north worker-ledger --summary` adds a per-category table of splits, parts, parts closure, summed part minutes and minutes from the split to the last part.
- Ledger pull (north#394): on the ledger host (no `~/.config/threads/remote`, Nexus) every recording `north worker-ledger` run also runs `north worker-ledger --emit` over ssh on each other `[hosts.NAME]` with an `ssh` destination, passing the ledger's run ids as JSON on stdin; that host prints the rows it would record against those ids and the ledger ingests them in the same batch, so a host that cannot reach Nexus (gex45) has its runs recorded once within the 15-minute timer, and an unreachable host prints `north worker-ledger: HOST runs unread: WHY` without stopping the rest.
- Recurring recalibration: every recording `north worker-ledger` run (the 15-minute timer) ends with a recalibration step: on the ledger host (no `~/.config/threads/remote`, Nexus) it runs `threads calibrate --write` when the newest calibration row is over `calibrate_after_min` (55) minutes old, and on the host holding the Codex rollouts (the laptop) its first run from Monday 00:00Z each week runs `north defaults-measure --priors` and records one `prior` calibration row per provisional default through `threads record-priors` (cell the default, n its settling count, value the count it needs).
- Loop report: `agents report` prints the latest `calibration` batch per kind with its age, n and `(uncalibrated: <reason>)` for cells under n=5 or older than 7 days, the latest `prior` batch as `WAIT <default> n=<n>/<need>` below its need, `MEASURABLE-NOT-MEASURED` at its need while no sweep result is recorded for it, and `SETTLED` only when its `settles_when.measured` records one, the 7-day stall recovery line `north worker-ledger --summary` prints, spawn-gate denials over 7 days by gate (capacity, flow, pace), and each project's latest goal score (on-date, in-budget with spent against budget, spec).
- Incidents by construction (north#112): the lander writes one `incidents` row to the threads ledger for every verdict but landed (refused, conflict, hang, transient, deferred) and once per held candidate and base, and `north land withdraw TICKET --reason TEXT` moves a queued ticket to the queue's `withdrawn/`, tells its session and records the row; `north incident guard` names the commit that closes a class, so an earlier row is fixed by it and a later one is marked recurred after its guard. `north flow` prints the last 7 days by class, the detector-first rate with its denominator, the median minutes to detect and to fix, and the classes that recurred; `north incident report --since --until` reads any window, and `north incident import` loads a backfill.
- Tool mining: `north tool-mine` reads the last 7 days of Bash tool calls through `north convo`, turns each command into program-and-subcommand steps, and files one box on north#112 per maximal sequence of 3 to 8 steps that 5 or more sessions ran, naming the sequence, its session count and the `north` subcommand it should become; `--dry-run` prints the patterns without filing, each box is filed once per sequence through the detectors' filer, and its spend lands in the ledger as the `recurring-sequence` detector.

## Policy measurement

- Prompt grounding: `north grounding hook` (the UserPromptSubmit hook `harness/hooks/prompt-grounding.sh`, Tom's top-level session only) injects only what a typed message needs: nothing for a task notification, system reminder or local-command event; a block only when a hit reaches cover 0.5 or the typed message refers to past work (then the one-line tier-B instruction first), filled with hits down to cover 0.2 ranked prose before code, one file per line; no path, issue, convo or decision already injected in the same session (state in `~/.local/state/north/grounding/sessions/`, pruned after 14 days); the usage and fleet block only when it changed; at most 1,500 characters. `north grounding query --hook` renders that shape for a fresh session and `north grounding score EVAL --hook` scores it.
- Context audit: `north context audit [--since 7d] [--json] [--session ID]` reads the Claude profile transcripts modified within the window file by file and prints, per lead and worker session, injected characters and chars/4 tokens by source (startup from policy-gate measure, SKILL bodies, skill references, UserPromptSubmit grounding, other hook context), grounding precision (share of named paths the session later read) and grounding injections on background task notifications; without `--json` it prints p50 and p90 per source for leads and workers and the top 10 injected skills, and never prints message contents.
- Hook verdict stats: `north worker-ledger` ingest records every PreToolUse and PostToolUse hook refusal, rewrite and advisory it finds in Claude transcripts into the ledger's `hook_events` table (session, tool call, tool, stable rule id from `guard/hook_rules.rs`, time, call ordinal); `north hook stats [--since 7d]` prints per rule its fires, sessions, refusals, rewrites, advisories, in-session repeats and median calls lost to a repeat, then auto-fix candidates (mechanical rules still refusing), skill-text candidates (most-repeated rules with the skill line that should have prevented them) and prune candidates (no fire in 30 days).
- Policy regression gate: `agents sync` measures the candidate policy's session-start tokens and compares the policy's sha256 against `south:agents/operating-point.toml` and its recorded `sweep-*.jsonl` replay rows; it refuses to publish when no sweep covers the live policy, a scenario the operating point passed flips to failing, conformance drops significantly, or tokens grew without a conformance gain, and otherwise prints the token breakdown and whether a sweep is due. `safe-push` refuses a south change to `agents/AGENTS.md` that lands without a sweep row for the new policy, and `agent-config-check` requires each `rules.toml` entry to name its `placement` and cite incidents. Replays run through `north policy-replay` (its feature entry).
- Skill prune: `north skill-prune [--measure]` (laptop timer, Sundays 09:00) runs one Claude Opus medium session that prunes the shared SKILL.md bodies toward the 60-line playbook target and shrinks duplicated or stale rules, logs each moved or removed line in `skill-prune-moves.md`, folds `codex-lessons.md` into the skills and `codex-lessons-folded.md`, lands each repository through `safe-push` and runs `agents sync`; it writes the before and after body and lesson counts to `~/.local/state/agents/handoffs/skill-prune.md`. `--measure` prints each shared skill's body lines, marks domain skills and reports the total beside the operating point in `south:agents/operating-point.toml`, with no cap.
- Policy replay: `north policy-replay` measures how well a policy makes agents behave by replaying scenarios from `south:agents/replay/` through `claude -p` with the policy in place of the live one and scoring each run with the scenario's detector. `run` compares policy arms (and model or effort overrides) and writes one row per run; `sweep` runs every variant of `variants.toml`, writes per-variant rows the `agents sync` regression gate reads and a candidate operating point with the fewest startup tokens and no significant conformance drop; `promote`, run in a south worktree and landed through `safe-push`, copies that candidate into `south:agents/operating-point.toml` unless it drops below the current point or the frozen anchor, with `--accept-drop REASON` to re-anchor. Arms, detectors and row fields are in `north policy-replay --help`.
- Experiment registry: `docs/rationale/experiments.toml` holds one entry per live policy or routing change, naming the north flow outcome metric it should move, the bar and the review date, so every such change is judged on that date instead of kept by default. `north experiments judge` reads finished worker runs from the threads ledger and keeps, reverts, re-measures or brings each due entry to Tom, and with `--file` posts each verdict once as a box on the entry's owner issue; `north flow --stall-alarm` runs it every five minutes. `north experiments check`, a `.safe-push` land check on `docs/rationale/`, refuses a landing whose rationale review rule no entry quotes exactly. The entry fields are the ones experiments.toml already holds, and the verdict rules live in crates/north-ops/src/ops/experiments/.
- Proxy calls: `north proxy calls TRANSCRIPT` reads a Claude Code transcript's main-thread tool calls, skipping subagent calls and repeated tool-use ids, and prints them by kind (delegate, child message, Tom-facing, briefing, monitoring scripts, bookkeeping, hands-on landing and editing, landing logs, status checks, diagnosis), the streaks of calls between hand-offs (delegations, child messages, briefs and Tom-facing calls) with their median, 90th percentile and the counts reaching 5 and 15, and every counted shape (the `north` verb, or the first two words of each stage after any `cd`) run 20 or more times. A `north` command takes the kind its verb declares in the CLI's verb table (`src/cli/verbs.rs`, where a two-word entry overrides its verb for that subcommand and a test fails any dispatched verb without a kind); foreign commands (`git`, `gh`, `threads`, `safe-push`, `sed -i`, `journalctl`, loops, sleeps, helper scripts) go through an ordered rule list, and a call with several stages takes the earliest kind in that order. The classifier, `crates/north-core/src/proxy/`, is pure, so the delegation guard and the daily readout share it (north#112).

## Issues and native items

- Native items: `threads new life|accounts|travel|ops TITLE [--due D] [--body -]` captures an item that lives only in threads.db (`life#1`), with `threads note`, `close` and `reopen`; `need`/`unneed` involving a native item are recorded locally, and `ready`, `show`, `list` and claims treat native items like GitHub issues without calling gh. Native items never reach GitHub: NorthThreads' gh calls, `safe-push` (commit messages, branch and tag names) and the `native-item-guard` hook (gh writes naming a native ref or quoting an item's title (20+ characters, 3+ words)) refuse them; `new` and `note` refuse text `gitleaks stdin` flags. Under `THREADS_NO_NATIVE` (exported by `agy`) or `CLAUDE_CODE_REMOTE` (cloud workers), NorthThreads hides native items and refuses to show them or the snapshot.
- Public GitHub text: `north hook` runs gitleaks with the public deny-list (`~/code/south/main/privacy/public-denylist.toml`, or `NORTH_PUBLIC_DENYLIST`) over the inline `--body`/`--title`, `--body-file`, `gh api -f/-F/--input` and heredoc text of `gh issue|pr create|comment|edit|review|close|reopen|merge` and `gh api`, and refuses a match naming its rule unless the target repository is private. `sops decrypt` or `sops -d` output that would reach the terminal is refused; `--extract` into a pipe, `--output` or a redirect to a file passes.
- Issue box lint: `north issue-box-lint [REPO#N...] [--repo REPO]` (each also as `OWNER/REPO`) prints each unchecked Done when box that hands Tom a mechanical check (input, sizes, frames, sounds, menus, launches), which agents verify on VM pairs and native capture instead, or names a bar without an origin or `soft`; it exits 1 when any box is flagged.
- GitHub as the Socrates Agent app: `gh-app-token` prints a cached installation token (decrypted from south's `secrets/github-app.yaml`), and `gh-as-app ARGS` runs `gh` with it.
- Observation boxes: an unticked box that waits on an observation names its command as ``Observe: `CMD` `` on its line. `north task check [--dry-run] (--body-file FILE | REPO#N | --repo OWNER/REPO)` runs each such command on the host it runs on, ticks the box with `Evidence: ` and the date when the command exits 0 and leaves it open otherwise, and edits the issue body (`--dry-run` and `--body-file` print the edited body instead). Run it from a timer on the host that can see the observation.
- Tom digest: `north digest [--since 24h]` reads the fleet store and prints four sections in order, each with its count: what landed in the window (task, short sha, age), the sessions in flight on every host, the open gates with the option their opener recommends, and stalls (a working session with no update for 2 hours, a starting one past the launch grace, a gate past its default time). Run it on request and after each usage reset.

## Machines, capacity and scheduled jobs

- Product verification: `verify-north` builds north from the checkout around the current directory (or takes `--north PATH`), then in a 160x45 tmux terminal opens `north fleet`, launches a Claude haiku session from the Ctrl+N form, checks an Alt+U urgent answer within 10 s during a running `sleep 120`, a Ctrl+G deepen run in the ledger, a Codex `fleet ask`, and a `north task check` verdict; a separate cleanup process forgets its sessions, kills its terminal and asserts none of its session hosts or app-servers survive, even when the run is interrupted. One line per step with wall ms; nonzero exit on any failure.
- Fleet landings: fleet exports `NORTH_FLEET_SESSION` to every command a session runs, `safe-push` logs that name in `pushes.tsv` with the default-branch commit it landed, and north records that commit as the landing of the session's task (its `--task`, else the session name) when each turn ends and every 30 s while the fleet screen is open, so `north task landed` is optional.
- Fleet receipts: `north fleet launch` makes the calling session the new session's parent, or the `proxy` session for a launch from outside the fleet, unless `--parent` says otherwise. When a child ends a turn that landed a commit or whose reply opens Done, Not done, Split, Stop or Blocked, its host queues one `[from NAME · turn N · exit E · landed SHA]` message with the reply to the parent; other turns stay in `north fleet show NAME` without waking it, a failed turn arrives with its transcript tail and a host death arrives urgently. A gate the child opens reaches the parent as one line; one opened with `--issue` holds that issue from dispatch and launches until `north gate answer` closes it and the child receives a `[gate ID]` message. The ledger claims each notice once, so a restart never resends one, and `--test` sessions keep their gates out of Tom's digest.
- Runtime promotion: every host runs origin/main's north within minutes of a landing, and rolls back on its own when the new runtime cannot run a land check. After a north landing safe-push runs `north runtime follow`, and each host's `north-runtime-follow` timer runs `north runtime update`, which pulls or builds the runtime, swaps `current` and swaps back with an alert to the proxy when `north runtime health` fails. On the host that settles the fleet, `north runtime settle` judges each landing live on every host by `landing_live_deadline_sec` and runs one canary land check per promoted SHA on each host, calling `north runtime rollback` there when it fails. See `north runtime --help`.
- Landing watch: safe-push appends one JSON line per stage end, known wait, retry, failure, refusal and landing to `~/.local/state/safe-push/events.jsonl` and starts `north watch --once` on any failure or refusal; the `north-watch` user timer runs it too. Each pass gathers those events, the queue, live safe-push processes, runtime settle results and GitHub Actions runs, and the probes listed in `PROBES` (`crates/north-landing/src/watch/mod.rs`) raise alerts on landing and CI trouble. `crates/north-landing/src/watch/sink.rs` sends each new incident once to the proxy and the owner's lead, repeats it while it lasts and says when it clears; `north flow` prints `landing watch: silent` when the watch heartbeat goes stale.
- Orphan lease reaper: `north capacity reap-orphans` stops the scope of every run lease whose wrapper process is gone, so no Warcraft client or run outlives its runner and the lease's slot frees; it is the stop half of the laptop's `laptop-auto` tick and needs no `laptop` command, so gex45, which has no such tick, runs it from the `lease-reaper` user timer every 30 s (south `modules/lease-reaper.nix`, imported by `hosts/gex45/configuration.nix`) (north#191, north#335).
- Capacity estimates: `machine-capacity estimate -- CMD ARG...` predicts a command's cores, peak memory, I/O and disk busy share from its newest matching measured runs (`capacity_sizing_runs`), falling back from the exact signature through owner, family and repository to the declared class, and prints the match level and confidence (`capacity_high_confidence_runs`). An expensive target with no history of its own stays heavy at low confidence. Admission reserves from these estimates with `capacity_memory_margin`, and status and probe publish the committed totals the spawn gate reads.
- Resource model: every finished capacity run records its command key, host, cache state, queue wait, memory peak and stall, whether its memory cap censored it, and what admission predicted. Successful runs feed a per-host model at three levels (exact command and cache state, exact command, owner and shape), and admission sizes a command's memory from the answering level once it has enough runs (`capacity_memory_margin`); a key with no level reports `unknown` instead of borrowing a wider estimate, and a censored run only raises the key's memory floor. `north capacity model [KEY]` prints the levels and `north capacity calibration` prints predicted against actual wall time and memory per key and host, flagging drift.
- Nexus RAM and CPU stalls: `north nexus-ram record` (Nexus minutely timer, nixos-config `modules/nexus-ram`) appends one row to `$NEXUS_RAM_DIR/YYYY-MM-DD.jsonl` (UTC day, default `~/.local/state/nexus-ram`): MemAvailable, swap, zram used and compressed, memory PSI some/full avg60, resident agent CLIs (top-level interactive claude and codex; `-p`/`--print`, codex `exec`/`app-server`/`mcp-server`/`cloud` and `--cloud` excluded) and their process-tree PSS, plus since the previous row `gap_s` (wall seconds), `steal_pct` (steal share of `/proc/stat` cpu jiffies), and `cpu_psi`/`io_psi` (avg10, cumulative `total` microseconds and their deltas); the first row and a counter reset after a reboot record null. `north nexus-ram report [--days N]` (default 7) prints p50/p95/max agent CLIs and PSS, min MemAvailable, PSI-full minutes, minutes with steal over 20%, the longest row gap, OOM kills from the journal and one verdict: UPGRADE when on 3 or more days MemAvailable stayed under 600 MiB or PSI full avg60 over 1% for over 10 minutes, or an OOM kill hit an agent; otherwise STAY. Test inputs: `NEXUS_RAM_DIR`, `NEXUS_RAM_PROC`, `NEXUS_RAM_ZRAM`, `NEXUS_RAM_NOW`, `NEXUS_RAM_JOURNAL`.
- Rest check: `north capacity watchdog rest-check [--seconds N] [--expected FILE] [--observed FILE] [--save FILE]` compares running system and user services and scopes, active timers and listening sockets (`PROTO ADDR:PORT UNIT`, `-` for a gone creator such as kernel WireGuard) with the host's expected-at-rest set (`~/.config/capacity-watchdog/rest.json`, declared in firn as `myConfig.modules.capacity-watchdog.rest`), measures each unit's CPU and context switches over N s (default 30), prints extra units, sockets and over-budget units, lists claude/codex/tmux sessions as agents, and exits 1 when anything is not at rest.
- Poll loops: `poll-loop-guard` (Rust PreBash, Claude Bash and Codex exec) refuses a foreground call that can wait over 60 s in `sleep` or in an `until`/`while` loop that sleeps, unless `timeout` or the tool's own timeout bounds it at 60 s; the refusal names `job-run --notify` and Monitor. Background calls pass, since their exit notifies the session.
- Farm-only commands: `heavy-command-guard` reads `.agents/farm-only.toml` at each command's Git root. Each `[[command]]` declares leading `pattern` words (mode flags match in any order after the verb), `narrowing` flags and `narrowing_env` environment variables (set non-empty before the command) that permit local work, and a `farm` command with `why`. Whole-roster matches are refused even inside `machine-capacity run`; missing or malformed declarations leave existing capacity checks in place. Claude Bash and Codex exec payloads share this identity.
- Scheduled job runs: `job-run [--path DIRS] [--user USER] [--notify] NAME -- CMD...` wraps a timer's command, records its start and finish (name, host, started, finished, rc) through `threads job-run` (spooled while the remote ledger is unreachable) and exits with the command's code; `--notify` instead detaches the command into its own session with its output in `~/.local/state/north/jobs/`, returns at once and sends `job-run: NAME exited RC` to the fleet session `$NORTH_FLEET_SESSION` when it ends (the session host reads the job's JOB-START lease with `north fleet row leased SESSION` to know a quiet child waits on it, and `bin/job-run` writes no `.job` record), so an agent ends its turn and wakes on the result, and the job outlives a subagent's teardown; `threads job-runs` shows runs, failures and the last rc per name and host. Firn's `jobRun` helper wraps every registry timer.
- Overdue jobs: `north job-watch run [--registry DIR] [--peers FILE] [--state FILE] [--dry-run]` (nexus, every 15 min) reads registry routines with a `placement` and `deadline`, `threads job-runs --json` and WireGuard presence from `/run/nexus/peers.json`, and sends one normal (priority 2) alert per job when it becomes overdue (a laptop job also when the laptop has been online period + 30 min with no success), repeats at most daily and sends a normal note on recovery; `JOB_WATCH_TOPIC` overrides the topic.
- Private checks: `north private-check` runs the checks of `north-data/private-checks.toml` that need a GPU or private art and so cannot run on hosted runners or in the farm-runner containers. Per check it fetches the repository's origin/main into its own locked worktree, skips a tip already judged or one whose diff touches none of the check's paths, runs each step under a machine-capacity lease and posts the verdict as a GitHub commit status; a step capacity never admitted posts nothing and is retried on the next run. `--dry-run` prints the status requests instead of posting. The config schema and verdict rules are in its usage text.
- Queued laptop jobs: `threads queue add` queues work for a machine that may be asleep, `take`, `msg` and `drop` claim, settle and withdraw it, and `threads queue` lists jobs with their waits and, for a job left waiting, which host last polled for its placement. `north laptop-runner` (a laptop timer, also run on Nexus) claims jobs for its placement, plus the shared `pool` placement on AC power with room for a heavy lease, from its own ledger and every other fleet machine's, runs each through `job-run` and records the result on the job's issue. `north laptop` is the single writer of the laptop's availability; the runner takes `laptop` jobs only while it is available and requeues a running job once a drain's grace ends. See `north laptop --help`.
- Battery shed: while the laptop runs on battery at any charge (`/sys/class/power_supply`, or `AGENT_LOAD_POWER_SUPPLY`), each `north capacity laptop-auto` tick holds laptop placement as `draining` with reason `battery` and freezes heavy batch leases through the `pause-heavy` effect in `agent_load::enforce` (the effect play mode also applies while its CPU split is not enforced), and the charger-lost alert and UPower warning steps follow the same decision. On battery means the system battery discharges and every Mains or USB line supply reads offline, or it has discharged on every tick for 120 s while a charger stays online (one that renegotiated to too little power), so a charge controller's few-second Discharging flicker under its limit sheds and alerts nothing; `battery-discharging-since` under the capacity dir holds the first discharging tick, and `LAPTOP_AUTO_NOW` injects the clock. The first tick on AC thaws them and returns placement to the window state. `north fleet launch --local REASON` is refused there with the battery's charge and the machines and `anthropic-cloud` that take the box instead, unless `--pin "REASON"`, which the session records beside the `local:` reason.
- Peer forced command: a peer host's ssh key runs `north remote-serve --peer HOST --repos REPO,...` as its forced command, which lexes `SSH_ORIGINAL_COMMAND` without a shell, admits only allowlisted verbs, and then guards them for that peer: `threads queue add` and `job-run --host` must name the peer, `queue take` only the peer and `pool`, `queue msg` and `drop` only the peer's own jobs and a `failed` or `requeued` message only on a granted repository, no `queue follow` step, every item ref only in a granted repository, and every `fleet row put|exchange|register|wait|settle` runs with `--peer HOST` forced. A refusal exits 126; every call, admitted or refused, appends one row (verb, refusal, exit, milliseconds) to `~/.local/state/north/remote-serve/HOST.jsonl`. `north remote-serve audit --peer HOST` counts the calls, refusals and failures in that log and prints the key's days to its `expiry-time` in `~/.ssh/authorized_keys`.

## Development tools

- Dependency sandbox: `depbox fetch|run -- CMD...` runs installs, builds and tests in bwrap with the home directory masked except the checkout (read-write), the package and build caches it needs and the immutable firn and north pins (read-only), a scrubbed environment, no sudo and, under `run`, no network. Each checkout builds into its own `target/`, because cargo hashes a path package by its workspace-relative path and worktrees sharing a target directory would run each other's outputs. Before the sandbox starts, depbox roots the checkout's `nix develop` shell so `nix-collect-garbage` cannot delete it and break offline runs. It mounts the checkout a second time at `~/code/<project>/sandbox` and runs there, so every lane of a project builds at one path and a seeded `target/`'s incremental state stays valid (a one-line north-core change built in 14 s seeded this way against 112 s from another lane's path, 2026-11-05). The exact mounts are in `bin/depbox`.
- Retention: `north retain`, run on the laptop, archives the GPU host's expired makgora evidence, capture batches and unpinned build-input store versions into `~/archive/makgora-gex45/`, verifying every file's sha256 against the source before it deletes the source, and stops starting new batches once its time budget is spent. Ages and budget are the `evidence_retention_hours`, `capture_batch_retention_hours`, `build_input_retention_hours` and `retention_budget_minutes` keys in `harness/defaults.toml`. A folder holding a `PINNED` file, held open by a process, holding a socket, fifo or device, or whose copy differs is kept, and when makgora's pins cannot be read no store version is archived. Flags are in `north retain --help`.
- Disk budget: a host's `[hosts.NAME.disk_budget_gib]` in orchestration.toml gives each store on its shared root disk a GiB share (`cargo_target` for each shared cargo target `north reclaim` and `north land-clean --sweep` trim, `map_store` for wisp's per-host map-build store, `makgora_evidence` for retained Mak'gora evidence, `mutant_cargo` for the mutant step's cargo target `north reclaim` trims, `capture_batches` for the capture queue's batch folders `north reclaim` deletes oldest first once a day idle with their results kept, never one with a queued or running job, a `PINNED` file or a holder); every sweep reads its cap from it, and a store whose share is unset keeps its built-in cap (10 GiB per cargo target and mutant target, 8 GiB map store, `evidence_budget_gib`, 15 GiB capture batches). `north capacity disk-share SHARE` prints this host's share in GiB (nothing when unset), which wisp's map store reads.
- Lane target seed: `north target-seed [DIR]`, run by the devShell hook and by `depbox` before its sandbox (which hides `north` and the sibling checkouts), gives a checkout with no `target/` (and no `CARGO_TARGET_DIR` other than its own `target`, as the land checks set it) a `cp -a --reflink=auto` copy, `incremental/` included, of the newest idle `target/` of the same container's `main` or `worktrees/*` that holds a `CACHEDIR.TAG` and a byte-identical `Cargo.lock`, then deletes the fingerprints of every `Cargo.lock` package without a registry or git source so those rebuild; a sibling whose `.cargo-lock` is held mid-build is skipped (compile-times.md, "Measured: a new lane's first build").
- Compiler cache: every user session on the laptop, gex45 and ccx33 exports `RUSTC_WRAPPER` as the firn module `sccache`'s wrapper, with its local disk cache in `~/.cache/sccache` capped at 30 GB (`SCCACHE_CACHE_SIZE`). On the laptop a shared level sits behind it: an rclone WebDAV store on nexus, capped at 20 GiB and open only to the wg-nexus peers. gex45 and ccx33 stay off that level until it serves from Finland, because from there a hit cost more than a compile. The wrapper roots `SCCACHE_BASEDIRS` at the checkout that rustc writes into, with one sccache server per checkout, so worktrees share Rust entries too; CMake uses the same wrapper as its compiler launcher. A local nginx relay answers every failure of the store as a miss within 3 s, so a nexus or network outage leaves builds on the local disk. `depbox run` passes the variables and binds the cache directory, and its network-less sandbox reaches the relay through `/run/sccache-remote/http.sock`; `depbox fetch` does neither. sccache skips incremental crates, so each project keeps its `CARGO_INCREMENTAL`.
- Build-cache gate: `north build-cache-gate --repo DIR --base REV --head REV`, which safe-push runs beside the language gate in every repository, refuses a landing whose added lines turn the rustc wrapper off (`RUSTC_WRAPPER` set empty, unset or removed, an empty `build.rustc-wrapper`) or set `CARGO_INCREMENTAL`, under which sccache 0.15 refuses every compile; a `Build-cache-off: REASON` trailer in the landing records why and lets it pass. Build incrementally with `CARGO_BUILD_INCREMENTAL=true`, which sccache accepts. A Wisp change of 2026-11-01 had emptied the wrapper for the window library build and recompiled every registry crate on gex45.
- Evidence budget: `north reclaim` and `north evidence start RUN` (which then creates and prints `~/.local/state/makgora/evidence/RUN`) keep the Mak'gora evidence store under the host's `makgora_evidence` disk share (`evidence_budget_gib` in harness/defaults.toml when the host names none) by deleting whole run folders oldest first, never one changed within `evidence_min_age_hours`, held open by a process, holding a `PINNED` file or named as `evidence/RUN` in an open makgora, north or wisp issue or comment; when those issues are unreadable it deletes nothing. When capacity admission would return `DEFER_DISK_FREE` on a disk it measured itself, it first runs every `north reclaim` sweep once (at most once per `disk_reclaim_cooldown_minutes` on the host), measures again and decides on what is left.
- Dedicated automation Chrome: `automation-chrome start` starts or reuses persistent headful Chrome on the private desktop, with a separate state profile and loopback-only CDP. `automation-chrome tool` takes a JSON action on stdin for opening, screenshots, click/type, page text/JavaScript, close, and secret transfer between fields without returning the value. `stop` preserves the profile. Install its pinned dependency with `bun install --frozen-lockfile --cwd lib/automation-chrome`. Claude and Codex use the automation-chrome skill for web UI work.
- Effect kit: `effect-kit init|check|sync|upgrade|scan [ROOT]` (in `agent-machinery/scripts/effect-kit.mjs`) keeps one setup in every TypeScript project that depends on `effect`, configured by its `effect-kit.json`. `check` fails on drift between the vendored `repos/effect.json` version and the lockfile's `effect`, any Effect language-service diagnostic (all count at error severity), a plugin that ignores them in the exit code, or a raw spawn, timer, promise or fetch outside Effect in host tools, and prints the counts. `init` vendors upstream at the installed version and sets the plugin, `sync` moves the vendored copy, `upgrade` bumps Effect packages to the newest stable release at least 7 days old, and `scan` lists `ROOT/*/main` projects (default `~/code`) that depend on `effect` without `effect-kit.json`.
- Code health: `code-health` (in `harness/code-health/`) measures hand-written TypeScript, JavaScript, Rust and C against the repo's committed `structure.toml` through `ast-grep`: file and function size, complexity, import cycles, layer violations, fan-in and fan-out, co-change and churn hotspots. `gate BASE HEAD` refuses new debt and lets existing debt stay put, `check FILE` applies the same rules to one dirty file, and `signal` says when a recurring review is due; the `code-health-tick` timer then starts a uniquely named review session per repository. `north health` reports a `capacity-watchdog` timer whose service keeps failing and opens a north issue for it. Subcommands and flags are in `code-health --help`. `north code-health crate-lines [--repo DIR] [BASE HEAD]` (bare `north code-health` runs it on the worktree) prints each workspace crate's non-test Rust lines against its `structure.toml` `[crate_lines]` cap (10000 for a crate with 3 or more in-repo dependents) and, given BASE HEAD, exits 1 when a crate over its cap grew or a new crate is over, naming the crate the new code should go to; the `crate-lines` after-landing gate runs it (`docs/rationale/crate-split.md`).
- Rust build times: `north code-health build-time` times a cold `cargo build --timings` and the median of one-line edits in a leaf and in the most-depended-on module, in a scratch target without sccache, appends a row with the host load and the effective `build.incremental` and debuginfo, each with the env var or config file that set it, to `~/.local/state/north/build-times.tsv`, and exits 1 when the leaf-edit `cargo test --no-run` exceeds 10 s, a cap a `[[build_time]] test_no_run_seconds` in `structure.toml` may only lower; a run above the workspace's `contention_ceiling` is `contended` and judges nothing. With `--file` it keeps one box per workspace near or over the cap in the "Split north-core" section of north#259 and ticks it once the workspace is within. gex45 runs it daily for north (`build-time.timer`); method and the measured table in `docs/rationale/rust-build-times.md`.
- Rust habits: `north code-health habits [--repo DIR]` exits 1 with one line per `Rc<RefCell>`, `RefCell` or `Arc<Mutex|RwLock>` in non-test Rust and per trait with exactly one non-test implementation and no test double, unless a `[[rust_habits.allow]]` entry in `structure.toml` names the rule, file (and trait as `item`) and a reason; it also flags allow entries that match nothing. It runs only where `structure.toml` has a `[rust_habits]` table, gates landing through the north-core test `the_north_tree_keeps_its_rust_habits`, and the PostToolUse code-health edit guard reports the same findings for the edited file; workspace clippy lints `redundant_clone`, `implicit_clone`, `unnecessary_to_owned`, `redundant_allocation`, `rc_buffer`, `rc_mutex` and `cloned_instead_of_copied` refuse wasteful clones and allocations.
- Features index: `north docs features-index` regenerates `docs/features.md` from the one-file-per-feature tree under `docs/features/` (`_header.md` for the text above the first section, one `NN-name` directory per section holding `_title.md` and one `NNNN-name.md` file per entry, all joined in name order with a blank line between entries unless both are list items); to add a feature, add a file under the section's directory, never edit `docs/features.md` by hand. `north docs rationale-index` writes `docs/rationale/README.md`, one line per note with its title, link and first sentence. `--check` fails when the index is stale, which is also a land check for each, and `--root DIR` names the checkout. Both indexes are `regenerate` entries in `harness/merge-sets.toml`: when a rebase or cherry-pick stops on one, `north merge-driver continue` runs its generator on the merged sources, stages it and continues, which safe-push and the lander do on their own; the lander also regenerates an index after each lane that changes its sources (`sources` in that file) without committing it, folded into that lane, so batch-mates never make each other stale.
- Stub-exec gate: `north land enqueue` refuses a landing whose changed Rust files under `crates/`, `src/` or `tests/` make a file executable outside `north_base::foundation::shim` (a `from_mode(0o7..)`, a local `fn executable(path: &Path, ..)` or an `fs::copy` of a built or `bin/` binary) and are not in the `.stub-exec-allowlist.json` the landing carries, or that leave an entry whose file no longer needs it; a repository without the allowlist is not judged. The `stub_exec_policy` test checks the whole tree against the same list in the lander. A stub written in the test process can be inherited writable by a concurrent fork and fail to exec with `Text file busy`; from 2026-11-04 to 2026-11-05 lanes that missed the policy were refused 6 times after a full lander precheck, 2 of them candidates stacked on another lane's stub (north#360).
- Enqueue clippy: `north land enqueue` runs the repository's listed `cargo clippy` land check on the lane's affected crates (`SAFE_PUSH_LAND_PACKAGES`, the changed packages and their workspace dependents, as the lander computes them) under the land capacity lease before it writes the ticket, prints its diagnostics and refuses the lane on any warning; a repository whose clippy check is only inferred, or a lane that touches no Rust input, runs none. The last 8 land-check failures before it were lanes' own clippy errors found after about 40 min queued (north#259).
- Layer gate: `north code-health layers [--repo DIR] BASE HEAD` reads HEAD's `structure.toml` and exits 1 for each reference a changed Rust file adds, as a `use` item or an inline `crate::`, `self::`, `super::` or crate-name path, that breaks a `[[module]]` `may_use` rule (`✗ layer`) or the planned crate DAG in `[[crate_dag.crate]]` (`✗ crate-dag`, the twelve-crate plan of `docs/rationale/crate-split.md#next-cuts`, transitive, crate roots exempt). A reference the file already made on BASE, even after a rename, stays put. It runs as a land check over the whole diff, so a breach is refused before landing, not only at edit time.
- Crate split: `north split move-module [--dry-run] [--from FROM] --crate CRATE [--allow-test-item NAME]... [--target-dir DIR] MODULE...` moves one or more modules (`tui`, `ops/tempo`) out of `crates/FROM` (default `north-core`) into the sibling crate `crates/CRATE` as byte-identical `git mv` renames, writes that crate's `Cargo.toml` with exactly the in-repo and workspace crates the moved files name and its `lib.rs` as re-exports plus a `mod` list, wires the workspace and the root callers, rewrites path mentions except in `*_tests.rs` and `fixtures/`, adds the paths to the moved module's `structure.toml` entry without widening any `may_use`, widens only what `cargo check` names as private, refuses a `#[cfg(test)]` item unless `--allow-test-item` names it, ends with `cargo test --workspace --no-run` and the new crate's tests, and prints one `Dependency:` trailer per added dependency; a second run is a no-op. Method in `docs/rationale/crate-split.md`.

## Wisp payoff

`north wisp payoff [--since YYYY-MM-DD] [--json]` reads retained Mak'gora evidence, Wisp state, and Wisp evidence/build directories without creating a store. It prints per-kind UTC Monday weeks, completed comparison agreement, invalid native attempts, native client-minutes, Wisp main commit counts, retirement candidates, and disagreement evidence paths. JSON includes each contributing run for audit. The fleet Ctrl+T digest refreshes its summary in background upkeep.

Pad families use their script directory (standalone pads use their name). Pad client-minutes count two clients over game, reset, reload and run time; Wisp, comparison and wait time are excluded. Acceptance report elapsed time is divided equally over checks and marked estimated. Batch dates use file modification time because the format has no timestamp. PASS and FAIL count as comparisons only when both headless and comparison ran; INVALID never counts as disagreement.

Retire candidates have at least ten agreeing comparisons and zero disagreements across the last fourteen days, independent of the display filter. They select Wisp-only evidence with a one-in-ten native sample. The weekly projected sample saving is 90% of those kinds’ historical native minutes, a counterfactual estimate. Actual avoided minutes, closed Public 0.1 boxes, native minutes per closure and Wisp-only closure shares remain unknown when retained evidence lacks closure provenance and skipped-run records. Do not equate projected savings with observed payoff. The command never files issues or sends messages; its evidence paths support deduplicated issue filing and planner handoff.

The planner contract is `schema_version: 1`. `families[]` is computed from the full rolling fourteen-day window even with `--since`. Each entry has `id`, `match_rule: {kind, values}`, `verdict` (`wisp-only` or `native`), `native_sample_rate` (0.1 or 1.0), `counts`, and inclusive `window_start_unix` / `window_end_unix`. `parent-directory` matches an immediate POSIX dirname in `values` and a `.pad` basename; `exact-path` matches a whole path in `values`; `none` applies to accept checks, not scripts. Unknown or ambiguous matches select native. Paths are repo-relative POSIX strings; reject absolute paths, backslashes, and dot segments. Headless-session batches are excluded regardless of their comparison message.

Sampler `sha256-first-u32be-mod10-v1` hashes UTF-8 `scriptPath + "\n" + fullSourceRevision`, without a trailing newline. Interpret the first four SHA-256 bytes as an unsigned big-endian integer and take modulo ten. Select native when the verdict is `native` or that bucket is zero. JSON `sampler` carries the identity, exact input description and a test vector. This gives identical reruns the same sample and prevents display filtering from changing routing.
