# Choosing evidence

## Claim before instrument

A check is useful when a pass and failure select different immediate actions.
Start with the requested artifact and exact bounded claim. Unknown exposure
means owner-controlled research, not an inferred production obligation.
Generalized assurance needs explicit instruction or a concrete consumer/boundary.

## Vocabulary, not a ladder

| Context | Candidate evidence |
| --- | --- |
| Explore a thesis | cheapest discriminating falsifier |
| Deliver a reversible change | nearest deterministic seam or controlled integration |
| Stabilize a cross-cutting change | affected suite/shard and any required journey |
| Authorized release boundary | exact-commit local non-publishing preflight |
| Named irreversible/security risk | targeted evidence for that failure |

These labels do not automatically select every mechanism in a row. An existing
real repository gate remains binding; no label weakens it.

Instrumentation ranges from a pure parser/rule seam (L0), through controlled
integration (L1), to a named end-to-end journey (L2) and exact-commit release
preflight (L3). Choose the lowest layer that actually decides the claim.

## End-to-end versus component evidence

Freeze the smallest useful operator journey before implementation and run it
once safely runnable. Component fixtures help identify their own seams but do
not prove that the combined journey works. Extra fixtures after the required
pass do not strengthen a claim that needs no further decision.

Control only verdict-sensitive inputs: actual launcher, directory, environment,
executable, TTY/login semantics, and mutable fixture state. A wrapper changing
one of those can invalidate the observation. Repair the driver, not the product,
from that evidence.

## Provenance and performance

Require provenance when producer substitution changes the decision. Verify the
existing producer → artifact → consumer edge; do not recursively attest
attestors or invent a ledger for an unresolved metadata gap.

For performance, define the metric and threshold before measuring. Compare
matched instrumented/uninstrumented runs before blaming probe overhead.
Public history repair, when explicitly authorized, retains one chronological
tag-to-release mapping; failed candidates consume no final version.

## Stop after the decision

Do not add broad suites, hermeticity, compatibility, remote-CI waits, manifests,
or independent confirmation merely for reassurance. Each may be useful at an
actual boundary, but eligibility is not an assignment. Report unobserved
dimensions as uncertainty instead of manufacturing more work.
