# Build or reuse

1. Separate distinctive behavior from supporting machinery.
2. Compare adoption, configuration, extension, fork and local implementation on fit, integration, ownership, migration, licensing and replacement cost.
3. Use `prior-art` for unknown options and `external-code` before derivation.
4. Define the local implementation's interface, replacement boundary and falsifying check when it wins.

Read [option worksheet](references/notes.md) when comparing candidates.
