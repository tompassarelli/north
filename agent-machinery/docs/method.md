# Composition method

Route from the deliverable shape, then set the other axes independently.
Repository location and felt difficulty are weak proxies; decision ownership,
seams, error exposure, oracle strength, and dependency shape determine the
minimum capability floor.

Templates cover recurring contracts. A bespoke composition is appropriate
when responsibility, deliverable, topology, capabilities, done criteria, or
report shape differs. Repeated successful bespoke use is evidence for a later
explicit template change, never automatic promotion.

Template identity is provenance metadata inside `composition`; it is
independent of the request's role and contributes no ownership or authority.

Generated templates flatten role, grade, topology, posture, capabilities, and
communication source blocks. They omit concrete providers and models because
those are resolved at run admission from the selection catalog, empirical
evidence, and the consumer's live inventory. Consumers execute that plan; they
do not layer a second model mapping over it.

Each generated template also states effective filesystem authority. Treat
capability implications as authority: search includes read, unrestricted shell
includes read/search/write, and read-only shell is usable only where shell
writes are denied. An unenforceable mapping fails closed.

A task brief identifies an inspectable result and an observation capable of
refuting completion. The final response separates direct observations from
conclusions and discloses unfinished work that materially changes the result.
