Usage: safe-push [--dry-run] [--to BRANCH] [--keep-lane] [--message FILE | --several-commits REASON]
       safe-push [--dry-run] --tag NAME
       safe-push [--dry-run] --delete-tag NAME
       safe-push abandon [BRANCH | scratch/NAME | --superseded BRANCH [--by COMMIT]]

Scan secrets and private values and run the landing checks, then push the current
branch or one tag. Process gates (code-health, instruction limits,
generated rewrites, CI budget) run after a landing on the default branch
and file one issue per landed commit.
Repository AGENTS.md: 100 lines.
Move longer detail to CLI --help, help TOPIC, or indexed docs.

Options:
  --dry-run    run all safety checks without pushing
  --to BRANCH  explicitly publish HEAD to a remote branch. On origin's default
               branch the lander lands the lane: north land route queues it
               when this host is landing.lander-host or in landing.remote-hosts
               (the committed .safe-push first, then this host's git config),
               and refuses any other host, a landing.queue other than lander,
               and --direct; the lander checks, squashes and pushes the queued
               lane and reports the landing;
               a BRANCH other than origin's default (farm/*, scratch) publishes
               through north land push: no lock, no queue and no rebase (an
               origin BRANCH that is not an ancestor of HEAD is refused), and
               the hook runs in its own push
               (.safe-push land.check entries replace the hook; with
               land.workflow set, each check not in land.local-only or
               land.machine-bound, written REASON :: COMMAND, runs as a job of
               that GitHub Actions workflow; a land.machine-bound check runs on
               the land.runner build host, a land.local-only one here)
  --keep-lane  with --to main from ~/code/<project>/worktrees/<slug>, keep the
               lane and its branch after the lander lands it, and keep the
               cargo target its land checks otherwise remove
  --message FILE
               with --to main, the message of the one commit the lane lands as
               (default: the first lane commit's message, the other subjects
               listed below it); the lane's trailers are appended, de-duplicated
  --several-commits REASON
               with --to main, land the lane's unpublished commits as they are
               instead of as one commit; REASON travels with the lane's ticket
  --tag NAME   push an existing annotated tag after scanning new content;
               a v* tag is refused: north release publishes it with its
               GitHub release
  --delete-tag NAME
               delete a tag from origin once its commit is on origin's default
               branch or held by a ref in the lane-gc mirror for this
               repository ($LANE_GC_MIRRORS or
               ~/.local/state/agents/lane-gc/mirrors/<repo>.git); a v* tag
               (a release) is refused
  -h, --help   print this help without inspecting a repository
  abandon      delete this lane's claude/land-<lane>-<sha>, or a claude/*
               BRANCH, from origin once main holds each of its commits by
               subject or patch or Autoland handed it back (a failure or
               error status); with --superseded, a claude/* or
               farm/* BRANCH goes only once each of its commits is on origin by
               subject or patch, whatever Autoland reported; with
               --superseded BRANCH --by COMMIT, any branch but main, master,
               gh-pages and release/* goes once COMMIT, named as the change
               that supersedes it, is on origin's default branch; a scratch/NAME
               goes once this session pushed its tip, the session that pushed
               it has exited, or it has been untouched for a day; any other
               branch is refused

On the default branch, plain "safe-push" lands it as --to that branch. On
any other branch, plain "safe-push" (no --to/--tag) is refused —
one-branch-main doctrine: origin carries the default branch only. Publish
with --to main, or --to another branch as a deliberate escape hatch.

Generated records opt in through committed .safe-push:
  [generated "path/to/record"]
      input = path/to/primary-source
Repeat input for each exact tracked primary file. The base/head inventory union
counts changed file blobs; private external assets are outside this guarantee.
Rewriting over half the old rows with fewer than 5% of those files changed, or
missing enabled input authority, is reported after landing; undeclared files pass.

Each running safe-push needs its own output log file; a second one writing to
the same file is refused.

A landing on origin's default branch runs the after-landing gates in the
background (log ~/.local/state/safe-push/after-landing/), and with them each
  [after-landing]
      check = NAME :: COMMAND
in the landed .safe-push, run with sh in a detached tree of the landed commit;
each failure goes into one issue for that commit with its output's tail, and
nothing is refused or reverted.

A landing on origin's default branch runs follows-release, which starts each
queued Follows box (threads queue follow) whose predecessor is now on it.

A clean lane landed with --to main is removed afterwards (git worktree remove,
then git branch -d), and its same-named origin branch is deleted when main
holds all of it.
