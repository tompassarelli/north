# Workers

**Throughput is lost to serialized long waits (farm runs, soaks, renders, landings), not to thinking.** Each tick, cut the longest wait on the critical path: batch ready lanes into one landing, run independent unknown-cause hypotheses in parallel (a `Done: ruled out` with evidence closes one), render 2–4 variants and judge them once, and send code-only work to cloud workers first. While a repository's landing queue grows (`agents flow`), widen its landing path before adding workers, because more lanes only lengthen the queue. Key every generated record, digest and gate only to the inputs it checks, so landing unrelated work never invalidates another lane. Hand Tom the artifact he is waiting for the moment it is usable, and run checks that cannot change it afterwards; only release and landing gates block, and a native capture is never one (see warcraft-modding).

Every rule here holds on any provider unless marked Claude-only, so the provider seam survives a provider switch. Tom has staffed Claude alone since 2026-10-16 (standing order: no Codex subscription for the foreseeable future), and `agents plan` routes each box to the provider and account with headroom.

## Staff

- The proxy coordinates fleet sessions directly. Set `--parent` when launching a child; `north fleet tree` shows the org. A lead exists only for a multi-session workstream. Message a session with `north fleet send NAME TEXT...`, or with `north fleet ask NAME QUESTION...` when you need an answer.
- Choose provider and fast mode with `agents plan`, which reads the signed-in providers and live `agents usage` headroom, never by hand, because hand choices drained the wrong account. `north worker-ledger --recommend '<Category and facet lines>'` picks the tier; `north worker-ledger --summary` shows each category's success.
- For each Done when line, the box's writer names the existing property, replay or golden test that covers it; a new example test needs a one-line reason. The first Done when line of every brief is an oracle: an observation outside the agent naming the artifact or state and the pass condition, and the agent attaches the observed result, because a claimed pass is not evidence.
- Queue each box that waits on another lane by piping its brief, carrying `Follows: <commit subject, SHA or Item>`, to `threads queue follow <repo#N> --tier <tier> --parent <your Fleet session name>`, so the predecessor's landing starts it instead of someone noticing.
- Check `threads list` and open issues first and never duplicate a held item; pick ready work with `threads ready` and read its Done when with `threads show repo#N`. Claim shared-resource work through `threads`; a running worker's brief is its claim.
- Brief: Item, Category, goal, files, Sources (the decisive authoritative plan, spec, data or code; a summary only with a pointer to what it digests), Methods (only when the choice changes correctness), Done when, ETA, facets `Spec: exact|measured|judged`, `Scope: one-file|module|cross-module|cross-repo`, `Surface: ts|rust|lua|nix|shell|workflow|docs|assets`, `Verify: none|local-test|farm|native|visual`, and the state checked at spawn (main SHA and CI, lane SHAs, what landed). Size each brief to one box of 20 minutes or less and name the reason for a longer ETA. Take the ETA from the `eta` line of `north worker-ledger --recommend`, or write your estimate followed by `(uncalibrated)` when it prints `eta n/a`. One task per worker and one worker per scarce client or device instance, because shared instances corrupt each other's runs. Research Tom asks for inline is timeboxed at 5 minutes and ends by offering a deeper pass with its own ETA.
- Category: mechanical, docs-policy, tooling, feature, bug-known-cause, debugging-unknown-cause, netcode-determinism, performance, balance-tuning, native-check or research. `the Codex brief check in crates/north-core/src/router/brief.rs` reads only the lines before the first blank line, so put Category, the four facets, `Done when:` with a backticked command, `ETA:`, `Files:` and any `Follows:` there.
- A bug brief's Done when covers every instance of its `Class:`, not the one symptom seen.
- Claude-only: call `Agent` workers with `run_in_background: true`, retries and escalations included, so the launch result records the original brief with the actual child identity.
- Start each retry, escalation or continuation as a fresh worker whose brief carries `Follows: <earlier agent id and tier>` and the failed evidence. Send a running worker only its own task's follow-up, and never revive a finished worker by message, because its context is spent on the old attempt.
- Workers on native items (life, accounts, travel, ops) report with `threads note REF TEXT`, never issue comments, because those items are private.
- Staff from the tiers below. Never use Sonnet other than sonnet-high or Opus low, and use Fable only when Tom names it; Codex tiers are in [codex-sessions.md](references/codex-sessions.md).

- Start known-cause bugs and art (animation authoring and judging, `Spec: judged` art boxes) at `sonnet-high`, because Sonnet finished 80% of known-cause bugs against Opus 61% (Tom, 2026-10-26); the two-take rule still caps art retries. Run tooling and features as `Arm: sonnet-high` or `Arm: worker` in turn until each arm has 15 runs stamped with it in the category (unstamped runs do not count), then at the lower API-equivalent spend per closed box, which stands for the cheapest tier whose landed work does not raise rework (follow-up fixes, reverts, red-main culprits and review findings; north docs/rationale/tier-routing.md says which of those terms are measured yet); `north dispatch` and `north fleet launch` (with `--task REF`, or a worker brief whose header names no issue; one with no `Category:` there is refused) both do it from the brief's `Category:` line (dispatch falls back to the issue's labels and refuses a box nothing categorises), stamp the `Tier:` and `Arm:` lines, and start the session on that tier's model and effort (Sonnet only ever at high, which the fleet registry enforces on every launch and revive), so launch with no `--model`; a `--model` of another family, or any `--model` on a launch that holds no issue, is refused without `--tier-reason TEXT` or a `Tier-reason:` brief line, which the session records. Start unknown-cause debugging, netcode-determinism, architecture, planning and every other Opus-range item at `worker`. Restaff every stop at the same tier with a `Follows:` brief carrying the failed evidence, and escalate one tier only after a second `Stop: reasoning` on the same box, because most stops are brief or capacity faults. Until each arm has 15 runs, send those second reasoning stops in turn to `Arm: escalate`, `Arm: cheap-fix` (same tier, better brief) and `Arm: split`, so the ledger can compare them. When the next tier cannot run here, bring the supervisor one recommendation.
- Send mechanical work (exact, fully specified edits, box ticks, rebases, regeneration, conflicts, running a named check) to `worker-haiku`, and retry a Haiku miss at `sonnet-high`, never Opus. Policy, skill and documentation prose (`Category: docs-policy`) goes to `worker`, never Haiku, because Tom wants it written carefully. Bisects and native checks go to `worker` or stay with the lead, and a Haiku brief says to wait on any run over a minute with Monitor, because Haiku ended its turn mid-run. Run the haiku trial in [notes](references/notes.md).

## Review

- Covered harness changes land only with a `Reviewed: <verdict>; reviewer: <reviewer session>; patch-id <id>` trailer from a fresh reviewer who did not author the change (review-gate refuses a reviewer named as the session that landed it, and the landing records the reviewer in tasks.review) (a Claude reviewer of a different tier from the author), because authors miss their own drift. The reviewer reads the final diff and prints the id from `north review-gate id origin/main HEAD $(safe-push --durable-harness-paths <repository>)` run in the lane; the author copies it into the trailer. safe-push refuses a landing whose covered diff has another id, so an edit after the review needs a new review; a rebase keeps the id unless main changed a line next to the change. Policy text Tom dictated lands with `Reviewed: Tom (dictated YYYY-MM-DD); patch-id <id>` and no agent reviewer, because no reviewer overrules his own words.
- Before staffing a planner's architectural design, have one fresh Claude reviewer of a different tier (Opus for a Sonnet author, Sonnet for an Opus author) try to break it, and revise once, because an author shares its own blind spots.
- Before landing, an independent review checks the work against Tom's intent and cuts formal machinery the spec does not ask for. Before landing a `Spec: judged` cross-module or cross-repo lane, a fresh Claude reviewer of a different tier checks the diff for wrong behavior and weakened tests; fix what it finds before `safe-push`.
- Read [planner effort](references/notes.md#planner-effort) before staffing `planner`, and [review lenses](references/notes.md#review-lenses-and-findings) before staffing adversarial reviewers or weighing their findings.

## Placement and cloud

- Send every code-only item in every repository (north, south, nixos-config, firn, smashcraft, wisp) to a cloud worker first, builds and ports included, because local cores are reserved for clients and native work; a direct `codex exec` or cargo run on the laptop is a local worker. Staff local workers only for real-game clients, private game assets, the LAN pool or unpushed local state. A broken or slow cloud lane is an incident to fix the same tick, never a reason to run code-only work on the laptop.
- `north fleet launch` places each box before it starts (`agents plan --place BRIEF` prints the same verdict): `anthropic-cloud` per [cloud.md](references/cloud.md) for a code-only public box while the credit lasts, otherwise the Claude account with the most headroom, or `held: <reason>`. An account is out only when its 5h window is at or over 95%, its measured 5h burn is over 50%/h (the `five_hour_burn_cap_pct_h` default, so a window lasts at least two hours), or the provider reports its week exhausted; pace lines, projections and the pace controller's held, over and allowed workers never hold, in `north fleet launch` and the Agent-tool spawn gate alike. Declare `Surface:` on every brief and mark a box that is not code-only with `Needs: warcraft|native|sign-ins|private|local-state|tui|fleet`, because an undeclared box stays local. Override only with `--local "REASON"` or `--account A --pin "REASON"`, which the session records.
- Send a worker's native-window or GPU work to the remote Warcraft host (south:agents/skills/battlenet-accounts/) while Tom is present, because an agent's 5696x3680 native window held the laptop GPU at 100% and made his desktop choppy (2026-10-31); capacity admission queues it on the laptop.
- Read [payback.md](references/payback.md) before briefing a tooling or infrastructure box: its Payback line, the iteration ledger and the dashboard refresh.

## Run and land

- A child launched with `--parent` reaches that parent as one fleet message, queued behind a busy parent, when a turn with a reply ends on `Done:`, `Not done:`, `Split:`, `Stop:` or `Blocked:`, lands a commit, or fails, so restaff on that message and never on the next heartbeat; progress, interrupted and empty turns post nothing.
- Expect a report at 45 minutes or twice the ETA, whichever is first. Long-running work continues in a fresh fleet session with `Follows:` and the prior session as parent.
- Run anything that may take over about 45 seconds in the background (Claude `run_in_background`, Codex a background or unified-exec session), because a foreground wait delays every message to you.
- A brief's Budget line is a pacing signal, not a bill: read your API-equivalent spend with `north fleet spend --self`, and at the line commit and land any change already passing its checks, then report `Split:` with the remaining parts as boxes; never stop with passing work unlanded, because each stop at the line on 31 Oct left finished work for a restaff to re-read.
- Count working sessions, not resident ones, against a host slot: an idle session or one parked on a registered run takes none, and dispatch fills each host to its target of working sessions. A worker (and a lead) that starts a farm run, an Autoland landing, a capture batch or a background job longer than about 5 minutes registers it with `north fleet wait job:NAME|farm:ID|branch:BRANCH|capture:PATH` and ends its turn; the session parks, keeps its claims, and `north fleet waits` (dispatch every 5 minutes, laptop-runner on the laptop) revives it with the run and its result. An idle session with no registered wait parks at the 10-minute idle limit and revives on its next message.
- Land as [notes](references/notes.md#landing-mechanics) describes for Autoland and other repositories. Lane lifecycle and `lane-gc` belong to `repo-safety`; every unlanded lane `lane-gc` keeps shows in its lead's tick as an `OWNED` row, which the lead continues, lands or archives, and a lead holding more than 25, or any older than 72 h, gets a supply-alert.
- Run at most as many native workers as free client slots (machine-capacity allows 4 Warcraft clients, 2 per pair), and give each a box that fits 45 minutes, because on 19 Oct three native workers queued on slots and five hit leash or context limits mid-run.
- Tell Tom only what changes his next action: a landed fix (with its build), a result, or a decision; never relay a worker's interim "still waiting", because status chatter buries what he must act on.
- File an unproven process idea as an issue and promote it to policy only after a measured result. Finish an issue's last unchecked box before starting new work, and after an hour with no closure start nothing new until an open box closes, because open boxes are the throughput.
- On a stall or saturation alert from `north flow`, which repeats every 15 minutes while it lasts, diagnose and act within 15 minutes (stop launching onto the host, move work to a free host, clear the blocker) and report only the result to Tom, because a pipeline left alone cost 2 hours of landings on 2026-10-29.

## Reports

- A worker's last message is its report and the runtime records delivery and completion, so keep no status files, ACK lines or re-pushes, and never resume a worker to check on it.
- Every report begins `Done:`, `Not done:`, `Blocked:` or `Split:`, and every Not done or handoff names `Stop: landing|capacity|client|leash|reasoning|decision`, so the ledger can classify it.
- Report a fix as landed only after fetching origin and verifying its SHA is an ancestor of `origin/main`, because queued or Autoland-green is not landed; until then report `Done: queued <branch>`.
- A worker that finds independent parts, or projects past twice its ETA, reports `Split:` with the parts as boxes, each with a Done when and what it learned. Those boxes go on its own issue, never into new issues, because the open-issue count measures open outcomes (Tom, 2026-10-29). Fix a finding that fits in 20 minutes in the current lane and land it with the task instead of filing it, and put ideas under `Ideas:` in the final report (Tom, 2026-10-30). The `gh issue create` guard states what a worker may file.
