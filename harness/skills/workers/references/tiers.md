# Tier routing in full

Read this when the routing line in `SKILL.md` does not settle a tier, an arm trial applies, or the next tier cannot run here. Ledger experiments behind these rules are in [notes.md](notes.md#tier-and-ledger-experiments).

- `north worker-ledger --summary` shows each category's success; `--recommend` picks the tier. Choose provider and fast mode with `agents plan`, which reads the signed-in providers and live `agents usage` headroom, because hand choices drained the wrong account.
- Start art (animation authoring and judging, `Spec: judged` art boxes) at `sonnet-high`; the two-take rule still caps art retries.
- Run tooling, features, known-cause bugs, native checks and balance tuning as `Arm: sonnet-high` or `Arm: worker` in turn until each arm has 15 runs stamped with it in the category and 15 closed boxes whose first run carried it (unstamped runs and boxes do not count), then at the arm's lower API-equivalent spend per closed arm box over 30 days, which stands for the cheapest tier whose landed work does not raise rework (follow-up fixes, reverts, red-main culprits and review findings; north docs/rationale/tier-routing.md says which of those terms are measured yet).
- `north dispatch` and `north fleet launch` (with `--task REF`, or a worker brief whose header names no issue; one with no `Category:` there is refused) both route from the brief's `Category:` line (dispatch falls back to the issue's labels and refuses a box nothing categorises), stamp the `Tier:` and `Arm:` lines, and start the session on that tier's model and effort (Sonnet only ever at high, which the fleet registry enforces on every launch and revive). A `--model` of another family, or any `--model` on a launch that holds no issue, is refused without `--tier-reason TEXT` or a `Tier-reason:` brief line, which the session records.
- Start unknown-cause debugging, netcode-determinism, architecture, planning and every other Opus-range item at `worker`.
- Restaff every stop at the same tier with a `Follows:` brief carrying the failed evidence, and escalate one tier only after a second `Stop: reasoning` on the same box, because most stops are brief or capacity faults. Until each arm has 15 runs, send those second reasoning stops in turn to `Arm: escalate`, `Arm: cheap-fix` (same tier, better brief) and `Arm: split`, so the ledger can compare them. When the next tier cannot run here, bring the supervisor one recommendation.
- Mechanical work is exact, fully specified edits, box ticks, rebases, regeneration, conflicts and running a named check. Policy, skill and documentation prose (`Category: docs-policy`) goes to `worker`, never Haiku, because Tom wants it written carefully. Bisects and native checks go to `worker` or stay with the lead, and a Haiku brief says to wait on any run over a minute with Monitor, because Haiku ended its turn mid-run. Run the haiku trial in [notes](notes.md).

The Agent-tool spawn guard applies the same authority: a `worker*` spawn is refused when its brief has no `Item:` line, or when the subagent tier differs from the tier `route()` picks for the brief and the brief carries no `Tier-reason:` line (a `Follows:` escalation is exempt).

Where a box runs (decided 2026-11-04, gate default): a box that builds, waits on a run or lands is a fleet session (own identity, `north fleet wait`); an in-process Agent subagent is for read-only research. The spawn guard enforces it: a `worker*` Agent brief without `Category: research` is refused with the `north fleet launch` instruction.
