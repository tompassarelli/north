# Cloud workers (Claude-only)

Read [Placement](#placement) for where a box runs. Read the rest when `north fleet launch` refuses a box for `anthropic-cloud` (or `agents plan --place` prints `target anthropic-cloud`), or when you write a RemoteTrigger routine. Both lanes run Claude in Anthropic's cloud.

The launcher enforces placement: `north fleet launch` of a code-only box on a public repository exits nonzero with the cloud-host `north cloud launch` command below and how the box lands, unless `--local "REASON"` is given, which the session records and `north fleet list` shows. A box is code-only only when its brief declares a code `Surface:` (rust, ts, lua, shell...), no local `Needs:` (warcraft, native, sign-ins, private, local-state, tui, fleet, live) and a public repository (`Repository:` or the `Item:` repo); an undeclared box stays local.

## Placement

Read this section when a box may need a local client, a GPU or the laptop, when placement holds it, or when you override it.

- Send every code-only item in every repository (north, south, nixos-config, firn, makgora, wisp) to a cloud worker first, builds and ports included, because local cores are reserved for clients and native work; a direct `codex exec` or cargo run on the laptop is a local worker. Staff local workers only for real-game clients, private game assets, the LAN pool or unpushed local state. A broken or slow cloud lane is an incident to fix the same tick, never a reason to run code-only work on the laptop.
- `north fleet launch` places each box before it starts (`agents plan --place BRIEF` prints the same verdict): `anthropic-cloud` per this file for a code-only public box, run under the Claude account with the most headroom on the host where that account is signed in (the verdict names both), otherwise the Claude account with the most headroom, or `held: <reason>`. An account is out only when its 5h window is at or over 95%, its measured 5h burn is over 50%/h (the `five_hour_burn_cap_pct_h` default, so a window lasts at least two hours), or the provider reports its week exhausted; pace lines, projections and the pace controller's held, over and allowed workers never hold, in `north fleet launch` and the Agent-tool spawn gate alike. Declare `Surface:` on every brief and mark a box that is not code-only with `Needs: warcraft|native|sign-ins|private|local-state|tui|fleet`, because an undeclared box stays local. Override only with `--local "REASON"` or `--account A --pin "REASON"`, which the session records.
- Tell a worker whose output Tom is waiting on to add `--priority tom-ask` to its capacity runs, and never to use `--class tom`, because the tom class belongs to the play path's own builds and machine-capacity refuses it for other owners, while the priority places the ticket first in its class and still obeys pressure (north#460).
- Send a worker's native-window or GPU work to the remote Warcraft host (south:agents/skills/battlenet-accounts/) while Tom is present, because an agent's 5696x3680 native window held the laptop GPU at 100% and made his desktop choppy (2026-10-31); capacity admission queues it on the laptop.

## Cloud credit lane

The credit's account, login, host, expiry, spend rate, environment and routine IDs are in south:agents/skills/claude-accounts/; this section is the method.

- Cloud compute has no separate charge and a cloud session draws its account's plan limits, so placement sends a code-only box to `anthropic-cloud` on any account with headroom (an account out by the 5h or week stop is never chosen), and the credit (`[placement] cloud_credit` in orchestration.toml names its costs.toml entry) is only an extra balance a session on its account spends first, shown on the verdict line whether unread, spent or expired.
- Run it on the host the verdict names, with `CLAUDE_CONFIG_DIR=$HOME/.local/state/north/profiles/claude-LABEL` set so `north cloud` uses that account's login (the printed command does), and never change or copy a login.
- Start: write the brief to `/tmp/cloud/NAME.md` on the launch host and run `north cloud launch REPO NAME /tmp/cloud/NAME.md` there (`north dispatch` does the same for makgora and wisp). It refreshes a depth-1 checkout of the public repository under `/tmp/cloud/src/REPO` (depth-1 refetch of main with every file, local `main` tracking `origin/main`; a partial clone cannot be bundled, so a login without GitHub connected, as claude:d, fails to launch from one), writes `hasTrustDialogAccepted` for it into the login's `~/.claude.json` just before launching, because running sessions rewrite that file and drop the entry, and runs `claude --cloud` from it with the cloud safety line and the landing steps appended. A session launched from a folder that is not a checkout of the target repository gets 403 on push. It prints the `session_...` ID and `claude/land-NAME`; record both in the brief's thread.
- Every cloud brief carries this line, because cloud sessions always run in auto mode and send a permission prompt to the account owner's devices for some Bash calls, which no launch flag suppresses (three probes on 15 Oct): "Run only build, test, git and file commands inside your clone and /tmp. Never kill, pkill or signal a process, never use sudo, and use no network beyond git clone, git fetch and package installs. If a command is blocked or would need approval, do not retry it or work around it; stop and report `Blocked:` with the command." `north cloud launch` appends it with the one push allowed, `git push origin HEAD:refs/heads/claude/land-NAME`. Never answer a cloud prompt for Tom.
- Every tick of a lead with cloud sessions out runs `north cloud sweep /tmp/cloud/swept` on the cloud host, so a prompt never sits waiting on Tom: it saves and archives each cloud-run session waiting on a human, and never touches a Remote Control session (kind `bridge`), because archiving one cut the proxy's link to Tom on 15 Oct. Restaff a swept box with the blocked step named.
- Never teleport a cloud session, because `claude --teleport <id>` stops it (4 of 6 on 15 Oct ended `Interrupted` and lost their work). Read sessions on the cloud host with `north cloud list` (id, status `running|idle|requires_action|archived`, kind, update time, title) and `north cloud events <id> OUT.jsonl` (whole transcript, without stopping it). Collect a session once it is `idle`; one still `running` at twice its ETA is restaffed with `Follows:` and a smaller scope.
- Wait for a session whose push failed with `north cloud wait <id> OUT.jsonl [--after UUID] [--timeout SECS]` (default 3600): it polls every 30 s and writes the transcript once the session is `idle` and its newest `assistant`, `user` or `result` event ends the turn (a `result`, or an `assistant` reply with `stop_reason` `end_turn`, never a pause between tool calls), and exits 1 on timeout. Never watch for `Done:` wording instead, because a report whose `Done:` paragraph came before trailing notes delivered the #53 handback about 2 h late.
- A session that went `idle` mid-task without pushing or handing back is resumed with `north cloud send <id> FILE`, which posts FILE as a user message and prints the HTTP status and the message's uuid (200 moves it back to `running`); pass that uuid to `wait --after`, because the session can still read `idle` with its previous `result` for a moment after the send; write FILE as the next instruction, for example "finish the brief and push its land branch", then `wait` again. Never restaff it instead, because that loses its unpushed work.
- The session lands by pushing, through the Claude GitHub App on tompassarelli: its last steps run the repository's checks, set `git config user.name tompassarelli` and `user.email 6378995+tompassarelli@users.noreply.github.com`, rebase onto origin/main, fold the work into one commit with `git reset --soft origin/main` and commit it with no `Claude-Session:` or `Co-Authored-By:` trailer, because an earlier commit's private email or session URL makes the deny-list refuse the branch, and push `claude/land-NAME`.
- In an Autoland repository (makgora, wisp) it reports `Done: queued claude/land-NAME` and no courier runs: the `denylist-attest` timer on the cloud host attests the branch and dispatches Autoland, and the box is collected when the branch lands.
- In north the session reports `Done: pushed claude/land-NAME`, and a courier on another host, never the cloud host, fetches the branch once `git ls-remote origin claude/land-NAME` shows it, reruns the checks in a worktree and lands it with `safe-push --to main`.
- The proxy refuses branch deletes, so whoever collects a landed or abandoned `claude/land-*` branch deletes it with `git push origin --delete` from a host with GitHub write access.
- The patch handback remains only for a private repository, which the app cannot reach, and for a session whose push was refused: the brief's fallback is `git format-patch origin/main..HEAD --stdout | gzip -9 | base64 -w 76 > /tmp/handback.b64`, then one Bash call per 300-line part i of n, because a transcript keeps only the first 30,000 characters of one tool output: `echo BEGIN-HANDBACK part i/n; sed -n <first>,<last>p /tmp/handback.b64; echo END-HANDBACK part i/n`. It hands back through a Bash call, never a retyped patch, because retyped base64 arrived corrupted for 3 of 5 sessions on 15 Oct.
- To decode a handback, run `north cloud collect EVENTS.jsonl OUT.mbox` on the saved `events` transcript: it reads the file only, needs no login and never teleports or transfers the session. It takes the latest handback in the tool outputs, joins each part's lines in part order and pipes them through `base64 -d | gunzip`; a missing part, a failed decode or output not starting with `From ` exits 1 as corrupt (restaff the box), and empty output exits 1 saying the session committed nothing. Apply the mbox with `git am -3` in a worktree, re-author each commit with `git commit --amend --no-edit --reset-author` and drop the `Claude-Session:` and `Co-Authored-By:` trailers, because the patch carries the login's private email, then land it through safe-push.
- Only the credit account's claude.ai usage page shows the balance, so never open it; record Tom's readout as cumulative `usd_spent_period` with `read_at` in the file the credit's `readout` line in south:agents/costs.toml names. `agents plan --credit` prints `cloud credit: unread, expires in N days` while no readout is under 7 days old, and the tick asks Tom weekly.

## RemoteTrigger routines

- Use them only for public Wisp/Mak'gora code tasks without private or local inputs, Warcraft clients or Tom's install, because the routine clones the public repository and nothing else.
- Budget 4 cores, 15 GB, Bun 1.4.2, gcc/clang and 100 runs/hour/account; use the repositories' pinned Bun 1.3.13, and build Lua 5.3.6 with LUA_32BITS or Wisp's pinned command when Lua is required, so results match local checks.
- Keep account extra usage off so plan limits pause work instead of billing.
- Run RemoteTrigger only from the main session and reuse one routine per repository, because routines are deleted only by hand at claude.ai/code/routines.
- Set `session_context.model` on every update (`claude-opus-5-5` for meaningful or complex work, `claude-haiku-5-5` for very simple mechanical work), because an unset model falls back to an unchosen default.
- Update the brief with a fresh v4 UUID, then run it in a separate later call, because a run sent in parallel with its update fires the previous prompt. Keep the returned session ID and read the result with get_run_log or list_runs.
- The brief is self-contained (goal, files, Done when, ETA, `Refs repo#N` commits, no push notifications), fetches and rebases onto origin/main right before its push, because most cloud refusals are conflicts from main moving during the run, and ends with `push to claude/<name>; it lands itself if it passes`.
- Autoland rebases, checks, runs the farm compare and lands sequentially; fix conflicts or new failures on the same branch. Read a refusal's reason in its run's job summary and annotation (`gh run list --workflow autoland.yml --branch claude/<name>`, `gh run view ID`), because Autoland posts no issue comments. Retry with `gh workflow run autoland.yml -R tompassarelli/<repo> -f branch=claude/<name>`. Land workflow changes locally through safe-push. Each repository's docs/ci.md Autoland topic has the landing details.

Routine schema:

```json
{"name": "<repo>-cloud-worker", "run_once_at": "<far future>", "enabled": true,
 "job_config": {"ccr": {
   "environment_id": "<environment_id>",
   "session_context": {"model": "claude-opus-5-5",
     "sources": [{"git_repository": {"url": "https://github.com/tompassarelli/<repo>"}}],
     "allowed_tools": ["..."]},
   "events": [{"data": {"uuid": "<fresh v4>", "session_id": "", "type": "user",
     "parent_tool_use_id": null,
     "message": {"role": "user", "content": "<PROMPT>"}}}]}}}
```

Each repository's routine and environment IDs are in south:agents/skills/claude-accounts/. An API-created routine needs one save in the web editor to bind it.
