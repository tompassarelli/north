# Runtime incident cases

Read when unsure whether an observation seeds, joins, splits or closes an incident.

## Silent worker

An admitted worker starts, then passes its supervisor window without liveness or valid terminal reporting. Preserve admission, last activity, liveness, control and reporting evidence, compute the signature and create one record; a second complete-signature observation increments it. Quarantine only that worker seam. A replacement or already-authorized fallback keeps delivery moving while one priced reproduction tests the hypotheses. Closure needs the owner's repair, the focused regression, activation, restored topology, a primary-path canary showing healthy startup, liveness, control and terminal reporting, and the runtime's restoration-debt exit evidence. If fallback delivery finishes first, delivery is complete while the incident and debt stay open.

## Retry with a new run identity

A retry changes only the run identity and timestamp; every signature field is unchanged. It increments the existing record instead of creating another.

## Same shape, different seam

Two failures share lifecycle class, operation, call shape, runtime mode and error class, but one affects worker admission and the other terminal reporting. Their seams differ, so they produce two signatures and two records.

## Opaque report payload

A sub-lead emits an opaque token where its parent expects a plaintext status card. The tuple is `reporting`, the sender role, `parent plaintext-status-card`, `agent-report/message-body`, `opaque-token:<prefix>`, the runtime mode, `opaque-report-payload` and `sub-lead-terminal-reporting`. Keep only the normalized token prefix, never the token body. A plaintext resend admitted by the runtime after side-effect proof keeps delivery active; its route and debt facts join the same record and do not close it.

## Reopen rejects stale evidence

A closed generation recurs with the same signature. Reopening increments the generation; old repair, regression, activation, canary and debt-exit evidence is history only, and the new generation passes through every state before closure.

## Not an incident

A worker inside its supervisor window, an expected cancellation with complete reporting, or an explained policy rejection is not an unexplained failure. Do not quarantine adjacent workers, seed per retry or observer, merge distinct seams, promote fallback to the default, count fallback success as the primary canary, or close reliability because the artifact was delivered.
