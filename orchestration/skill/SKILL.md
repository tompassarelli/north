# Orchestration — read the doctrine before you dispatch

The doctrine is one file and it is canonical. This skill is only the pointer:
it does not restate the laws, and a summary of it is not a substitute for it.

**Read `~/code/north/main/orchestration/doctrine.md` in full now**, before the
dispatch decision. (Relative to this skill directory it is `../doctrine.md`.)

It carries what you need and this file deliberately does not duplicate:

- the orthogonal axes (function/role · task grade · domain requirements ·
  topology · semantic tier · deliberation · posture) and the rule against
  smuggling one decision inside another
- SHAPES → TEMPLATES: which template plays each task shape, at which pinned
  semantic tier, and the exact agent type name to invoke
- the routing laws (minimum-sufficient floor, shingle, quality floor, pinning,
  blast radius, when delegation actually buys delivery, owner judgment)
- resource policy, substitution vs. degradation, and allocation strategy
- orchestrator/worker jurisdiction law, the stop-rule, reduction to the
  immediate parent, and settlement gates
- the adapter's concrete spawn surface, and the bespoke-composition spec for
  when no template fits

Read it, then route. Do not route from memory of it — the templates, pins, and
laws change, and a stale recollection is exactly the failure this pointer
exists to prevent.
